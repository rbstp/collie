# Rex backend

Spike for [#703](https://github.com/rbstp/collie/issues/703), 2026-11-12. This page is the design of collied's Rex backend for "Phase 8: Rex integration", the evidence behind it and the issues that built it. All phases are built: 1 (agents and status, #704), 2 (screens, #705), 3 (input and approvals, #706), 4 (sessions, #707) and 5 (tasks, #708), then the removal of an archived task's own session (#727); 6 (#709) found that Rex.app does not follow focus, so focus stays refused. [Shape](#shape) says how each phase was built, and [architecture.md](architecture.md#rex) what collied does with Rex. Since #765 a watched terminal is followed as a stream ([Streams](#streams-765)), and since #755 a block that runs a shell is listed under Terminals, as herdr's shells are ([Terminals](#terminals-755)). The phone's **Start tasks in** setting (#723) and the agents each runtime starts (#729) are in architecture.md; Copilot CLI stays read-only in Rex ([Copilot CLI](#copilot-cli-741), #745). Most of the design reuses herdr-core's: its design is [herdr-core.md](herdr-core.md), and what collied does with it is in [architecture.md](architecture.md#herdr-core-herdr-core).

## Summary

- Rex 0.1.0-preview.16 (API revision 13) already gave collied what it needs to follow Claude Code agents beside herdr's, with no hook and no polling for status. Each terminal block keeps the OSC 7501 status its programs report (`program_status`, pushed as `program_status_changed`) and its foreground process (`process`, pushed as `process_changed`), reads its screen as text or escape sequences (`format`), and takes pastes and named keys (`block.event`). The issue's list of what Rex leaves undocumented predated that build: the server documents its whole API, both WebSocket protocols included, at `/llms.txt` on its own socket.
- Claude Code 2.1.322 reports `idle`, `working`, `blocked` (`kind: permission`, `msg: approve Bash: touch rex-spike-probe.txt`) and `done` in a Rex block, as it does under herdr-core, and nothing at its folder trust prompt (verified). Codex and Copilot CLI were not run in the spike (Codex was in #707, Copilot CLI in #741): Codex reports OSC 7501 under herdr-core. Copilot CLI 1.0.106 and later reports too, but `idle` at its folder trust prompt and with a picker open, so only an agent whose record names Claude Code or Codex takes phone input, and a Copilot agent is read-only ([Copilot CLI](#copilot-cli-741)).
- collied talks to the control WebSocket (`/api/control`, subprotocol `rex.control.v1`) and never runs the CLI. A call costs 0.2 to 0.3 ms on an open connection against 25 to 35 ms for each `rex` process, and status, process and title changes arrive as events. collied already depended on `tokio-tungstenite`.
- collied's approval parser, menu gate and fingerprint read the screen as text, and Rex's `format` text works for them unchanged; as built (#705), that text comes from collied's `alacritty_terminal` emulator fed with `format`'s VT output, which draws the same screen as the text (verified). Reads and watches poll `format`, as collied polls herdr: every poll is the terminal's whole current state, so no output is applied twice or lost. A poll costs about 1 ms at 1,000 lines of scrollback and 39 to 46 ms at 100,000. The data stream was not used at first: nothing lines it up with `format`, and it opens with a binary Ghostty snapshot (4.5 MB at 100,000 lines) that `alacritty_terminal` cannot read ([Screen](#4-screen)). Since #765 a watched terminal is followed through it with libghostty-vt, which reads the snapshot, and costs Rex 0.9% of a core where polling cost 28 to 32% ([Streams](#streams-765)).
- Lost or weaker for a Rex agent: `terminal.send`'s `if` and its typing hold, which Rex has no equivalent for, closing a whole Rex session from the phone (refused, as for a herdr-core group), and desktop focus (Rex.app does not follow `session.focus_block`, #709). Built in collied: the agent kind, the session binding (Claude Code's `sessions/<pid>.json`, as for herdr-core), `state_change_seq`, task records and worktrees.
- Shape: a third runtime beside herdr and herdr-core, `crates/collied/src/runtime/rex/`, with ids `rex:block:<uuid>`, one group per Rex session (`rex:session:<uuid>`), and the phone protocol unchanged.

## What Rex is

- One server per user, owning sessions, their windows (tabs) and their blocks (today, terminals). Clients such as Rex.app and the CLI connect to it. Ids (`session:<uuid>`, `window:<uuid>`, `block:<uuid>`, UUIDv7) never change and are never reused; labels can change and repeat.
- The CLI finds the local server at `$REX_RUNTIME_DIR/server.sock`, else `$XDG_RUNTIME_DIR/rex/server.sock`, else, on macOS, `~/Library/Application Support/rex/server.sock`, where Rex.app's server listens; `REX_SERVER` and `-S` name another server (verified from the CLI's errors on scratch paths). Linux without `XDG_RUNTIME_DIR` was not checked (the API examples in the binary show `/run/user/1000/rex/server.sock`). A socket path over 103 bytes is refused. A personal server's socket is `0600` in a `0700` folder, and the server admits callers by their peer credentials. Rex also documents a shared server on Linux (`/run/rex/server.sock`, open to the `rex` group, programs run as `rex`) and network listeners, all off by default.
- Two WebSockets on that socket. `/api/control` (`rex.control.v1`): a `hello` naming the API revisions the client speaks, a `welcome`, then JSON requests, responses and events; each response carries the `seq` of the last event it already reflects. `/api/data`: one block's output per connection, opened with a single-use ticket from `data.connect`.
- Events: a connection receives a session's events, block events included, once it calls `session.attach` (or `session.bootstrap`); `session.attach_all` with `event_scope: session` adds sessions being created and destroyed but no block events, and `event_scope: all` adds every client joining and leaving (each CLI call is four events). `seq` counts per connection and starts again at 1 on a new one.
- A terminal block's methods include `format` (text, HTML or VT, screen and scrollback), `program_status`, `process`, `title`, `size`, `modes`, `write`, `resize`, `blob_read`, `list_dir`, `upload_begin` and `download_begin`. Its events include `program_status_changed`, `program_status_removed`, `process_changed`, `title_changed`, `size_changed`, `child_exited` and `desktop_notification`.
- Every terminal gets `REX_SESSION`, `REX_BLOCK`, `REX_BIN_DIR`, `TERM_PROGRAM=rex`, `COLORTERM=truecolor` and the server's own environment (verified: the scratch server's `REX_CONFIG` and `XDG_*` reached its blocks). The docs add `REX_SERVER`; a server started with `rex server run` did not set it, and Rex.app's own server (build 1972) did, with `TERM_PROGRAM_VERSION`, and passed no `HC_*` or `HERDR_*` variable (a one-off manual check on the owner's server with their permission, #707).
- A client may own a block, which then takes that client's size and colors; a client that creates a block owns it. A block kept its creator (the CLI) as owner after that client left, and another client's resize then waited (seen). A block no client owns or sized is 80x24.
- The server saves each terminal's screen to disk (`<state>/terminal/<pid>-<id>/<uuid>.snap`, `0600` in `0700` folders), even with `--restore=false`.
- Beyond terminals, the API stops the server, turns Tailscale on and signs it in, edits the host list, grants macOS file access, loads and runs Lua (`client.set_script`, `client.action`), asks Rex.app to perform its actions (`client.perform`), lists folders and moves files (`list_dir`, `upload_begin`, `download_begin`).

## Questions

### 1. Agent status

- Rex keeps it. `terminal.program_status` lists the records programs reported with OSC 7501: `state` (`idle`, `working`, `done`, `blocked`, `error`), `kind` on a blocked record (`permission`, `question`, `auth`), `app`, `msg`, `updated_at`, and `owner`, the foreground process (pid and name) when the report arrived. `program_status_changed` carries each report, even one that changes only `updated_at`; `program_status_removed` drops records, with a reason (`clear`, `child_exited`, `reset`, `prompt`, `foreground`, `evicted`). Claude Code reports the root record (no `id`).
- Claude Code 2.1.322 in a Rex block: `idle` with `app: claude-code` once started, then `working`, `blocked` (`permission`, with its `msg`) and `done` (verified). At its folder trust prompt it reported nothing (no records), so it stays read-only from the phone until it reports, as under herdr-core.
- Rex 0.1.0-preview.16 dropped a record when its program was suspended (Ctrl+Z: `program_status_removed`, reason `foreground`), unlike herdr-core 0.1.16, but kept the record of a program that exited with its shell leading the terminal again (both checked with a stand-in reporting `app=codex`, under a zsh without shell integration, so no `prompt` reason). 0.1.0-preview.19 (build 1985, API revision 14) keeps it through Ctrl+Z and `fg`: no `program_status_removed`, and `program_status` lists the record, its owner unchanged, all along (#719, stand-ins that report once, under `sh -i` and `zsh -f -i` on a scratch server). collied keeps herdr-core's rule (no terminal whose foreground process is a shell is an agent) and adds one Rex allows: a record whose `owner` is not the current foreground process (pid and name) is stale.
- Claude Code and Codex on suspend and resume, checked by the owner on 2026-11-15 on Rex 0.1.0-preview.19 (API revision 14) with collied's listing sampled once a second (#719; Claude Code 2.1.325, Codex 0.169.0): each leaves the list at Ctrl+Z, since the shell leads the block, and is listed again after `fg` (5 to 6 s after it left the list, with `fg` typed about 5 s after Ctrl+Z) with the status it had, `done` for Claude Code and `idle` for Codex. The same process leads the block again, so the record Rex kept is its own and collied lists it, and on preview.19 the agent takes input from the phone as before; a server that drops the record on Ctrl+Z, as preview.16 at revision 13 did, would list it with no status, so read-only, until it reports. Whether either reports on resume does not show here; under herdr-core, Claude Code does not, and Codex apparently does ([herdr-core.md](herdr-core.md#input)).
- No hook is needed for status. Claude Code's hooks ran in the Rex block with `REX_BLOCK` set (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest and Stop, from a scratch `--settings` file), so a hook could report it, but the server already has the status. Codex needs collied's SessionStart hook for its session, as under herdr-core, reading `REX_BLOCK` as it reads `HC_TERMINAL_ID` (verified, #707: Codex 0.167.1 reports `idle` and `working` with `app: codex`, and runs the hook as a child of the Codex that leads the block, with that block's `REX_BLOCK`).
- Copilot CLI 1.0.105 reports no OSC 7501 (herdr-core spike), so it is listed `unknown`. 1.0.106 and later reports, but `idle` at its folder trust prompt and with a picker open, so in Rex, as in Herdr Core, only an agent whose record names Claude Code or Codex, with a matching foreground CLI, takes phone input, and a Copilot agent is read-only ([Copilot CLI](#copilot-cli-741), #745).

### 2. Identity and kind

- `terminal.process` describes the `foreground` process, its `ancestors` up to the terminal's `child`: `pid`, `name` (the executable's file name; Claude Code's is its version, `2.1.322`), `path`, `invoked_path` (`~/.local/bin/claude`), `argv0` (the only argument Rex returns, cut to 256 bytes) and `cwd`.
- A block is an agent once it reports OSC 7501 or its foreground process runs an agent CLI, as for herdr-core. Kind: the status record's `app` (`claude-code` is `claude`), else the basename of `argv0` among `claude`, `codex` and `copilot` (verified: `claude`). A shell is the basename of `argv0`, a leading `-` aside, in herdr-core's list (`zsh` verified). Plain shells and other programs were not listed; since #755 a block that runs a shell is listed as a terminal ([Terminals](#terminals-755)), and other programs still are not.
- `process_changed` pushes each foreground change, so the kind needs no polling. It is also sent each time a client starts receiving a terminal's output.
- A block whose `host_id` differs from the server's runs on another machine and is skipped, as herdr-core's `box/t7` (not verified: every block here was local).

### 3. Transport

- The CLI works, one process per call: `rex events -s SESSION --json` held open streams that session's block events, `rex block call -b BLOCK METHOD ARGS` makes a call. A call took 41 to 49 ms under `sandbox-exec`, whose own start costs 15 ms, so 25 to 35 ms. Without `-s`, `rex events --json` carries no block events; with `--all`, every client's coming and going. With no server, calls exit 4 as documented, except `rex server status`, which exits 1; a missing block exits 3 and a usage error 2.
- The control connection: 0.19 ms for `program_status`, 0.25 ms for `process` or `format` of a small screen, 0.34 ms to connect, say hello and make one call (measured over a Unix socket from Python). Status, process, title and size changes are pushed, so nothing is polled for them; screen output has no event (only the data connection carries it).
- collied therefore follows Rex on one long-lived control connection: `tokio-tungstenite` (a dependency already, 0.30.0) over a `UnixStream`, without compression, answering the server's pings (every 120 s). It subscribes before it reads, so nothing that happens in between is missed: `session.attach_all` with `event_scope: session` first (sessions created and destroyed, not `event_scope: all`), then `session.list`, then for each session `session.attach` (its block events from then on) followed by `session.list_blocks` and the reads of each block. An event whose `seq` is at most a read's response `seq` is already in that read; a later one is applied on top, and a session created meanwhile is attached and read the same way. After a reconnect `seq` starts at 1, so collied does all of it again.
- Method check: the `hello` sends `api_revision: 13` and `api_min_revision: 13`, so an older server closes the connection (1008) instead of answering in older shapes. Then the server methods collied calls must be in `help.all`'s `methods`, and the terminal methods in `block_creator.list`'s `com.superlogical.terminal` creator, each against the set collied calls ([Effort and phases](#effort-and-phases)); otherwise collied does not follow that server and `doctor` names what is missing, as for herdr-core.
- collied never starts a server and never runs the `rex` CLI: an absent socket means Rex is not running, while any `rex` command would start one (`--autostart` defaults to true).

### 4. Screen

- `format` returns the screen and the whole scrollback as text, HTML or VT (SGR, truecolor, cursor moves for runs of blanks), with `trim` and `unwrap` (soft-wrapped lines joined, herdr's `recent_unwrapped`). The visible screen is the last `rows` lines of the text (verified: 27 lines for 3 of history and 24 rows). There is no visible-only or tail-only option.
- Text: approvals, menus and startup checks read Rex's text unchanged ([Approvals](#6-approvals)); as built (#705), they read the emulated VT below as text (`DETECTION` in `runtime/rex/screen.rs`), not a text `format`. ANSI: collied's `Screen` (`alacritty_terminal` 0.26.0) fed with `format`'s VT output, its final line break dropped, drew the same 24 rows as the text (verified on Claude Code's permission dialog). So `agent.read`, `pane.read`, drafts, the jump banner and notices can come from an emulator fed by one `format` read.
- Size limits: with 100,000 lines of scrollback (4.3 MB of text), `format` failed with `too_large` (the message limit is 1 MiB). With `max_bytes` set, `format` answers the first part and keeps the whole result for `blob_read`, which reads it from any byte offset. A Rex terminal keeps up to 64 MiB of scrollback.
- `rex block stream` answered "not implemented" in this build. A data connection (`data.connect`, then `/api/data` with `rex.data.terminal.v1`) delivered its first bytes 0.5 to 2.9 ms after the ticket: a binary Ghostty snapshot (`GHOSTSNP`), then the program's output with Rex's own messages as `ESC _ rex1;<nonce>;<json> ESC \` (`resize` right after the snapshot, `theme`, `child_exited`). `alacritty_terminal` cannot read the snapshot, and nothing lines the stream up with `format`: `format` answers `content`, `id`, `total` and `eof`, and the stream carries only those messages and, for a resume, a byte count of its own. Seeding an emulator from `format` and then following the stream could apply output twice or drop it.
- So reads and watches poll `format` VT, as collied polls herdr's reads for a watch (every 250 ms, every 1 s once the screen has not changed for 5 s): one `format` with `max_bytes`, then `blob_read` of the tail the phone's lines need, cut at a line break, emulated afresh. Each poll is the terminal's whole current state, so output is never applied twice and never lost from what the screen and its history hold; output a program overwrites between two polls is never seen, as with herdr.
- Cost, measured against a terminal filled with numbered lines (one `format` with `max_bytes: 65536` plus one `blob_read` of the last 64 KB): 0.9 to 1.2 ms at 1,000 lines (0.04 MB of VT), 10 to 14 ms at 10,000 (0.45 MB) and 39 to 46 ms at 100,000 (4.4 MB). What crosses the socket stays bounded; the server's work grows with the scrollback. At 250 ms that is about a sixth of a core while a phone watches a 100,000-line terminal that keeps changing, a twentieth once it is quiet (estimated from these call times on numbered lines; measured as Rex's own CPU time in #739, a changing 80x24 terminal at 100,000 lines cost 28% of a core, [libghostty-vt.md](libghostty-vt.md#watch-cost)). The data connection's snapshot, by comparison, sent 0.05 MB in 1 ms at 1,000 lines and 4.5 MB in 65 ms at 100,000 before any live output. If polling proves too dear, two later options remain: a data connection used only as a sign that output arrived (its bytes discarded, the snapshot paid once per watch), or libghostty-vt, which the app already builds from pinned tarballs, to restore the snapshot itself (a new native dependency for collied; built with its snapshot feature, which the app's build leaves out, it reads Rex's snapshots, and [libghostty-vt.md](libghostty-vt.md) weighs it).
- Size: neither `format` nor a data connection changed a terminal's size or owner (verified on a terminal resized to 100x30 with no owner). collied never calls `resize`, `own_block` or `set_theme`; since #765 it opens a data connection while a phone watches a terminal ([Streams](#streams-765)). A block Rex.app owns has Rex.app's size: 198x68, its owner Rex.app's client, and `format` and `blob_read` left both unchanged (verified in #705 on the owner's server, 0.1.0-preview.19).
- Checked in #705 against 0.1.0-preview.19 (build 1972, API revision 14, speaking 13 to collied), on a scratch server and, read-only, on a Claude Code permission dialog in a block Rex.app owns:
  - VT rows are joined by `\r\n`, with none after the last row, which may be empty: the whole rendering is fed as it comes. The spike's "final line break dropped" held for a screen with no scrollback; with scrollback it shifts the screen down by one row.
  - At revision 13 a `format` with `max_bytes` answers `content`, `id` and `total`, and no `eof`; `blob_read` answers `eof`. Nothing in either answer, and no terminal event, says whether the screen changed: Rex has no revision, output event or `updated_at` for a screen. A poll that finds the screen unchanged therefore still calls `format` and, for a terminal over 64 KiB, `blob_read`; it skips only the emulator.
  - A result's lifetime: `blob_read` documents "about five minutes"; in practice a block keeps its newest four results, with ids counted per block, readable from any connection (300 `format`s in a row left only the last four readable). An older one answers `not_found`. So the server's memory is bounded by four renderings per block: 150 s of polling a 100,000-line terminal (6 MB of VT) every 250 ms left its RSS between 438 and 593 MB, with no growth.
  - A `blob_read` from inside a character answers its first bytes as replacement characters, one per byte; collied cuts the tail after its first line break, so they never reach the emulator.
  - A result's first `blob_read` costs more than later ones of the same range: 5 to 6 ms at 1,000 lines and 10 to 12 ms at 100,000, against 0.5 to 1.3 ms (64 KB). `format` itself: 2.6 ms at 1,000 lines, 33 to 48 ms at 100,000.
  - A whole read through collied (release build, 200 lines asked, median of 20): 1.6 ms for an unchanged 1,000-line terminal, which one `format` answers whole, and 7.9 ms for one that changes every 50 ms; 45 to 58 ms at 100,000 lines whether it changed or not, nearly all of it Rex's `format`.

### 5. Input

- `rex send TEXT` (and `terminal.write`) types the text as raw bytes, with no bracketed paste and no Enter (verified with a raw-mode reader: `w1\nw2` arrived as is). `block.event` with a `paste` event pastes: inside `ESC[200~` and `ESC[201~` when the program turned bracketed paste on, newlines as `\r` otherwise, and an `ESC` in the text arrives as a space, so a pasted `ESC[201~` cannot end the paste (verified). A prompt is a paste and then a `key` event for Enter, which run in order on one connection (verified: Claude Code took the prompt and answered).
- Keys: on the socket a `key` event takes W3C key codes (`key_a`, `arrow_up`, `escape`, `bracket_left`), a modifier string (`ctrl+alt`, with `cmd` as `super`), the text the key types and its unshifted code point, so collied maps its names. For 39 names, the named `Key`s and combinations of each kind, a raw-mode reader received the same bytes from those `key` events as from `rex send-key` with collie's name, and the bytes herdr sends (verified): `enter`, `esc`, the arrows, `shift+left`, `tab`, `shift+tab`, `backspace`, `ctrl+c`, `ctrl+enter` as `ESC[27;5;13~`, `ctrl+a`, `ctrl+b`, `ctrl+e`, `ctrl+k`, `ctrl+l`, `ctrl+u`, `ctrl+w`, `ctrl+end` as `ESC[1;5F`, `end`, `space`, `a`, `1`, `/`, `` ` ``, `[`, `alt+x`, `ctrl+alt+x`, `shift+f5`, `f1`, `f12`, `alt+enter`, `shift+enter`, `ctrl+space`. Lost on a Rex agent: `cmd+k` (any `cmd` combination), `ctrl+[` and `ctrl+shift+x` send nothing either way to a program without a keyboard protocol, and `ctrl+alt+[` sends `ESC [` (Alt's `ESC`, then `[` without its Control); `ESC [` followed by the next keys could spell an escape sequence, which is why collie allows `[` only with Control. collied refuses these four kinds for a Rex agent, as herdr-core refuses `cmd`, rather than send nothing or `ESC [`. A program that turned on a keyboard protocol was not tried. `rex send-key` refuses an unknown name (exit 2). Phase 3 added a live test of keys over the socket (`live_rex_input`, below).
- As built (#706), checked on preview.19 (build 1972, API revision 14 speaking 13) by a raw-mode reader in a block of a scratch server, against herdr-core in a core of its own: 504 names (every named key, function key and character key with each combination of Control, Alt and Shift, `cmd+k` and `ctrl+end`) through collied's own key path, once. Rex and herdr-core sent the same bytes for all but these, which corrects the list above: Shift with a character that is not a letter (`shift+1`, `shift+/`) is the key itself in herdr-core, not its shifted character, so collied now sends that text (the sweep ran with the shifted character; `live_rex_input` pins the fix for every character key); `ctrl+shift` on a named key (`ctrl+shift+up`, `ctrl+shift+enter`, `ctrl+shift+f5`) and `ctrl+alt+shift` on anything arrive as herdr-core sends them, so only Control and Shift without Alt on a character, or on `space` (`ctrl+shift+space`, which herdr-core refuses), send nothing; `ctrl+i`, `ctrl+'`, `ctrl+,`, `ctrl+-`, `ctrl+.`, `ctrl+;`, `ctrl+=` and ``ctrl+` `` also send nothing in Rex, and herdr-core refuses them; `ctrl+alt+[` arrives as `ESC [` in herdr-core too. collied refuses `cmd`, those Control keys, `ctrl+shift+space`, `ctrl+[` and `ctrl+alt+[`, before any key of the call is sent. This is narrower than the issue's wording ("`ctrl+shift` combinations are refused"), a measured deviation: collied refuses only what Rex drops, so `ctrl+shift` on a named key still reaches the program. `live_rex_input` keeps the check for every named `Key`, every character key alone and with Shift, the combinations herdr-core's live test pins and a few more, Ctrl+End, a notice digit and a paste. In a one-off manual check on the owner's own Rex server, with the owner's permission, the same `key` and `paste` payloads reached a block of the check's own with the same bytes; tests never do this and run a server of their own (AGENTS.md). Inferred, not run: a program with a keyboard protocol, and Rex.app's own blocks beyond that one.
- `block.event` is refused (`conflict`) on a connection not attached to the block's session (verified), so collied sends on its follower's connection, which attaches every session; it opens no connection per send.
- No write can be held to a status (as built in #706, collied checks the status again before each event of a prompt; see architecture.md): `block.event` and `write` take no condition, and Rex holds nothing while someone types on the Mac. collied's ready check, `program_status` right before the write, is the only guard: the gap herdr leaves, wider than herdr-core's.
- Text without Enter (the slash mirror, an approval note) is a paste alone.

### 7. Grouping

- A Rex session is a group of related work, as a herdr workspace is: one group per session, `rex:session:<uuid>`, with the session's label (`session_label_changed` follows renames), numbered after herdr's and herdr-core's. Windows (tabs) are not shown. One group per server would hide the user's own grouping.
- `pane.close` is `block.close`, which ends the program; a window whose last block closes closes too. A session outlives its last block and window (verified).
- `workspace.close` on a Rex group is refused ("close its agents one at a time"), as for a herdr-core group. It would be `session.destroy`, which ends every block in the session, Rex.app's included, while the phone shows only agents, and Rex offers no conditional destroy (`server.stop` has `if_idle`; `session.destroy` takes only the session), so a check that the session holds only agents could be overtaken by a block Rex.app opens before the destroy.

### 8. Tasks

- On Automatic, the app's default, New task starts in herdr while herdr answers, else in a followed herdr-core, else in a followed Rex, so a machine that runs both herdr and Rex changes nothing. The app's **Start tasks in** setting can ask for Rex (or Herdr, or Herdr Core) instead: the task then starts there or nowhere, and collied's error names the runtime and why, such as "Rex is not running on this computer" (#723, Runtime in [architecture.md](architecture.md#herdr-integration-verified-against-093-source-and-live-socket)).
- A task is a session of its own, as herdr's `workspace.create` makes a workspace: `session.create` with the task's label (else its name) as label and one window whose block runs `/usr/bin/env -u <name> ... <CLI path> <args>` (`options.command`, `options.cwd`), the API form of `rex new NAME -- COMMAND` (verified with `shell: none`: Claude Code started there and reported). With Rex's default shell (a login shell, not interactive) the agent gets the user's profile `PATH`, as Rex.app's terminals do; with `shell: none` it gets the server's environment. Checked in #708: `options.command` is an argument vector the login shell `exec`s unchanged ([Shape](#shape)). `rex run` and `session.new_window` would put a task in an existing session instead.
- The `-u` list is herdr-core's sixteen names: a Rex server passes its environment to every terminal (verified), and a server started by a `rex` command inside a herdr pane would carry that pane's variables (not verified: `rex server start --env` suggests only named variables pass).
- `session.create` makes collied the owner of the new block, which would keep collied's size (80x24) and keep Rex.app from sizing it. collied disowns it at once (`session.disown_block`, which needs the session attached), so Rex.app sizes it as it does the user's own blocks (not checked with Rex.app: on the owner's server the block had no owner afterwards and kept 80x24 while nothing showed it).
- A block has one label, which Rex.app shows, and nothing like herdr-core's `collie.kind` and `collie.worktree`. collied records the blocks it starts (kind, worktree checkout) by block id in its data folder; ids are never reused.
- Worktrees and archive as for herdr-core: `git worktree`, then `block.close` of the task's own block by id, then `git worktree remove`. Archive also removes the session collied created for the task once nothing is left in it ([Shape](#shape), #727); any other session stays, for the reason `workspace.close` is refused. The check that nothing else works in the checkout, read again after closing the task's block, has the same short window herdr-core's has.

### 9. Focus

- `rex focus BLOCK` (`session.focus_block`) makes the block's window the session's active window and focuses the block, on the server (verified with `session.view`), with no Rex.app setting. It answers `{"revision": N}`; on a block already focused in the active window, which a new task's only block always is, it changes nothing and, on a scratch server, sent no event.
- Rex.app does not follow it (checked by the owner with Rex Beta.app 0.1.0-preview.19 on 2026-11-15, #709). Showing another session, the app stayed on it after `session.focus_block` on a one-block session; behind another app, it neither came forward nor switched to the session after a call whose revision shows it changed the session's active window. The call changes only the server's view of the session. Not checked: whether the app, already showing the session, follows the new active window.
- Rex.app's own actions (`client.tab.goto`, `client.window.*`, through `client.perform` or `rex -C`) are refused while Remote Control is off in its settings: its binary holds "Rex.app is not accepting actions. Turn on Remote Control in its Settings under Rex Server." collied never calls them: they drive the app, and that setting is the user's.
- `agent.focus` on a Rex agent is therefore refused, as for herdr-core, with "a Rex agent cannot be focused from the phone" (`internal`). collied does not call `session.focus_block`, and never calls Rex.app's own `client.*` actions.

### 10. Alongside the others

- Ids: a block is `rex:block:<uuid>` (46 bytes) and a group `rex:session:<uuid>` (48 bytes), within `TerminalId`'s `[A-Za-z0-9_:.-]{1,64}`. Rex ids are never reused, so a restarted or wiped server never aliases old ids. collied routes by the `rex:` prefix, as it routes `hc:`; the phone parses no id.
- Discovery as the CLI does it, from collied's own environment ([What Rex is](#what-rex-is)), never `REX_SERVER`, which can name another machine, and never the hosts list. Rex missing or stopping behaves as herdr-core does: a server that never answered is quiet, one that stops after answering logs once and its agents leave with one `flock.changed`, and `herdr_unavailable` is answered only when no runtime answers.
- `collied status`: a `rex:` line with the version and API revision (or `not running`), the socket and its folder's mode, any method the server lacks, and remote access when it is on.
- `collied doctor`: informational when Rex is absent; else the version and the socket, and a warning for a server it does not follow (API revision, missing methods, the personal-server checks, a listener admitting anonymous callers), for Tailscale mode or a tailnet listener, and for a server whose environment (read by name only, from `server.status`'s `pid`, as for herdr-core's holder) holds `HERDR_PANE_ID`, `HERDR_SOCKET_PATH` or `CLAUDE_CODE_CHILD_SESSION`.
- Platforms: macOS, verified. Linux, where collied and CollieTray also run, is not verified; `rex server install ssh://...` installs a server on a Linux machine, and a collied there would follow that machine's own server. Remote hosts are never followed.
- Threat model, the supported boundary: a personal server. collied follows a server only when its socket is owned by the user and has no group or other permission bits, its folder is owned by the user with mode `0700`, and the peer on the socket (the server) runs as the user; otherwise it refuses, logs once and `doctor` says why. That keeps out Rex's shared server on Linux, whose group members all see and type into every session as the `rex` account, and a personal socket opened to a group with `--socket-mode`. Only the scratch personal server was checked here; Linux was not.
- Remote access, off by default and off in the issue's assumption: built-in Tailscale (the tailnet owner, or every member the ACLs allow), tailnet and Tailscale Serve listeners (the owner, or every identified caller), plain HTTP with `--allow-anonymous` (anyone who reaches the port, with full access) and SSH forwards. collied reads `server.status` (`listeners` with their `transport` and `admission`, and `tailscale.state`) when it connects: a listener admitting `anonymous` callers makes it refuse to follow, since anyone on that network types into the same agents; Tailscale `running` or a tailnet listener lets it follow, with one log line and a warning in `collied status` and `doctor`, since those reach the same terminals outside collie's allowlist and audit.
- What collied calls: the API is wider than herdr-core's (Tailscale, Lua, Rex.app's actions, files), so the client refuses anything but `hello`, `help.all`, `block_creator.list`, `server.version` (the version `collied status` shows), `server.status`, `session.list`, `session.attach`, `session.attach_all`, `session.list_blocks`, `block.close`, `block.event` (`paste` and `key` only), the terminal methods `program_status`, `process`, `title`, `size`, `format` and `blob_read`, and for tasks `session.create`, `session.disown_block` and `session.destroy` (an archived task's own session, once empty, #727), and `data.connect` for a watched terminal's stream (#765); never `server.stop`, `server.tailscale.*`, `hosts.*`, `server.apple.*`, `client.*`, `own_block`, `resize`, `set_theme`, `write`, `list_dir`, `upload_begin` or `download_begin`. The paste neutralizes `ESC`, so a prompt cannot break out of bracketed paste. Screens are kept on disk under the state folder, same-user only. The threat model has a Rex section, added in phase 1 and extended with each phase.

## Shape

Phase 1 as built (#704):

- Routing: `Owner::of` classifies an id once by its prefix (herdr's have none, `hc:`, `rex:`), and every `Runtime` call matches on it, so a fourth runtime is a new arm the compiler asks for in each call. Callers outside the runtime module ask `Owner`, not a prefix test, where phase 1 needed a Rex answer (status times, stars, pull request wakes, herdr's held agents); the rest test `herdr_core::owns` only for what is herdr-core's alone (its typing hold, its Chat hints).
- `crates/collied/src/runtime/rex/`, one concern per file: `wire.rs` (wire types), `client.rs` (the method enum, the handshake and hello, calls matched to responses with timeouts, the event pump), `discovery.rs` (the socket and the personal-server checks), `model.rs` (sessions and blocks from reads and events, and the agents and groups they list) and `mod.rs` (the method check, subscribe then read, reconnect with herdr-core's backoff, `status` and `doctor`'s report). Later phases add files.
- Shared with herdr-core, moved rather than copied: `runtime/agents.rs` holds the agent CLI and shell lists, kind from `argv0` and `app`, OSC 7501 state to collie's status, the title without its spinner, a group's status and an agent's pane. The sixteen stripped names moved there in phase 5.
- The allowlist is the type: `client::Method` named each method phase 1 called and nothing else, and each later phase added its own; a unit test pins their wire names. `server.version` was added to the plan's list for the version `collied status` shows.
- Listing (`poll`, `agent.list`, `session.snapshot`, `agent.get`) reads the model the events keep current: no call per poll. `pane.close` and `task.archive` are `block.close` on a listed agent only; `workspace.close` is refused; every other call on a Rex id answered "not available for Rex agents yet" from routing until a later phase built it; herdr's own pane calls still do. An agent with no status is read-only, as for herdr-core.
- `state_change_seq` comes from the root record's `updated_at` (a SHA-256 prefix) rather than a counter: every report moves it, and an unchanged record keeps it across a reconnect and a restart of collied, which a counter would not. Only equality is ever compared.
- A session's label also comes from `session.attach`, so a rename whose event arrived before the session was listed is kept. A block whose reads fail is skipped and logged rather than dropping the connection; a server that answered and then failed is reported as not followed, with the reason, and logged once per reason. The core and Rex share one record of herdr's reachability.
- `ServerConfig.rex` names the socket to follow; only the daemon discovers it, so tests never reach the user's server.
- Phone protocol unchanged: `claude-code` is `claude`, `error` is `unknown`.

Phase 2 as built (#705):

- `runtime/rex/screen.rs` reads screens; `mod.rs` routes them to the listed agent's session, block and size. `Screen` is shared with herdr-core, with one addition, `text`, the screen as plain text for herdr's `detection` source.
- A read: `format {format: vt, max_bytes: 1}`, then `blob_read` of the last 64 KiB, cut after its first line break and doubled while it holds fewer line breaks than the screen's rows plus the lines asked for, then fed to a fresh `Screen` at the block's size. One answer holds 983,040 bytes as a JSON string, its quotes included (so 983,040 bytes of plain text never fit, checked live): a doubled tail that does not fit is not used, the last one that did is, and that reader never asks for the larger size again. A tail without the screen's rows fails the read. A block whose rendering was 64 KiB or less last time is read by one `format` asking up to 960 KiB, which holds it whole.
- `unwrap: true` for reads with history, so `recent_unwrapped` joins soft-wrapped rows, which herdr-core's paint cannot; `visible` and `detection` read rows as drawn, since with `unwrap` a line longer than the tail left nothing above the prompt (50 lines, 2,000,000 `x`, then a prompt; `live_rex` checks the rows).
- Unchanged: each reader (block, source, and lines for a read with history) keeps the tail it fed and the text it read; the same tail at the same size answers that text with no emulator work, and the watch then sends nothing.
- A result gone before its `blob_read` is formatted again, three times at most; a read that still fails is an error, which a watch skips.
- `size` is the first read of each block, so no block is listed before its size, and `size_changed` keeps it current; `pane_columns` answers from it.
- A block whose reads fail is read again on its next block event, not only with its session's next read, and logged once until it is read.
- `agent.explain` answers the blocked report's `kind` from the model, and the `detection` read gives the screen as text, which approvals read since #706.
- The plan's `detection_text` from `format` text was not built: the text keeps every row, so its last `rows` lines are the screen only when the screen is full; the emulator's screen is right either way and costs nothing more.

Phase 3 as built (#706):

- `runtime/rex/input.rs` builds the only events collied sends, a `paste` and a `key` press, and sends them as `block.event` (a new `Method`, so the method check requires it) on the follower's connection, in order, each awaited. A prompt and a typed answer are a paste then Enter, text alone a paste, which Rex brackets itself (the slash mirror's markers are added only for herdr and herdr-core), and keys, Ctrl+End and a notice digit key presses, every key of a call checked before the first is sent. Only a listed agent is reached (`Model::target`, as for `block.close`); the ready check and the refusal of an agent with no status are drive's, shared with herdr and herdr-core.
- Approvals: the engine is given Rex (`Approvals::with_rex`, and the daemon's) and reads a Rex agent through #705's `detection_text` and `explain`; nothing of it is Rex's own but the bound on screen reads. While a blocked Rex agent's approval stands, its screen is read on at most `REX_READS` (3) reconciles per report, then not until its next report: each read makes Rex render the whole scrollback, and Claude Code reports each dialog anew. A failed read does not count, and an approval that ends while the report stays (expired, or superseded because its dialog changed) lets the next reconcile read again and raise a fresh one, up to three reads more. Measured with no phone connected on the owner's Claude Code 2.1.325 left blocked: 3 `format` calls in 60 s, all in the first 3 s, against one per 1 s reconcile before; that is three per report, plus three more each time an approval expires (the approval TTL, 10 min by default). The cost of the bound: a dialog that changes without a new report after those reads keeps its approval until a decision's own read refuses it or it expires.

## Streams (#765)

Built in #765, against Rex 0.1.0-preview.20 (API revision 16, which speaks 13 to collied), on the measurements of [libghostty-vt.md](libghostty-vt.md#watch-cost) and the prototype in draft #767. What collied does is in [architecture.md](architecture.md#rex) (Streams); this is the design and its evidence.

- Scope: a terminal is followed only while a phone watches it (`Runtime::watch`, held by the watch loop as herdr-core's attach is). One stream per terminal is shared by every watch of it and closed with the last one, with status 1000, which ends Rex's stream at once; any other close would keep it waiting 60 s for a resume. Rex allows one data connection per client and block (REJECT 2), which sharing keeps. Every read of a terminal whose stream is live comes from it, detection reads included; every other read is polled, exactly as before.
- The data protocol, from the server's `/llms.txt` and checked live: a ticket from `data.connect` (16 bytes as 22 base64url characters, once, within 60 s, from a connection attached to the session), a HELLO (`0x01` and the ticket), a WELCOME (`0x81`, a 16-byte reconnect token, 3 zero bytes, the resume window as a `u32` in milliseconds, 60,000 here, and a `u64` channel nonce) or a REJECT (`0x82` and a reason). Then binary messages of 1 to 65,536 bytes whose boundaries mean nothing: the snapshot, then the program's output with Rex's messages `ESC _ rex1;<nonce>;<json> ESC \` (`resize` right after the snapshot and on each size change, `theme`, `child_exited`, after which the stream stays open). A RESUME (`0x02`, the latest token and the count of stream bytes received) on a new connection continued the stream with the same nonce and a new token (checked on a scratch server by dropping a connection without a close frame); `live_rex_stream` reads the same streamed and polled after its relay cuts the connection, so nothing was lost or repeated.
- Version check: the snapshot's envelope is 10 bytes, `GHOSTSNP` and a little-endian `u16` version, 1 at libghostty-vt 1.0.1 (`src/terminal/snapshot/envelope.zig`). collied checks both before the decoder reads anything, so an unknown version from a newer Rex polls `format` for the rest of the watch, with a log line, rather than relying on the library's own refusal.
- Restore: the decoder pulls the snapshot through a blocking reader on a blocking thread while the async side queues each message; it reads nothing past the snapshot's last byte (its reader adapter takes one byte at a time at a boundary, `src/terminal/c/io.zig`), so the rest of the piece it stopped in, then the queue, are the live stream in order. A restored terminal keeps the byte limit of the terminal that wrote it (64 MiB in Rex, read back after a restore); collied then sets a line limit of 3,024 rows, which on the 100,000-line capture kept 2,920 rows, and drops each snapshot piece once read.
- Rex's messages: found only with the connection's own nonce, which a program never sees, so a look-alike a program prints (another nonce, checked live with `{"type":"resize","cols":40,"rows":10}`) stays output, as Rex's own terminal saw it. A message cut across pieces waits for the rest; one over 64 KiB, which Rex never sends, is written through. `resize` resizes the terminal at that point of the stream; `child_exited` marks it finished, so a later drop ends the stream instead of resuming it; `theme` and unknown types are ignored.
- Reads: the screen's rows (`visible`, `detection`) or twice the rows and history asked for, as one VT rendering from the formatter (one selection between two grid references, no extras, `unwrap` for history), fed to the same emulation a polled read feeds `format`'s tail to. The captured fixtures (`crates/collied/src/runtime/rex/fixtures/rex-0.1.0-preview.20`, from a scratch server, with Rex's own `format` renderings) read byte-identical streamed and polled: a stand-in with colored lines, a wide line, a wrapped line, a look-alike, Rex's resize to 100x30 and the exit, in pieces of 1 byte, 1,000 bytes or whole; and a stand-in that leaves five lines and its cursor mid-screen, then enters the alternate screen and draws a dialog with its cursor inside it, both as it happened live and restored from a snapshot taken on the alternate screen. Nothing else is pinned. A format is capped at 983,040 bytes, what one polled answer holds: the formatter writes a cell's whole OSC 8 link again each time the link changes, and 80x24 cells alternating between two 2,000-byte links formatted to 3.4 MB (`a_format_past_its_ceiling_fails_and_holds_no_more`); a read past the cap, or one the library fails, polls. A read formats only once the stream brought something since that reader's last read, so a watch of a still terminal formats nothing and the watch loop's 250 ms tick costs a lookup.
- Fallbacks: a refused HELLO, an unknown envelope, a snapshot libghostty-vt refuses, a history it cannot trim, an unreadable ticket and close 1008 poll for the rest of the watch. A dropped connection resumes at once. REJECT 2 or 4, close 1011 or 1013, a refused RESUME, a resumed connection that ends before any byte arrives, a resize libghostty-vt refuses and a stream cut during the snapshot start a new stream after the delay: 1 s, doubling to 30 s, and back to 1 s only once a stream has stayed live longer than 30 s. Each fallback and each new stream logs one warning with its reason (the service logs warnings unless `RUST_LOG` says otherwise), so a stream that keeps failing logs at most once per delay. So whatever Rex answers, collied waits at least the delay between two HELLOs and resumes a connection again only after it brought a byte (`streams_ended_soon_after_they_start_are_asked_for_less_and_less`, `a_resumed_connection_that_ends_before_any_byte_starts_a_new_stream`, `a_refused_resume_starts_a_new_stream_after_the_delay`, on a paused clock). While the stream is not live, reads poll `format`, so any gap is covered.
- A watch that ends once a data connection exists, during the snapshot included, closes it with status 1000, which ends Rex's stream at once; a resume under way finishes first (within its timeouts) and is then closed the same way. Checked on the scratch server: a new HELLO while a stream dropped without a close frame still waits for a resume is welcomed at once, from the same control connection or a new one (Rex ends the waiting stream, as `/llms.txt` says); only a HELLO while this client's previous connection to the block is still open gets REJECT 2. So the normal close spares Rex 60 s of a waiting stream; it is not what lets a watch reopen.
- Rex's minimum does not move: `data.connect` and the data connection were there at 0.1.0-preview.16 ([Screen](#4-screen)), #739 streamed on preview.19 and this work on preview.20. Since `data.connect` joined the method check, a server without it would be refused outright, not polled.
- Containment: a program whose output, or whose state in the next snapshot, trips one of libghostty-vt's `ReleaseSafe` checks aborts collied, which drops every phone session, pending approval, queued push and upload, for every runtime; launchd or systemd restarts it, and without more it would abort again each time the phone watched that terminal. collied writes `rex-streaming` in its data folder before a stream's first byte reaches the library and removes it when the last stream ends and when it stops cleanly. A run that starts and finds it left over removes it and polls every Rex read, with one warning in the log; one that cannot remove it polls too (`a_marker_left_by_an_earlier_run_turns_streaming_off`, `the_marker_lasts_while_a_stream_does`). One abort still happens, and a kill or an unrelated crash during a stream costs one run of polling; the marker does nothing for a bug that corrupts memory without aborting. If the marker cannot be written, collied logs a warning and streams without that protection.

Measured on an M3 Max with a release build, Rex 0.1.0-preview.20 on a scratch server. The watch: an 80x24 terminal of 100,000 numbered, colored lines, then one more every 0.2 s, watched through collied's own watch loop (`Driver::watch`, 200 lines) for 60 s after 2 s, in the e2e test process, so collied's figure is that whole process, its Rex follower included; CPU time from `ps`, one run each, with the library built `ReleaseSafe` (as shipped) and, for comparison, `ReleaseFast`. Rex's per-block result ids counted collied's `format` calls in the minute: none.

| | Rex CPU | collied CPU | collied resident |
|---|---|---|---|
| No watch | 0.7% of a core | 0.2% | 29.3 MB |
| Watch, polled ([libghostty-vt.md](libghostty-vt.md#watch-cost), 0.1.0-preview.19; 29.7% through collied in the prototype) | 28.2% | | |
| Watch, streamed, `ReleaseSafe` | 0.9% | 1.5% | 56.0 MB |

What the tables say:

- The bar holds: a watched, changing 100,000-line terminal costs Rex 0.2 points of a core over no watch, against 28 to 32% polled.
- collied pays 1.3 points over no watch while the screen changes, and 0.1 once it is still. The stream's own share of that is small: four 200-line reads a second at 0.7 ms each are about 0.3% of a core, and the program's output parses at 190 MB/s; the rest is the watch loop's own work on a screen that changes every tick (patches, reflow and draft parsing), which every runtime's watch pays (inferred from the read time, not measured apart). It also holds about 27 MB per watched terminal of this size once the snapshot is restored and trimmed.
- `ReleaseFast` is 15 to 25% faster on the stream path, a few milliseconds per watch and a fraction of a millisecond per read, and changes neither process's CPU on the watch. collied keeps `ReleaseSafe`.

## Terminals (#755)

Built in #755, on the owner's request of 2026-11-15 to reach Rex's plain terminals from the phone as herdr's are. What collied does is in [architecture.md](architecture.md#rex) (Terminals); this is the rule and its evidence.

- What herdr lists: a pane with no agent, whatever runs in it, since every herdr pane starts a shell and keeps it. Rex can start a program with no shell at all (`rex new NAME -- COMMAND`, `options.command`), so collied lists a block as a terminal when it is no agent and a shell runs in it: its foreground process is a shell, or one of the `ancestors` Rex reports between the foreground and the terminal's own program is. The shell list and the `argv0` rule are herdr-core's ([Identity and kind](#2-identity-and-kind)).
- Why the ancestors, not the foreground alone: a command the phone runs (`make`) leads the terminal while it runs, and with the foreground alone the block would leave Terminals for that time and end the phone's watch. Checked on a scratch server (Rex Beta build 2003) with a block started as Rex.app starts one (`rex new` with the default shell): `child` is `/usr/bin/login`, run as root and with no `argv0` or `cwd`, and the foreground `-zsh`; `sleep 20`, then `vim`, each led the terminal with `ancestors` `-zsh` then `login`, in `process` and in `process_changed` alike.
- Not listed: a block whose program Rex started with no shell above it, one whose program exited, one on another host, and one whose shell keeps an agent in front. An agent under `sh -c 'cd x && claude'` is no agent, since a shell is in front, and Rex names that shell as the record's owner. Checked on the scratch server (build 2003) with a stand-in reporting OSC 7501: run from an interactive shell, directly or from a nested one, it owned its own record; under `sh -c` the `sh` owned it through `idle`, `working` and `done`, and the record stayed after both exited; after a normal exit, Ctrl+C or Ctrl+Z, no shell back at its prompt owned a live record, and a directly run agent's record was dropped on Ctrl+Z. Shell input there would reach the agent past every agent check, so the block is a pane hosting an agent while a shell in front that is not a login shell owns the record (pid and name), whatever it says (a login shell, `argv0` with a leading `-` as Rex.app starts one, is left out, so a report ever credited to the user's own shell cannot hide it for as long as it lives; `sh -c` is never one), or while the record says working or blocked under a live owner: Terminals leaves it out and a terminal call drops its grants, as on a herdr pane where an agent started. A wrapper suspended at idle or done leaves the shell listed for `fg`; one suspended mid-turn keeps it unlisted. An agent CLI run from a shell is an agent, as before, and the block is a terminal again once the shell leads it; a program a shell `exec`s replaces the shell, and the block leaves Terminals.
- Groups: a session that holds only terminals is a group too, so the phone names it under the terminal. With terminals off it is a group with no agents, as a herdr workspace of shells is.
- Input: herdr's `pane.send_input`, `pane.send_keys` and `pane.send_text` become the `block.event` pastes and keys agents take ([Input](#5-input)), with the agents' key refusals: no new method, and still no `write`. herdr types a line as keystrokes; Rex takes it as a paste, which it brackets only for a program that turned bracketed paste on ([Input](#5-input)); `live_rex_terminals` checks that a line runs as typed in macOS `/bin/sh`, which does not. Each event goes only while the model still lists the block as a terminal.
- Streams: a terminal watch holds the stream as an agent watch does ([Streams](#streams-765)). An unwatched terminal costs Rex nothing more: it is listed from the model, as agents are, and no screen of it is read.
- Herdr Core's plain terminals stay unplanned, the owner's decision in #755: its terminals are listed only as agents.
- Tests: against the fake, the listing rule (a shell, a command under one, an agent CLI under one, a program with no shell, a shell on another host, the moves between them on `process_changed`, and a shell keeping an agent under it, unlisted while it owns the record or a live owner's record says working, listed for `fg` when suspended at idle and once the owner is gone, its terminal calls answered as on a pane hosting an agent), a group per session with no call to the server, input reaching only a listed terminal of this host through drive's grant and shell checks, an agent started during a line getting no Enter, and a watched terminal streamed while an unwatched one is never read; live, `live_rex_terminals` on a scratch server.

## Risks

- **Preview API.** Rex is a closed preview: collied was built and checked against 0.1.0-preview.19 (build 1972 and later builds of that preview), its API at revision 14, of which collied speaks revision 13. collied pins the revision and fails closed per missing method.
- **Native parser.** A watched terminal's snapshot and output reach libghostty-vt, native code with unchecked pointer arithmetic and two C++ libraries, inside collied ([threat model](threat-model.md#libghostty-vt-in-collied)). The snapshot format is versioned apart from the library and Rex writes it with its own Ghostty: a version collied does not know polls instead.
- **Polling cost.** Unwatched reads still poll; a watch streams since #765. At revisions 13 and 14 `format` takes no range, no visible-only and no since parameter, and Rex has no output event, so every poll makes Rex render the whole scrollback (up to 64 MiB): 33 to 48 ms of server time at 100,000 lines (measured), 13 to 19% of a core at four polls a second while the screen changes, a quarter of that once quiet (estimated from those times; Rex's own CPU time, measured in #739 on a changing 80x24 terminal, was 28 to 32% at 100,000 lines and near the cap, [libghostty-vt.md](libghostty-vt.md#watch-cost)); a whole read through collied takes 45 to 58 ms there ([Screen](#4-screen)). Readers of one block share `format`s only when they overlap: one `format` runs at a time per block and `unwrap`, and the readers that asked while it ran share the next one; readers that do not overlap (a watch's poll and a preview's a moment later) each run their own. A reader that asks while one runs waits for it first, up to one more `format` (33 to 48 ms at 100,000 lines); a `format` that fails or times out is not shared, and each reader fails within one 5 s timeout of when it asked, as with a `format` of its own.
- **Session removal.** Rex has no conditional `session.destroy`, so archive's check that a task's own session is empty can be overtaken: a block or window added in the round trip between the check and the destroy ends with the session. Sessions left empty another way (an agent that exited, a block closed in Rex.app, a failed start, earlier builds) stay until the user closes them.
- **A block never given up.** If collied crashes or its connection drops between `session.create` and `session.disown_block`, or the answer to `session.create` is lost, the block stays owned by a client that is gone: it keeps 80x24 and is not closed when its program exits (checked live in the review). collied's start says an agent may have been started; archive from the phone still closes it.
- **The environment.** A Rex server passes its own environment to every terminal; one started from inside a herdr pane or a Claude Code session would hand its variables to every agent, as herdr-core's core did ([herdr-core risks](herdr-core.md#risks)). collied strips them from the agents it starts and `doctor` warns.
- **No input guard.** Without `if`, a dialog that opens after collied's last status check and before Rex handles the event, one round trip, takes the prompt's Enter.
- **Remote access.** A Rex reachable over the tailnet is a second way into the same agents, outside collie's audit; collied follows it with a warning, and refuses a server that admits anonymous callers.

## Copilot CLI (#741)

Spike for [#741](https://github.com/rbstp/collie/issues/741), 2026-11-15: the three questions are answered in [herdr-core.md](herdr-core.md#copilot-cli-741), from runs in herdr-core and in Rex. What Rex showed, verified with Copilot CLI 1.0.112 in a block of a scratch server (Rex 0.1.0-preview.19, API revision 14), with a scratch `COPILOT_HOME`:

- Rex keeps Copilot's own report as a root record with `app: copilot` and the copilot process (the block's foreground process) as its `owner`, so collied lists it: `idle` once started, `working`, `blocked` with `kind: permission` or `kind: question`, `done` after a turn, and `idle` after Esc cancelled a dialog. No record carries a `msg`.
- At the folder trust prompt the record says `idle` (three starts), and with the `/model` picker open it does not change. An Enter sent to the block there answered it (the folder was trusted for the session), so a Copilot agent is read-only: only an agent whose record names Claude Code or Codex takes phone input (#745).
- Hooks run in the block with `REX_BLOCK` set, as children of the copilot process; their events and payloads are herdr-core's.
- Copilot draws on the alternate screen: after several turns `format` returned the block's 24 rows (4.2 KB of VT), so a screen check before each write (#742) costs a small screen's `format` (inferred from [Screen](#4-screen), not measured).
