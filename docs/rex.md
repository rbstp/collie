# Rex backend plan

Spike for [#703](https://github.com/rbstp/collie/issues/703), 2026-11-12. This page is the plan, the evidence behind it and the follow-up issues for "Phase 8: Rex integration". Phases 1 to 5 (#704 to #708) are built: [Shape](#shape) says how, and [architecture.md](architecture.md#rex) what collied does with Rex. Most of the design reuses herdr-core's: its plan is [herdr-core.md](herdr-core.md), and what collied does with it is in [architecture.md](architecture.md#herdr-core-herdr-2).

## Summary

- Rex 0.1.0-preview.16 (API revision 13) already gives collied what it needs to follow Claude Code agents beside herdr's, with no hook and no polling for status. Each terminal block keeps the OSC 7501 status its programs report (`program_status`, pushed as `program_status_changed`) and its foreground process (`process`, pushed as `process_changed`), reads its screen as text or escape sequences (`format`), and takes pastes and named keys (`block.event`). The issue's list of what Rex leaves undocumented predates this build: the server documents its whole API, both WebSocket protocols included, at `/llms.txt` on its own socket.
- Claude Code 2.1.322 reports `idle`, `working`, `blocked` (`kind: permission`, `msg: approve Bash: touch rex-spike-probe.txt`) and `done` in a Rex block, as it does under herdr-core, and nothing at its folder trust prompt (verified). Codex and Copilot CLI were not run here: Codex reports OSC 7501 under herdr-core and Copilot CLI does not, so a Copilot agent would be read-only from the phone.
- collied should talk to the control WebSocket (`/api/control`, subprotocol `rex.control.v1`), not run the CLI. A call costs 0.2 to 0.3 ms on an open connection against 25 to 35 ms for each `rex` process, and status, process and title changes arrive as events. collied already depends on `tokio-tungstenite`.
- collied's approval parser, menu gate and fingerprint read Rex's `format` text unchanged, and its `alacritty_terminal` emulator fed with `format`'s VT output draws the same screen (verified). Reads and watches poll `format`, as collied polls herdr: every poll is the terminal's whole current state, so no output is applied twice or lost. A poll costs about 1 ms at 1,000 lines of scrollback and 39 to 46 ms at 100,000. The data stream is not used: nothing lines it up with `format`, and it opens with a binary Ghostty snapshot (4.5 MB at 100,000 lines) that `alacritty_terminal` cannot read ([Screen](#4-screen)).
- Lost or weaker for a Rex agent: `terminal.send`'s `if` and its typing hold, which Rex has no equivalent for, closing a whole Rex session from the phone (refused, as for a herdr-core group), and desktop focus (Rex.app does not follow `session.focus_block`, #709). Built in collied: the agent kind, the session binding (Claude Code's `sessions/<pid>.json`, as for herdr-core), `state_change_seq`, task records and worktrees.
- Shape: a third runtime beside herdr and herdr-core, `crates/collied/src/runtime/rex/`, with ids `rex:block:<uuid>`, one group per Rex session (`rex:session:<uuid>`), and the phone protocol unchanged.

## What Rex is

- One server per user, owning sessions, their windows (tabs) and their blocks (today, terminals). Clients such as Rex.app and the CLI connect to it. Ids (`session:<uuid>`, `window:<uuid>`, `block:<uuid>`, UUIDv7) never change and are never reused; labels can change and repeat.
- The CLI finds the local server at `$REX_RUNTIME_DIR/server.sock`, else `$XDG_RUNTIME_DIR/rex/server.sock`, else, on macOS, `~/Library/Application Support/rex/server.sock`, where Rex.app's server listens; `REX_SERVER` and `-S` name another server (verified from the CLI's errors on scratch paths). Linux without `XDG_RUNTIME_DIR` was not checked (the API examples in the binary show `/run/user/1000/rex/server.sock`). A socket path over 103 bytes is refused. A personal server's socket is `0600` in a `0700` folder, and the server admits callers by their peer credentials. Rex also documents a shared server on Linux (`/run/rex/server.sock`, open to the `rex` group, programs run as `rex`) and network listeners, all off by default.
- Two WebSockets on that socket. `/api/control` (`rex.control.v1`): a `hello` naming the API revisions the client speaks, a `welcome`, then JSON requests, responses and events; each response carries the `seq` of the last event it already reflects. `/api/data`: one block's output per connection, opened with a single-use ticket from `data.connect`.
- Events: a connection receives a session's events, block events included, once it calls `session.attach` (or `session.bootstrap`); `session.attach_all` with `event_scope: session` adds sessions being created and destroyed but no block events, and `event_scope: all` adds every client joining and leaving (each CLI call is four events). `seq` counts per connection and starts again at 1 on a new one.
- A terminal block's methods include `format` (text, HTML or VT, screen and scrollback), `program_status`, `process`, `title`, `size`, `modes`, `write`, `resize`, `blob_read`, `list_dir`, `upload_begin` and `download_begin`. Its events include `program_status_changed`, `program_status_removed`, `process_changed`, `title_changed`, `size_changed`, `child_exited` and `desktop_notification`.
- Every terminal gets `REX_SESSION`, `REX_BLOCK`, `REX_BIN_DIR`, `TERM_PROGRAM=rex`, `COLORTERM=truecolor` and the server's own environment (verified: the scratch server's `REX_CONFIG` and `XDG_*` reached its blocks). The docs add `REX_SERVER`; a server started with `rex server run` did not set it, and Rex.app's own server (build 1972) did, with `TERM_PROGRAM_VERSION`, and passed no `HC_*` or `HERDR_*` variable (a one-off manual check on the owner's server with their permission, #707).
- A client may own a block, which then takes that client's size and colors; a client that creates a block owns it. A block kept its creator (the CLI) as owner after that client left, and another client's resize then waited (seen). A block no client owns or sized is 80x24.
- The server saves each terminal's screen to disk (`<state>/terminal/<pid>-<id>/<uuid>.snap`, `0600` in `0700` folders), even with `--restore=false`.
- Beyond terminals, the API stops the server, turns Tailscale on and signs it in, edits the host list, grants macOS file access, loads and runs Lua (`client.set_script`, `client.action`), asks Rex.app to perform its actions (`client.perform`), lists folders and moves files (`list_dir`, `upload_begin`, `download_begin`).

## Questions

### 1. Agent status

- Rex keeps it. `terminal.program_status` lists the records programs reported with OSC 7501: `state` (`idle`, `working`, `done`, `blocked`, `error`), `kind` on a blocked record (`permission`, `question`, `auth`), `app`, `msg`, `updated_at`, and `owner`, the foreground process (pid and name) when the report arrived. `program_status_changed` carries each report, even one that changes only `updated_at`; `program_status_removed` drops records, with a reason (`clear`, `child_exited`, `reset`, `prompt`, `foreground`, `evicted`). Claude Code reports the root record (no `id`).
- Claude Code 2.1.322 in a Rex block: `idle` with `app: claude-code` once started, then `working`, `blocked` (`permission`, with its `msg`) and `done` (verified). At its folder trust prompt it reported nothing (no records), so it stays read-only from the phone until it reports, as under herdr-core.
- Rex 0.1.0-preview.16 dropped a record when its program was suspended (Ctrl+Z: `program_status_removed`, reason `foreground`), unlike herdr-core 0.1.16, but kept the record of a program that exited with its shell leading the terminal again (both checked with a stand-in reporting `app=codex`, under a zsh without shell integration, so no `prompt` reason). 0.1.0-preview.19 (build 1985, API revision 14) keeps it through Ctrl+Z and `fg`: no `program_status_removed`, and `program_status` lists the record, its owner unchanged, all along (#719, stand-ins that report once, under `sh -i` and `zsh -f -i` on a scratch server). collied keeps herdr-core's rule (no terminal whose foreground process is a shell is an agent) and adds one Rex allows: a record whose `owner` is not the current foreground process (pid and name) is stale.
- Claude Code and Codex on suspend and resume, checked by the owner on 2026-11-15 on Rex 0.1.0-preview.19 (API revision 14) with collied's listing sampled once a second (#719; Claude Code 2.1.325, Codex 0.169.0): each leaves the list at Ctrl+Z, since the shell leads the block, and is listed again after `fg` (5 to 6 s after it left the list, with `fg` typed about 5 s after Ctrl+Z) with the status it had, `done` for Claude Code and `idle` for Codex. The same process leads the block again, so the record Rex kept is its own and collied lists it, and on preview.19 the agent takes input from the phone as before; a server that drops the record on Ctrl+Z, as preview.16 at revision 13 did, would list it with no status, so read-only, until it reports. Whether either reports on resume does not show here; under herdr-core, Claude Code does not, and Codex apparently does ([herdr-core.md](herdr-core.md#input)).
- No hook is needed for status. Claude Code's hooks ran in the Rex block with `REX_BLOCK` set (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest and Stop, from a scratch `--settings` file), so a hook could report it, but the server already has the status. Codex needs collied's SessionStart hook for its session, as under herdr-core, reading `REX_BLOCK` as it reads `HC_TERMINAL_ID` (verified, #707: Codex 0.167.1 reports `idle` and `working` with `app: codex`, and runs the hook as a child of the Codex that leads the block, with that block's `REX_BLOCK`).
- Copilot CLI reports no OSC 7501 (herdr-core spike, 1.0.105), so a Copilot agent in Rex is listed `unknown` and is read-only, as in Herdr 2.

### 2. Identity and kind

- `terminal.process` describes the `foreground` process, its `ancestors` up to the terminal's `child`: `pid`, `name` (the executable's file name; Claude Code's is its version, `2.1.322`), `path`, `invoked_path` (`~/.local/bin/claude`), `argv0` (the only argument Rex returns, cut to 256 bytes) and `cwd`.
- A block is an agent once it reports OSC 7501 or its foreground process runs an agent CLI, as for herdr-core. Kind: the status record's `app` (`claude-code` is `claude`), else the basename of `argv0` among `claude`, `codex` and `copilot` (verified: `claude`). A shell is the basename of `argv0`, a leading `-` aside, in herdr-core's list (`zsh` verified). Plain shells and other programs are not listed.
- `process_changed` pushes each foreground change, so the kind needs no polling. It is also sent each time a client starts receiving a terminal's output.
- A block whose `host_id` differs from the server's runs on another machine and is skipped, as herdr-core's `box/t7` (not verified: every block here was local).

### 3. Transport

- The CLI works, one process per call: `rex events -s SESSION --json` held open streams that session's block events, `rex block call -b BLOCK METHOD ARGS` makes a call. A call took 41 to 49 ms under `sandbox-exec`, whose own start costs 15 ms, so 25 to 35 ms. Without `-s`, `rex events --json` carries no block events; with `--all`, every client's coming and going. With no server, calls exit 4 as documented, except `rex server status`, which exits 1; a missing block exits 3 and a usage error 2.
- The control connection: 0.19 ms for `program_status`, 0.25 ms for `process` or `format` of a small screen, 0.34 ms to connect, say hello and make one call (measured over a Unix socket from Python). Status, process, title and size changes are pushed, so nothing is polled for them; screen output has no event (only the data connection carries it).
- collied therefore follows Rex on one long-lived control connection: `tokio-tungstenite` (a dependency already, 0.30.0) over a `UnixStream`, without compression, answering the server's pings (every 120 s). It subscribes before it reads, so nothing that happens in between is missed: `session.attach_all` with `event_scope: session` first (sessions created and destroyed, not `event_scope: all`), then `session.list`, then for each session `session.attach` (its block events from then on) followed by `session.list_blocks` and the reads of each block. An event whose `seq` is at most a read's response `seq` is already in that read; a later one is applied on top, and a session created meanwhile is attached and read the same way. After a reconnect `seq` starts at 1, so collied does all of it again.
- Method check: the `hello` sends `api_revision: 13` and `api_min_revision: 13`, so an older server closes the connection (1008) instead of answering in older shapes. Then the server methods collied calls must be in `help.all`'s `methods`, and the terminal methods in `block_creator.list`'s `com.superlogical.terminal` creator, each against the set the built phases need ([Effort and phases](#effort-and-phases)); otherwise collied does not follow that server and `doctor` names what is missing, as for herdr-core.
- collied never starts a server and never runs the `rex` CLI: an absent socket means Rex is not running, while any `rex` command would start one (`--autostart` defaults to true).

### 4. Screen

- `format` returns the screen and the whole scrollback as text, HTML or VT (SGR, truecolor, cursor moves for runs of blanks), with `trim` and `unwrap` (soft-wrapped lines joined, herdr's `recent_unwrapped`). The visible screen is the last `rows` lines of the text (verified: 27 lines for 3 of history and 24 rows). There is no visible-only or tail-only option.
- Text: approvals, menus and startup checks read it unchanged ([Approvals](#6-approvals)). ANSI: collied's `Screen` (`alacritty_terminal` 0.26.0) fed with `format`'s VT output, its final line break dropped, drew the same 24 rows as the text (verified on Claude Code's permission dialog). So `agent.read`, `pane.read`, drafts, the jump banner and notices can come from an emulator fed by one `format` read.
- Size limits: with 100,000 lines of scrollback (4.3 MB of text), `format` failed with `too_large` (the message limit is 1 MiB). With `max_bytes` set, `format` answers the first part and keeps the whole result for `blob_read`, which reads it from any byte offset. A Rex terminal keeps up to 64 MiB of scrollback.
- `rex block stream` answered "not implemented" in this build. A data connection (`data.connect`, then `/api/data` with `rex.data.terminal.v1`) delivered its first bytes 0.5 to 2.9 ms after the ticket: a binary Ghostty snapshot (`GHOSTSNP`), then the program's output with Rex's own messages as `ESC _ rex1;<nonce>;<json> ESC \` (`resize` right after the snapshot, `theme`, `child_exited`). `alacritty_terminal` cannot read the snapshot, and nothing lines the stream up with `format`: `format` answers `content`, `id`, `total` and `eof`, and the stream carries only those messages and, for a resume, a byte count of its own. Seeding an emulator from `format` and then following the stream could apply output twice or drop it.
- So reads and watches poll `format` VT, as collied polls herdr's reads for a watch (every 250 ms, every 1 s once the screen has not changed for 5 s): one `format` with `max_bytes`, then `blob_read` of the tail the phone's lines need, cut at a line break, emulated afresh. Each poll is the terminal's whole current state, so output is never applied twice and never lost from what the screen and its history hold; output a program overwrites between two polls is never seen, as with herdr.
- Cost, measured against a terminal filled with numbered lines (one `format` with `max_bytes: 65536` plus one `blob_read` of the last 64 KB): 0.9 to 1.2 ms at 1,000 lines (0.04 MB of VT), 10 to 14 ms at 10,000 (0.45 MB) and 39 to 46 ms at 100,000 (4.4 MB). What crosses the socket stays bounded; the server's work grows with the scrollback. At 250 ms that is about a sixth of a core while a phone watches a 100,000-line terminal that keeps changing, a twentieth once it is quiet. The data connection's snapshot, by comparison, sent 0.05 MB in 1 ms at 1,000 lines and 4.5 MB in 65 ms at 100,000 before any live output. If polling proves too dear, two later options remain: a data connection used only as a sign that output arrived (its bytes discarded, the snapshot paid once per watch), or libghostty-vt, which the app already builds from pinned tarballs, to restore the snapshot itself (a new native dependency for collied; whether its C API reads Rex's snapshots is unknown).
- Size: neither `format` nor a data connection changed a terminal's size or owner (verified on a terminal resized to 100x30 with no owner). collied never calls `resize`, `own_block` or `set_theme`, and opens no data connection. A block Rex.app owns has Rex.app's size: 198x68, its owner Rex.app's client, and `format` and `blob_read` left both unchanged (verified in #705 on the owner's server, 0.1.0-preview.19).
- Checked in #705 against 0.1.0-preview.19 (build 1972, API revision 14, speaking 13 to collied), on a scratch server and, read-only, on a Claude Code permission dialog in a block Rex.app owns:
  - VT rows are joined by `\r\n`, with none after the last row, which may be empty: the whole rendering is fed as it comes. The spike's "final line break dropped" held for a screen with no scrollback; with scrollback it shifts the screen down by one row.
  - At revision 13 a `format` with `max_bytes` answers `content`, `id` and `total`, and no `eof`; `blob_read` answers `eof`. Nothing in either answer, and no terminal event, says whether the screen changed: Rex has no revision, output event or `updated_at` for a screen. A poll that finds the screen unchanged therefore still calls `format` and, for a terminal over 64 KiB, `blob_read`; it skips only the emulator.
  - A result's lifetime: `blob_read` documents "about five minutes"; in practice a block keeps its newest four results, with ids counted per block, readable from any connection (300 `format`s in a row left only the last four readable). An older one answers `not_found`. So the server's memory is bounded by four renderings per block: 150 s of polling a 100,000-line terminal (6 MB of VT) every 250 ms left its RSS between 438 and 593 MB, with no growth.
  - A `blob_read` from inside a character answers its first bytes as replacement characters, one per byte; collied cuts the tail after its first line break, so they never reach the emulator.
  - A result's first `blob_read` costs more than later ones of the same range: 5 to 6 ms at 1,000 lines and 10 to 12 ms at 100,000, against 0.5 to 1.3 ms (64 KB). `format` itself: 2.6 ms at 1,000 lines, 33 to 48 ms at 100,000.
  - A whole read through collied (release build, 200 lines asked, median of 20): 1.6 ms for an unchanged 1,000-line terminal, which one `format` answers whole, and 7.9 ms for one that changes every 50 ms; 45 to 58 ms at 100,000 lines whether it changed or not, nearly all of it Rex's `format`.

### 5. Input

- `rex send TEXT` (and `terminal.write`) types the text as raw bytes, with no bracketed paste and no Enter (verified with a raw-mode reader: `w1\nw2` arrived as is). `block.event` with a `paste` event pastes: inside `ESC[200~` and `ESC[201~` when the program turned bracketed paste on, newlines as `\r` otherwise, and an `ESC` in the text arrives as a space, so a pasted `ESC[201~` cannot end the paste (verified). A prompt is a paste and then a `key` event for Enter, which run in order on one connection (verified: Claude Code took the prompt and answered).
- Keys: on the socket a `key` event takes W3C key codes (`key_a`, `arrow_up`, `escape`, `bracket_left`), a modifier string (`ctrl+alt`, with `cmd` as `super`), the text the key types and its unshifted code point, so collied maps its names. For 39 names, the named `Key`s and combinations of each kind, a raw-mode reader received the same bytes from those `key` events as from `rex send-key` with collie's name, and the bytes herdr sends (verified): `enter`, `esc`, the arrows, `shift+left`, `tab`, `shift+tab`, `backspace`, `ctrl+c`, `ctrl+enter` as `ESC[27;5;13~`, `ctrl+a`, `ctrl+b`, `ctrl+e`, `ctrl+k`, `ctrl+l`, `ctrl+u`, `ctrl+w`, `ctrl+end` as `ESC[1;5F`, `end`, `space`, `a`, `1`, `/`, `` ` ``, `[`, `alt+x`, `ctrl+alt+x`, `shift+f5`, `f1`, `f12`, `alt+enter`, `shift+enter`, `ctrl+space`. Lost on a Rex agent: `cmd+k` (any `cmd` combination), `ctrl+[` and `ctrl+shift+x` send nothing either way to a program without a keyboard protocol, and `ctrl+alt+[` sends `ESC [` (Alt's `ESC`, then `[` without its Control); `ESC [` followed by the next keys could spell an escape sequence, which is why collie allows `[` only with Control. collied refuses these four kinds for a Rex agent, as herdr-core refuses `cmd`, rather than send nothing or `ESC [`. A program that turned on a keyboard protocol was not tried. `rex send-key` refuses an unknown name (exit 2). Phase 3 keeps a live test of every key over the socket.
- As built (#706), checked on preview.19 (build 1972, API revision 14 speaking 13) by a raw-mode reader in a block of a scratch server, against herdr-core in a core of its own: 504 names (every named key, function key and character key with each combination of Control, Alt and Shift, `cmd+k` and `ctrl+end`) through collied's own key path, once. Rex and herdr-core sent the same bytes for all but these, which corrects the list above: Shift with a character that is not a letter (`shift+1`, `shift+/`) is the key itself in herdr-core, not its shifted character, so collied now sends that text (the sweep ran with the shifted character; `live_rex_input` pins the fix for every character key); `ctrl+shift` on a named key (`ctrl+shift+up`, `ctrl+shift+enter`, `ctrl+shift+f5`) and `ctrl+alt+shift` on anything arrive as herdr-core sends them, so only Control and Shift without Alt on a character, or on `space` (`ctrl+shift+space`, which herdr-core refuses), send nothing; `ctrl+i`, `ctrl+'`, `ctrl+,`, `ctrl+-`, `ctrl+.`, `ctrl+;`, `ctrl+=` and ``ctrl+` `` also send nothing in Rex, and herdr-core refuses them; `ctrl+alt+[` arrives as `ESC [` in herdr-core too. collied refuses `cmd`, those Control keys, `ctrl+shift+space`, `ctrl+[` and `ctrl+alt+[`, before any key of the call is sent. This is narrower than the issue's wording ("`ctrl+shift` combinations are refused"), a measured deviation: collied refuses only what Rex drops, so `ctrl+shift` on a named key still reaches the program. `live_rex_input` keeps the check for every named `Key`, every character key alone and with Shift, the combinations herdr-core's live test pins and a few more, Ctrl+End, a notice digit and a paste. In a one-off manual check on the owner's own Rex server, with the owner's permission, the same `key` and `paste` payloads reached a block of the check's own with the same bytes; tests never do this and run a server of their own (AGENTS.md). Inferred, not run: a program with a keyboard protocol, and Rex.app's own blocks beyond that one.
- `block.event` is refused (`conflict`) on a connection not attached to the block's session (verified), so collied sends on its follower's connection, which attaches every session; it opens no connection per send.
- No write can be held to a status (as built in #706, collied checks the status again before each event of a prompt; see architecture.md): `block.event` and `write` take no condition, and Rex holds nothing while someone types on the Mac. collied's ready check, `program_status` right before the write, is the only guard: the gap herdr leaves, wider than herdr-core's.
- Text without Enter (the slash mirror, an approval note) is a paste alone.

### 7. Grouping

- A Rex session is a group of related work, as a herdr workspace is: one group per session, `rex:session:<uuid>`, with the session's label (`session_label_changed` follows renames), numbered after herdr's and herdr-core's. Windows (tabs) are not shown. One group per server would hide the user's own grouping.
- `pane.close` is `block.close`, which ends the program; a window whose last block closes closes too. A session outlives its last block and window (verified).
- `workspace.close` on a Rex group is refused ("close its agents one at a time"), as for a herdr-core group. It would be `session.destroy`, which ends every block in the session, Rex.app's included, while the phone shows only agents, and Rex offers no conditional destroy (`server.stop` has `if_idle`; `session.destroy` takes only the session), so a check that the session holds only agents could be overtaken by a block Rex.app opens before the destroy.

### 8. Tasks

- On Automatic, the app's default, New task starts in herdr while herdr answers, else in a followed herdr-core, else in a followed Rex, so a machine that runs both herdr and Rex changes nothing. The app's **Start tasks in** setting can ask for Rex (or Herdr, or Herdr 2) instead: the task then starts there or nowhere, and collied's error names the runtime and why, such as "Rex is not running on this computer" (#723, Runtime in [architecture.md](architecture.md#herdr-integration-verified-against-093-source-and-live-socket)).
- A task is a session of its own, as herdr's `workspace.create` makes a workspace: `session.create` with the task's name as label and one window whose block runs `/usr/bin/env -u <name> ... <CLI path> <args>` (`options.command`, `options.cwd`), the API form of `rex new NAME -- COMMAND` (verified with `shell: none`: Claude Code started there and reported). With Rex's default shell (a login shell, not interactive) the agent gets the user's profile `PATH`, as Rex.app's terminals do; with `shell: none` it gets the server's environment. Checked in #708: `options.command` is an argument vector the login shell `exec`s unchanged ([Shape](#shape)). `rex run` and `session.new_window` would put a task in an existing session instead.
- The `-u` list is herdr-core's sixteen names: a Rex server passes its environment to every terminal (verified), and a server started by a `rex` command inside a herdr pane would carry that pane's variables (not verified: `rex server start --env` suggests only named variables pass).
- `session.create` makes collied the owner of the new block, which would keep collied's size (80x24) and keep Rex.app from sizing it. collied disowns it at once (`session.disown_block`, which needs the session attached), so Rex.app sizes it as it does the user's own blocks (not checked with Rex.app: on the owner's server the block had no owner afterwards and kept 80x24 while nothing showed it).
- A block has one label, which Rex.app shows, and nothing like herdr-core's `collie.kind` and `collie.worktree`. collied records the blocks it starts (kind, worktree checkout) by block id in its data folder; ids are never reused.
- Worktrees and archive as for herdr-core: `git worktree`, then `block.close` of the task's own block by id, then `git worktree remove`. Archive also removes the session collied created for the task once nothing is left in it ([Shape](#shape), #727); any other session stays, for the reason `workspace.close` is refused. The check that nothing else works in the checkout, read again after closing the task's block, has the same short window herdr-core's has.

### 9. Focus

- `rex focus BLOCK` (`session.focus_block`) makes the block's window the session's active window and focuses the block, on the server (verified with `session.view`), with no Rex.app setting. It answers `{"revision": N}`; on a block already focused in the active window, which a new task's only block always is, it changes nothing and, on a scratch server, sent no event.
- Rex.app does not follow it (checked by the owner with Rex Beta.app 0.1.0-preview.19 on 2026-11-15, #709). Showing another session, the app stayed on it after `session.focus_block` on a one-block session; behind another app, it neither came forward nor switched to the session after a call whose revision shows it changed the session's active window. The call changes only the server's view of the session. Not checked: whether the app, already showing the session, follows the new active window.
- Rex.app's own actions (`client.tab.goto`, `client.window.*`, through `client.perform` or `rex -C`) are refused while Remote Control is off in its settings: its binary holds "Rex.app is not accepting actions. Turn on Remote Control in its Settings under Rex Server." collied never calls them: they drive the app, and that setting is the user's.
- `agent.focus` on a Rex agent is therefore refused, as for herdr-core, with "a Rex agent cannot be focused from the phone" (`internal`). collied does not call `session.focus_block`, and never calls Rex.app's own `client.*` actions.

### 10. Alongside the others

- Ids: a block is `rex:block:<uuid>` (46 bytes) and a group `rex:session:<uuid>` (48 bytes), within `TerminalId`'s `[A-Za-z0-9_:.-]{1,64}`. Rex ids are never reused, so a restarted or wiped server never aliases old ids. collied routes by the `rex:` prefix, as it routes `hc:`; the phone parses no id.
- Discovery as the CLI does it, from collied's own environment ([What Rex is](#what-rex-is)), never `REX_SERVER`, which can name another machine, and never the hosts list. Rex missing or stopping behaves as herdr-core does: a server that never answered is quiet, one that stops after answering logs once and its agents leave with one `flock.changed`, and `herdr_unavailable` is answered only when no runtime answers.
- `collied status`: a `rex:` line with the version and API revision (or `not running`), the socket and its folder's mode, any method the server lacks, and remote access when it is on.
- `collied doctor`: informational when Rex is absent; else the version and the socket, and a warning for a server it does not follow (API revision, missing methods, the personal-server checks, a listener admitting anonymous callers), for Tailscale mode or a tailnet listener, and for a server whose environment (read by name only, from `server.status`'s `pid`, as for herdr-core's holder) holds `HERDR_PANE_ID`, `HERDR_SOCKET_PATH` or `CLAUDE_CODE_CHILD_SESSION`.
- Platforms: macOS, verified. Linux, where collied and CollieTray also run, is not verified; `rex server install ssh://...` installs a server on a Linux machine, and a collied there would follow that machine's own server. Remote hosts are never followed.
- Threat model, the supported boundary: a personal server. collied follows a server only when its socket is owned by the user and has no group or other permission bits, its folder is owned by the user with mode `0700`, and the peer on the socket (the server) runs as the user; otherwise it refuses, logs once and `doctor` says why. That keeps out Rex's shared server on Linux, whose group members all see and type into every session as the `rex` account, and a personal socket opened to a group with `--socket-mode`. Only the scratch personal server was checked here; Linux was not.
- Remote access, off by default and off in the issue's assumption: built-in Tailscale (the tailnet owner, or every member the ACLs allow), tailnet and Tailscale Serve listeners (the owner, or every identified caller), plain HTTP with `--allow-anonymous` (anyone who reaches the port, with full access) and SSH forwards. collied reads `server.status` (`listeners` with their `transport` and `admission`, and `tailscale.state`) when it connects: a listener admitting `anonymous` callers makes it refuse to follow, since anyone on that network types into the same agents; Tailscale `running` or a tailnet listener lets it follow, with one log line and a warning in `collied status` and `doctor`, since those reach the same terminals outside collie's allowlist and audit.
- What collied calls: the API is wider than herdr-core's (Tailscale, Lua, Rex.app's actions, files), so the client refuses anything but `hello`, `help.all`, `block_creator.list`, `server.version` (the version `collied status` shows), `server.status`, `session.list`, `session.attach`, `session.attach_all`, `session.list_blocks`, `block.close`, `block.event` (`paste` and `key` only), the terminal methods `program_status`, `process`, `title`, `size`, `format` and `blob_read`, and for tasks `session.create`, `session.disown_block` and `session.destroy` (an archived task's own session, once empty, #727); never `data.connect`, `server.stop`, `server.tailscale.*`, `hosts.*`, `server.apple.*`, `client.*`, `own_block`, `resize`, `set_theme`, `write`, `list_dir`, `upload_begin` or `download_begin`. The paste neutralizes `ESC`, so a prompt cannot break out of bracketed paste. Screens are kept on disk under the state folder, same-user only. The threat model gains a Rex section in phase 1.

## Shape

Phase 1 as built (#704):

- Routing: `Owner::of` classifies an id once by its prefix (herdr's have none, `hc:`, `rex:`), and every `Runtime` call matches on it, so a fourth runtime is a new arm the compiler asks for in each call. Callers outside the runtime module ask `Owner`, not a prefix test, where this phase needs a Rex answer (status times, stars, pull request wakes, herdr's held agents); the rest still test `herdr_core::owns` until their phase.
- `crates/collied/src/runtime/rex/`, one concern per file: `wire.rs` (wire types), `client.rs` (the method enum, the handshake and hello, calls matched to responses with timeouts, the event pump), `discovery.rs` (the socket and the personal-server checks), `model.rs` (sessions and blocks from reads and events, and the agents and groups they list) and `mod.rs` (the method check, subscribe then read, reconnect with herdr-core's backoff, `status` and `doctor`'s report). Later phases add files.
- Shared with herdr-core, moved rather than copied: `runtime/agents.rs` holds the agent CLI and shell lists, kind from `argv0` and `app`, OSC 7501 state to collie's status, the title without its spinner, a group's status and an agent's pane. The sixteen stripped names move there in phase 5.
- The allowlist is the type: `client::Method` names each method this phase calls and nothing else; a unit test pins their wire names. `server.version` was added to the plan's list for the version `collied status` shows.
- Listing (`poll`, `agent.list`, `session.snapshot`, `agent.get`) reads the model the events keep current: no call per poll. `pane.close` and `task.archive` are `block.close` on a listed agent only; `workspace.close` is refused; every other call on a Rex id answers "not available for Rex agents yet" from routing. An agent with no status is read-only, as for herdr-core.
- `state_change_seq` comes from the root record's `updated_at` (a SHA-256 prefix) rather than a counter: every report moves it, and an unchanged record keeps it across a reconnect and a restart of collied, which a counter would not. Only equality is ever compared.
- A session's label also comes from `session.attach`, so a rename whose event arrived before the session was listed is kept. A block whose reads fail is skipped and logged rather than dropping the connection; a server that answered and then failed is reported as not followed, with the reason, and logged once per reason. The core and Rex share one record of herdr's reachability.
- `ServerConfig.rex` names the socket to follow; only the daemon discovers it, so tests never reach the user's server.
- Phone protocol unchanged: `claude-code` is `claude`, `error` is `unknown`.

Phase 2 as built (#705):

- `runtime/rex/screen.rs` reads screens; `mod.rs` routes them to the listed agent's session, block and size. `Screen` is shared with herdr-core, with one addition, `text`, the screen as plain text for herdr's `detection` source.
- A read: `format {format: vt, max_bytes: 1}`, then `blob_read` of the last 64 KiB, cut after its first line break and doubled while it holds fewer line breaks than the screen's rows plus the lines asked for, then fed to a fresh `Screen` at the block's size. One answer holds 983,040 bytes as a JSON string, its quotes included (so 983,040 bytes of plain text never fit, checked live): a doubled tail that does not fit is not used, the last one that did is, and that reader never asks for the larger size again. A tail without the screen's rows fails the read. A block whose rendering was 64 KiB or less last time is read by one `format` asking up to 960 KiB, which holds it whole.
- `unwrap: true` for reads with history, so `recent_unwrapped` joins soft-wrapped rows, which herdr-core's paint cannot; `visible` and `detection` read rows as drawn, since with `unwrap` a line longer than the tail left nothing above the prompt (50 lines, 2,000,000 `x`, then a prompt; `live_rex` checks the rows).
- Unchanged: each reader (block, source, and lines for a read with history) keeps the tail it fed and the text it read; the same tail at the same size answers that text with no emulator work, and the watch then sends nothing.
- A result gone before its `blob_read` is formatted again, three times at most; a read that still fails is an error, which a watch skips.
- `size` is the first read of each block, so no block is listed before its size, and `size_changed` keeps it current; `pane_columns` answers from it.
- A block whose reads fail is read again on its next block event, not only with its session's next read, and logged once until it is read.
- `agent.explain` answers the blocked report's `kind` from the model, and the `detection` read gives the screen as text, which approvals read since #706.
- The plan's `detection_text` from `format` text was not built: the text keeps every row, so its last `rows` lines are the screen only when the screen is full; the emulator's screen is right either way and costs nothing more.

Input and approvals as built (#706):

- `runtime/rex/input.rs` builds the only events collied sends, a `paste` and a `key` press, and sends them as `block.event` (a new `Method`, so the method check requires it) on the follower's connection, in order, each awaited. - Approvals: the engine is given Rex (`Approvals::with_rex`, and the daemon's) and reads a Rex agent through #705's `detection_text` and `explain`; nothing of it is Rex's own but the bound on screen reads. Phase 5 as built (#708), against Rex 0.1.0-preview.19 (build 1972, API revision 14):

- `runtime/rex/tasks.rs`; the task code is herdr-core's, made to take `runtime::TaskHost` (a followed core or a followed Rex) instead of the core, so start, the ready check, prompt delivery, worktrees and archive are one path for both. `Runtime::task_host` picks herdr while it answers, else a followed core, else a followed Rex. - Start: one `session.create` with the task's label (or name) and one window whose block is the `com.superlogical.terminal.shell` flavor with `options: {command, cwd}` and the task's name as its label. `command` is `/usr/bin/env -u <name> ... <CLI path> <args>`, an argument vector: no `shell` option, so the user's login shell (from the user database, `/bin/zsh` here, whatever the server's `SHELL`) reads the profile and `exec`s it unchanged. The agent's process leads the block itself (the shell `exec`s), with `REX_BLOCK` and `REX_SESSION` set.
- Ownership: `session.disown_block` fails (`bad_request`) on a connection that only called `session.attach_all`, so collied attaches the new session first; attaching twice is harmless (checked). The start fails, naming the block it left running, if collied's client still owns it.
- Exit: a block no client owns closes when its program exits (`child_exited`, then `block_closed`); one a client still claims stays with `last_exit` (seen with a block whose creator, the CLI, had left). collied follows both for its task blocks, so an agent that exits before it is ready fails the start at once.
- Rex sends `process_changed` only when the foreground's pid or name changes: a bash script that `exec`s bash with another `argv[0]` kept the first `argv0` in the model and was never listed (the live test's first stand-in did this). Claude Code and Codex start through `env` under other names; the live stand-ins are Perl.
- Records: name and checkout by block id in `rex-tasks.json`, forgotten on the block's `block_closed` or once a full read no longer finds the block.
- After review: the ready check also requires the agent's foreground process to run in the folder asked for, since Rex starts a block whose folder is gone in the home folder (checked live by the reviewer) and the prompt would follow it there; herdr-core refuses that start (`spawn_failed`, checked live), and its tasks take the same check. A herdr-core that answered and whose connection ended is an error for New task, not a reason to start in Rex, until collied's next attempt finds it gone; past that, collied cannot tell a restarting core from a stopped one without probing, so a task can start in Rex during the rest of the backoff (up to 30 s). Occupancy for the archive is read afresh (`session.list`, `session.list_blocks`, `process` per terminal block), since a shell's `cd` sends no event.

A probe block of the check's own on that server had no owner after `session.disown_block`, with Rex.app running. The check's sessions and branch were removed by hand afterwards.

Session removal as built (#727), against Rex 0.1.0-preview.19 (build of 2026-11-13, API revision 14), on the owner's decision of 2026-11-15 that collied may remove a session it created once it is empty:

- Ownership: the task record (`rex-tasks.json`, by block id) also keeps the id of the session `session.create` made for the task. The file survives a restart of collied, so a task started before one is still known; a record without a session (earlier builds), or none at all, leaves the session alone. Rex moves blocks only within a session, but the archive also requires the block's session in the model to be the recorded one.
- Archive: `block.close` of the task's own block, as before, then, only for that recorded session, `session.attach` (its view, whose `windows` Rex leaves out when there are none) and `session.list_blocks` (detached blocks included). Both must come back empty, else the session stays; a missing view or block list counts as not empty. Then `session.destroy`, a new `Method`. Checked live: a window whose last block closes closes before `block.close` answers, so the reads right after it find the session empty; `session.destroy` of a session already gone answers `session_not_found`.
- Rex has no conditional destroy (`session.destroy` takes only the session), so a block or window added to that session after `session.list_blocks` answers and before `session.destroy` arrives, one round trip on the local socket, ends with it. Rex.app opening a window in a task's session in that instant is the case left.
- The archive's answer, which the phone shows, says what became of the session: "Removed its Rex session.", "Kept its Rex session, which still holds something or could not be read.", or "Could not remove its Rex session (...)." The task is archived in each case; nothing is said for a session collied did not create.
- Resume reads the agent's own transcript and starts a new session, so an archived task resumes as before (`live_rex_tasks`).

## Testing against Rex

The AGENTS.md rule this plan adds: a test or check that needs a live Rex starts a server of its own (`rex server run --listen unix://<scratch>/rex.sock --state-dir <scratch> --config <empty file> --restore=false`) from a clean environment with scratch `HOME`, `XDG_RUNTIME_DIR` and `REX_RUNTIME_DIR`, passes `--autostart=false` and `-S` with that socket on every call, stops only that server by its pid and deletes its folder. `--state-dir` alone is not enough: the server also writes under its runtime folder, and with neither `HOME` nor a runtime folder set aside the default socket is the user's. The socket path must stay under 104 bytes, so the scratch folder is a short one under `/tmp`.

As built: CI has no Rex, so `runtime/rex/fake.rs` serves `rex.control.v1` in process on a Unix socket in a temporary folder, with hooks that send events before or after a chosen read, to test the revision refusal, the method check, subscribe before read with a session created in between, `seq` reconciliation, reconnect, the owner and shell rules, other hosts, the folder, socket and listener checks and the message limit. `live_rex` (e2e, `RexServer` in `crates/e2e/tests/common`) runs a scratch server by the rule above, with a stand-in agent in Perl that reports OSC 7501 from the foreground process (a shell script would hand the terminal to `sleep` and its record would be stale), and is skipped when no `rex` is found without running it. `live_rex_phone` (#707) adds the phone over a test tailnet: a stand-in Claude Code that writes its pid file, a stand-in Codex (the test binary named `codex`) whose hook runs `collied hook`'s code with the block's `REX_BLOCK`, Chat for both, `task.sessions`, and a `/clear` with no report followed by the reconcile tick. `live_rex_tasks` (#708) runs New task with stand-in `claude` and `codex` CLIs found first on collied's `PATH`, on a server holding dummy values for the sixteen names, with a login profile in its scratch home; it checks the environment and `PATH` the agents got, the block's owner, the session label, a worktree task, hostile arguments, an archive refused under a shell that `cd`s into the checkout, and the archives: a task's own session removed once empty and kept while it holds a window the test opened, the session of an agent collied did not start kept, and an archived task resumed (#727).

## Risks

- **Preview API.** Rex is 0.1.0-preview.19 (build 1972), its API at revision 14, of which collied speaks revision 13. collied pins the revision and fails closed per missing method.
- **Polling cost.** At revisions 13 and 14 `format` takes no range, no visible-only and no since parameter, and Rex has no output event, so every poll makes Rex render the whole scrollback (up to 64 MiB): 33 to 48 ms of server time at 100,000 lines (measured), 13 to 19% of a core at four polls a second while the screen changes, a quarter of that once quiet; a whole read through collied takes 45 to 58 ms there ([Screen](#4-screen)). Readers of one block share `format`s only when they overlap: one `format` runs at a time per block and `unwrap`, and the readers that asked while it ran share the next one; readers that do not overlap (a watch's poll and a preview's a moment later) each run their own. A reader that asks while one runs waits for it first, up to one more `format` (33 to 48 ms at 100,000 lines); a `format` that fails or times out is not shared, and each reader fails within one 5 s timeout of when it asked, as with a `format` of its own.
- **Session removal.** Rex has no conditional `session.destroy`, so archive's check that a task's own session is empty can be overtaken: a block or window added in the round trip between the check and the destroy ends with the session. Sessions left empty another way (an agent that exited, a block closed in Rex.app, a failed start, earlier builds) stay until the user closes them.
- **A block never given up.** If collied crashes or its connection drops between `session.create` and `session.disown_block`, or the answer to `session.create` is lost, the block stays owned by a client that is gone: it keeps 80x24 and is not closed when its program exits (checked live in the review). collied's start says an agent may have been started; archive from the phone still closes it.
- **The environment.** A Rex server passes its own environment to every terminal; one started from inside a herdr pane or a Claude Code session would hand its variables to every agent, as herdr-core's core did ([herdr-core risks](herdr-core.md#risks)). collied strips them from the agents it starts and `doctor` warns.
- **No input guard.** Without `if`, a dialog that opens after collied's last status check and before Rex handles the event, one round trip, takes the prompt's Enter.
- **Remote access.** A Rex reachable over the tailnet is a second way into the same agents, outside collie's audit; collied follows it with a warning, and refuses a server that admits anonymous callers.
