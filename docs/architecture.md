# collie architecture 🐑

```
iPhone (Collie.app)                                   Mac (or Linux)
┌───────────────────────────────┐                     ┌──────────────────────────────────────┐
│ SwiftUI (Swift 6, UI only)    │                     │ collied (launchd agent, user)        │
│  └ CollieCore (UniFFI)        │   tailnet (WG)      │  ├ tailnet node (user-owned)         │
│     ├ protocol codec          │ ── WebSocket/JSON ─▶│  │   tailscale_listen :port only     │
│     └ tailnet node (libts)    │   dial only         │  ├ whois gate → paired node IDs      │
│ CollieWidgets  (Swift only)   │                     │  ├ protocol allowlist + audit log    │
│ ColliePush NSE (Swift only)   │◀── APNs ────────────│  ├ approvals (nonce, expiry, replay) │
└───────────────────────────────┘                     │  ├ APNs client (Keychain .p8, HTTP/2)│
                                                      │  ├ herdr client ─▶ herdr.sock (0600) │
                                                      │  └ herdr-core client ─▶ hc socket    │
                                                      └──────────────────────────────────────┘
```

On Linux, collied is a systemd user unit ([Linux](#linux)).

## Decisions (2026-10-03)

- Phone and computer run independent embedded nodes owned by the same personal Tailscale user. Authorization checks the node's own positive owner, a same-user untagged and unshared whois, the paired StableID and independent TLS key pins. Neither needs an OS VPN profile or the native Tailscale client; the Mac's corporate VPN is separate.
- libtailscale: upstream submodule pinned by SHA, plus a patch series in `crates/tailscale-sys/patches`.
- XcodeGen generates the iOS project from `Collie/project.yml`; `.xcodeproj` is not checked in.
- APNs display content (alert titles, bodies and approval context; initial, update and end Live Activity labels and state) is authenticated ciphertext under each phone's per-machine notification key. Public alerts stay generic. Approval nonces never enter a push.
- macOS: arm64 only.
- 2026-10-04: collied also runs on Linux. x86_64 is built and tested; aarch64 is mapped in `tailscale-sys` but not built or tested. Any other OS is a compile error.
- 2026-10-04: on Linux the service is a systemd user unit with the launchd agent's semantics: kept alive, and `collied stop` keeps it off across reboots until `collied start`.
- 2026-10-04: each machine sends its own pushes with its own APNs key (own key ID, revoked on its own). On Linux the key is a systemd user credential (host key, plus the TPM2 when systemd finds one usable), or a 0600 file when systemd-creds is unavailable.
- 2026-10-06: plain shell panes from the phone ([Terminals](#terminals)): off by default, turned on per machine only in `collied.toml`, never from the phone; their own allowlist class, audited like prompts. Opening one and typing into it need a grant collied verifies, signed by a second Secure Enclave key that signs only after Face ID or the passcode; one grant covers one terminal for 5 minutes in one session.
- 2026-10-16: user-owned embedded desktop nodes replace the per-OS tagged identities. Existing tagged nodes and old phone owner pins need an explicit reset and re-pairing; nothing is migrated or retagged. Normal user key expiry applies on both ends. No version bump: no phone wire type changed; the positive owner pin is local persistence and the OS is netmap presentation metadata.

## herdr integration (verified against 0.9.3 source and live socket)

- The socket answers **one request per connection** (NDJSON, 5 s timeouts, 1 MiB line), so collied opens a connection per call; long calls (`events.subscribe`, waits) get their own.
- herdr has **no auth**: same-UID means full control. collied's allowlist is the only boundary between the phone and every shell on the machine.
- **No global agent-status stream**: `pane.agent_status_changed` is per pane, and `pane.updated` ignores status. collied keeps one subscription (lifecycle events plus a status entry per agent pane), rebuilt on `pane.created/closed/moved/exited/agent_detected`, `workspace.closed` and `events_lost` because an entry for a vanished pane goes silent; a 1 s `agent.list` reconcile plus `ping` covers silent streams. It sends `agent.status` when an agent's `state_change_seq`, status, title, name, kind or cwd changes, or, while a phone has a session open, its transcript values ([below](#context-and-inbox)), and `flock.changed` when agents come, go or change workspace, or a workspace is renamed or renumbered.
- Agents are keyed by `terminal_id`; `pane_id` changes on cross-workspace moves and never reaches the phone. Statuses: `idle | working | blocked | done | unknown`.
- With no phone session connected, a status change reads no transcript and builds no event; status times, pane cleanup, approvals, done alerts, followed Live Activities, Tailscale upkeep and APNs carry on. A connection lost without a close frame ends at the 45 s silence limit (collied pings every 15 s).
- **No output stream** in the JSON API. During `agent.watch`, collied polls `agent.read {source: recent_unwrapped, lines, format: ansi}` at 4 Hz (1 Hz after 5 s without a change) and pushes only changes. The phone's `lines` is clamped to 1 to 1000, 200 when absent. In Low Data Mode (`NWPath.isConstrained`) the phone sends `low_data: true` on `agent.watch` and `terminal.watch`, and collied polls that watch at 1 Hz throughout; `low_data` can only slow a watch.
  - The first push of a watch is a full `agent.output`; later ones are `agent.output_patch {terminal_id, base, head, skip, keep, tail, trail, truncated}` when that carries at most half the text. The new text is, joined with `\n`: the `head` lines, lines `skip..skip + keep` of the previous text, the `tail` lines, then the last `trail` lines of the previous text, starting at or after `skip + keep`. A Claude Code spinner tick then costs a few hundred bytes. `base` is the 64-bit FNV-1a of the previous text; collie-core applies a patch only to the text its watch delivered last and only when `base` matches, else it re-issues `agent.watch`.
  - The phone sends its Scrollback setting with `agent.watch` and `recent` reads. It renders at most 2000 rows and, without wrapping, 500 columns. In wrap mode it drops the oldest lines that would not fit and breaks a line after the last space that fits, continuing at the line's indent or past a leading symbol such as `⏺`; each break is a NEL, so selection, copy and links read the line whole.
  - Claude Code's fullscreen mode (`"tui": "fullscreen"`) draws in the alternate screen and keeps its own transcript, so the pane has no scrollback and an ANSI read returns only visible rows.
  - Reads and changed watch output drop Copilot's terminal-cell scrollbar, a trailing `┃` set off by a space: at the column that repeated, separately styled scrollbar cells outside boxes give (Copilot 1.0.100-1 can draw it one column inside the width herdr reports), else at the pane width. A `┃` in a row with box drawing stays unless styled apart. Wrap detection runs on the original rows. No version bump: only read normalization changes.
  - Copilot's `wraps` and `splits` (as for Claude Code, below) cover its prose under `●` and its sent prompts, shaded `▄`-to-`▀` boxes whose text wraps at the box's width before an `HH:MM` timestamp. A row joins the next only where Copilot certainly broke it after a word: it ends with one space in the text's style and the next word would not have fit. Any other row stays, since a typed newline looks the same.
  - Claude Code wraps its prose at the pane width with real line ends, which `recent_unwrapped` cannot undo, so for a Claude Code agent `agent.read` and each changed watch push list the rows that continue a paragraph wrapped at the layout width: `wraps` (after a space) and `splits` (inside a word), on `TerminalRead` and, when they changed, on `agent.output_patch`. With line wrapping on, the phone joins those rows and rewraps at its own width.
    - Width: the widest all-`─` row from column 0 that is no wider than the pane (the input box's rules, drawn at exactly the terminal width), else herdr's `pane.layout` width, which is 1 to 3 columns wider than the terminal (1 for a single pane, 2 or 3 in a split): enough to read a soft wrap as a typed newline. A zoomed tab, or no width from herdr, joins nothing.
    - Rows that count: prose under an indent-0 `⏺` or `※` row at exactly the hang of the row above (numbered items also at the number's indent, as Claude Code 2.1.303 continues them across blank rows; Claude Code 2.1.317 numbers nested items `a.` and then `i.`), and a shaded sent prompt's rows, wrapped 3 columns short of the terminal width, after a row ending with a space in the text's style where the next word would not have fit. In a list, Claude Code 2.1.317 draws an item's code block at the list's indent and the paragraph after it back at the item's text indent, without blank rows. A row at another indent than the hang above starts a paragraph only at the marker or text indent of a list item since the last blank or indent-0 row, and only where the row above certainly ended (its first word would have fit there); after any other such row, nothing joins until a blank row. A letter or roman numeral marker counts only at a list item's text indent: a wrapped row like `v. Wade` elsewhere still joins, but at that indent it reads as an item, so it and the rows after it stay unjoined. A paragraph whose first row keeps leading spaces (Claude Code 2.1.317 keeps them on the first row only, also after `⏺`, where they count toward the row's width) continues at the reply's indent, unless a list or held rows, such as code, came after the last paragraph at the reply's indent: there an indented row may belong to them, so it keeps its own indent. Never list items, tool calls and their output, box, table and quote (`▎`) rows or the status line. Wide characters cut one column short of the edge split only inside a word longer than a row, so Korean words keep their spaces.
    - The input box's unsent `❯` text joins where [Draft sync](#draft-sync) reads a soft wrap or a split word, at the box's own width (its bottom rule's, minus 4), so the phone rewraps the whole draft and its cells match Claude Code's text. A typed newline stays a row of its own, except one right where the next word would not have fit, which looks the same as a soft wrap and joins. Bash mode (`!`) and other modes join nothing. No version bump: only which rows are listed changes.
    - Claude Code's true black background (a standalone `48;2;0;0;0`, used by its logo) becomes the default background, so it does not show as black cells on the phone.
  - Codex's `wraps` and `splits` (prose under `•`, sent prompts under `›`) take the width of the widest blank row shaded from column 0 that is no wider than the pane (Codex pads its composer and sent prompt boxes to exactly the terminal width), else the `pane.layout` width, 1 to 3 columns too wide here as well (codex-cli 0.163.0 and herdr 0.9.5: 205 columns for a 206-column rect, 101 and 100 for two 103-column split panes).
- herdr's `agent.prompt` refuses blocked agents; its `agent.send_keys` does not. collied also rejects `agent.prompt` for an agent it sees as `blocked`, re-read with `agent.get` just before the call. Manual input to a blocked agent goes through `agent.send_keys` and `agent.type_text` ([Prompts without decisions](#prompts-without-decisions)).
- **Scrolled-up Claude Code.** While Claude Code's fullscreen transcript is scrolled up on the machine, a permission prompt scrolls out of view and herdr reports the agent idle, so keys would answer it unseen. collied refuses `agent.send_keys`, `agent.type_text` and `agent.prompt` to a Claude Code agent that is not blocked (`agent_not_ready`) when the visible screen, read just before the write, shows the "Jump to bottom" or "N new messages" banner. `protocol::jump_banner` matches it as Claude Code draws it, a space-padded label on an SGR background: its own background run (with or without its hint) or, as herdr writes no escape between it and same-style prompt text, label and hint centered on the row inside a run.
  - `agent.scroll_bottom {terminal_id}` (Drive class, audited, idempotent so no `op_id`) sends Ctrl+End as the fixed bytes `ESC[1;5F` through `pane.send_text` (herdr 0.9.3 has no key name for it), only to a ready or blocked `claude` agent while the banner shows; nothing from the phone becomes input. Ctrl+End never moves a dialog's selection; a prompt it brings back is `blocked` again with a new `state_change_seq`, so its approval is raised again. Meanwhile the phone offers a Jump to bottom button and disables the key strip.
  - Limits: background text quoting the padded banner (a prompt row or diff line) reads as scrolled up until it scrolls away. A banner without color (`FORCE_COLOR=0`) or in reverse video is not detected. A prompt that appears while already scrolled up is not `blocked`, so it raises no approval or notification until scrolled back down.
- **Claude Code notices.** Notices above Claude Code's input box (the "Heads up" tip, its Learn more explanation, the feedback row after a Dismiss, the session rating) take a single keypress, which a prompt cannot carry (herdr pastes it and ends it with Enter). `protocol::notice` reads any notice's options from the screen by one rule, not a list of known notices:
  - Options are rows indented two spaces whose cells all read `<digit>: <label>`: digits exactly 1 to n (n up to 4), then `0: Dismiss`; each label non-empty, at most 64 characters, with no control or format character and no `:`. Above them is the lead: a row starting at column 0 with `✦` (tips) or `●` (rating), which may carry the first options, then rows indented two spaces or blank. Below them, after at most three blank rows and right-aligned hint rows, is the input box: the last row starting at column 0 with `❯`, directly under the box's top rule (`─`, or a renamed session's `─── <title> ─`). A dialog replaces the box, so it never matches.
  - Transcript rows start with other glyphs (`⏺` reply on macOS, `❯` prompt, `✻` finished turn), so a reply in that shape does not match; on Linux Claude Code marks replies with `●` (see the threat model). When the lead holds a blank row, as an explanation's side-agent text does, the options must follow a blank row and sit directly on the box's top margin (or the blank rows above a hint), with no other blank row below them, since each card a side agent writes ends with a blank row. Anything else gives no options.
  - `agent.answer_notice {terminal_id, digit, label}` (Drive class, audited with the digit and label; no `op_id`, since a replay finds the notice gone) sends the digit alone through `pane.send_text`. collied sends it only to a ready `claude` agent (never `blocked`, where a digit could pick a permission option) with no banner, and only when the visible screen, read just before the write, lists that digit with that label directly above an empty input box (the dim placeholder counts as empty): notices reuse digits, and a digit must never land in a draft. It then holds the input box lock for up to 1 s, until the box shows something other than empty or the digit, since the option Claude Code runs 400 ms later can fill the box and a prompt pasted meanwhile would submit that fill.
  - The phone shows the options as buttons for a Claude Code agent that is not blocked or scrolled up, 600 ms after first seeing them (Claude Code ignores a digit typed sooner, leaving it in the box).
  - Option effects are Claude Code's: Chat in main session and feedback option 4 (`/plugin disable cc-plugin-you-should-know@builtin`) fill the box unsent (Claude Code would submit the note only with no input box, and collied answers only above an empty one), and the phone withholds Enter from the key strip while it knows the box starts with `/`; feedback options 1 to 3 log an event about the tip (enums and counts, never its text or the transcript). A Claude Code plugin whose band draws this shape is answered the same way, and its option's code runs (see the threat model). What follows a rating is answered on the machine.
- Prompt text rejects ESC and C0/C1 controls because herdr pastes it with bracketed paste.
- Residual race (herdr side): herdr checks the foreground agent before queuing the text and the delayed Enter, so if the agent exits in between, the shell receives the prompt. Closing it needs a conditional input in herdr (`expect: {terminal_id, state_change_seq, foreground pid}` on `agent.prompt` / `agent.send_keys`), to be proposed upstream.
- Mutations (`agent.prompt`, `agent.send_keys`, `agent.type_text`, `agent.send_text`, `task.new`, `task.archive`, `terminal.run`, `terminal.send_keys`, `terminal.send_text`, `attachment.begin`, `attachment.commit`) carry a client `op_id`; collied keeps a per-peer outcome cache so a retry after a dropped connection returns the first result.
- **Task folders.** `task.options` also returns `roots`, the canonical `[tasks] roots`. `task.folders {path}` (Drive class, read-only so no `op_id`, audited with the path and count, never the names) lists the folders directly inside a folder under the roots. collied opens the canonical path one component at a time from its root with `openat(O_DIRECTORY | O_NOFOLLOW)`, so a folder swapped for a symlink after the check fails instead of leading outside, and refuses (`folder is hidden`) a path through a folder below the root that starts with a dot or, on macOS, carries `UF_HIDDEN`, such as `~/.ssh` or `~/Library`. Of at most 10,000 scanned entries it returns at most 500, sorted case-insensitively: valid `FolderName`s (1 to 255 bytes; no leading dot, `/`, `\`, control, format or invisible character, or surrounding whitespace) that are directories, or symlinks resolving to a directory under the roots, and on macOS not `UF_HIDDEN`. Nothing inside the folders is read.
  - `new_folder` on `task.new` (a `FolderName`) is created inside `cwd`, which is opened and refused when hidden the same way; a path reaching 1024 bytes is refused. collied runs `mkdirat(parent_fd, name, 0755)` (any existing entry, symlink included, is `folder already exists`) and checks that `<parent>/<name>` resolves under the roots to that folder (same device and inode) before starting the agent there; nothing else is created. The audit target is `<path> (created)`, else `<cwd> new_folder="<name>"`. The `op_id` covers the whole request, so a retry replays the first result. A failed start leaves the folder and says so.
  - Only the phone keeps the base folder, per machine (`taskBases` in `prefs.json`), as `task.folders` returned it, so a folder collied refuses is never stored; New Task completes names locally and sends `<base>/<name>`, which collied checks like any `cwd`.
- **Clone.** `clone` on `task.new` (a `CloneSource`, exclusive with `new_folder` and `worktree`) is `owner/repo` (GitHub), `https://host[:port]/path` or `git@host:path`, every path segment ASCII letters, digits, `.`, `_` or `-`, starting with neither `.` nor `-`. Both ends refuse any other transport, a local path, userinfo, a query, `..` or a leading `-` at parse time. collied creates the folder (the last segment without `.git`) inside `cwd` as for `new_folder`, then clones into it: `owner/repo` with `gh repo clone -- owner/repo <folder>` when `gh` is in `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` or `~/.local/bin`, otherwise (or when gh exits 4, not logged in, and left the folder empty) with `git clone -- https://github.com/owner/repo.git <folder>`; a URL with `git clone -- <url> <folder>`.
  - The child gets null stdin, `GIT_TERMINAL_PROMPT=0`, `GH_PROMPT_DISABLED=1`, none of collied's `GIT_*` variables, no `GH_TOKEN` or `GITHUB_TOKEN`, and, through `GIT_CONFIG_COUNT`, `protocol.allow=never` with only `https` and `ssh` allowed (`file`, `ext`, `git` and `http` denied explicitly), which outranks config files and survives a `url.<base>.insteadOf` rewrite. It runs in its own process group, killed 75 s after the first attempt or when dropped.
  - A failed clone returns the cleaned tail of git's stderr (at most 1000 bytes) and removes the folder if it is empty again. The audit target is `<cwd> clone="<source>"`, or `<folder> (cloned) clone="<source>"` after a successful clone, which stays if the agent then fails to start. The phone waits 165 s for the reply.
- **Pull request worktree.** `task.new`'s `worktree` can be `{"mode": "pull_request", "number": N}`, N from 1 to 2^32 - 1. collied lists the repository with herdr as for Create, then runs `gh pr view N --json headRefName,headRefOid,isCrossRepository` in its checkout, with the linked pull request read's `gh` and environment (30 s).
  - A pull request from a fork (`isCrossRepository`) is refused: its branch is someone else's code, and a project's agent settings in it would run on the machine. The untrusted head branch must pass the typed branch name rules (ASCII letters, digits, `/`, `.`, `_` and `-`, no `..`, no leading `-`, no trailing `/`, at most 255 bytes) and `git check-ref-format --branch`, the head commit must be 40 or 64 lowercase hex digits, and `.worktree/<branch with / as ->` must not exist.
  - collied fetches only that branch, with the clone's environment (`git fetch --no-tags --no-recurse-submodules --no-write-fetch-head origin -- +refs/heads/<branch>:refs/remotes/origin/<branch>`), checks that `origin/<branch>` is the head commit gh named (else `try again`), and creates a tracking branch unless the branch exists; an existing local branch at another commit refuses the task and is not moved. The task then continues as Create. The gh read, the checks and the fetch share one 75 s budget. The audit target is `<cwd> pull_request=<N>`; the phone waits 165 s for the reply.
- **Resume.** `task.sessions {cwd}` (Drive class, read-only so no `op_id`, audited with the path and count, never the prompts) lists up to 20 recent sessions of a folder under the roots, newest first, for the allowed kinds among `claude` and `codex`, leaving out sessions a herdr agent already reports as its `agent_session`.
  - Claude Code sessions are the `<uuid>.jsonl` files directly in `~/.claude/projects/<project dir of cwd>/`. Codex sessions are the rollouts under `$CODEX_HOME/sessions/YYYY/MM/DD/` (newest folders first, at most 10,000 listed; a plain `.jsonl` wins over its `.jsonl.zst`) whose first line is `session_meta` with that exact `cwd`, the file name's id and a `cli` or `vscode` source.
  - Only the 400 newest files of each kind are opened (`O_NOFOLLOW | O_NONBLOCK`), reading at most their first 256 KiB (a compressed rollout decodes with an 8 MiB window limit). Chat and the status readers read only plain rollouts: Codex decompresses a rollout before appending, so a live session is never compressed.
  - An entry has the kind, the session id (a lowercase UUID), the mtime and the first line of the first human prompt, cleaned and capped at 160 characters like `last_prompt`. A session whose head holds no complete prompt is listed with an empty one if the transcript is longer than the head, and left out otherwise. The prompt line goes to the phone only: never logged, audited or pushed.
  - `resume` on `task.new` (a `SessionId`, exclusive with `new_folder`, `worktree` and `clone`) makes `prompt` optional. collied refuses a kind other than `claude` or `codex`, a session whose transcript is not in that folder, and one a herdr agent already reports. It starts the agent with `args: ["--resume", <id>]` for Claude Code (2.1.296) or `["resume", <id>, "--no-daemon"]` for Codex (0.162.1); without a prompt nothing is typed and the startup dialog check is skipped. The audit target is `<cwd> resume=<id>`.
- **Ultracode.** `ultracode` on `task.new` (default false; refused for agents other than Claude Code) is the Ultracode switch of Claude Code's `/effort` picker, which Claude Code 2.1.299 also takes at launch as a session setting: collied adds `["--settings", "{\"ultracode\":true}"]` to `args` (after `--resume <id>` on a resume), which herdr 0.9.4 quotes for the shell. Claude Code leaves it off when unavailable (dynamic workflows off, or a model without it), so once the agent is ready collied waits up to 1 s for the input box's top rule to carry the `ultracode` tag (`─── ultracode ─`); otherwise the start fails with `agent_not_ready` ("ultracode could not be enabled; nothing was sent"), leaving the workspace open and the prompt unsent.
- **Agent kinds.** `[tasks] agents` in `collied.toml` defaults to `["claude", "codex", "copilot"]`. `task.options` offers those herdr has a manifest for (`server.agent_manifests`), the first as the default, and `task.new` refuses any other. herdr 0.9.5 starts each with `agent.start` and its canonical executable (a missing CLI fails the start, leaving the workspace open) and reads their state from its screen manifests (codex 2026.10.11.1, copilot 2026.08.29.1). While herdr is not running and a herdr-core core answers, tasks start there instead ([herdr-core](#herdr-core-herdr-2), Tasks).
  - Codex: collied passes `--no-daemon`, so Codex's SessionStart hook inherits the launching pane's environment instead of a shared app-server's, keeping `/new` and resume reports bound to that pane. The hook (version 10, `herdr integration install codex`) reports only the session; `collied doctor` warns about a missing or older hook. Codex falls back to `unknown` when no rule matches, so a Codex agent that is `unknown` but `interactive_ready` counts as started.
  - A startup prompt (Codex's or Copilot's folder trust, Codex's update picker) fails the start with `agent_blocked`, to be answered in the terminal. herdr does not rule every one `blocked`, so before the prompt collied reads a Codex or Copilot agent's screen and fails the start the same way if it shows a numbered option (`❯`, `›` or no cursor) or folder trust wording, or cannot be read. For Codex's update picker, nothing is typed and the message ends "Codex is asking to update. Answer it in Terminal."
  - On macOS herdr refuses an `agent.start` whose launch line exceeds the terminal's canonical input limit while the shell starts (`agent_start_input_failed`); collied answers `too_large`, asking to wait for the prompt and try again.

## herdr-core (Herdr 2)

collied also lists the agents of a running herdr-core core (`hc`, 0.1.16), beside herdr's, with no setting: herdr only, herdr-core only and both work alike. It lists agents and their status, reads their screens, binds Claude Code and Codex sessions to them, sends them prompts, keys and approval decisions, and archives and closes them. While herdr is not running, it also starts and resumes tasks there ([the herdr-core plan](https://github.com/rbstp/collie/blob/master/docs/herdr-core.md)).

- **Discovery.** collied resolves the socket as `hc` does, from its own environment: `HC_SOCKET`, else `socket` in `$XDG_CONFIG_HOME/herdr-core/config.toml` (`~/.config`), else `$XDG_RUNTIME_DIR/herdr-core/<session>.sock` (or `/run/user/<uid>/...` when that folder exists), else `$XDG_STATE_HOME/herdr-core/<session>/<session>.sock` (`~/.local/state`), where the session is `HC_SESSION` or `default`. collied never starts a core: an absent socket means none runs. It retries every 1 s, backing off to 30 s.
- **Connection.** JSON-RPC 2.0, one message per line; a connection keeps answering. collied refuses a socket whose peer is another user (`peer_cred`): the socket is 0755, so only its folder keeps others from serving one there. It sends `hello {generation: 1}` and follows the core only when it speaks generation 1, is 0.1.16 or later and lists every method collied calls. It then calls `events.subscribe` on the same connection: a snapshot with its `seq`, then every change in order, a heartbeat every 15 s (45 s of silence drops the connection) and `missed` with a fresh snapshot for a subscriber that fell behind (events at or below its `seq` are ignored). The 1 s reconcile reads what the subscription holds, so no call reaches the core per poll.
- **Methods.** collied calls only `hello`, `events.subscribe`, `terminal.get`, `terminal.read`, `terminal.send`, `terminal.keys`, `terminal.attach` (watch-only to read, typing only to write text without Enter), `terminal.run` (a task's agent, by absolute path, Tasks below), `terminal.kill` and `terminal.rm`, and `server.status` from `collied doctor`; never `machine.*`, `file.*`, `doc.*`, `server.stop`, `server.restart` or a template; the client refuses any other method before it writes.
- **Agents.** A live terminal is an agent once it reports OSC 7501 or its foreground process is `claude`, `codex` or `copilot`, and no shell leads it (Input, below); plain shells are not listed. Terminals on other machines (`box/t7`) are skipped. Its id is `hc:<core id>:<address>` (at most 64 bytes; the core id is permanent, so a wiped core never aliases old ids), used as both `terminal_id` and `pane_id`; herdr's are `term_<hex>`, and collied routes each call by the prefix. The phone parses no id, so it needs no change.
  - Kind: `status.app` (`claude-code` is `claude`), else the foreground CLI. Only the basename of the leader's `argv[0]` is kept, never the rest of `argv`.
  - Status: the OSC 7501 state (`idle`, `working`, `blocked`, `done`); `error`, and an agent that never reported (Copilot CLI 1.0.105), are `unknown`.

## Tailscale (libtailscale, pinned commit, never tagged upstream)

- libtailscale `main@d1dc45d` (bindings 0.2.0, with the listener fd-passing fix 258321b) as a git submodule. Upstream pins tailscale.com v1.104.1; patch 0001 only raises its `go` directive to 1.27.3, and patch 0011 only raises tailscale.com to v1.104.4 in `go.mod` and `go.sum`, with the newer golang.org/x and gliderssh versions it requires, since no upstream commit uses it yet. Requires Go ≥ 1.27.3; builds use `GOTOOLCHAIN=local`, `-mod=vendor`, `-trimpath`, `-buildvcs=false`, `-ldflags=-w`.
- collie calls neither `tailscale_getremoteaddr`, which before 0.2.0 returned the wrong peer 17% of the time under concurrent fd churn in testing, nor `tailscale_loopback`, which would open a 127.0.0.1 TCP listener (SOCKS5 + LocalAPI) on the machine and which iOS reclaims on suspend. The series (patches 0002 to 0010):
  1. `tailscale_accept_with_addr` returns the peer `ip:port` from the record that carries the fd (upstream's holds the IP only). A per-listener lock keeps concurrent accepts from interleaving a record whose `MSG_WAITALL` read was cut short; the short-read path keeps the control message (upstream drops it and miscounts on `EINTR`); a failed accept closes any fd it received; an accept that waited for the lock re-checks that the listener is open. The tailnet end-to-end tests check each accepted address and whois against its dialer under concurrent accepts.
  2. `tailscale_whois_json(sd, addr)` via the in-memory LocalClient (as `tailscale_status_json`).
  3. Disable log upload to log.tailscale.com in Go (`TS_NO_LOGS_NO_SUPPORT`): a c-archive snapshots the environment at load, so a later `setenv` is invisible to Go.
  4. Guard the per-handle `lastErr` with a mutex (also where `getremoteaddr` sets it): upstream's unsynchronized write is a Go data race when one handle is used from several threads.
  5. Keep the Go copy of each accepted fd open until C has received it: macOS's unix-socket GC can dispose of a socket whose only reference is in flight, losing the peer's first bytes (reproduced at about 1 in 150 connections).
  6. `tailscale_dial_timeout` and `tailscale_set_advertise_tags`.
  7. Socketpair proxy: a non-blocking Go end so close always delivers EOF (a lost shutdown wakeup left readers hanging), shutdowns through `Control` so they never hit a reused fd number, cleanup once as soon as either direction ends (upstream waits for both), no fd-number-keyed map.
  8. `UserLogf` discarded: tsnet otherwise prints the interactive login URL to stderr every few seconds.
  9. Listener socket close waits for in-flight `sendmsg` (and item 5 sends each fd inside its `os.File` `Control`), so no fd number can be reused under a send.
  10. `tailscale_rebind(sd, default_if)`. iOS can defunct netmon's route socket while the app is suspended (XNU exempts only local and system sockets), and on iOS netmon has no time-jump check, so it never sees another change and the node keeps binding to the Wi-Fi interface the phone left. The call records `default_if` from NWPathMonitor (`netmon.UpdateLastKnownDefaultRouteInterface`, like Tailscale's own apps) so new sockets bind to it, injects a netmon event and waits up to 1.5 s for netmon to re-read the interfaces through a routing-table sysctl, not its route socket, and publish a move as a major link change (engine rebind, DERP reconnect, control connection closed), then runs the LocalAPI `rebind` and `restun` debug actions: magicsock re-binds its UDP sockets, reconnects any DERP connection that misses a 3 s ping, forgets the peers' direct paths and re-STUNs.
  11. `logtail.Disable()` next to `TS_NO_LOGS_NO_SUPPORT`: with uploads off, every log line was still written to the `tailscaled.log*.txt` buffer, read back and compressed. `crates/tailnet/tests/end_to_end.rs` asserts both files stay empty.
  12. `tailscale_close` first cancels a context every dial derives from: netstack's close aborts only the TCP endpoints registered when it starts and waits for later ones, so a racing dial held the close, and the node restart, up to its 5 s timeout. collie-core closes a replaced node while its dials are in flight.
- The iOS archive is built with `-tags=ios,ts_omit_portmapper`: no NAT-PMP, PCP or UPnP probes of the Wi-Fi gateway on every netcheck. collied keeps its port mapper, so a direct path to a phone behind a hard NAT can still form from the Mac's side.
- Vendored module patches (`patches/<import path>/<file>.patch`, applied after `go mod vendor`; go.sum still verifies every module):
  - tailscale.com `tsnet/tsnet.go`: with no advertised tags specified, keep the existing requests (read through the sanitized `LocalBackend.Prefs()` API before startup), so fresh nodes stay untagged and an old tagged node can be observed and rejected without removing its requests or forcing reauthentication. Explicit nonempty requests keep upstream behavior.
  - tailscale.com `ipn/ipnlocal/peerapi.go`: never open the kernel peerapi listener when netstack is present; upstream binds it to every interface in netstack mode, exposing a TCP port to the LAN. Tests and `collied doctor` check that no kernel TCP listener exists ([Kernel TCP listener check](#kernel-tcp-listener-check)).
  - gvisor `tcp/connect.go` + `stack/stack.go`: a SYN reusing a 4-tuple in TIME-WAIT goes to the forwarder instead of being dropped (the cause of a 63 s dial stall).
  - tailscale.com `wgengine/netstack/netstack.go`: close link queues before aborting endpoints so `tsnet.Server.Close` cannot hang.
  - tailscale.com `wgengine/magicsock/magicsock.go`: `TS_DEBUG_MAGICSOCK_BIND_LOOPBACK=1` binds the UDP sockets to 127.0.0.1 and ::1 instead of every interface. Only the tailnet tests set it (with `TS_DISABLE_PORTMAPPER`), so the macOS firewall never prompts for a new test binary; collied and the app leave it unset.
- Every patch applies with `patch --fuzz=0`: a hunk whose context lines changed fails the build, naming the patch; one whose context only moved still applies.
- Bumping: move the submodule, rebase the patches and review upstream's changes to the files they touch; redo a patch that no longer applies by hand, never force it. `crates/tailnet/testcontrol` must use the same tailscale.com as libtailscale's patched `go.mod` (`crates/tailscale-sys/tests/versions.rs` checks the build's copy). To run a newer tailscale.com than upstream pins, run `go get tailscale.com@vX.Y.Z` and `go mod tidy` in a copy of the submodule with the series applied, save the `go.mod`/`go.sum` diff as a patch and do the same in `testcontrol`; drop the patch once upstream pins that version or newer.
- Control sees Hostinfo `App` `libtailscale`, `Package` `tsnet`, `IPNVersion` `1.104.4-ERR-BuildInfo` (the suffix from `-buildvcs=false`) and `GoVersion`, but no libtailscale version, so it cannot tell 0.2.0 from an older one. What Tailscale keys its libtailscale notice on is unknown (collie's nodes were flagged while already reporting 1.104.1); stamping `-X tailscale.com/version.longStamp=...` and `shortStamp` waits on that answer.
- Gate per connection, before the WebSocket upgrade: whois(peer) must show an untagged node, not shared in, owned by the owner user. The owner is the daemon's verified positive embedded self user before listening; the optional `[tailnet] owner_user_id`, the persisted owner and every paired phone must agree, and a first pairing cannot choose or replace it. Then:
  - paired `StableID` with a pinned TLS key → full session (`hello` first, then the allowlist). While a pairing window is open, a paired phone's `pair.complete` goes through the same y/N confirmation as a new phone's and replaces its record, so a phone that removed the machine while it was unreachable pairs again without a revoke. A paired phone's `unpair`, which the app sends when it removes a connected machine, revokes it as `collied peers revoke` does: collied answers, then removes it, drops its push tokens and closes its sessions;
  - unpaired (or paired without a TLS key), while a locally opened pairing window is active → pairing-only session: `hello` and `pair.complete` only, one attempt, then close;
  - otherwise a fixed `403` without reading the request, close, and log; the phone treats 403 as final.
  - At most 4 live sessions per node: a fifth evicts that node's oldest, so a phone reconnecting after iOS killed its sockets is never locked out. Global cap 64. Revocation cancels in-flight replies and re-checks authorization before every frame.
- Phone: `tailscale_dial`s the IP of the Mac's pinned entry in its own netmap (`tailscale_status_json`) after the ownership and whois checks in [tailnet.md](tailnet.md#pairing-and-connection-authorization); no DNS lookup.
- `tailscale_up` blocks until Running and is not cancellable; collied drives its own state machine from `status_json` (`BackendState`, `AuthURL`) and always calls `tailscale_start` first.
- Accepted fds are AF_UNIX socketpairs: collied awaits the listener's readability with tokio's `AsyncFd`, accepts, and reads each fd as a non-blocking `tokio::net::UnixStream`.
- magicsock binds a UDP socket on real interfaces: that is the WireGuard tunnel itself and the one unavoidable non-tailnet socket. No TCP listener exists outside the tailnet.

## Mutual TLS

Inside the tunnel, after the whois gate and before the WebSocket upgrade: TLS 1.3 only, RFC 7250 raw public keys (no certificates), ECDSA P-256 with SHA-256 only, and no session resumption (it would skip the key check). Each side pins the other's key by the SHA-256 of its SubjectPublicKeyInfo (`KeyPin`, base64url); the shared verifiers are in `crates/tls`.

- collied makes its P-256 key on first start (`tls-key.json`, PKCS#8, 0600 in the data dir). Its pin is in the pairing QR (`k=`, invite `v=2`), and the phone keeps it as the machine's `key`. A new key means pairing every phone again.
- The phone's key is a non-exportable Secure Enclave key, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` so lock-screen decisions can connect. collie-core holds only its public key and asks the app to sign each handshake. The simulator uses a software key.
- A full session needs the phone's pinned key (`peers.json` `tls_key`). A pairing session takes any P-256 key, and confirming the pairing records it.
- A peer the gate rejects gets the fixed clear `403` before any TLS, so nothing from it is parsed; the phone recognizes it from the first bytes (`Sniff`) and stops retrying. A machine presenting another key is a pin violation, and collied refusing the phone's key reaches the phone on its first read as `KeyRefused` (TLS 1.3 checks the client after the client's side is done); both stop retrying and ask to pair again.
- After the handshake collied runs the gate again under the peers, pairing and sessions locks and refuses the connection on a different decision, such as a revoke, a pairing or the window closing during the handshake. The per-node session cap and the registration happen under those same locks.

## Negotiated protocol compatibility

Revision 26 is the first negotiated baseline; the floor is 26 (`PROTOCOL_MIN_VERSION`) and the ceiling 32 (`PROTOCOL_VERSION`). Revisions 3 through 25 used exact matching and have no retained codecs: update both peers once to reach the baseline; paired keys do not change.

`hello.protocol_version` offers the highest supported revision and the optional `protocol_min_version` the floor (absent: that one revision). The daemon selects the highest common revision and returns it as `protocol_version`, with its own `protocol_min_version` and `protocol_max_version` and the selected `capabilities`. It rejects a reversed or zero range, a duplicate capability, an unknown request field or a malformed parameter; an empty intersection closes the session with `unsupported_protocol`, the daemon's maximum and which side to update. The phone rejects a selection outside the common range or below the highest common revision, and capabilities it did not implement.

Omitted offer capabilities mean exactly the baseline set, currently `terminal_grants_v1`; `[]` opts out, and unknown names are ignored and never echoed. A baseline phone omits its singleton floor and baseline capabilities, so its hello has revision 25's fields and a strict revision-25 daemon refuses the version rather than a new field; nothing falls back or sends revision-25 operations. A wider offer sends its floor explicitly, which revision 26 accepts; the current phone offers 26 to 32, so a revision-25 daemon rejects its hello as malformed.

`terminal_grants_v1` names the existing P-256 terminal grant codec and the optional pairing `terminal_key`. Without it, the phone omits the key and refuses terminal methods locally; the daemon rejects an unsolicited key or terminal method and never serializes terminal challenge or grant results. Every request, daemon result and event passes through the negotiated codec, which for revision 26 covers the complete baseline, including current request parameters and enum variants; unknown events cannot be emitted. Paired sessions, pairing and short-lived approval or bootstrap connections all negotiate through `Session::hello`, after TLS pinning, whois, pairing windows and authorization.

Rules for new revisions:

- Retain the current and previous two negotiated revisions; raise the floor only once three real codecs exist.
- Before the advertised range widens, every wire change gates its fields and enum variants (request, parameter, response or event) for each retained revision.
- A future relay grant or encrypted payload format needs its own implemented capability and codec; `terminal_grants_v1` promises nothing about them.
- Never claim pre-baseline compatibility by widening a range.
- Before removing a revision, publish the new floor in the release notes and the update guide, and test both upgrade orders with serialized fixtures for every retained revision and for peers below the floor.

The checked-in compatibility fixtures exercise the real revision-26 to 32 codecs; synthetic 33/34 ranges test negotiation arithmetic, not claimed codecs.

## Approvals

The agent reconcile (`approvals.rs`) issues one approval per `blocked` `terminal_id`: `{approval_id (16 B), terminal_id, agent_label, workspace_label, snippet, tool, reason, options, choices, accepts_input, has_text_field, supports_note, nonce (32 B), created_at_ms, expires_at_ms}`, expiring after 600 s (`approvals::TTL`, not a `collied.toml` key). collied reads the screen (`pane.read source=detection`) and the matched rule id (`agent.explain`, whose output carries raw pane text and is never exposed).

- **Menu.** collied answers only Claude Code's select menu: agent kind `claude`, a rule in `prompt::CLAUDE_MENU_RULES` (herdr claude manifest 2026.10.11.1), and the last numbered block after the dialog's last rule (one above it is old output), numbered from 1 without gaps, with exactly one `❯`. Anything else raises an approval with no options, which the phone shows but cannot decide.
  - Renamed sessions (Claude Code 2.1.300, herdr 0.9.5 rule `live_blocked_form_named_session`): the name sits on a rule (`─── <name> ─`) under the question's footer. Under that rule only, `prompt::without_session_name` cuts the name rule and all below it and reads the rest as `live_blocked_form`, if the last rule on screen carries text after its dashes (so a menu typed into an idle input box is not read), the last line above it ends in "Esc to cancel", and only blank lines and task panel rows follow. A footer wrapped in a very narrow pane is not cut, so that question is answered in the terminal.
  - Folder trust: the only unnumbered menu read is the folder trust prompt ("No, exit", then "Yes, I trust this folder"; rule `live_blocked_form`), and only in its exact layout: one `❯` line, one-line options at the cursor's label column set off by blank lines, each mapping to its own decision and one carrying trust wording. It is then handled as a numbered menu.
- **Other agent kinds.** Codex and Copilot CLI prompts are not parsed: their approval's alert has no actions and never goes on a Live Activity, and `approval.decide` is refused (`invalid_params`, nothing sent). Any agent can be answered by hand ([Prompts without decisions](#prompts-without-decisions)). A pending approval ends when its snippet no longer matches the screen, so a new prompt never shows with the old command.
- **Why no approval actions for Codex and Copilot** (codex-cli 0.160.1, Copilot CLI 1.0.94): collied never takes an approval from screen parsing alone, Copilot has no usable non-screen source, and Codex's is not built. Codex's `PermissionRequest` hook hides the terminal prompt until it exits, gets a stale `HERDR_PANE_ID` and must be trusted by hand; its app-server sends approvals (`item/commandExecution/requestApproval`) to every same-uid client, but under `approvals_reviewer = "auto_review"` asks the user only when neither hooks nor guardian decide, so a phone path would rarely fire, and each request would need binding to a pane. Copilot's `permissionRequest` hook fires before allow rules, locks the terminal, misses path prompts and carries no request id; its SDK extension path needs the global experimental flag and `@experimental` permission RPCs and gets the session's whole RPC surface. Revisit if Codex's `approvals_reviewer` is `"user"` or Copilot's extension and permission APIs become stable.
- **Settings pickers** (`prompt::settings_picker`, Claude Code 2.1.294): `/effort` and `/config`'s time format, output style and flagged message pickers change a setting, run no tool and grant nothing, so they raise no approval. Each must match its exact text under the last `▔` border, whitespace removed, for agent kind `claude` under `live_blocked_form` or the renamed-session rule. Any other dialog still raises one, as do a picker whose text a later Claude Code changes and `/advisor`, whose "No advisor" reads as a decision. `/model` raises none: herdr leaves its status unchanged. A suppressed picker still takes arrows, Enter and Esc on the agent screen.
- **Options.** Each decision maps to exactly one option label: `approve` to `Yes`, `Yes, proceed` or `Yes, I trust`; `approve_always` to `Yes, and don't ask again` and similar; `deny` to `No` or `No, ...`. Decisions matching zero or several options, and other options ("Yes, and switch to auto mode"), are not offered. A menu with no approve or approve-always option (questions, plan prompts) is not a permission prompt and offers no decision, not even `deny`.
- **Choices.** `choices` lists any parsed menu, permission prompts included, as `{index (0-based), label, current}`, `current` marking the `❯` option; labels lose controls, bidi and format characters and are capped at 120 chars. An approval with no `options` is answered with `approval.decide {decision: "choose", choice: <index>}`. A permission prompt never takes `choose`, which would bypass the decision mapping (Deny is sent as Esc).
- **Note.** `supports_note` is set when the menu offers `approve` or `deny` and "Tab to amend" shows under its last option, not in the body above, which can quote any text.
- **Tool.** `collied hook`, Claude Code's `PermissionRequest` hook, sends `{session_id, tool_name, shown}` over the control socket, `shown` being the call as the dialog shows it (the Bash command and Claude's description, else any file path, URL, query or pattern). It never answers (no output, exit 0, 2 s limit), so the dialog appears as usual with or without collied. The hook runs beside the dialog, which may be answered before collied looks, so a report counts only if its dialog offers decisions and each `shown` part is a run of whole dialog lines, whitespace removed. collied keeps each session's last report (at most 64 sessions, each for the approval TTL); a matching one sets `tool` to `{name, summary}` (cleaned like the context, at most 600 chars with the name) and the alert context to `<Tool>: <summary>`.
- **Reason.** Claude Code can ask even in auto or bypass mode and says why only in the dialog (the 2.1.308 hook input has no reason field), at the question's margin between the command block's closing `╌` rule and a blank line (or the deny countdown) above the question, in rows barred with `│ ` (2.1.308) or plain (2.1.295).
  - `prompt::without_reason` reads it only there, for agent kind `claude` with a parsed menu and paired dashed rules: rows joined, escape sequences dropped, whitespace collapsed, cut at 200 chars with `…`. Text with any other control, bidi or invisible format character, or that only repeats whole dialog lines, sets no reason, and the screen is read whole. A set reason's rows are removed before anything else reads the screen.
  - The reason is hashed into every fingerprint and counts in drift, so no decision acts on a stale reason. The encrypted alert body puts it on its own line after the context, which is cut first to fit the phone's 600 characters; the Live Activity shows only the first lines, where a long command can push the reason out.
  - No version bump: `reason` is an optional, additive field on a server-to-phone type that every retained codec passes whole; an older app ignores it, and an older collied sends none.
- **Snippet and labels.** The snippet is the end of the dialog (a menu's last 12 body lines), at most 200 chars in whole lines (a line too long alone is cut with a leading `…`), without Claude Code's tips. Labels are at most 64 chars. Both lose controls, bidi and format characters and box borders.
- **Context** (`prompt::context`): the dialog from the last horizontal rule to the last option block, lines kept, controls, bidi and format characters stripped, at most 600 chars with `…`. A Bash prompt gives `Bash: <every non-empty line between the header and the last "Do you want to" question>`, Claude's description included, since plain text cannot tell it from a command line. The approver acts on this text, so a command must not be able to hide its own lines (with a `Tip:` line, a blank line, a fake question or option): nothing in the command block is dropped, and `Tip:` lines are skipped only at the dialog's margin, never between the first and last `╌` rule. Another tool gives `<Tool>: <target>` (`Edit: src/main.rs`); else the question line; else the dialog's first line (and the next when it ends in `:`).
- **Fingerprint.** Since `state_change_seq` moves only on status changes, the approval is also bound to SHA-256 over the length-prefixed agent kind, rule id, `terminal_id`, agent session id, dialog region (last horizontal rule through the last option, cursor included) and reason. collied also keeps, per option, the fingerprint with the cursor on that option.
  - Deny countdown (Claude Code 2.1.295 on, in a session it takes for unattended): `⚠ Claude Code will automatically deny this request in M:SS, to avoid blocking progress on an unattended session` (or `about N minutes` / `about N seconds`) ticks every second, so `prompt::without_deny_countdown` removes it before approvals, or drive paths typing into a dialog, read the screen: only for agent kind `claude` with a parsed last option block, in that exact wording on up to three rows of its own at the dialog's margin, above a blank line and the question. A copy in the transcript or the command stays. Its time is not read, and its ticking neither reissues nor supersedes the approval; when Claude Code denies on its own, the agent leaves `blocked` and the approval ends.

### `approval.decide`

1. Rate limit per paired `StableID`: 1/s, burst 5 (`rate_limited`).
2. Claim. Any attempt burns a pending approval, whatever the result; a burned id answers `approval_already_resolved`, an unknown one `approval_not_found`.
3. Expiry, nonce (constant time), decision offered. `choose` needs empty `options` and an index inside the menu; the decoder requires `choice` exactly with `choose`. A `note` needs `approve` or `deny` and `supports_note`; the decoder takes one line of at most 200 characters without bidi or invisible format characters, so the amend field still parses once it wraps (onto at most 4 rows). Anything else is `invalid_params`.
4. Re-read the screen: still `blocked`, same `state_change_seq` and fingerprint, else `superseded`. Re-check peer authorization.
5. Keys, from a fixed set (`up`, `down`, `enter`, `esc`), never pane text:
   - Deny is a single `esc`, wherever the cursor is, when its label ends in `(esc)` or on the folder trust prompt, whose "Esc to cancel" exits like "No, exit".
   - Otherwise: arrows to the target option, 150 ms pause, re-read (the fingerprint must equal that option's cursor fingerprint, else `superseded`), peer re-checked, then `enter` in its own call, since lost arrows would confirm another option. Digit shortcuts, which vary across Claude Code versions, are not used.
   - `choose` always takes this path and never sends `esc`.
   - With a `note`, Approve and Deny take this path too, never sending `esc` (in the amend field it cancels the whole prompt). Before `enter` go `tab`, a poll until the cursor's option shows its amend field (`Yes, and tell Claude what to do next`, `No, and tell Claude what to do differently`), the note through herdr's `pane.send_text`, and a poll until the option reads `Yes, <note>` or `No, <note>`. Each poll (every 100 ms, up to 1 s) needs the rest of the dialog unchanged and the agent still `blocked` with the same `state_change_seq`; the peer is re-checked before each write. On any mismatch nothing more is sent: `superseded`, and the next reconcile issues a new approval.
6. Settle: poll `agent.list` every 250 ms for up to 3 s (`approvals::SETTLE`) for the agent to leave `blocked` or move its `state_change_seq`.

The decide budget is 6 s from the claim to the last key; no key is sent after it. With the 3 s settle, a decision answers in under 10 s. A note to a herdr-core agent gets 3.5 s more, to wait out the core's typing hold ([herdr-core](#herdr-core-herdr-2)); notes are never sent from the lock screen.

| Outcome | When |
|---|---|
| `applied {decision, by}` | final key sent, agent left `blocked` within the settle |
| `unconfirmed {decision, by}` | final key sent (or its send timed out, it may have arrived), agent still `blocked` |
| `chosen {choice, by}`, `chosen_unconfirmed {choice, by}` | the same two for `choose`, as their own outcomes so an older app decodes them as `other`. A multi-question form stays `blocked` on its next question: `chosen_unconfirmed`, then a new approval |
| `superseded` | fingerprint, seq or cursor mismatch; amend field or note not shown; budget spent before the final key; bad nonce; decision not offered; peer no longer authorized; herdr failed; on reconcile, the agent left `blocked` or moved seq without a decision |
| `expired` | past `expires_at_ms`, at decide or on reconcile |

Every attempt that passes the per-peer frame limit is audited with its decision (`choose <index>`, `<decision> with note`) and result, replays, rate-limited and expired ones included. Sent keys are logged as `terminal=<id> keys=<keys>`; the note never is.

**Reissue.** A resolved approval is never reused: while the agent stays `blocked`, the next reconcile issues a new one (new id and nonce), sent at once to live sessions. It alerts for a new blocked episode, a changed screen (seq or fingerprint) or an expired previous alert, never for the same prompt within 30 s of the last alert, so bad attempts cannot flood the phone; the new alert replaces the old one ([APNs](#apns)).

**Drift.** `state_change_seq` stays put when a form moves to its next question, a question is answered on the Mac or a dialog finishes drawing after the approval was built. So each reconcile re-reads every pending, undecided approval of a `claude` agent and supersedes and rebuilds it when what it tells the phone changed (snippet, `reason`, `options`, menu labels, `accepts_input`, `has_text_field` or `supports_note`; not the cursor alone). The rebuilt approval does not alert within 30 s of the episode's last alert, so typing on the Mac cannot become an alert stream.

### Prompts without decisions

Every agent takes manual input on permissions, trust prompts, questions and plans: every terminal button stays enabled (Codex's Shift+Left included), and the composer sends a typed answer whenever the agent is blocked, an approval is pending or a Codex question editor is open. Manual input relies on the paired session, not an approval nonce, expiry or LocalAuthentication: it can grant permissions, accept plans or trust a folder, and a changed prompt receives whatever the user sends.

- `agent.send_keys` forwards `Key`s (listed and combinations, as `terminal.send_keys` below) after checking the live agent identity and peer authorization, with no approval, menu or decision check; blocked startup prompts take input too. When a fresh read shows a Claude Code agent not blocked, keys and typed answers still respect a scrolled transcript, whatever approval metadata the phone holds. Enter reaches a box that starts with `/`: the phone withholds it only for a command it mirrored, so a slash command typed in the terminal view submits on Return.
- `agent.type_text {op_id, terminal_id, text}` sends bracketed-paste text and Enter in one ordered `pane.send_input` write, without selecting a free-text option, reading an answer back or binding to a prompt fingerprint; the terminal buttons focus the intended control first. Newlines and tabs pass; unsafe controls, bidi and invisible format characters are rejected; the 32 KiB prompt limit applies.
- `agent.send_text {op_id, terminal_id, text}` types `TypedText` as is with `pane.send_text` (herdr-core: a typing attach), no Enter and no bracketed paste. `TypedText` is 1 byte to 32 KiB with no C0 or C1 control (so no ESC, newline or tab, which go as keys) and no bidi or invisible format character. It takes `agent.send_keys`'s agent, authorization and scrolled-transcript checks; Enter goes through `agent.send_keys`. Audit: the terminal and result, never the text.
- `agent.prompt` still refuses blocked agents, so the composer answers them through `agent.type_text`; attachments wait for the next normal prompt. `accepts_input` and `has_text_field` restrict nothing.
- The phone queues terminal keys and typed answers in order, approval card answers included. A failed input cancels queued actions with a visible error; an agent-to-shell transition discards pending agent input.
- Authorization is re-checked before every herdr write; both methods carry an `op_id` through the outcome cache. Audit: keys to a blocked agent log `<terminal_id> blocked keys=<keys>`, separated by spaces, which no key contains (`,` is a key); `agent.type_text` logs the terminal and result, never the text.
- No version bump: the method, `choices`, `accepts_input`, `has_text_field`, `supports_note`, `note`, the `choose` decision and the two outcomes are additive. An older app ignores `choices` and decodes the new outcomes as `other`; an older collied sends no `choices` (it defaults to empty) and no `accepts_input`, `has_text_field` or `supports_note` (all default to false), and answers `choose` and a `note` with `invalid_params` and `agent.type_text` with `unknown_method`, so the app and collied update together.

## APNs

- `[apns]` in `collied.toml` holds `key_id`, `team_id` (10 uppercase alphanumerics), `bundle_id` and the key's location; `key` with `key_path`, or a store for the other OS, is an error. `collied apns test` sends a test alert through the selected sender and reports acceptance, not display.

| Key location | macOS | Linux |
|---|---|---|
| `key = "keychain"` | the default when omitted | config error |
| `key = "systemd-creds"` | config error | the default when omitted ([APNs key on Linux](#apns-key-on-linux)) |
| `key_path` (a 0600 file owned by the user, opened without following symlinks) | legacy; `collied doctor` warns | the fallback when systemd-creds is unavailable; `collied doctor` warns while systemd-creds works |

- Keychain item (macOS): generic password in the login keychain, service `dev.rbstp.collied.apns`, account = key ID. Its ACL trusts only the storing program's designated requirement, so only a collied signed with the same Developer ID Application identity (team `RM3UT3MMSR`) and identifier `dev.rbstp.collied` reads it without a prompt. `just collied-install` signs that way (hardened runtime, timestamp), installs to `~/.cargo/bin/collied` as a fresh inode and restarts a loaded launchd agent; an ad hoc signed `cargo install` build cannot read the item unattended.
- `collied apns import <AuthKey_ID.p8>` (macOS) needs the `[apns]` ids, refuses a file named for another key ID, and requires an ES256 key passing the `key_path` checks. It stores the key (keeping an existing item), reads it back to compare, rewrites `key_path` to `key = "keychain"` (atomic, same mode, never through a symlink), then asks y/N before deleting the file if it is still the same inode.
- `collied doctor` (macOS) checks the signature, reads the item with user interaction disabled as the daemon does, signs a provider token as a dry run, and warns about any `.p8` left in `<data dir>/apns`.
- `push.register` tokens are stored per `StableID` in `push.json` (0600, atomic) with the device's notification key and environment (Debug builds sandbox, TestFlight production; collied keeps a client for each). Every send re-checks the pairing, so a registration racing a revoke gets no alert. `Unregistered` and `BadDeviceToken` drop the token; revoking a peer forgets its tokens. Direct sends use a 64-alert queue, dropped when full, and 10 s per send.
- Approval alert: push type `alert`, priority 10, `apns-expiration` = approval expiry, collapse id per terminal (table below). A device whose Live Activity for that terminal shows approvals gets the approval there instead ([Approval on the activity](#approval-on-the-activity)).
- Approval clear: when an alerted approval's agent is no longer blocked (answered anywhere, or gone), collied pushes `{"aps":{"content-available":1},"approval_id":…,"node_id":…}` to every registered device: push type `background`, priority 5, no collapse id, `apns-expiration` 0, since APNs keeps one undelivered push per app and a stored clear would displace a pending alert. Each alert gets at most one clear, recorded in memory only, so an alert whose agent moves on while collied is stopped gets none. The woken app (`remote-notification` mode) removes the delivered alerts with that `node_id` and `approval_id`; since iOS may delay or drop clears, it also removes alerts of approvals no longer pending whenever it runs.
- Done alert: when an agent's turn of 30 s or more ends (checked each 1 s reconcile, after approvals). A turn runs from `working` to the next `done` or `idle`, through any `blocked`; `blocked` to `idle` (a denial, Esc) and `unknown` end it silently. An agent's first poll never alerts; a turn under way when collied first sees it is timed from then. The 30 s, equal to the approvals' alert gap, skips quick replies and slash commands and limits a flapping agent to one alert per 30 s per terminal; the record is in memory only.
  - Push type `alert`, priority 10, `apns-expiration` 0 and the approval alert's collapse id, so a terminal shows only its latest notification. It cannot replace a pending approval: it needs the agent out of `blocked`, which supersedes the approval, and the single send queue keeps the order. `mutable-content: 1` runs ColliePush for the encrypted title and body (PR watch wake and archive-on-merge alerts too).
  - A device registered with `mute_done` gets none. A followed agent's Live Activity gets only a silent status update.

| Public alert field | Value |
|---|---|
| `aps.alert` | `{"title":"Collie","body":"An agent needs attention"}`; done alerts use `An agent finished` |
| `aps.thread-id`, collapse ID | base64url of the first 16 bytes of SHA-256(`terminal_id`) |
| `aps.mutable-content`, `aps.sound` | `1`, `default` |
| `node_id`, `event_id`, optional `approval_id` | opaque machine, fresh event and approval lookup IDs |
| `enc` | versioned authenticated display envelope, canonical unpadded base64url |

The alert as sent carries no category. ColliePush adds `APPROVAL` locally only after authenticating display content that offers both Approve and Deny, and restores the private terminal ID for navigation. An extension timeout, unavailable key or failed decryption leaves the generic alert without approval controls. The app authenticates encrypted responses again before classifying a decision.

### Relay sender

`[push.relay]` selects the fixed publisher endpoint `https://collie-push.rbstp.dev/v1/send` ([relay.md](relay.md)), `[apns]` direct delivery for self-built apps; configuration rejects both together.

No version bump: optional `relay_grant` registrations and `hello.push_mode` require both `relay_grants_v1` and `encrypted_display_v1`. The configured sender determines `none`, `direct` or `relay`; no endpoint comes from the phone. Grants persist only beside their own device or activity in private `push.json`, redacted in diagnostics. HTTP sends carry only the grant, in a sensitive Authorization header, and the strict v1 encrypted or generic envelope, never a caller-provided destination, topic or URL. Redirects are refused; responses are capped at 1 KiB and each attempt at 15 s.

Relay delivery has its own bounded worker: a 64-job ingress and at most 64 each of pending encrypted destinations, activity cadence records and routed-approval deduplication records.

- Routine updates keep only each activity's newest state and go out at most once per 60 s per agent and phone, unchanged refreshes included. Ready urgent updates, clears, alerts and ends bypass that cadence and go first; an urgent retry due later never blocks ready routine work. With cadence tracking full, replacing a record first pauses all routine work for 60 s, so the limit holds. Direct APNs keeps its own cadence and order.
- Network failures, timeouts, 429, 5xx and unexpected non-JSON responses (such as Cloudflare error 1027 HTML) enter bounded exponential backoff with random jitter; Retry-After (seconds or date) is clamped to one hour; a daily quota reset is used only within 24 hours, else 60 s. An exhausted routine daily quota pauses only routine work, keeping the reserved urgent budget; other outages pause everything. The server enforces quotas per installation, across machines, so the remaining budget is unknown locally.
- Non-approval work expires after 2 min, approval work with its approval (at most one hour). A restart loses all work: with no durable queue or exactly-once claim, an ambiguous accepted send can be duplicated.
- Before every attempt, retries included, the worker re-checks the pairing, the exact destination token and grant generation, grant and approval expiry, the approval's live state, and whether the activity was replaced or ended; a clear or newer activity state replaces obsolete pending work. Only an authenticated `410 invalid_route` removes a registration, and only the exact token or grant that failed; configuration and authorization errors keep registrations for repair or renewal. A failed activity send keeps the encrypted approval-notification fallback.
- `collied doctor` shows counts, the earliest grant expiry, the last send error and retry or reset times, never grants, destinations or payloads. A push outage does not block the tailnet or control tasks.

### Encrypted display envelope

- The phone generates a 32-byte notification key per paired machine, kept in the shared Keychain (`AfterFirstUnlockThisDeviceOnly`) and a 0600 App Group mirror (no backup, protected until first unlock) so CollieWidgets can decrypt without Keychain access. Only the authenticated tailnet `push.register` sends it to collied, which keeps it beside the token in `push.json` and never logs it. Re-pairing rotates it; unpair or revoke removes it.
- No version bump: the additive `display_binding` registration field and the replacement APNs and ActivityKit codec require the explicitly negotiated `encrypted_display_v1` capability; revision 26's omitted capabilities still mean only `terminal_grants_v1`. A peer without the encrypted codec cannot register push or activity tokens. Persisted registrations without the encrypted-display marker or activity binding send no private display content and stay disabled until refreshed. There is no plaintext compatibility path.
- `enc` is canonical unpadded base64url of `header || nonce(12) || ciphertext || tag(16)`, ChaCha20-Poly1305 with a fresh random nonce. `header` is binary `version(1 byte = 1) || kind(1 byte) || node_id_length(1 byte) || scope_length(1 byte) || node_id(UTF-8) || scope(UTF-8) || event_id(16 random bytes)`; node and scope are 1 to 64 ASCII letters, digits, underscores or hyphens. Kinds: `1` alert, `2` activity state, `3` private static attributes. AAD is the bytes `collie.push.v1`, a zero byte, the header, and SHA-256 of the 32-byte destination notification key, so the key binds the receiving phone and machine, and the authenticated header binds kind, machine, scope and event. The public `event_id` is the header event in unpadded base64url; the widget reads it from the envelope because ActivityKit exposes only `content-state`.
- Alerts: scope is the opaque thread ID; plaintext is `{"v":1,"title":...,"body":...,"terminalId":...,"offersApproval":...}`, with `approvalId` only on approval alerts. ColliePush checks the authenticated machine, thread, event and optional approval against the public lookup fields, then restores title, body and routing locally. The body is the approval context, if any; done and agent alerts carry their own complete body. Unsupported versions, noncanonical encoding, oversized input and failed authentication produce no private text or controls.
- Activities: the phone gives each a fresh UUID `bindingId` before ActivityKit assigns its activity ID, and sends `display_binding: {node_id,binding_id}` with its token over the tailnet. State is kind `2` under this scope (`{"v":1,"state":...}`); static attributes keep only opaque machine, terminal, node and binding IDs and a kind `3` envelope of `{"v":1,"machineLabel":...,"title":...}`. Initial, local and remote updates and ends carry only ciphertext. A widget checks the envelope against its own immutable node and binding before using any state; without keys (as before first unlock after a reboot) it shows a neutral `Collie` state without approval controls.
- Limits: envelopes 3,800 encoded characters; APNs payloads 4,096 serialized bytes; static activity attributes 1,536 bytes; each encrypted initial, update or end state 2,400 bytes; attributes and state together 4,000 bytes, leaving ActivityKit framing room. The remote sender always reserves the full static-attribute allowance; the phone checks both caps and the combined size before every local update. An oversized alert is dropped; an activity that cannot be encrypted or fit falls back to the approval notification where it applies. Alert bodies are visibly truncated at 1,800 JSON-escaped bytes and activity approval context at 600 bytes before its inner command seal, on whole Unicode scalars.
- Still observable: IDs, generic categories, priority and urgency, timing, size, and the update or end lifecycle. Public activity relevance is omitted remotely and zero locally, and activity alert text is generic. The raw APNs token stays a delivery destination. No push carries an approval nonce.
- [protocol/push-display-vectors.json](protocol/push-display-vectors.json) holds exact Rust and CryptoKit vectors for all three kinds and relay-compatible public payloads. [protocol/live-activity-content-state.json](protocol/live-activity-content-state.json) describes the private state before the outer seal; its inner approval command uses the [notification-vector.json](protocol/notification-vector.json) seal, authenticated by approval ID, which never appears outside the authenticated display envelope.

## Lock-screen approval

- Category `APPROVAL` has two actions, Approve and Deny (no Always allow, no note), both `authenticationRequired`: iOS makes the user unlock first, then launches the app in the background without UI.
- The app holds a background task assertion and calls collie-core's `decide_from_notification` with a 20 s budget (the cap; 0 is refused). This one-shot session runs outside the connection supervisor: node up from cached state (never a login), the pinned Mac in the netmap, dial, `hello`, the nonce from the cached snapshot or `approval.list`, then `approval.decide`, never retrying past the budget.
- It fails at once with `Unauthorized` when Tailscale is not set up on the phone, the node reports `NeedsLogin` or `NeedsMachineAuth`, the netmap violates the pin, or `hello` reports the phone unpaired.
- A follow-up local notification in the same thread claims success only for `applied`:

| Background outcome | Follow-up | Opens the approval |
|---|---|---|
| `applied` | "Approved/Denied: agent. The agent moved on." | no |
| `unconfirmed` | "..., not confirmed": keys sent, agent still looks blocked | yes |
| `expired`, `already_resolved`, `not_found` | expired or no longer pending, nothing was sent | no |
| `superseded` | the prompt changed, nothing was sent | yes |
| `unreachable` at `decide` | could not confirm the decision reached collied | yes |
| `unreachable` earlier, `unknown_machine`, `unauthorized`, `failed` | "Couldn't reach collied, open to decide" | yes |

- Tapping the alert opens the agent's session, found by node and approval id while the approval is pending, else by a validated notification thread. Structured in-app approval actions pass LocalAuthentication (`deviceOwnerAuthentication`, a fresh `LAContext` each time); manual terminal input does not.

## Attachments

The phone uploads a prompt's photo or file over the tailnet session; collied stores a private copy and returns its absolute path, which the app inserts into the prompt draft for the agent to read from disk. Nothing goes through herdr.

### Flow

1. `attachment.begin {op_id, name, size, sha256}` answers `{upload_id}` (16 random bytes, hex). `name` (`AttachmentName`: 1 to 64 characters, no control, bidi or format characters, no `/` or `\`, no surrounding whitespace, not `.` or `..`) is only a hint; `size` is 1 byte to 20 MiB; `sha256` is lowercase hex of the whole file.
2. `attachment.chunk {upload_id, offset, data}` in order: `offset` must equal the bytes received so far; `data` is padded standard base64 of 1 byte to 32 KiB, so a chunk frame stays under the 64 KiB frame cap. collie-core sends one chunk at a time and awaits each reply.
3. `attachment.commit {op_id, upload_id}` answers `{path}` once the received size equals `size` and the SHA-256 matches; otherwise the partial file is deleted and the error is `invalid_params` (size) or `checksum_mismatch`.
4. `attachment.abort {upload_id}` is best effort and always answers `ok`.

An upload is bound to the session and peer `StableID` that began it; another session, even of the same phone, gets `not_found`. Nothing resumes across connections: closing the session drops its uploads, which collie-core reports as interrupted. `begin` and `commit` go through the `op_id` outcome cache, so a retried commit returns the stored path. Authorization is the `agent.prompt` gate (a paired, full session), re-checked on every frame and before `begin`, each chunk and the commit.

On any failure collie-core sends `attachment.abort`. UniFFI 0.32 does not forward Swift task cancellation to Rust, so the app cancels with `cancel_uploads(machine_id)`, which fails the upload with `Cancelled` and aborts it on the Mac.

No version bump: the methods, responses and error codes (`too_large`, `checksum_mismatch`) are additive. An older collied answers `unknown_method`, which collie-core reports as "update collied".

### Limits

| Limit | Value |
|---|---|
| File size | 20 MiB, checked by the phone, the protocol decoder and collied |
| Chunk | 32 KiB decoded, in order, never past the declared size |
| Uploads in flight | 2 per session (`rate_limited` beyond) |
| Stored bytes | 200 MiB: committed files (the larger of length and allocated blocks) plus the declared size of every upload in flight; else `begin` answers `too_large` |
| Stored entries | 1000 under the root, uploads in flight included, so tiny files cannot exhaust the disk or slow `begin`'s scan; else `too_large` |
| Chunk rate | own bucket per paired `StableID`, 128/s, burst 128 (4 MiB/s); collie-core retries a rate-limited chunk up to 8 times with backoff. Other attachment frames use the shared 20/s bucket |

### Storage

- Root: `~/Library/Caches/dev.rbstp.collied/attachments` on macOS, `$XDG_CACHE_HOME/collied/attachments` (else `~/.cache/collied/attachments`) on Linux, with no spaces so the path reads cleanly in a prompt. Created 0700; an existing root that is a symlink, owned by someone else or not exactly 0700 stops collied at start.
- Each upload gets a fresh `<root>/<16 hex>/` (0700, `create_dir`, fails if it exists). Data goes to a `.part` file opened `create_new` with `O_NOFOLLOW`, mode 0600; the commit fsyncs it and renames it, inside that directory, to the sanitized name. Files are never executable.
- Sanitized name: `[A-Za-z0-9._-]` kept, each run of anything else becomes `-`, leading dots and dashes dropped, at most 64 characters keeping an extension of up to 16 alphanumerics, `attachment` when nothing is left (`.env` becomes `attachment.env`).
- Audit: `attachment.begin` with the sanitized name, and one `attachment.commit` line per committed upload with result `ok size=<bytes> sha256=<first 12 hex>`. Chunks and aborts are not audited; content and base64 are never logged.
- `collied doctor` prints an `attachments` line: root, mode, bytes stored.

### Cleanup

- Session close: its uploads in flight are dropped and their directories removed.
- Every 10 s: uploads idle for 60 s are dropped with their directories.
- At start and every hour: root entries older than 24 h are removed (symlinks as links, never followed). At start, directories still holding a `.part` from a previous run are removed too.

## Files from Chat

Chat links file paths in agent messages and tool records, never hidden names or tokens with `..`, `://`, `*`, `$`, `=`, `@` or `\`, and an agent session's Terminal selection menu offers Open on a selection holding exactly one path and no http link. Both open a read-only preview; collied decides what may be read.

### Flow

1. `file.open {terminal_id, path}` (Read class; `path` 1 to 1024 bytes, no control characters) answers `file_opened {download_id, name, size, kind, sha256}`.
   - collied takes the agent's checkout as `agent.changes` does, joins a relative path to it, refuses `..`, requires the result under a task root, then opens the parent one component at a time from the root with `O_NOFOLLOW` (`open_beneath`) and the file with `O_NOFOLLOW | O_NONBLOCK`.
   - `open_beneath` refuses a folder that starts with a dot or carries `UF_HIDDEN`, except the checkout path's own folders when the file lies below the checkout, so a worktree in `<repo>/.worktree/<branch>` opens its files; other hidden folders, below the checkout or outside it, are refused. A checkout that is or lies inside a hidden folder (an agent started in `~/.ssh` or under `~/Library`) thus exposes the non-hidden regular files below it, as the threat model notes.
   - Hidden names, symlinks, folders and anything but a regular file are refused with a plain message (`invalid_params`). `kind` is `image` (PNG, JPEG, GIF, HEIC or WebP by extension), `pdf`, `text` (other files whose first 8 KiB are UTF-8 without a NUL) or `other`; an unknown kind decodes as `other`. A file over 20 MiB, or over 1 MiB for text, is refused with `too_large` and its `fstat` size before any content is sent. `sha256` is computed from the open descriptor.
2. `file.chunk {download_id, offset}` answers `file_chunk {data}`: up to 32 KiB of base64 from `offset`, read with `pread` from the same descriptor, so a chunk frame stays under the 64 KiB frame cap. A file that shrank fails with "The file changed while it was read"; one rewritten in place fails the phone's checksum. Chunks draw from the attachment chunk bucket (128/s).
3. `file.close {download_id}` always answers `ok`.

A download is bound to the session and peer `StableID` that opened it (another session gets `not_found`), at most 2 per session (`rate_limited` beyond), and closed by `file.close`, at session end or after 60 s without a chunk. Nothing is copied, cached or written on the machine. `file.open` is audited with `<terminal_id> path="<path>"` and its outcome; chunks and closes are not, and content never reaches a log or a push.

collie-core's `open_file` fetches chunks 4 at a time (retrying a rate-limited chunk up to 8 times), checks each chunk's length and the whole file's SHA-256, and always sends `file.close`, waiting at most 1 s for its answer since collied also drops the file with the session. Closing the viewer cancels the transfer but lets a pending `file.open` answer, so the file it opened is closed. The viewer keeps the bytes in memory and, once the file opens, writes a copy for Share to a fresh folder in the app's temporary directory (complete Data Protection), removed when the viewer closes.

## Draft sync

Claude Code keeps unsent text in its input box, and herdr's `agent.prompt` pastes after it. For agent kind `claude` only:

- `agent.draft {terminal_id}` answers `{text}`: the box's text from the visible screen (`pane.read source=visible format=ansi`), `""` for only its dim placeholder, `null` when the phone may pre-fill nothing (another agent kind, no box, an opaque box).
  - The box is the last block on screen between two horizontal rules drawn from column 0, its first row at column 0 and the others indented two spaces, so a typed row of `─` never closes it. A first row other than `❯` (bash mode's `!`), or a collapsed paste or image placeholder (`[Pasted text #1 +40 lines]`, `[Image #1]`, `[...Truncated text #1 ...]`), makes the box opaque: its screen text is not its content. Dim text (placeholder, completion hints) is not typed text.
  - Claude Code 2.1 soft-wraps the draft (wrap-ansi `{hard: true, trim: false}` at the terminal width minus 4) and hides the space at each wrap; collied rejoins rows as a soft wrap, a split word or a typed newline.
  - Controls, bidi and format characters are dropped, trailing whitespace is trimmed, and the text is capped at 32 KiB.
- `agent.prompt` takes an optional `expected_draft`, what the phone last saw. After the ready check, collied reads the box before the paste and fails closed:

| The box | `agent.prompt` |
|---|---|
| empty | goes ahead. Prompts queued while Claude Code works draw outside the box, above the spinner, so they are never cleared and the new prompt queues after them |
| missing or opaque | `draft_not_cleared`, nothing sent: whatever replaced the box may still take the paste, and an opaque box may be a shell command or hold content the phone never saw |
| a selection below it | `input_unfocused`, nothing sent, and `agent.draft` answers `null`; the phone asks the user to press ↑ and send again |
| equal to `expected_draft` (both normalized) | clears it, then re-reads every 100 ms for up to 1 s until the box is empty, else `draft_not_cleared`, nothing sent |
| any other draft, or no `expected_draft` | `draft_changed`, nothing sent, with the current text in `ErrorBody.draft` so the phone can show it and send again to replace it. The audit line is `draft_changed` alone: draft text is never logged |

- Why `input_unfocused` (#588; Claude Code 2.1.310, herdr 0.9.5): `down` on the box's last row selects the background task pill, then the agent list below. The box looks unchanged, but a paste may be dropped and herdr's Enter opens the tasks dialog or switches agent: `agent.prompt` answered ok for prompts that never arrived.
- Clearing (verified on Claude Code 2.1.310 in herdr 0.9.5, a draft of N visual rows, the cursor anywhere): N times `ctrl+e`, `ctrl+u`, `backspace` (clear a row, join it to the one above) empties the cursor's row and those above, then N-1 times `ctrl+k`, `ctrl+k` (join the next row, clear it). Never `down` (on the last row it selects the task pill while a task runs), `ctrl+c` (interrupts a working agent) or `ctrl+d` (exits Claude Code on an empty input); no key used interrupts a working agent, and herdr has no `delete` key name. collied sends these keys itself, whatever the phone's `Key` allowlist holds, in batches of at most 16, re-checking authorization before each.
- The phone loads the box's text into an empty prompt field once per visit to the agent's screen. Until the phone edits it, a new non-null `last_prompt` triggers one `agent.draft` read, and an empty box, meaning the text was sent on the machine, empties the field but keeps its attachments. `last_prompt` comes from human prompts only, so text deleted on the machine, an approval, a background task's turn or `last_prompt` going null leave the field alone. Key strip text shortcuts send `expected_draft: ""`, so they never replace unsent text.
- No version bump: the method, response, field and error codes are additive. An older collied answers `agent.draft` with `unknown_method`, which collie-core returns as no draft, so the phone never sends it `expected_draft`. An older app sends no `expected_draft`, so a Mac draft refuses its prompt rather than being appended to. An older app reads `input_unfocused` as `unrecognized` and shows collied's message; an older collied never sends it.
- **Slash command mirror.** While the phone's draft starts with `/`, its command token (up to the first whitespace) is mirrored into the box, so Claude Code's command menu shows on the machine and in the phone's terminal view.
  - `agent.slash_draft {terminal_id, command, expected_draft}` (Drive class, idempotent so no `op_id`, audited with the terminal only) takes a `SlashCommand`: `""`, or `/` and up to 63 of `A-Z a-z 0-9 _ : . -`, so nothing can end the paste early. For a ready `claude` agent (never `blocked`, launch pending, or another agent or session) without a "Jump to bottom" banner, collied replaces the draft as `agent.prompt` does. For a non-empty `command` it then repeats the ready, banner and authorization checks, requires an empty `❯` box (else `agent_not_ready`) and pastes the command in one bracketed `pane.send_text` (herdr 0.9.3 has no paste without Enter). It replies and releases the lock only once a re-read (every 100 ms, up to 1 s) shows exactly the command, since a paste takes up to about 110 ms to render and a next call reading the box empty would paste after it (`/stat/statu`); other text gives `draft_changed`, an empty or unreadable box `agent_not_ready`, and nothing more is written. It never sends Enter or a key; a paste that did not land heals on the next call.
  - The phone mirrors only keyboard typing (the iOS keyboard's dictation and paste included, not the app's own dictation, paste, restored drafts or text it sets), one call at a time 150 ms after the last keystroke, for a Claude Code agent not blocked or scrolled up, never while dictating or sending, and only while it knows the box holds nothing or a command. It clears the box once when the draft stops starting with `/`. A `draft_changed` with the command this screen last asked for (a lost reply) is replaced; other text pauses the mirror and shows until the next send, so machine text is never replaced unseen. A reopened screen trusts only a bare command equal to its draft's token, and tokens, not text, are compared, so a hint after a completed command (`/rename  [name]`) triggers no write.
  - Picking a command: the key strip's joystick moves Claude Code's highlight up and down and ⇥ takes it. 150 ms after keys sent while the box holds a command, the phone reads the box and takes its command into the draft, keeping its own arguments (`/mod opus` and ⇥ give `/model opus`); at send, a `draft_changed` whose command extends the draft's catches a missed read. Send is refused after ↑ or ↓ until ⇥ or an edit, and ⏎ and ⌃⏎ are off, and dropped from queued keys, while the box holds a command no prompt covers. collied does not refuse them: only the phone knows a command came from its mirror, and one typed straight into the terminal view submits on Return.
  - `agent.prompt`, `agent.send_keys` and `agent.slash_draft` share one lock, so another session's input never lands between a mirror's read and its paste. Only the phone's send runs a mirrored command: after any mirror call in flight, `agent.prompt` clears the token (it equals `expected_draft`) and pastes the whole draft with Enter. A partial command runs Claude Code's top match.
- Codex and Copilot: collied refuses `agent.slash_draft`, and the phone never calls it. collied cannot read, so cannot check or clear, their input box, and their prompts paste after whatever it holds, so a mirrored token would lead the prompt.
- Residual: text typed on the Mac between collied's read and its clearing keys is cleared too; text typed after the empty re-read is appended to by the paste. A typed newline exactly where the next word would not have fit reads as a space. When Claude Code limits the box to a viewport (a draft taller than its visible rows), only the visible rows are read and cleared, so the re-read refuses the prompt.

## Context and inbox

herdr reports each agent's session id (`agent_session.value` in `agent.list` and `session.snapshot`), which its SessionStart hooks set, so it follows `/clear`, resume and compaction. From that session's transcript collied derives four optional `Agent` fields: `context_left` (0 to 100), `last_line` (the latest reply's first non-empty line), `last_prompt` (both cleaned and capped at 160 characters) and `last_activity_ms` (the transcript's mtime). No version bump: the fields are additive on a server-to-phone type, so an older app ignores them and an older collied leaves them out.

- **Live Claude Code session**: herdr's id can be stale (a session restarted while herdr's server was down) or name a client showing another conversation (`/resume` of a background session), and a `claude attach <id|name>` pane has none: the attach client fires no hook and writes no `sessions/<pid>.json`.
  - collied takes a Claude Code pane's foreground pids from herdr's `pane.process_info` (every 10 s per pane and on a pane id change), keeping only the pids and a foreground `claude attach` target, never the rest of `argv` or `cmdline`. A pid's `sessions/<pid>.json` (at most 64 KiB) counts only when its `pid` matches, the process is alive and started no later than the file's `startedAt` (2 s of slack for Linux's whole-second start times), and its `cwd` is the pane's. When all such files agree on one `sessionId`, it replaces herdr's (logged once per terminal, ids only).
  - Otherwise, for `claude attach <target>`, the session is the one live `bg` process (same checks except `cwd`) whose `jobId` starts with a target of 1 to 8 lowercase hex, or whose `name` equals any other target exactly. None or several keep herdr's id, as does a target lost on Linux when Claude Code overwrites `argv` with a process title. The client can switch sessions without changing `argv`, so a named record counts only while the pane title (herdr's `terminal_title_stripped`, which Claude Code sets to the shown session's name) equals its name.
  - collied then follows at most 4 hand-offs in that session's last 64 KiB (a loop or longer chain keeps the starting session): the latest `continued-in` record (`continuedInSessionId`) to a transcript in the same project directory, or a `/resume` whose output ends `running in the background (<8 hex>)` when exactly one live `bg` process (same pid checks) has that `jobId`, a `sessionId` starting with it, the same project directory and that transcript. A later reply or human prompt drops the hand-off.
  - Chat history, the summaries and `subagents` all read the session found. The summaries cache it per terminal until herdr's id or the pane's pids refresh, following hand-offs again when the starting transcript changes.
- **Claude Code**: `projects/<cwd with every non-alphanumeric character as '-'>/<id>.jsonl` under `CLAUDE_CONFIG_DIR` or `~/.claude`, else `projects/*/<id>.jsonl` for a session started in another directory.
  - Usage: the latest main-thread (`isSidechain: false`), non-`<synthetic>` assistant entry's `input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens`, as Claude Code's auto-compact indicator counts it (its status line leaves out `output_tokens`); after a `compact_boundary` with no reply since, its `compactMetadata.postTokens`.

## Linked pull requests

Each `Agent` can carry an optional `pull_request`: `number`, `state` (`open`, `draft`, `merged`, `closed`), `checks` (`passing`, `failing`, `pending`, `none`), `url`, `failing_checks` (names), `remarks` (reviews plus comments) and `conflicting`. No version bump: the fields are additive on a server-to-phone type, and both enums read an unknown value as `unknown`.

- **Daemon**: a task beside the reconcile loop wakes every 30 s. It works only with `gh` in `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` or `~/.local/bin` (without it no agent has a pull request), and only while a phone is connected or a paired phone has [Archive when the PR merges](#archiving-when-the-pull-request-merges) on.
  - It finds the agent's checkout as `agent.changes` does (only inside the task roots), then the repository root and branch; an agent outside a repository or on a detached head has none. There it runs `gh pr view --json number,state,isDraft,url,statusCheckRollup,mergeable,reviews,comments,headRefOid --jq '.reviews |= length | .comments |= length'` with no argument, so gh finds the current branch's pull request, no branch name reaches the command line, and reviews and comments reach collied as counts, never text.
  - Cadence: once per 2 minutes per checkout and branch, except that a pull request last read as `MERGED` is read again only once `HEAD` leaves its `headRefOid`, or after 30 minutes, so a new pull request from the same commit is still found. "no pull requests found" caches none; any other failure keeps the last value for one refresh, then shows none, and logs nothing. A read whose branch changed while `gh` ran is dropped. A change to what the phone is shown sends `flock.changed`.
  - `gh`, here and for `gh poi`, runs from a fixed path with `GH_PROMPT_DISABLED=1`, without `GH_TOKEN`, `GITHUB_TOKEN` or the enterprise token variables, with null stdin, a timeout (30 s here) and `kill_on_drop`. An unknown state, or a `url` that is not `https://` or holds whitespace or control characters, drops the read. `failing_checks` holds at most 10 distinct names, in rollup order, without control or format characters or `"`, cut at 100 characters.
- **Checks** (from `statusCheckRollup`): a status context passes on `SUCCESS`, is pending on `PENDING` or `EXPECTED`, and otherwise fails; a check run is pending until `COMPLETED`, then passes on `SUCCESS`, `NEUTRAL` or `SKIPPED` and otherwise fails. Any failure makes `failing`, else any pending `pending`, else `passing`; an empty rollup is `none`. `conflicting` means `mergeable` is `CONFLICTING`.
- **Phone**: grid cards, Inbox rows and the agent screen's header show a badge with the state's icon, color and number. A tap opens the `https` `url`, except on the agent screen, where it opens a menu: Open PR; while open or a draft, Fix failing checks (`checks` `failing`), Address review comments (`remarks` above 0) and Resolve conflicts (`conflicting`); and Explain this PR. Each adds one line to the composer, after any draft, holding the `url` (and for failing checks the quoted names), and sends nothing.
- `collied doctor` warns when `gh` is missing or `gh auth status` fails.

### Watching a pull request

For a Claude Code agent, the session menu offers "Watch PR" while its linked pull request is open or a draft, and "Stop watching #N, every M min" while the terminal has a watch. `agent.watch_pull_request {terminal_id, watching, every_minutes}` starts or ends a watch; `Agent.pr_watch` (`number`, `url`, `every_minutes`) reports it, and the badge shows "Watching" when it follows the linked pull request. Starting needs `every_minutes` of 2, 5, 15 or 30, a Claude Code agent, an open or draft linked pull request with a `https://host/owner/name/pull/number` URL in GitHub's characters, a checkout on a branch, and `gh` with `gh auth status` passing (else the error asks for `gh auth login` on the machine); stopping takes no interval, and watching the same pull request again only changes it. Watches belong to the machine, one per terminal, in `pr-watches.json` (0600, data directory) with the interval, checkout, branch and the starting phone's `StableID`, so they survive a restart.

- **Reads**: a daemon task ticks every 30 s, with or without a phone, and reads each watched pull request once its interval has passed (at once for a new watch and after a restart) with `gh api graphql --hostname <host>` in the data directory, owner, name and number as variables, in the linked pull request read's environment. The query asks for the signed-in user, state, `mergeable`, head commit, the base branch's required check names (protection rule and `RequiredStatusChecksParameters` rulesets), the head's check runs and status contexts (name, outcome, `isRequired`) and rollup state, and the author, URL and time of the last 20 comments and 20 reviews, but no body, so no comment or review text reaches collied.
- **Wakes**, queued on the watch until the agent takes them:
  - A failing check: once per check until it passes again or the head moves. An empty check list keeps the last check state.
  - All required checks passing: once per head commit. Required checks are the base branch's plus any listed check marked `isRequired`; each must be listed and pass, so an unreported one or a rollup state of `EXPECTED` holds the wake, while an optional check failing or running does not. With no required check, every listed check must pass and the rollup must not be `PENDING` or `EXPECTED`. A required check from a rule the signed-in user cannot read counts only once it reports.
  - A comment or review newer than the newest seen, by someone other than the signed-in `gh` user. Times are compared, with URLs breaking ties within a second, so a deletion that lets an older one into the window wakes nothing. The first read only records what is there.
  - `mergeable` turning `CONFLICTING`; `UNKNOWN` keeps the last answer.
- **Prompt**: while changes are queued, each tick wakes the agent only if `agent.list` shows an idle or done Claude Code agent still on the watched repository root and branch; otherwise the wake waits. The wake goes through `Driver::prompt` and its guards, with no `expected_draft`: an agent just starting work, a box holding text, a scrolled screen or a blocked agent refuses it until a later tick. Right before the write, collied re-checks that the agent is still Claude Code and that the watch still exists for that URL with its phone paired, so "Stop watching" or a revoke during the attempt types nothing.
  - The prompt is one line naming at most 10 changes: `Pull request #N (<url>) changed: check "<name>" failed; new review <url>; ...`. Check names lose control and format characters and quotes and are cut at 100 characters; comment and review URLs must be `https://` without whitespace or control characters.
  - A head move drops queued check changes, and a queued failure, pass or conflict that no longer holds is dropped.
- **After a wake**: an audit line (`pr.wake`, the terminal id, the summary and the pull request URL) and an alert "Woke \<agent>" with the summary through the done alert path, so `mute_done` silences it.
- **Wake prompts in Chat**: collied records each wake's exact prompt, summary and time in `pr-wakes.json` (0600, data directory), never in the log or a push: the last 20 per terminal, apart from the watch, so they outlive it (a merge ends the watch right after its last wake) and a restart, until the terminal is missing from a non-empty `agent.list`.
  - `agent.history` sets `HistoryMessage.origin` (`kind: "pr_watch"` and the summary) on a main-thread user message whose text equals a remembered prompt for that terminal, and `Agent.last_prompt_origin` when `last_prompt` equals one's first line. Matching compares text only, so re-sending a wake's exact text also shows as a wake. Marks are keyed by herdr's terminal id, so a herdr restore after a reboot, which reassigns it, loses them.
  - Chat shows a marked message as one collapsed "PR watch: \<summary>" row with the eye, expanding to the full prompt; grid previews and the Inbox show that line instead of the prompt. No version bump: both fields are optional and additive on server-to-phone types, which no retained revision decodes strictly, so an older app ignores them (and an unknown `kind` shows as an ordinary message) and an older collied sends neither.
- **Stops**: the watch ends, with anything queued, when:
  - the pull request is merged or closed;
  - 10 wakes in a row held only comments and reviews (a wake with any other change resets the count);
  - 8 reads in a row failed (no `gh`, no login, network, an unreadable answer);
  - the terminal is missing from a non-empty `agent.list`;
  - the phone that started it is revoked, unpairs, or is no longer paired when the task ticks (a revoke while collied was stopped);
  - the user picks "Stop watching".
  The menu and badge follow through `flock.changed`.

### Archiving when the pull request merges

A merged pull request's badge reads "Merged", and the session menu puts Archive first. Settings > Sessions > "Archive when the PR merges" (off by default; `archiveOnMerge` in `prefs.json`, absent until the user picks it) has collied archive the task itself. Once the user has picked it, collie-core sends `task.archive_on_merge {enabled}` (Drive class, audited with `enabled=`) to every connected machine on a change and to each machine at every session start, after `push.register`. collied keeps the `StableID`s of the phones that turned it on in `archive-on-merge.json` (0600, data directory), so it holds with no phone connected and across a restart, while any of them is paired. Any phone turning it off empties the file, so a stale `StableID` (after a reinstall) cannot keep it on; a revoke or unpair removes that phone.

- **When**: on the linked pull request task's 30 s tick, also with no phone connected (then one herdr snapshot per tick, only for agents passing the workspace check below, without changing what a phone is shown), once per 2 minutes per checkout and branch, so a merge is noticed within about 2 minutes. Only a fresh `gh pr view` finding `MERGED`, or a kept merged result, makes the agent a candidate; one failing a check is tried again at the next such read.
- **Checks, all read fresh in this order** (`Driver::archive_if_merged`):
  1. The setting is on.
  2. A herdr snapshot shows the terminal's workspace is a linked worktree whose every pane is an idle or done agent with no subagent running. A plain shell pane, an agent working, blocked or unknown, or a Claude Code agent with a running subagent, an unreadable transcript or an incomplete subagent scan holds it.
  3. `git status --porcelain --untracked-files=normal --ignore-submodules=none` in the checkout prints nothing (ignored files do not count; a submodule with changes, untracked files or a commit other than the recorded one does, whatever `.gitmodules` or the config say), and `git ls-files -v --recurse-submodules` lists no assume-unchanged (lowercase tag, as `core.ignoreStat` sets) or skip-worktree (`S`) entry, since `git status` does not look at those files.
  4. `gh pr view --json number,state,headRefOid` again still says `MERGED` with the same number.
  5. `git merge-base --is-ancestor HEAD <headRefOid>` (a 40 or 64 hex character id only): the checkout holds no commit the pull request does not.

  Then `Driver::archive_merged` runs `task.archive`'s archive, which re-checks the workspace on its own snapshot and refuses a regular folder (it never only closes the pane). Right before `worktree.remove`, after its last authorization check (a paired phone still has the setting on, so turning it off or revoking the phone stops an archive in flight), it requires the checkout herdr will remove to be the one whose pull request was read and repeats the git checks. It skips the manual archive's `gh poi`, which deletes every merged branch and removes the repository's other clean worktrees, whatever their agents are doing.
- **After**: one audit line per attempt that reached `archive_merged` (`collied`, `task.archive`, the terminal id, `PR #N merged: <result>`); a candidate failing an earlier check is not audited. On success, an alert "Archived \<agent>" with "PR #N merged" through the done alert path, so `mute_done` silences it, and `flock.changed`.

## Git reads

Git changes, the archive checks and the pull request branch checks run git in the agent's checkout through `git::git_command`, which treats the repository's config as untrusted: null stdin, none of collied's `GIT_*` variables, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `core.fsmonitor=false`, `diff.external=` and an 8 s timeout. Diffs pass `--no-ext-diff` and `--no-textconv`; `diff` and `status` blank `filter.<driver>.clean` and `.process`. In a partial clone, a diff needing a missing blob would fetch it, running repository-configured programs such as `remote.<name>.uploadpack`, `core.sshCommand` or a credential helper. `GIT_NO_LAZY_FETCH=1` stops that fetch (git 2.45, and the 2.39.4 to 2.44.1 security releases). For older git, an empty `GIT_ALLOW_PROTOCOL` refuses every transport, overriding `protocol.*.allow`, and a blank `fetch.bundleURI`, which the fetch inherits, keeps it from starting `git-remote-https` for a bundle URI before that check (its setup can run a credential helper for `http.sslCertPasswordProtected`), so such a read fails instead.

## Git changes worktrees and pull requests

Git changes opens on the repository's worktrees: `agent.changes` with scope `worktrees` (revision 30) answers the agent's checkout as `root`, no files, the listed worktrees (at most 20, the agent's own always kept) and the user's open pull requests whose branch has no worktree.

- **Worktrees**: each listed worktree other than the agent's checkout is re-checked as a picked one is (it must resolve to itself under the task roots and share the checkout's Git common directory, read once per list) before collied reads it; one failing the check keeps only its path and branch. Up to 8 are read at once with the git reads above: `log -1 --no-show-signature --format=%ct %s` for `subject` (control and format characters removed, cut at 200 characters) and `committed_at_ms`; `status --porcelain -z --untracked-files=all --ignore-submodules=none` for `uncommitted` (entries, a rename counted once, each untracked file as in the Uncommitted scope); against the branch scope's base, `rev-list --count <base>..HEAD` for `ahead` and `diff --numstat -z --merge-base <base>` for `additions` and `deletions` (tracked files, committed or not, binary files counting no lines). A field whose read fails is left out.
- **Pull requests**: with `gh` installed, collied runs `gh pr list --author @me --state open --limit 100 --json number,state,isDraft,url,headRefName,title,isCrossRepository` in the agent's checkout, in the linked pull request read's environment and timeout; any failure means none. Only open and draft pull requests are read, so merged or closed ones never crowd out an open one; a worktree whose pull request merged shows no badge here. A worktree gets the newest listed pull request whose head branch equals its branch (state and URL; `checks` is `unknown`). Those matching no worktree are listed in `pull_requests` with their branch and title. Pull requests from forks, a URL that is not `https://`, a number outside 1 to 2^32 - 1, or a branch name empty, over 255 bytes or holding control or format characters are dropped; titles are cleaned like subjects. `pull_requests` is trimmed first when the answer passes the 48 KiB response cap.
- **Pull request scope**: `agent.changes {scope: "pull_request", pull_request: N}` reads, in the agent's checkout, `gh pr view N --json number,baseRefName,headRefName,changedFiles` (base and head cleaned like subjects as `base` and `branch`), then `gh api repos/{owner}/{repo}/pulls/N/files?per_page=100&page=P --jq 'map({filename, previous_filename, status, additions, deletions, sha})'` for pages 1 and 2 (200 files, the listing cap), so the list is GitHub's: the pushed head against the pull request's base, whether or not a worktree still has the branch. Files are in section `pull_request`; a file whose path or previous path is not a plain relative path is left out and the listing marked `truncated`, as it is when GitHub has more files. `status` maps GitHub's to one letter (`added` A, `removed` D, `renamed` R, `copied` C, `changed` T, anything else M); a count above 2^32 - 1 is unknown. `hash` digests the number, status, paths and blob `sha`, so a Viewed mark clears when GitHub's file changes.
- **Pull request diff**: `agent.diff {section: "pull_request", pull_request: N, path}` reads the same pages, at most two, with `--jq '{count: length, file: ([.[] | select(.filename == $ENV.COLLIE_PATH) | {filename, previous_filename, status, patch}] | first)}'` and the path in `COLLIE_PATH`, so no path reaches gh's command line or program text and only the one patch reaches collied; the answer must name the same file. A missing patch (binary, or too large for GitHub) shows as a binary notice. Output over 2 MiB is refused, and the patch is cut to the response cap like a local one. `root` is not used for this section.
- A pull request read fails with gh's first stderr line (control and format characters removed, 200 characters), or asks for `gh auth login` on exit code 4. All of one pull request read's gh calls share one 30 s deadline, and the worktree list's `gh pr list` has its own 30 s timeout beside the git reads; collie-core waits 40 s for these reads.
- **Phone**: the list shows each worktree's branch, the session's own checkout marked, last commit subject and age, commits ahead, uncommitted files, line totals and the pull request badge, plus the herdr agents of the machine whose folder lies in it (the deepest worktree holding the agent's `cwd`, from the flock; Claude Code subagents are not placed, since their transcripts record the parent session's folder unless started in a worktree). A worktree opens on Uncommitted and Branch, plus Pull request while its pull request is open or a draft; a pull request without a worktree opens on that scope alone. Pull request files use the agent's checkout as their root, so feedback on them stays valid after the worktree goes and names `pull request #N` instead of a folder; it is sent only while the agent's checkout is still that root, so it cannot name another repository's pull request. Agents are placed by the `cwd` herdr reports, not a canonical path, so one whose folder goes through a symlink to a worktree is not placed.
- **Clean up**: Select mode on the list picks worktrees other than the agent's checkout and any on `main` or `master` (the default branch fallbacks; the phone is not told the `origin/HEAD` branch). Clean up first re-reads the agent's checkout and refuses if it moved since the list loaded, then sends one prompt through the feedback path, so the same checks apply: it is refused while the agent is blocked or the session is a plain terminal, while the phone is sending another prompt, answering a question or dictating, and when the agent's input box holds unsent text. The prompt lists each worktree's path and branch as JSON strings (so a U+2028 or U+2029 in a name cannot start a line of its own) and asks the agent to remove only those not in use (no agent or process in it, no uncommitted, untracked or unpushed work, pull request merged, closed or absent, and without a pull request nothing created or changed in it in the last 24 hours, since a background agent that just started there shows no other sign) with their local branches, keep the main worktree and the default branch, and report what it kept and why. The phone removes nothing itself, so no protocol or collied change.

## Conversation history

`agent.history` is a read method on the paired connection: a terminal ID, an optional `before` or `after` cursor and an optional case-insensitive `query`. Cursors bind the agent kind, session UUID, file device and inode, byte offset and a hash of the preceding 64 bytes; replacement, truncation, changed cursor bytes or a session change reset the page. The daemon resolves the live agent before reading and verifies it again before replying. Identity comes from herdr, never a folder or recency guess; a missing identity or an unreadable file returns `available: false` with a distinct `unavailable_reason`, so the next poll can recover, and an existing empty transcript `available: true` with no messages. No version bump: an older daemon rejects the additive method, and the phone keeps Terminal available.

- Copilot CLI reads the conversation selected for the pane (Live Copilot conversation in [Context and inbox](#context-and-inbox)), not herdr's possibly stale ID; without a unique selection the reply is `available: false` with its own reason. Since `/new` can switch conversations without changing herdr's ID, the daemon selects again after the read and refuses a page from another session.
- `latest: true` (revision 27, with no cursor or query) returns, without cursors, only the last two user messages and the last two assistant text messages, in order, from the same tail window and per-record caps, within 40 KiB. Tool calls, results, events, subagent records and blank text never count, and thinking and reasoning are never read (except a Claude progress update written as thinking, below); a record mixing text and tool calls counts only its text.
- The reader uses the transcript locations of [Context and inbox](#context-and-inbox). A blocking worker reads at most a 64 KiB format header and a 2 MiB history window without holding the shared transcript mutex, consuming only newline-terminated records, so a partial append is retried. Backward pages and forward updates carry distinct cursors. A reply holds at most 40 message blocks and 40 KiB of serialized messages, below the 64 KiB transport limit; an oversized record is skipped with a notice, and cursors still progress. Search matches the full text; large text is then truncated on UTF-8 boundaries. No transcript content or search text reaches audit, push or notification state. Stable record and block IDs prevent duplicates across pages and reconnects.

**Claude.** The reader takes main-thread user and assistant content blocks, `tool_use` and `tool_result` included, and excludes synthetic replies, foreign session records and user records the harness injected (`isMeta`, such as skill text and subagent hand-backs, compaction summaries, and `task-notification` origins). No version bump for any of the following: each arrives as an ordinary message.

- A subagent hand-back leaves a one-line `event` message, "Subagent finished: \<description>" (the description, else the agent type, from the subagent's meta file); a task notification, with no structured status or summary, leaves "Background task finished".
- A slash command (a user record with no `promptSource`, not `isMeta`, whose string content starts with `<command-name>` or `<command-message>` and names a `/` command; a typed prompt always has a `promptSource`) leaves its name and arguments, such as "/effort high", and its `<local-command-stdout>` record is left out. These `event` lines carry no other record text, are capped at 120 characters without control characters and stay out of search.
- A `!` shell command (a user record with no `promptSource`, not `isMeta`, whose string content is `<bash-input>CMD</bash-input>`) shows as the user's message `! CMD`. The next record, `<bash-stdout>OUT</bash-stdout><bash-stderr>ERR</bash-stderr>`, becomes one `tool` result with no call ID: stdout, then any stderr on the next line, without terminal escape sequences (removed before truncation and search). Chat shows it as its own collapsed activity row.
- A prompt sent while Claude is working is written only as an `attachment` record (`attachment.type` `queued_command`, `commandMode` `prompt`, `origin.kind` `human`) once Claude Code absorbs it into the running turn; its `prompt` (a string, or text and image blocks) shows as an ordinary user message there. A prompt that waits for the turn to end is a `user` record with `promptSource` `queued` instead, never both. Other attachments and queued commands (task notifications, subagent hand-backs, coordinator messages) stay hidden.
- Claude 5.1 and later (from `message.model`, such as `claude-opus-5-5`: a family name, a major version and an optional one- or two-digit minor) write the short progress update before a tool call as a second thinking block. Claude Code writes each block as its own record sharing `message.id`, numbered by `apiBlockIndex`, and thinking blocks lead a message, so from such a model a main-thread thinking block at index 1 or later (`apiBlockIndex` plus its position in the record) is that update. It shows as assistant text and as `last_line`, even when a page or tail window splits the message. Every other thinking block (a lone or first one, or any from an older model, a synthetic reply or a subagent) stays hidden as reasoning.
- Subagents: each subagent's records live in `<session>/subagents/agent-<id>.jsonl`, with `agent-<id>.meta.json` naming the parent Agent call (`toolUseId`). The reader adds them after the Agent call, tagged with its ID in `parent_call_id` (additive), and on forward pages after the hand-back (`origin.from`), so an open Chat gets the steps when a background subagent finishes. It opens them like the transcript, only for an id of letters and digits through real directories under the session's. They share one more 2 MiB tail window, plus up to 64 KiB of each file's head for its prompt, and count toward the page's 40 blocks and 40 KiB: a subagent larger than the room left keeps its first and latest steps and marks the page omitted, as do records left out in between, and its call starts the next page only when not one step fits. Context and the last line ignore subagents.

**Codex.** Codex 0.160 and later (or a header window containing `item_completed`) uses `UserMessage` and `AgentMessage` completion events for conversation text, avoiding their overlapping `response_item` messages; older Codex uses `response_item` messages. Both read `function_call` and `custom_tool_call` and their outputs with call IDs; encrypted reasoning and internal instructions are excluded.

**Copilot CLI.** The file must start with a `session.start` naming the selected conversation. The reader shows typed `user.message` content with no `source` or `source: "user"` (other sources, such as autopilot, `skill-*` or `agent-<id>` outside a subagent, were injected), `assistant.message` content with its `toolRequests` as calls, and `tool.execution_complete` results (`result.content`, or `error.message` on failure) paired by `toolCallId`; reasoning, system prompts, hooks, model and usage records and the duplicate `tool.execution_start` are hidden. A `system.notification` of kind `agent_idle` or `shell_completed` leaves a "Subagent finished" or "Background task finished" `event` line. Subagent records, marked with the child's `agentId`, are tagged in `parent_call_id` (additive, no version bump) with their `parentToolCallId`, or, for the child's prompt, the `toolCallId` of its `subagent.started` or of another record of that child in the same 2 MiB window; a child record whose call is not in the window is left out rather than shown as the parent's. Record IDs come from each event's `id`.

**Phone.** Chat projects records into a lazy timeline: text replies stay visible, consecutive tools form one collapsed activity row paired by call ID, and an Agent call nests its subagent's steps. It keeps an ID-based scroll position, loads older pages on demand, polls only the appended portion while visible in the foreground, and searches in bounded batches back to the beginning. Terminal keeps keys and wrapping and serves shells and unavailable transcripts.

## Plan usage

Claude Code passes the plan's limits only to the status line command, on stdin at each refresh (a new reply, `/compact`, a mode change, or a window reaching its reset), as `rate_limits.five_hour` and `rate_limits.seven_day` (`used_percentage` 0 to 100, `resets_at` in Unix seconds). On disk they sit only in a `/usage` cache in `~/.claude.json`, which also holds account data collied should not read. Codex's rollout `rate_limits` (`primary`, `secondary`) are null for credit-metered workspaces, so the daemon asks the local Codex app-server (`account/read`, `account/rateLimits/read`) every five minutes and keeps only `individualLimit`'s used credits, allowance and reset date; Codex manages its own OAuth token. A confirmed sign-out, or a successful response without a limit, clears the Codex reading; a failed fetch keeps it.

- **Tap**: `collied statusline` reads the status line JSON from stdin (at most 1 MiB), keeps the two windows (percentage rounded and clamped to 0 to 100, reset time in ms) and, for a lowercase-UUID `session_id`, `context_window.context_window_size` (1K to 100M), and drops the rest (`spend_limit` included). It merges them into `usage.json` (0600, data dir) under an exclusive `flock` on `usage.lock`, so concurrent sessions keep each other's windows, then replaces the file atomically without `sync_all` (a full drive flush on macOS; the next refresh redoes a lost write).
  - Each session reports the limits from its own last reply, so they merge per window: the later `resets_at` wins, then the higher percentage, since usage only grows within a window; a window one session leaves out is kept until its reset. `recorded_ms` moves only when the input agrees with the merged result, so a quiet session's older figures neither replace newer ones nor look fresh.
  - The status line runs several times a second while a reply streams, so an unchanged value is restamped at most once a minute, and input that changes nothing leaves the file alone. Input without `rate_limits` (a session before its first reply) keeps the last limits. At most 64 sessions' windows are kept, the oldest seen first out. The tap starts no runtime and prints nothing.
- **Daemon**: `Transcripts` re-reads `usage.json` (`O_NOFOLLOW`, regular file, at most 64 KiB) when its size or mtime changed, checked for `flock.snapshot`, `approval.list`, each `claude` transcript derivation and the 1 s reconcile poll. The plan belongs to the machine, so it goes out on the snapshot as `Flock.plan_usage` (`five_hour` and `seven_day`, each `used_percent` and `resets_at_ms`, and `recorded_ms`), with or without a Claude Code agent open. When it changes and a phone has a session open, that tick sends `plan.usage`, or `flock.changed` for a cleared plan. No version bump: the field is additive on a server-to-phone type, and an older app ignores the unknown event.
- **Phone**: Usage shows one card per machine with a plan recorded, with the recording's age once no reading is current (each past its agent's limit below), and blocks for Claude Code ("5-hour limit", "Weekly limit"), Codex ("Monthly limit", when Codex reports an individual limit) and Copilot ("Monthly premium usage", when collied read one). A block shows a bar with an elapsed-time tick, the amount used (percent for Claude; used and allowed credits for Codex and Copilot, or requests for a Copilot seat that is not token-billed; "Unlimited" with no bar for an uncapped seat) and the reset; Copilot overage keeps the bar full and shows the real amount. A window past its reset is hidden; Claude data over 5 minutes old and Codex and Copilot data over 10 minutes old are dimmed.
- **Copilot**: a task beside the Codex one runs `gh api --hostname github.com copilot_internal/user` (which also answers for a seat an enterprise assigns) every five minutes, with or without a phone, with the linked pull requests' `gh` setup ([Linked pull requests](#linked-pull-requests)) and the user's own `gh auth login`. It reads github.com only; GitHub Enterprise Cloud with data residency (`*.ghe.com`) is not read.
  - `--jq` reduces the answer inside `gh` to `token_based_billing`, `quota_reset_date`, `quota_reset_date_utc` and `quota_snapshots.premium_interactions`, so the login, account id, tracking id, organization and enterprise lists and service endpoints never reach collied.
  - collied keeps `used` (`entitlement` minus `remaining`, at least 0, plus `overage_count`, so overage counts however GitHub reports it), `limit` (`entitlement`), `unlimited`, `token_based_billing` and `resets_at_ms` (`quota_reset_date_utc`, else `quota_reset_date` as UTC midnight) as `copilot` in `usage.json` and `PlanUsage`.
  - No `gh`, `gh` exit code 4 (no login), an HTTP 404, an answer without `premium_interactions`, or an `entitlement` of 0 on a limited seat clears the reading; any other failure (network, timeout, a malformed answer, a reset already past) keeps the last one. The chat and completions quotas are not read. Nothing from `gh` is logged, audited or pushed. No version bump: `copilot` is an optional, additive field on a server-to-phone type, which an older app ignores.
- **`collied doctor`**: `plan usage` says when the tap last recorded the limits and how many sessions' windows it holds, or warns that it has recorded nothing. `copilot` reports the daemon's last read while under 10 minutes old; otherwise it asks GitHub once and says whether the usage is readable, that there is no `gh`, login or premium quota, or why the read failed.

Security: [Status line tap](threat-model.md#status-line-tap), [Copilot premium usage](threat-model.md#copilot-premium-usage).

## Token cost

The Usage view's "Tokens and cost" card reads `usage.costs` (revision 28, a read method) with a range (`today`, `7d` or `30d`) and the phone's current UTC offset in minutes (within 18 hours), so days end at the phone's midnight; one offset covers the whole range, so after a daylight saving change earlier days are an hour off. The reply carries `scanning`, token totals (input without cached input, output, cache read, cache write), the estimated cost and cache savings, a cost per day, and at most 32 model rows by cost, each with its agent, model id, tokens, `cost_usd` and `cache_savings_usd` (null for an unpriced model). Totals cover every model, listed or not; only priced models add to costs. The audit log leaves the method out, like `flock.snapshot`, since the card polls it.

- **Sources**: Claude Code's `projects` (every `*.jsonl`, subagent and workflow transcripts included), Codex's `sessions/YYYY/MM/DD/rollout-*.jsonl` and `rollout-*.jsonl.zst`, and Copilot CLI's `session-state/*/events.jsonl`. The walk never follows a symlink, opens only regular files, skips names starting with `.`, descends at most 5 levels and lists at most 20,000 files per root, counting only files modified in the last 32 days. When a root hits the cap, indexed files missing from the listing are kept. Codex compresses a rollout idle for 7 days to `.jsonl.zst` and decompresses one it resumes; while both forms exist, only the plain file counts, as Codex reads that one.
- **Claude Code**: `assistant` records with `message.usage` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` and its `cache_creation.ephemeral_1h_input_tokens` part), `speed: "fast"` and `message.model`. Sidechain records count; `<synthetic>` records do not. Claude Code writes one record per content block, and a resumed session repeats earlier records in its new file, so a record counts once per `message.id` plus `requestId` across all files, kept by the first file in path order. A streamed message's earlier block records carry a partial `output_tokens`, so the file keeps the output counted per key and adds only the increase when a later record of that key reports more.
- **Codex**: `event_msg` `token_count` events' `info.last_token_usage` (less `cached_input_tokens` and `cache_write_input_tokens`, which `input_tokens` includes), under the latest `turn_context`'s model; a call over 272,000 input tokens, cached included, is long. An event is skipped before any `turn_context`, or when its `total_token_usage` equals the last counted one (Codex repeats unchanged events). After a counter restart (`total_token_usage` equals `last_token_usage`) Codex can later replay that first request, so a hash of its timestamp and `last_token_usage` is kept and a restart to that exact event is skipped; a restart with the same counters at another time still counts, and a zeroed `total_token_usage` forgets the kept request. Codex forks and subagent rollouts start their own counts (checked against 0.163 rollouts), so no fork suppression is needed.
- **Copilot CLI**: `session.usage_record` events, one per model call of the main agent and each subagent: `data.usage.model`, `inputTokens` (including `cacheReadTokens` and `cacheWriteTokens`; long above 272,000) and `outputTokens`. A record without a model counts under `unknown`, unpriced. Copilot bills premium requests, so its cost is an API-equivalent estimate, and the card says so.
- **Model ids**: at most 64 characters of letters, digits and `._:/[]-`, else `unknown`, so only plain ids leave the machine.
- **Index**: `usage-costs.json` (0600, data dir) keeps per transcript path its device, inode and size, the offset past its last complete line, Codex's model, last counted total and sequence's first request (the last two hashed), token sums per 15-minute UTC slot, model, fast mode and long call, and the hashed Claude keys it counted with their slot and output.
  - A scan reads each file from its offset in 1 MiB chunks, consuming only newline-terminated lines (a line over 8 MiB is skipped), so a partial last line is read again once complete. A file of unchanged size is not opened past `fstat`; one that shrank or changed device or inode loses its counts and keys and is read from the start.
  - A compressed rollout is decoded (pure-Rust `ruzstd`, 8 MiB window as for Resume, stopping past 512 MiB of output) and read whole whenever its device, inode or size changes; one that decodes past the limit or fails is recorded with no counts until it changes.
  - Each scan drops slots and keys older than 32 days and files that disappeared or went quiet, and replaces a changed index atomically after releasing the lock; an index of another format version is rebuilt. Deleting a file that a resumed copy deduplicated against takes the shared records with it until the copy is read again from the start.
- **Scans**: `usage.costs` starts a scan on its own thread unless one is running or finished in the last 15 s, and answers at once from the index. The scan holds the index lock only to merge one file, so a reply during a cold scan has the totals so far and `scanning: true`. A first scan of about 4 GB of transcripts takes a few seconds; a later one, a fraction of a second.
- **Prices**: `crates/collied/data/prices.json` holds LiteLLM's entries for `anthropic` and `openai` chat and responses models: input, output, cache read, cache write and one-hour cache write rates, OpenAI's rates above 272K input tokens, and the fast-mode multiplier. `just prices` refreshes it and LiteLLM's license from the commit pinned in the justfile; collied fetches nothing at runtime.
  - Lookup lowercases the id, drops a `[...]` suffix (Claude Code's `[1m]`) and a provider prefix, writes Claude ids with `-` for `.` (Copilot's `claude-opus-5.5` is Claude Code's `claude-opus-5-5`), then tries the id without a trailing `-YYYYMMDD`.
  - A missing cache rate is the input rate, and a missing one-hour rate the cache write rate. A long call uses OpenAI's above-272K rates; other tiers, such as Claude Haiku 5.5's above-100K rates, do not apply. Fast mode multiplies every rate. Cache savings are cache reads times the input rate less the cache read rate.
- **Phone**: each machine's card asks on appear, on a range or link change and on pull to refresh, then every 2 s while `scanning`; a failed read keeps the figures shown for the same range. Below revision 28 the session refuses the method locally, and the card asks to update collied on that machine.

Security: [Agent transcripts on the Mac](threat-model.md#agent-transcripts-on-the-mac).

## Starred agents

- `agent.star {terminal_id, starred}` (Drive class: audited and rate limited) stars or unstars a pane and sends `flock.changed`. Starring reads `session.snapshot` and answers `not_found` for a terminal herdr does not list; unstarring reads nothing, so it works for a pane already gone.
- collied keeps the stars in `stars.json` (0600, data dir), one set per machine shared by all the owner's paired phones, as `terminal_id` to `pane_id`: a herdr session restore (after a reboot) gives every pane a new `terminal_id` but keeps the `pane_id`, and a cross-workspace move does the reverse. On each `flock.snapshot`, and every second while a star is missing from that tick's `agent.list` at its last pane (with or without a phone, at one more `session.snapshot` per tick), collied keeps a star whose terminal is listed (updating its pane id), moves one whose terminal is gone to the terminal now in its pane, and drops the rest; a snapshot with no pane changes nothing, since herdr answers before restoring its panes. `pane_id` never leaves the machine.
- The snapshot carries them as `Flock.starred` (additive, no version bump, but the app and collied update together since client params deny unknown fields). A star survives an app reinstall, a phone offline, an agent exiting (its pane stays) and a herdr restore; it goes when its pane closes or a phone removes the machine (`unpair` clears them all). Gaps: a pane id herdr reuses within about a second (or while herdr is unreachable) takes the old star with it, and a move followed by a restore in that window loses it. Closing every pane keeps their stars, since an empty list is not trusted, so a new pane that gets one of their pane ids inherits that star.

## Terminals

A pane with no agent is a plain shell: herdr keeps the pane and its `terminal_id` when the agent exits (verified on 0.9.3). The phone lists, watches and types into shells under these rules. Security: [Shell input from the phone](threat-model.md#shell-input-from-the-phone).

### Opt-in

```toml
[terminals]
enabled = true   # false, the default, when the section or the key is absent
```

- Read at start, so a change needs a restart, which ends every session. No method changes it; only `collied apns import` and `collied setup`'s push step rewrite `collied.toml`.
- Off: `flock.snapshot` has `terminals: []` and no `terminals_enabled`; every `terminal.*` request but `terminal.lock` (always `ok`) answers `terminals_disabled` before any herdr call, audited.
- `pane.read` reads agent panes only, whatever the setting.

### What is a shell

- A pane is a shell when its `PaneInfo.agent` is absent and its `terminal_id` is not in `session.snapshot.agents`, which includes agents herdr is still launching.
- `flock.snapshot` lists shells as `Terminal {terminal_id, workspace_id, label, cwd}`: `label` is the herdr pane name, `cwd` the foreground process's directory, else the pane's. Titles a program sets (`terminal_title`, which a zsh theme fills with the running command) never leave the machine.

### Grants

- **Terminal key.** A second Secure Enclave P-256 key beside the TLS key, created with `.userPresence` and `kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly`: every signature needs Face ID or the passcode, and removing the passcode destroys the key. Only the simulator uses a software key, behind a LocalAuthentication prompt.
- **Registration.** `pair.complete` carries `terminal_key`, base64url of the 91-byte SubjectPublicKeyInfo. The pairing fails (audited `invalid terminal key`) unless it is a P-256 key other than the session's TLS key, which would sign without Face ID. The machine's y/N prompt shows the key as none, new, unchanged or a replacement. collied keeps the key in the peer record, which pairing again replaces whole, so a pairing without a key forgets it. The phone keeps its paired key in `machines.json` and, when its current key differs (as after the passcode was removed), answers `TerminalKeyMissing` (pair again) before any Face ID.
- **Challenge.** `terminal.challenge {terminal_id}` needs a stored key (else `terminal_key_missing`) and a shell, and answers `{terminal_id, challenge, ttl_ms: 60000}`: 32 random bytes, one outstanding per session, a new one replacing it.
- **Grant.** `terminal.grant {terminal_id, challenge, signature}` burns the session's challenge on any attempt. The signature (ECDSA P-256, SHA-256, DER, base64url) covers `u32be(len) || bytes` of each of `"collie terminal grant v1"`, the machine's node ID (on the phone, the one pinned at pairing), the `terminal_id` and the challenge (`protocol::terminal_grant_message`). collied verifies it with the stored key and answers `{terminal_id, ttl_ms: 300000}`, else `terminal_locked` with the reason.
- A grant covers one terminal in one session for 5 minutes from its issue (not a `collied.toml` key) and is bound to the key that verified it; at most 16 per session. Grants and challenges live in collied's memory only (lock order peers, sessions, terminals). They end with `terminal.lock`, the session, a revoke, unpair or re-pairing, or an agent seen on the terminal.

### Watch and input

- `terminal.watch {terminal_id, lines?, low_data?}` needs a live grant and shares the session's one watch, and its events, with `agent.watch`. It reads nothing while the session lacks a live grant under the peer's current key (a new grant resumes it), and ends with `flock.changed` when the pane closes or an agent starts in it. `agent.watch {terminal_id: null}` stops either kind.
- `terminal.run {op_id, terminal_id, text}` sends one line of `PromptText` (no newline, tab or other control, no bidi or invisible format character) as `pane.send_input` with `keys: ["enter"]`, the one ordered write `herdr pane run` makes (verified on 0.9.3 with sh and zsh). On macOS, herdr 0.9.5 refuses a line over the canonical input limit while the pane is in canonical mode, as a starting shell is; collied answers `too_large` (wait for the prompt, then retry) and keeps nothing else of herdr's message.
- `terminal.send_keys {op_id, terminal_id, keys}` sends at most 16 keys. A `Key` is one of nineteen listed names or a combination (`KeyCombo`) in herdr's key-combo syntax: modifiers from `ctrl`, `alt`, `shift` and `cmd`, each once and in that order, then one key: `enter`, `esc`, `tab`, `backspace`, `space`, an arrow, `f1` to `f12`, a lowercase letter, a digit or one of `` ' , - . / ; = [ \ ] ` ``, the characters herdr-core 0.1.18 takes besides herdr. So a key names one key press, though a call of 16 can type 16 characters. `[` goes only with Control (ESC in herdr; herdr-core refuses it), so keys alone cannot put `[`, digits, `;` and a letter after an ESC from Esc, Alt or Control-3 to spell an escape sequence such as `ESC[100;5u`, the kitty form of Control-D; an Esc key followed by typed text still can, when both reach the program in one read. Control is refused with d, z and r, which would widen `agent.send_keys` too (EOT, SUSP, reverse search); j and m, which submit like Enter without its checks; o and t, which open Claude Code and Codex transcript views the scrolled-up check may miss, so later keys could answer a prompt hidden behind them; and 4 and `\`, which send QUIT. The refusal holds whatever other modifiers come with Control: herdr's legacy encoding sends Control-Shift-D as Control-D, and Alt only prefixes ESC. The phone withholds a combination ending in `enter` wherever it withholds Enter.
- Command (`cmd`, Super) reaches only a program that turned on a keyboard protocol: herdr 0.9.5 encodes it in the kitty protocol (`ESC[107;9u` for ⌘K) or modifyOtherKeys level 2, and sends nothing for it to a program in legacy mode, such as a shell. Claude Code 2.1.318 and Codex 0.166.0 turn the kitty protocol on in herdr (checked from their output in a scratch pane), and Claude Code binds `cmd` keys in its `keybindings.json`; herdr-core refuses `cmd` (above).
- `terminal.send_text {op_id, terminal_id, text}` types `TypedText` (as for `agent.send_text`) with `pane.send_text`, without Enter, under the same checks as `terminal.send_keys`.
- All three go through the `op_id` outcome cache: a retry from the phone's next session replays the first attempt, checked against the first session's grant. herdr targets panes by `pane_id` and reuses pane ids, so right before each write collied checks a fresh snapshot: an agent there now gives `not_found` and drops the terminal's grants. It then requires the peer, the sending session's grant under the peer's current key, and no approval pending on the terminal (hook-driven approvals see an agent before herdr does), else `terminal_locked` (never `not_paired`, which would stop the phone reconnecting). A herdr error from these writes keeps only its code, since its message may quote the input. Nothing checks the foreground process: ctrl+c and answers reach whatever runs in the shell.
- `terminal.lock` ends the session's grants and terminal watch.
- Creating shell panes (`tab.create`) is a follow-up.

### Typing into the terminal

The session's Terminal view (an agent's, or a shell's) has no prompt field; its keyboard types straight into the pane, as in a terminal app. Chat keeps its composer.

- A single tap on the terminal that clears no selection, or the keyboard button, makes the terminal view first responder (`UIKeyInput`, no autocorrection, capitals or smart punctuation); the button hides it again, as does Return (typed, or the composer's or the strip's return key) unless Keep keyboard open after sending is on. Scrolling, long-press selection and the double- and triple-tap gestures are unchanged.
- Tap to place the cursor (Claude Code, Codex and Copilot CLI): the pane's cursor position is not on the wire (`sanitize_ansi` drops cursor moves, herdr's `pane.read` does not report it, and Claude Code draws no cursor of its own), so the phone finds the agent's input box in the rendered frame and walks there with keys. Claude Code's is found as `draft::parse` does (the last two rules from column 0, the first row starting with `❯`, other Mac rows indented two); Codex's is the last row starting with `›` at column 0, shaded, between two blank rows in its shade, other Mac rows indented two; Copilot CLI's is the last `╻▄` border, then rows starting with `┃`, then a `╹▀` border. A tap in the box picks the character boundary nearest to it; the phone sends ⌃A, then ← and ⌃A once per further Mac row in the box, which reaches the start from anywhere, also past spaces typed at the end of a row, which the screen does not show (⌃A goes to the start of the line in Claude Code and Codex and of the row in Copilot CLI, and ← at the start does nothing), then ↓ once per Mac row above the tapped one, then → across the tapped row up to the tapped boundary, as keys in the strip's queue, and shows the keyboard. Checked on Claude Code 2.1.318, Codex 0.166.0 and Copilot CLI 1.0.105: ↓ moves by row as drawn, wrapped or after a newline, keeps the column, and lands on the row's first character shown, past spaces typed at the end of the row above (Claude Code and Codex hide them; Copilot CLI shows those that do not fit at the start of the next row, and the phone counts them there). So the walk counts only characters the screen shows: those before the tap on its own row, never past the typed text, so → never accepts a suggestion shown after it. Codex's ↓ at the very start of a draft recalled from history unchanged recalls the next entry instead, so for Codex the walk sends → before ↓: ↓ keeps that column (one cell, or two after a wide first character) and stops before a character that would cross it, and a row narrower than that column (an empty row, which may hold spaces typed there) takes the old single tap, as do rows after an empty first row. Where the screen shown joins rows the Mac wrapped (collied's `wraps` and `splits`: Claude Code's box as [Draft sync](#draft-sync) reads it, and Codex's rows under `›`), the phone renders the unjoined snapshot when tapped and maps the tap onto the Mac's rows: a joined row's space stands for the one hidden at the wrap. A wide character counts once. Taps elsewhere keep the old single tap, as do taps in a box showing only a dim placeholder or hint, a slash command (→ would complete its menu), a `❯` row below Claude Code's box (a selected background agent), a menu right above Codex's or Copilot CLI's box (Codex's ← and → switch its list), and in Codex and Copilot CLI any text in a color of its own or dim: Codex's scroll arrows and collapsed pastes and images, and Copilot CLI's suggestions. Claude Code's file and resource suggestions, drawn right above its box indented four, take ↓, so while they show only the box's first row places the cursor. Copilot CLI scrolls a box taller than about half its pane without a sign (10 rows in a 25-row pane), so its box of eight Mac rows or more takes the old single tap. The walk to the start counts the Mac's rows, not the lines shown: collied also joins a typed newline right where the next word would not have fit, which looks the same as a soft wrap. Known limit: a collapsed paste or image in Claude Code counts its label's characters.
- While the terminal is first responder, the view keeps that box above the keyboard: following the bottom stops at the offset that puts the box's bottom rule, blank row or border at the visible bottom (never past the real bottom). A scroll that ends elsewhere stops following; a change to the box's text while typing, or a scroll back to the bottom, resumes it.
- Text goes out with `agent.send_text` or `terminal.send_text`, Return as the `enter` key and Tab as `tab`, Backspace as `backspace`, in one queue with the key strip's keys, so order holds. Text typed while a call is in flight goes out together in the next one. Control and format characters are dropped on the phone. With ⌃ selected on the strip, a listed letter goes out as that Control key.
- A slash command typed into Claude Code's box shows its menu on the screen, and Return runs it (Claude Code's highlighted match); the phone withholds Return only for a command it mirrored from Chat ([Draft sync](#draft-sync)).
- Attachments upload as before; each file's machine path is then typed into the terminal, followed by a space. The app's dictation types its final text when it stops, leaving Chat's draft alone. A saved prompt is typed; the paste gesture types the clipboard with new lines as spaces, so it never submits. Quote from a terminal selection goes to Chat's draft and switches to Chat, since its newlines would submit.
- A herdr-core pane takes each batch through a typing attach, and the core holds a keys call until nobody has typed for about 3 s, so Return after typing lands about 3 s later there.

- Shells appear under "Terminals" in the Agents list and grid, without a grid preview, which would need a grant. The inbox and Live Activities show agents only; notification actions, the Live Activity intent and the lock-screen decide never send `terminal.*`.

## Menu bar app (macOS)

CollieBar (`Mac/`) is its own XcodeGen project: pure Swift, no packages, no CollieCore, a SwiftUI `MenuBarExtra` with `LSUIElement` (no Dock icon).

- It talks to collied only over the control socket, like the CLI, with three requests: `watch`, `pair` (then `confirm`) and `peers_list`. It opens no listener and reads none of collied's data files; Open Audit Log hands `audit.log` to Console.
- `watch` is read-only and not audited, like `status`: collied answers `{"type":"watch","pending_approvals":N,"collied_version":"VERSION"}` at once and again whenever the pending count changes. It does not subscribe to the phone event broadcast, whose receiver count means a phone is connected. An open connection means running, EOF off; the app retries a failed connect every 2 s, its only polling. The menu shows this connection's `collied_version`, never the installed binary's, or version unavailable without one. No version bump: `collied_version` is an optional additive field on the local control reply; the phone protocol is unchanged.
- While collied is off, Set Up runs `~/.cargo/bin/collied setup` in Terminal through a private 0700 command file that quotes the path and removes itself before exec (or when Terminal cannot open), so it needs no Automation permission or shell interpolation.
- Turn Off and Quit run `collied stop`, Turn On `collied start`, through the plist's `ProgramArguments[0]`, without a shell, so launchd's semantics (disabled until `start`, across reboots) stay in one place. The socket cannot do it: a stopped collied has no socket, and `KeepAlive` would restart one stopped from inside. A collied run by hand, outside launchd, is not stopped.
- Pairing shows what `collied pair` shows, each phone string escaped like `collied::printable`, with 60 s to answer. Pair is not the default button and goes live 1 s after the candidate appears (the window's `tcflush`); it sends one answer, never on its own. Only the QR image (correction level M) is kept: the invite is never shown as text, copied, logged or stored, and window restoration is off. Closing the window cancels, as Ctrl-C does.
- Open at Login uses `SMAppService.mainApp`, off by default.
- `just mac-install` signs it without App Sandbox, which would block the socket and running collied; [release.md](release.md#menu-bar-app-notarization-optional) covers signing and notarization.
- Its unit tests have no host app, so they never launch it against the live socket.

## Live Activities

The lock screen and the Dynamic Island show an agent only while the user follows it: off by default, at most 5 at once on the phone. The phone starts each activity from the foreground; collied only updates and ends it. Push-to-start is not used: it is unreliable from background wakes.

### Phone and collie-core

- Following starts an `Activity` (`pushType: .token`) with the agent's current state and registers each update token with that agent's Mac, again on every foreground. The app's title for the agent (its terminal title, at most 64 characters) is encrypted in the static attributes and fixed for the activity's life: the lock screen and the expanded island show it, while collied's pushes carry the agent name or kind. Unfollowing ends the activity at once and tells the Mac.
- collie-core keeps push and activity registrations per machine in memory only and sends them on every connection, `push.register` first, since collied takes the APNs environment from it. Ends the Mac has not acknowledged go out on every connection until it answers, even after an app kill: they persist in `activity-ends.json` in the state dir (0600, atomic; per machine, only `activity_id` and end time, at most 16). At start collie-core loads only paired machines' ends under 8 h old and ignores an unreadable file; removing a machine drops its ends.

### Protocol

- `push.activity_token {activity_id, terminal_id, token, shows_approvals?, display_binding?}` and `push.activity_end {activity_id}`, both `MethodClass::Push`. `activity_id` is ActivityKit's `Activity.id` (`[A-Za-z0-9-]`, at most 64); `token` is the update token in hex (64 to 256 characters, redacted in `Debug`). `shows_approvals` (omitted when false) means the activity shows an approval's command and buttons; collie-core always sends `true`, since every activity the app starts carries the Mac's node id.
- No version bump: push and activity registrations require the negotiated `encrypted_display_v1`; peers without it keep ordinary tailnet operations but cannot register this codec. The optional activity binding is sent only with that capability.

### collied

- Stored in `push.json` (0600, atomic) under `activities`: `{stable_id, activity_id, terminal_id, token, environment, registered_at, shows_approvals, display_binding}`.
- Bound to the session's `StableID`: a device registers, replaces and ends only its own activities. The same `activity_id` or `terminal_id` from that device replaces the old entry, so an activity the phone never ended holds no slot. The environment is the device's own from `push.register` (`not_found` without one). At most 8 per device (`too_large` beyond); ending an id the device does not have answers `ok`.
- Dropped on `push.activity_end`, on revoke, at start for peers no longer paired, on `Unregistered` or `BadDeviceToken`, when the terminal is gone, and quietly (no push, audited `ended: expired`) 8 h after that `activity_id` first registered, since ActivityKit ends an activity 8 h after it starts.
- Updates come from the 1 s agent reconcile, after the approvals pass, never from terminal output. Per activity:
  - first sight (a new activity, a new token, or a collied restart): one update without alert;
  - content changed: an update, at most one per 2 s (a change inside the gap goes out on the first reconcile after it); a status change alone never alerts, since the end of a turn is the [done alert](#apns);
  - an approval routed to the activity ([below](#approval-on-the-activity)): in the same reconcile, whatever the gap;
  - nothing changed: the same content every 10 min, moving the stale date while the Mac is up;
  - the terminal missing from two reconciles in a row: `end` with `dismissal-date` = now + 60 s, then the token is dropped. A failed `agent.list` (herdr down) changes nothing.
- Every send re-checks the pairing. The audit log has one line per register (`push.activity_token`, target `<terminal_id> activity=<activity_id>`) and per end (`push.activity_end`, `ended: agent gone` or `ended: expired`); tokens are never logged or audited.

| Header | Value |
|---|---|
| `apns-push-type` | `liveactivity` |
| `apns-topic` | `<bundle_id>.push-type.liveactivity` |
| `apns-priority` | 10 for an update carrying an approval alert and for the first update after an approval leaves the activity, else 5 (updates, refreshes, ends) |
| `apns-expiration` | for an update carrying an approval alert, the approval's expiry, as for the alert it replaces; else now + 5 min |
| `apns-collapse-id` | none |

```json
{"aps":{"timestamp":1791028800,"event":"update","content-state":{"v":1,"enc":"<authenticated envelope>"},
        "stale-date":1791029700,"alert":{"title":"Collie","body":"An agent needs attention"}},
 "node_id":"nMAC","event_id":"<opaque event>"}
```

- `timestamp`, `stale-date` (now + 15 min) and `dismissal-date` are Unix seconds; `alert` is present only on an approval alert. Public relevance scores are omitted so status does not leak through ranking.
- `content-state` is exactly `{v:1,enc}` for initial, local, update and end state ([Encrypted display envelope](#encrypted-display-envelope)). [protocol/live-activity-content-state.json](protocol/live-activity-content-state.json) describes the decrypted `state`; [protocol/push-display-vectors.json](protocol/push-display-vectors.json) holds the wire vectors.

### Approval on the activity

- A device that follows an agent gets that agent's approvals that offer Approve and Deny on the activity alone: one alert expands the Dynamic Island with the command and both buttons, and no approval notification comes. Other prompts, such as a question, a plan or a Codex or Copilot prompt, go as the approval alert, without actions.
- Only an activity registered with `shows_approvals` takes approvals. An activity without a current encrypted display binding gets no private state; an urgent send that cannot be encrypted falls back to the encrypted approval notification.
- When `alert_due` lets an approval alert go out, a device with such an activity for the terminal gets instead, in the same reconcile, a priority 10 activity update: a generic `aps.alert` and encrypted state holding `approvalId` and the inner context `enc`, sealed to that device's notification key like the alert's `enc` (AAD = `approval_id`; none without a key or a context) and cut at 600 JSON-escaped bytes, so the update fits APNs' 4 KB with labels at their caps. Other paired devices get the approval alert: an approval alerts once either way.
- A reissue that `alert_due` keeps quiet reaches only the activity, as a priority 5 update without alert carrying the new `approvalId` and `enc`, so its buttons never decide a burned approval.
- Fallback: if the activity push fails (any APNs or network error, or a dead token, dropped as usual), or the activity or the agent is gone by push time, the device gets the approval alert at once.
- Late fallback: APNs accepts pushes to an activity the phone has ended (dismissed, ended by iOS while suspended, Live Activities off, an update dropped by iOS's budget or replaced while offline), and nothing tells collied. So an approval that alerted on an activity and 2 min later is still pending and not being decided also reaches that device once as the approval alert, never after an early fallback. The cost: a reminder after 2 min unanswered, and up to 2 min of delay behind a dead activity. Both timers live in collied's memory; a restart reissues pending approvals, which alert again.
- The inner `enc` is sealed once per device and approval and repeated inside freshly sealed outer envelopes on later updates, so coalescing still sees an unchanged state. Once the approval resolves or the agent leaves `blocked`, the next update omits `approvalId` and `enc` and carries no alert; it goes out at once at priority 10, skipping the 2 s gap and the relay's 60 s cadence, so a locked phone drops the buttons. An `end` never carries them.
- On the phone, `AgentActivityAttributes` carries the Mac's `nodeId`. The widget authenticates the whole state against its node and activity binding, then shows the inner command, `privacySensitive` (redacted while locked), on the lock screen and the expanded Dynamic Island. Failed authentication shows a neutral display without buttons; authenticated blocked state without a command shows "Approval needed"; Approve and Deny need a command that decrypts. Their `LiveActivityIntent` requires authentication, so iOS makes the user unlock first; the intent then takes the notification actions' path in the app ([Lock-screen approval](#lock-screen-approval)).

## `collied setup`

One interactive command adds or updates a Mac or Linux machine. Its steps reuse the subcommands through a `setup::Host` trait, which unit tests fake to check the step order and skip rules. Each step checks its own done state, so a rerun resumes where the last one stopped:

| Step | Done when | Otherwise |
|---|---|---|
| login | the daemon answers `status` with backend `Running`, which it does only once its node passes the ownership checks; a loaded job first gets 20 s, for a daemon `just collied-install` just restarted | unload a loaded job without disabling it (a crash loop or a logged-out daemon holds the node lock or the socket), run `collied login`, and if that fails start the job again |
| service | the plist on disk is what `install` would write, the job is loaded, and the daemon's `started_ms` is not older than the binary's mtime | `service install` (bootout, then bootstrap), then wait up to 60 s for the daemon, including up to 10 s for an untagged device in its netmap, so a fresh node does not trigger the policy hint; on a timeout print the last 20 lines of `collied.err.log`. A plist with another `--config` stops setup: run `collied --config <path> setup` |
| doctor | no fail line | stop: fix, then run setup again |
| push | `[push.relay]` or `[apns]` is in `collied.toml` | offer it: by default add `[push.relay]`; with `--direct-apns`, ask for the `.p8` (key ID from `AuthKey_<KEY_ID>.p8`), team and bundle IDs, append `[apns]` and run `apns import`, restoring the old config if the import fails (a new file is created 0600; an existing one is rewritten atomically, keeping its mode). Then restart the service so the daemon reads it |
| pair | never: phones may need to pair again after an update | offer `collied pair` |

Before any step, setup refuses unless stdin is a terminal, so `yes | collied setup` cannot answer the pairing prompt, and unless it runs as `~/.cargo/bin/collied` (on Linux also a packaged `/usr/bin/collied`), a regular file, not a symlink, and on macOS Developer ID signed as `dev.rbstp.collied`. So the service never runs an unsigned binary or `target/release`, which the next `cargo build` replaces. Setup never confirms a pairing: the `y` typed after the `tcflush` does.

On Linux only the service backend differs:

| Step | Done when | Otherwise |
|---|---|---|
| login | as on macOS; "loaded" is any `ActiveState` but `inactive` and `failed` (a unit restarting after a crash counts); while a daemon answers, only `active` counts, so a foreground `collied run` beside a restart loop is refused as running outside the service | `systemctl --user stop` (the unit stays enabled), `collied login`, and if that fails `collied start` |
| service | as on macOS, for the unit file (executable, `--config`, pinned `XDG_*_HOME`) instead of the plist | `service install` (`daemon-reload`, `enable`, `restart`), then wait as on macOS; on a timeout print the last 20 lines of `journalctl --user -u collied.service` |

On Linux, the service check also stops setup when the user manager loads `collied.service` from another file or applies a `collied.service.d` drop-in, when the unit pins another `XDG_DATA_HOME` (another node's data dir, so setup would log in a new node), or when it runs another `--config`. The direct APNs step stores the key as [APNs key on Linux](#apns-key-on-linux) describes, and never prints it.

Doctor's `service` line reports the same state on both OSes: `up to date` (on Linux, adding that the unit stops at logout without linger), or a warn naming what setup would do. A doctor other than the installed binary skips it with a warn, since the check compares the service with the running binary.

The control socket's `status` reply carries `started_ms` and `user_peers` (visible untagged nodes of the daemon's verified user; visible does not mean TCP-reachable), both with serde defaults; setup treats a daemon reporting neither as outdated. The phone protocol is unchanged.

On macOS, an interactive login without an auth key prints the URL and QR, then tries once to open the URL with `/usr/bin/open` and an argument array if it is HTTPS with exact authority `login.tailscale.com` (port 443 optional) and no userinfo; failure is nonfatal. Other logins (noninteractive, auth key, custom control) only print the URL.

Startup verifies the node's own user identity ([tailnet.md](tailnet.md)) before exposing any listener or the control socket, with no first-phone-owner fallback. A restarted node reports `Running` from Tailscale's netmap disk cache, which can lack user profiles, so its own-address whois answers "peer not found" until control sends the live map: `collied run` and `collied login` repeat the whole check on exactly that answer until their start deadlines (60 s and 10 minutes), and stop at once on any other failure, a mismatch included. Admission and the post-TLS gate recheck the self identity and a fresh peer whois, so changing the owner or tagging the running node refuses new sessions instead of rebinding trust. Local reauthentication requires stopping the daemon first; `collied login` prints Tailscale's last login error.

User ownership gives the embedded daemon its user's network privileges, not a separate service tag's confinement. [tailnet.md](tailnet.md) covers doctor's `reach` line and setup's policy hint, key expiry, scoped state reset, reauthentication and the physical-device and corporate VPN acceptance gap.

| `aarch64-unknown-linux-gnu` | mapped in `tailscale-sys` (GOARCH `arm64`); needs a cross C compiler in `CC`; not built or tested |

### Paths

| What | macOS | Linux |
|---|---|---|
| Data dir | `~/Library/Application Support/collie` | `$XDG_DATA_HOME/collie`, else `~/.local/share/collie` |
| Attachments root | `~/Library/Caches/dev.rbstp.collied/attachments` | `$XDG_CACHE_HOME/collied/attachments`, else `~/.cache/collied/attachments` |
| Service | `~/Library/LaunchAgents/dev.rbstp.collied.plist` | `$XDG_CONFIG_HOME/systemd/user/collied.service`, else `~/.config/systemd/user/collied.service` |
| Logs | `collied.out.log`, `collied.err.log` in the data dir | the user journal (`journalctl --user -u collied`) |

- For the data dir, attachments root and unit path, an unset, empty or relative `XDG_*_HOME` is ignored, as the XDG spec says. The herdr resolver, like herdr, takes `XDG_CONFIG_HOME` as given.
- The data dir holds `collied.toml`, `tsnet/`, `tls-key.json`, `peers.json`, `peers.lock`, `push.json`, `status.json`, `stars.json`, `pr-watches.json`, `pr-wakes.json`, `archive-on-merge.json`, `usage.json`, `usage.lock`, `usage-costs.json`, `audit.log`, `control.sock`, `node.lock` and `apns/`. `status.json` (when collied first saw each agent's status) is replaced atomically, 0600, without `sync_all` (a full drive flush on macOS), so a power cut can reset those times.
- herdr socket, same resolver on both OSes: `[herdr] session`, else `HERDR_SOCKET_PATH`, else `HERDR_SESSION`; then `$XDG_CONFIG_HOME/herdr[/sessions/<name>]/herdr.sock`, else `~/.config/herdr/...`. Verified: herdr 0.9.3 on Linux puts its socket at `$XDG_CONFIG_HOME/herdr/herdr.sock` (mode 0600), not under `XDG_RUNTIME_DIR`.
- tsnet creates an empty `~/.local/share/tailscale` (0700) for a non-root user; collied keeps its node state only in `<data dir>/tsnet`. A system tailscaled (root, `/var/lib/tailscale`) is untouched: the embedded node is a separate device with its own keys.

### Embedded node ownership

Both OSes apply the same user-owned node rules; doctor fails on a tagged node. Neither daemon calls the native Tailscale CLI, changes system routes or reads the system VPN's account or state.

The phone records the verified positive embedded Tailscale user in `machines.json`; pairing, reconnects and one-shot background approval and list sessions require its current self user, the machine's netmap owner and a fresh whois to match it ([tailnet.md](tailnet.md#pairing-and-connection-authorization)). A zero owner pin needs explicit re-pairing, never inference from a new login, and a `machines.json` missing a field is set aside, so its machines pair again. `kind`, from netmap OS metadata at pairing, is presentation only and never changes on reconnect.

### systemd user unit

`collied service install` makes the data dir private, writes the unit with the canonical executable and `--config` paths (0644, through `collied.service.tmp` and a rename), runs `daemon-reload`, checks that the user manager loads the unit from that file (`FragmentPath`), then runs `enable` and `restart`. Another unit of that name, or another `XDG_CONFIG_HOME` in the manager, fails the install there (the written file stays), so it never reports success for a unit that never starts.

```ini

[Unit]
Description=collie daemon: herdr agents over the tailnet
Documentation=https://github.com/rbstp/collie
StartLimitIntervalSec=0

[Service]
Type=exec
ExecStart="<exe>" "--config" "<config>" "run"
Environment="XDG_DATA_HOME=<dir>"
Environment="XDG_CACHE_HOME=<dir>"
Environment="XDG_CONFIG_HOME=<dir>"
Restart=always
RestartSec=2s
RestartSteps=5
RestartMaxDelaySec=1min
UMask=0077
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectSystem=strict
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectKernelLogs=yes
ProtectControlGroups=yes
ProtectClock=yes
ProtectHostname=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
RestrictNamespaces=yes
```

The `--config` pair appears only when `--config` was given. No `User=`, no socket activation, no listener.

**Quoting** follows systemd.syntax; a test checks it with `systemd-analyze --user verify` where systemd-analyze and a user manager exist:

| Field | Rule |
|---|---|
| `ExecStart=` executable | absolute UTF-8 path with no `"`, `'` or `\`, else install refuses; quoted, `%` doubled (systemd does not expand `$` there) |
| `ExecStart=` arguments | quoted; `\` and `"` escaped; `%` and `$` doubled |
| `Environment=` | the whole `KEY=value` quoted; `\` and `"` escaped; `%` doubled (`$` is literal there) |
| every field | control characters and non-UTF-8 paths are refused |

**Pinned XDG.** Units the user manager starts (at first login, or at boot with linger) do not get the session's `XDG_*_HOME` (verified on the dev machine), so the unit pins all three to what the installing CLI resolved, fallbacks included; otherwise the daemon could use another data dir (control socket, peers), attachments root and herdr socket than the CLI. As with launchd, `HERDR_*` is not captured: `[herdr] session` in `collied.toml` picks a session.

**Restart** gives launchd's KeepAlive without a hot loop: the delay grows from 2 s to 1 min, and systemd never gives up. collied exits when the tailnet listener fails for good, so the manager restarts it.

**Sandboxing** is best effort: in a user manager most of these settings need unprivileged user namespaces, and systemd skips them without those. `ProtectSystem=strict` leaves the home directory and `/run/user` writable in a user unit. `UMask=0077` always applies.

| Command | `systemctl --user` |
|---|---|
| `collied stop` | `disable --now`, then `reset-failed`: off across logouts and reboots until `collied start`; the unit file stays |
| `collied start` | `enable`, then `start` unless already active |
| `collied service uninstall` | `disable --now` (when the file exists), remove the file, `daemon-reload`, `reset-failed`; refuses when the unit runs but its file is not at that path |

- `collied stop` and `collied start` fail when the unit file is not installed.
- A user unit runs while the user has a session; `loginctl enable-linger` keeps it running without one. The launchd agent likewise runs only in the GUI session.
- `just collied-install` on Linux builds in release, copies the binary to `~/.cargo/bin/collied` as a fresh inode (the running daemon keeps its copy until it restarts) and restarts the unit if it is active.

### Kernel TCP listener check

`tailnet::kernel_tcp_listeners(pid)` lists the kernel TCP sockets in LISTEN state that a live process (checked with signal 0) holds, for doctor's `listen` line and tests. It never reports an error as an empty list.

- macOS: `/usr/sbin/lsof`. Any stderr except exact copies of lsof's three-line warning for a mount point it cannot stat() (disk images under the temp folder; it never touches socket rows), or an exit other than 0 or 1, is an error.
- Linux: the inodes of the `socket:[N]` links in `/proc/<pid>/fd`, matched against the LISTEN rows (state `0A`) of `/proc/<pid>/net/tcp` and `tcp6` after a header check. It skips an fd closed during the listing, and a missing `tcp6` table without an IPv6 stack (no `/proc/sys/net/ipv6`); any other read or parse error is an error.

### APNs key on Linux

Each machine has its own APNs key and key ID, revoked on its own, so a Linux machine pushes while the Mac is off. The default store is `key = "systemd-creds"` ([APNs](#apns)).

- The credential `<data dir>/apns/<KEY_ID>.cred` is named `collied-apns-<KEY_ID>`, and the name is sealed in it, so a credential renamed or copied for another key ID does not decrypt. collied always passes the name: an empty or missing one skips systemd's check of the sealed name.
- collied runs `systemd-creds --user --no-ask-password {encrypt|decrypt} --name=collied-apns-<KEY_ID> - -` over stdin and stdout (at most 64 KiB each way), never through a file, and zeroizes the decrypted key after use. It runs `systemd-creds`, `systemctl`, `systemd-analyze`, `loginctl` and `journalctl` by absolute path (`/usr/bin`, else `/bin`, else `/run/current-system/sw/bin`), never from `PATH`.
- The credential file gets the `key_path` checks (0600 regular file owned by the user, opened with `O_NOFOLLOW`). The daemon, `collied apns test` and doctor decrypt it each time they load the key.

`collied apns import AuthKey_<ID>.p8` makes the macOS checks except the signature check, then writes the credential itself (0600, `O_NOFOLLOW`, atomic), since systemd-creds would write its output file with the umask's mode. It checks that the new credential decrypts to the key before storing it and after reading it back. An existing credential with the same key is kept unless only the new one has a TPM2 seal; one that no longer decrypts, or holds another key, fails the import. Import then rewrites `[apns]` to `key = "systemd-creds"` (the default, so nothing to rewrite without a key line) and asks y/N to delete the original file, only if it is still the same inode.

Where systemd-creds cannot encrypt (no systemd, no `systemd-creds.socket`, systemd older than 256, a container), import says so, copies the key to a 0600 `<data dir>/apns/AuthKey_<KEY_ID>.p8` (an existing file there must hold the same key and is kept), points `key_path` at it and offers the same delete, unless the imported file is that copy. If `<KEY_ID>.cred` already exists, a failed encrypt fails the import instead: it never falls back to a plaintext file.

**Seal.** An unprivileged caller cannot choose the key with `--with-key`: systemd's varlink service (`io.systemd.Credentials`, behind `systemd-creds.socket`) seals with the host key plus the TPM2 when one is usable, else the host key alone, and silently falls back to the host key alone if TPM2 sealing fails. So collied reads the seal from the credential header, whose first 16 bytes after base64 decoding are the key type id (ids from systemd `src/shared/creds-util.h`, v261 and main). The first encrypt on a machine makes systemd create `/var/lib/systemd/credential.secret` (root, 0400). The credential stops decrypting after an OS reinstall, a machine-id change, a uid or user name change, or a restore to another machine: import again from the backup.

**Doctor** on Linux has no `codesign` line. Its `apns` line:

| State | Result |
|---|---|
| credential, host key | ok, "host key only (no usable TPM2)"; warn when `systemd-analyze has-tpm2` finds a usable TPM2 (import again to bind it) |
| credential, host key and TPM2 | ok, "host key and TPM2" |
| credential, TPM2 only | ok, "TPM2" |
| credential, null key | fail, "null key, not encrypted" (integrity only) |
| credential, unrecognized seal | warn, "unrecognized seal" |
| credential missing or not decrypting | fail |
| `key_path`, systemd-creds works | warn: encrypt it with `collied apns import` |
| `key_path`, systemd-creds unavailable | ok: "0600 file fallback (systemd-creds unavailable): protected by its mode only" |

Only with `key_path` does doctor probe systemd-creds, by encrypting and decrypting a test value named `collied-apns-doctor-probe` (on a machine with no credential yet, that first encrypt creates the host secret). As on macOS, doctor also signs a provider token as a dry run and warns about any other `.p8` in `<data dir>/apns`.

**Storage difference.** Other unprivileged users cannot decrypt the credential, but any same-UID process can, without a prompt: no Keychain-style ACL binds it to collied. So same-UID malware on Linux can read the key, not only use collied to send pushes, and the 0600 fallback is protected by its mode only ([threat-model.md](threat-model.md#apns-key-storage-on-linux)).

### `collied status`

On both OSes, `collied status` also prints `tags:` (`(none)`, or `(not reported)` when the node status failed) and, when herdr answers, `agents: N` and one terminal-escaped line per agent (status, name or kind, workspace label, `terminal_id`), mapped from the daemon's herdr `session.snapshot` as for `flock.snapshot`, herdr-core agents included. With a herdr-core socket resolved, it also prints `herdr-core:` with the core's version and generation (or `not running`), the socket, its folder's mode and any method the core lacks ([herdr-core](#herdr-core-herdr-2)). A flock too large for one control line prints `too many to list here`, so the status request, also the liveness probe, never fails on a large session. The reply's `tags`, `flock`, `flock_too_large` and `herdr_core` have serde defaults, so a newer CLI reads an older daemon's reply.

## Client runtime

- collie-core runs one connection supervisor per paired machine, each with its own backoff, request queue and link state, so a machine that is off affects only its own section.
  - Backoff 3, 4, 8, 16, 30, 60 s, reset after 30 s connected. While the phone's tailnet is offline it re-checks every 3 s, and at once when the node first reaches Running.
  - An auth failure stops the link until the next resume or manual retry. Only a known, wrong self identity is a self-ownership failure: a tagged self node, a user other than the paired owner, an own-address whois naming another node or user, or a self node with a positive user and StableID but no Tailscale address. A self node without a positive user or StableID, or a failing own-address whois (after a suspend, a restarted node answers "peer not found" from its netmap disk cache until control sends the live map), is retried like a failed status call.
  - A protocol version mismatch also stops the link, naming the side to update (collied sends its version in `unsupported_protocol`); requests fail at once with that message until the next resume or manual retry, so an update needs no new pairing.
  - A machine the netmap reports offline is `Unavailable` and not dialed, since a 20 s dial to a dead peer occupies the node all machines share. It is re-checked locally after 3, 6, 12, then every 15 s (every 3 s for 30 s after a resume, and from 3 s again after any other outcome), and dialed once online or every 15 min in case control is wrong. Pairing, lock-screen decisions and each resume or manual retry dial once regardless, since the netmap can be stale after a resume; an attempt that ends before the dial (failed status call, phone key not loaded) keeps that dial.
  - A session that receives nothing for 45 s (collied pings every 15 s) reconnects, so a machine that slept or lost power does not stay Connected.
  - Resume: after 10 s or more in the background the link reconnects at once (iOS suspends sockets without a close); a shorter gap gets a 3 s probe. A resume restarts the normal backoff and dials an `Unavailable` link at once. For 10 s after it, failures (the old session's close, a node rebuilding its paths or not yet running) retry after 0.5, 1, then 2 s, the link staying Connecting with no error; a failure from just before the resume is retried at once, and auth failures still stop. A snapshot request cut off by the reconnect answers from the cache.
- Manual retry (`reconnect(machine_id)`): pull to refresh on the Agents list retries every machine, a tap on a machine's header that one. A live session gets the 3 s probe; any other link is dialed at once, past the offline flag.
- Offline reason: a link that is not connected carries an `OfflineReason` on `MachineFlock`, the sentence under its pill, classified from what each attempt already reads, with no extra polling:

  | Link | Cause | The reason says |
  |---|---|---|
  | `Offline` | the phone's node is not `Running` or not started | the phone is not connected to Tailscale |
  | `Unavailable` | the netmap reports the machine offline | the machine is asleep or off, last seen at its `LastSeen` when set (not Go's zero time) |
  | `Waiting` | the machine is online and the dial is refused (`connection was refused`) or times out (`context deadline exceeded`) | collied is not answering: run `collied start` there |
  | `Waiting` | any other dial error, including a dial forced past the offline flag | the phone cannot reach the machine |

  TLS, pin, hello and version failures carry no reason and keep their own messages. The classifier reads libtailscale's error text, which a concurrent failure on the same node can replace (`check_unlocked` in the tailnet crate), so a reason can name another dial's cause, and a machine that just powered off can read as not answering until control marks it offline. The reason clears when the link moves back to Connecting. Debug terminal demos show these errors with `COLLIE_DEMO_CONNECTION_ERROR`.
- The Agents tab reads the core's cache every 3 s (`agent.status` events keep it current), and every 0.25 s while a machine waits for a dial, its first list or, in the tab's first 20 s, the node. It asks connected machines for `flock.snapshot` when it appears, on pull to refresh, after a close and every 60 s, which covers shells (no event lists them). When reconcile first finds herdr unreachable, collied sends `flock.changed`; the refetch's `herdr_unavailable` stays on the link's view until a snapshot works, so the list shows the outage and asks again every 3 s.
- Node recovery, for paths that died while the app was suspended: on cellular, carrier NATs silently drop idle UDP mappings and TCP state, so the home DERP connection looks open until its 120 s read deadline. On any network iOS can defunct the node's UDP sockets, ending wireguard-go's receive loop for them (health "The MagicSock function ReceiveIPv4 is not running"); a rebind replaces the sockets but not the loop, so only DERP works until a restart.
  - Rebind (`tailscale_rebind`) when no machine is connected 3 s after a resume from a suspend or 10 s or more in the background. Not sooner: a dial in flight during a rebind can stall for its whole 5 s attempt, and a healthy reconnect takes well under 3 s.
  - Restart when no machine has connected 10 s after the resume while the node reports Running and a machine still dialing or failing is online (or the node cannot report status), and on a manual retry while dials fail. The old node is closed once only dial attempts hold it (a lock-screen decide holds it until answered), which fails a dial in flight at once; a new node starts from the same state and every link redials, showing connecting rather than an error. Measured with the phone on the Mac's Wi-Fi: every reconnect that came at all did so within 7 s of the resume, rebind included, while a node the rebind did not help stayed unreachable until a restart or relaunch, which connected within seconds.
  - Immediate restart, without the rebind or the 10 s wait, of a node with the receive-loop warning: when a dial to a machine Tailscale reports online had already failed on it before the resume and nothing is connected, or when such a dial fails past the resume grace in the foreground. Measured on Wi-Fi: most resumes with the warning still connected within a second through DERP, but once a dial to the online Mac had failed, nothing connected until a restart, and with a 10 s wait on each resume a short visit never got there.
  - Queued requests wait for the new node. The old node is put back if a machine connects meanwhile (no session is cut) or the app is suspended (a waiting lock-screen decide then gets it at once); a restart of a node another restart already replaced does nothing. Holding the node-start lock, a restart hands a waiting lock-screen decide the new node and never lets two nodes share the state dir. A new node that cannot start is retried at once, then on the next resume or manual retry.
- Network changes: the app reports the interface `NWPathMonitor` routes through (never a VPN tunnel; empty with no path) with `network_changed`, the first report only recorded. A move to another interface, or back after no path, that holds 1 s (paths flap at the edge of Wi-Fi) rebinds the node. A live session gets the 3 s probe, redialing only if it fails, since its TCP runs inside the node and can survive the move, but iOS reports no error when it does not. Other links redial past the offline flag with the resume grace. If nothing connects within 15 s (three dial attempts) while the node reports Running and a machine still dialing or failing is online, the node restarts as above; that check, like the 10 s one after a resume, is dropped once the path changed or a resume came, and restarts only the node its flow started with. A move reported while the core is suspended rebinds at once, for lock-screen decides; the redial waits for the resume. A Wi-Fi network replaced by another on the same interface without a gap is not a move.
- Diagnostics: each resume logs one line (subsystem `dev.rbstp.collie`, category `core`) with the node's state and health warnings and, per machine, the link phase, last dial, last error and netmap online state. Path changes, rebinds and restarts are logged with reason, outcome and timings. No keys, tokens or nonces.
- Snapshot plus sequence: `flock.snapshot` returns the `seq` it reflects; every event frame carries `seq`; the client drops `seq <= last applied`; unknown events still advance the cursor.
- Mutations are never replayed automatically, except a prompt to an unreachable machine: up to 5 attempts a minute apart (at once when the link reconnects while its agent screen is open), none later than 270 s after the first.
  - The app holds one such prompt per agent, in memory only: resends outlive the screen but not the app process or the machine's removal. Editing it, tapping its spinner, the agent exiting or another prompt from that screen stops it (the new one waits for any attempt in flight). A prompt that never arrived and that no screen shows returns to the agent's saved draft with a one-time "may not have been sent" note. Not detected: a new agent started in the same pane before the resend would receive it.
  - Each retry is `resend_prompt`, which collie-core sends only under the `op_id` an unanswered identical prompt still holds (300 s of wall time from its first send; collie-core reports `Unreachable` only while it holds it), and otherwise refuses with `NotResent`; only the user's Send mints an `op_id`. collied replays an attempt that arrived instead of typing the prompt twice, but its outcome cache lives in memory for 600 s, so a collied restart forgets the `op_id`. Before each retry the phone therefore treats the prompt as sent when the agent's last prompt, read with the link up, changed to its first line.
- Lock-screen approve and deny over an authenticated tailnet session ([Lock-screen approval](#lock-screen-approval)) has no prior art, and its timings still need measuring on device.

| libtailscale has no git tags and lags tailscale.com releases | security updates can be ours to carry | pin SHA + patch series; track upstream (0.2.0 at `d1dc45d`) |

| Suspend/resume leaves stale DERP/magicsock state | slow reconnects | redial, rebind and node restart on resume ([Client runtime](#client-runtime)) |
| Wi-Fi to cellular leaves the node bound to the old interface | no reconnect until a relaunch | `NWPathMonitor` drives a rebind with a netmon refresh, redials and a node restart ([Client runtime](#client-runtime)) |
| herdr server load (status entry polls `pane.get` every 100 ms) | CPU with many panes | measure; fall back to `agent.list` polling if needed |

## Release sample workspace

Welcome and Settings open a clearly labeled, bundled sample workspace, in Release builds too. Its synthetic in-memory core implements the agent and approval interfaces with no daemon, relay, pairing or network client; prompts, terminal input and decisions append visible local results. Reset replaces the sample session; Exit dismisses it. Its authenticator is private to the view that builds this core; real approvals keep device-owner authentication. The sample creates no Live Activities or push registrations, disables New task, and never persists or prunes real preferences, drafts, viewed changes, inbox markers, snoozes or layout order. Arbitrary fixture files, developer launch flags and screenshot environment overrides stay Debug-only. No version bump: the sample uses no wire protocol.

## Desktop distribution

Desktop releases (collied for macOS and Linux, CollieBar, CollieTray) share the TestFlight version tag and exact source commit. TestFlight, or a protected manual run, dispatches the desktop workflow from master, as the master-only signing environment requires. One publisher owns each release: it rejects moved tags and mismatched source markers, keeps already uploaded signed packages when a draft is retried, and verifies a completed release without replacing its assets.

The publisher and the installer check the macOS daemon's strict signature and notarization online. The installer, which only the user runs, copies the daemon to `~/.cargo/bin/collied` and changes only the executable of an existing launchd plist or systemd unit; Linux packages may own `/usr/bin/collied` instead. Package operations run no root hooks against user homes or sessions. [Desktop release downloads](desktop-releases.md) covers assets, platform floors, installation, AUR adoption, release controls and validation. No protocol change or version bump.

## Push relay

The Worker and D1 implementation under `relay/` provides a bounded authenticated send contract, fixed topics, deterministic provider JWTs and atomic indexed installation and global quotas. Released builds deliver through the production relay, whose hourly Cron trigger runs its bounded retention cleanup. [relay.md](relay.md) has the contract, local measurements and retention bound. No version bump: no phone or daemon wire type changes.

## Attested push control validation

The relay authenticates installation enrollment with Apple App Attest, and later operations with assertions over a stateless five-minute HMAC challenge bound to the operation, exact destination, pairing, installation, environment and prior counter and epoch. One D1 transaction advances the replay and control counters and changes routes; a conditional zero-row update alone never authorizes a route. Every send checks registered generations and revocation epochs, and an APNs expired or unregistered destination revokes only the matching generation and destination. The phone enrolls only for a paired daemon that reports relay mode through the negotiated capabilities, so direct senders never trigger enrollment. [relay.md](relay.md#attested-control-contract) has the contract, the client's rules, limits, renewal and retention. No version bump: optional `relay_grant` registration fields are sent only with the implemented `relay_grants_v1` and `encrypted_display_v1` capabilities, the optional server-to-phone hello `push_mode` is omitted without relay negotiation, revision 26 remains the codec, and older peers never receive new request fields.

The isolated Free-plan benchmark failed the CPU gate for full App Attest verification, so production runs on Workers Paid with the single internal crypto actor and a provisional shared 250 ms CPU ceiling ([validation report](reviews/relay-free-tier.md)).

## Internal relay crypto prototype

Apple verification and APNs signing run in one internal SQLite Durable Object, with no public HTTP handler, separate from the public HTTP policy and D1 state ([relay.md](relay.md#internal-crypto-prototype)). Missing or exhausted compute fails closed, with no inline fallback. Shared per-location control and enrollment admission limits repeated verification from rotating sources but is not a global spending cap, and local real-actor tests do not establish deployed Free-plan viability. No version bump: the public relay and phone-daemon wire contracts are unchanged.

## Simulator relay isolation

The local Simulator relay ([simulator.md](simulator.md)) provisions a software P-256 identity into a private local D1 and a DEBUG Simulator container, through a separate entry that refuses enrollment and fixes sandbox APNs. Everything after it uses the production validators and, in a Miniflare harness, the production `RelayCrypto` class. Production has no local key, local send secret, synthetic enrollment verifier or unsupported-attestation fallback; its Worker graph excludes `relay/dev`, and a separately seeded development database never counts as evidence of production trust. Only DEBUG Simulator builds include the Swift identity import, mock destinations and the exact loopback ATS exception, and only debug-assertion builds include the daemon's loopback sender switch; Release uses the fixed HTTPS publisher endpoint. No protocol change or version bump.

## Isolated VM and Simulator tailnet

The [VM procedure](vm-simulator.md) runs the Debug daemon in an owned macOS guest and the Debug iOS Simulator on the host. An account-free testcontrol server, DERP relay and mock publisher on host loopback reach guest loopback ports 8788 to 8790 through task-key SSH reverse forwards; each side runs its own STUN server on 8791. No owner Tailscale account, APNs key, home directory or Keychain enters the guest.

`COLLIE_VM_TEST=1` works only in Debug macOS and Debug iOS Simulator Rust builds. It requires a private `collie-vm-test` directory and a bounded private, non-symlink `vm-tailnet.json` with a synthetic test auth key, fixes the control URL at `http://127.0.0.1:8789`, and selects a separate data directory, state folder and Keychain namespace. The Simulator checks the Debug capability symbol before initialization, so a Release-profile core fails closed. Pairing pins, mutual TLS, owner checks, registration and relay proofs run their normal code, and the harness confirms only its expected candidate at the daemon's ordinary prompt. Release and physical-device artifacts exclude the test entry. No protocol change or version bump.
