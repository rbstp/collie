# collie architecture 🐑

```
iPhone (Collie.app)                                   Mac (or Linux)
┌───────────────────────────────┐                     ┌──────────────────────────────────────┐
│ SwiftUI (Swift 6, UI only)    │                     │ collied (launchd agent, user)        │
│  └ CollieCore (UniFFI)        │   tailnet (WG)      │  ├ tailnet node (user-owned)         │
│     ├ protocol codec          │ ── WebSocket/JSON ─▶│  │   tailscale_listen :port only     │
│     └ tailnet node (libts)    │   dial only         │  ├ whois gate → paired node IDs      │
│ CollieWidgets  (Swift only)   │                     │  ├ protocol allowlist + audit log    │
│ ColliePush NSE (Swift only)   │◀── APNs ────────────│  ├ approvals (nonce, expiry, replay) │
└───────────────────────────────┘                     │  ├ APNs client (Keychain .p8, HTTP/2)│
                                                      │  └ herdr client ─▶ herdr.sock (0600) │
                                                      └──────────────────────────────────────┘
```

On Linux, collied is a systemd user unit ([Linux](#linux)).

## Decisions (2026-10-03)

- Phone and computer run independent embedded nodes owned by the same personal Tailscale user. Authorization checks the node's own positive owner, a same-user untagged and unshared whois, the paired StableID and independent TLS key pins. Neither needs an OS VPN profile or the native Tailscale client; the Mac's corporate VPN is separate.
- libtailscale: upstream submodule pinned by SHA, plus a patch series in `crates/tailscale-sys/patches`.
- XcodeGen generates the iOS project from `Collie/project.yml`; `.xcodeproj` is not checked in.
- APNs display content (alert titles, bodies and approval context; initial, update and end Live Activity labels and state) is authenticated ciphertext under each phone's per-machine notification key. Public alerts stay generic. Approval nonces never enter a push.
- macOS: arm64 only.
- 2026-10-04: collied also runs on Linux. x86_64 is built and tested; aarch64 is mapped in `tailscale-sys` but not built or tested. Any other OS is a compile error.
- 2026-10-04: on Linux the service is a systemd user unit with the launchd agent's semantics: kept alive, and `collied stop` keeps it off across reboots until `collied start`.
- 2026-10-04: each machine sends its own pushes with its own APNs key (own key ID, revoked on its own). On Linux the key is a systemd user credential (host key, plus the TPM2 when systemd finds one usable), or a 0600 file when systemd-creds is unavailable.
- 2026-10-06: plain shell panes from the phone ([Terminals](#terminals)): off by default, turned on per machine only in `collied.toml`, never from the phone; their own allowlist class, audited like prompts. Opening one and typing into it need a grant collied verifies, signed by a second Secure Enclave key that signs only after Face ID or the passcode; one grant covers one terminal for 5 minutes in one session.
- 2026-10-16: user-owned embedded desktop nodes replace the per-OS tagged identities. Existing tagged nodes and old phone owner pins need an explicit reset and re-pairing; nothing is migrated or retagged. Normal user key expiry applies on both ends. No version bump: no phone wire type changed; the positive owner pin is local persistence and the OS is netmap presentation metadata.

## herdr integration (verified against 0.9.3 source and live socket)

- The socket answers **one request per connection** (NDJSON, 5 s timeouts, 1 MiB line), so collied opens a connection per call; long calls (`events.subscribe`, waits) get their own.
- herdr has **no auth**: same-UID means full control. collied's allowlist is the only boundary between the phone and every shell on the machine.
- **No global agent-status stream**: `pane.agent_status_changed` is per pane, and `pane.updated` ignores status. collied keeps one subscription (lifecycle events plus a status entry per agent pane), rebuilt on `pane.created/closed/moved/exited/agent_detected`, `workspace.closed` and `events_lost` because an entry for a vanished pane goes silent; a 1 s `agent.list` reconcile plus `ping` covers silent streams. It sends `agent.status` when an agent's `state_change_seq`, status, title, name, kind or cwd changes, or, while a phone has a session open, its transcript values ([below](#context-and-inbox)), and `flock.changed` when agents come, go or change workspace, or a workspace is renamed or renumbered.
- Agents are keyed by `terminal_id`; `pane_id` changes on cross-workspace moves and never reaches the phone. Statuses: `idle | working | blocked | done | unknown`.
- With no phone session connected, a status change reads no transcript and builds no event; status times, pane cleanup, approvals, done alerts, followed Live Activities, Tailscale upkeep and APNs carry on. A connection lost without a close frame ends at the 45 s silence limit (collied pings every 15 s).
- **No output stream** in the JSON API. During `agent.watch`, collied polls `agent.read {source: recent_unwrapped, lines, format: ansi}` at 4 Hz (1 Hz after 5 s without a change) and pushes only changes. The phone's `lines` is clamped to 1 to 1000, 200 when absent. In Low Data Mode (`NWPath.isConstrained`) the phone sends `low_data: true` on `agent.watch` and `terminal.watch`, and collied polls that watch at 1 Hz throughout; `low_data` can only slow a watch.
  - The first push of a watch is a full `agent.output`; later ones are `agent.output_patch {terminal_id, base, head, skip, keep, tail, trail, truncated}` when that carries at most half the text. The new text is, joined with `\n`: the `head` lines, lines `skip..skip + keep` of the previous text, the `tail` lines, then the last `trail` lines of the previous text, starting at or after `skip + keep`. A Claude Code spinner tick then costs a few hundred bytes. `base` is the 64-bit FNV-1a of the previous text; collie-core applies a patch only to the text its watch delivered last and only when `base` matches, else it re-issues `agent.watch`.
  - The phone sends its Scrollback setting with `agent.watch` and `recent` reads. It renders at most 2000 rows and, without wrapping, 500 columns. In wrap mode it drops the oldest lines that would not fit and breaks a line after the last space that fits, continuing at the line's indent or past a leading symbol such as `⏺`; each break is a NEL, so selection, copy and links read the line whole.
  - Claude Code's fullscreen mode (`"tui": "fullscreen"`) draws in the alternate screen and keeps its own transcript, so the pane has no scrollback and an ANSI read returns only visible rows.
  - Reads and changed watch output drop Copilot's terminal-cell scrollbar, a trailing `┃` set off by a space: at the column that repeated, separately styled scrollbar cells outside boxes give (Copilot 1.0.100-1 can draw it one column inside the width herdr reports), else at the pane width. A `┃` in a row with box drawing stays unless styled apart. Wrap detection runs on the original rows. No version bump: only read normalization changes.
  - Copilot's `wraps` and `splits` (as for Claude Code, below) cover its prose under `●` and its sent prompts, shaded `▄`-to-`▀` boxes whose text wraps at the box's width before an `HH:MM` timestamp. A row joins the next only where Copilot certainly broke it after a word: it ends with one space in the text's style and the next word would not have fit. Any other row stays, since a typed newline looks the same.
  - Claude Code wraps its prose at the pane width with real line ends, which `recent_unwrapped` cannot undo, so for a Claude Code agent `agent.read` and each changed watch push list the rows that continue a paragraph wrapped at the layout width: `wraps` (after a space) and `splits` (inside a word), on `TerminalRead` and, when they changed, on `agent.output_patch`. With line wrapping on, the phone joins those rows and rewraps at its own width.
    - Width: the widest all-`─` row from column 0 that is no wider than the pane (the input box's rules, drawn at exactly the terminal width), else herdr's `pane.layout` width, which is 1 to 3 columns wider than the terminal (1 for a single pane, 2 or 3 in a split): enough to read a soft wrap as a typed newline. A zoomed tab, or no width from herdr, joins nothing.
    - Rows that count: prose under an indent-0 `⏺` or `※` row at exactly the hang of the row above (numbered items also at the number's indent, as Claude Code 2.1.303 continues them across blank rows), and a shaded sent prompt's rows, wrapped 3 columns short of the terminal width, after a row ending with a space in the text's style where the next word would not have fit. Never list items, tool calls and their output, box and table rows, the input box or the status line. Wide characters cut one column short of the edge split only inside a word longer than a row, so Korean words keep their spaces.
    - Claude Code's true black background (a standalone `48;2;0;0;0`, used by its logo) becomes the default background, so it does not show as black cells on the phone.
  - Codex's `wraps` and `splits` (prose under `•`, sent prompts under `›`) take the width of the widest blank row shaded from column 0 that is no wider than the pane (Codex pads its composer and sent prompt boxes to exactly the terminal width), else the `pane.layout` width, 1 to 3 columns too wide here as well (codex-cli 0.163.0 and herdr 0.9.5: 205 columns for a 206-column rect, 101 and 100 for two 103-column split panes).
- herdr's `agent.prompt` refuses blocked agents; its `agent.send_keys` does not. collied also rejects `agent.prompt` for an agent it sees as `blocked`, re-read with `agent.get` just before the call. Manual input to a blocked agent goes through `agent.send_keys` and `agent.type_text` ([Prompts without decisions](#prompts-without-decisions)).
- **Scrolled-up Claude Code.** While Claude Code's fullscreen transcript is scrolled up on the machine, a permission prompt scrolls out of view and herdr reports the agent idle, so keys would answer it unseen. collied refuses `agent.send_keys`, `agent.type_text` and `agent.prompt` to a Claude Code agent that is not blocked (`agent_not_ready`) when the visible screen, read just before the write, shows the "Jump to bottom" or "N new messages" banner. `protocol::jump_banner` matches it as Claude Code draws it, a space-padded label on an SGR background: its own background run (with or without its hint) or, as herdr writes no escape between it and same-style prompt text, label and hint centered on the row inside a run.
  - `agent.scroll_bottom {terminal_id}` (Drive class, audited, idempotent so no `op_id`) sends Ctrl+End as the fixed bytes `ESC[1;5F` through `pane.send_text` (herdr 0.9.3 has no key name for it), only to a ready or blocked `claude` agent while the banner shows; nothing from the phone becomes input. Ctrl+End never moves a dialog's selection; a prompt it brings back is `blocked` again with a new `state_change_seq`, so its approval is raised again. Meanwhile the phone offers a Jump to bottom button and disables the key strip.
  - Limits: background text quoting the padded banner (a prompt row or diff line) reads as scrolled up until it scrolls away. A banner without color (`FORCE_COLOR=0`) or in reverse video is not detected. A prompt that appears while already scrolled up is not `blocked`, so it raises no approval or notification until scrolled back down.
- **Claude Code notices.** Notices above Claude Code's input box (the "Heads up" tip, its Learn more explanation, the feedback row after a Dismiss, the session rating) take a single keypress, which a prompt cannot carry (herdr pastes it and ends it with Enter). `protocol::notice` reads any notice's options from the screen by one rule, not a list of known notices:
  - Options are rows indented two spaces whose cells all read `<digit>: <label>`: digits exactly 1 to n (n up to 4), then `0: Dismiss`; each label non-empty, at most 64 characters, with no control or format character and no `:`. Above them is the lead: a row starting at column 0 with `✦` (tips) or `●` (rating), which may carry the first options, then rows indented two spaces or blank. Below them, after at most three blank rows and right-aligned hint rows, is the input box: the last row starting at column 0 with `❯`, directly under the box's top rule (`─`, or a renamed session's `─── <title> ─`). A dialog replaces the box, so it never matches.
  - Transcript rows start with other glyphs (`⏺` reply on macOS, `❯` prompt, `✻` finished turn), so a reply in that shape does not match; on Linux Claude Code marks replies with `●` (see the threat model). When the lead holds a blank row, as an explanation's side-agent text does, the options must follow a blank row and sit directly on the box's top margin (or the blank rows above a hint), with no other blank row below them, since each card a side agent writes ends with a blank row. Anything else gives no options.
  - `agent.answer_notice {terminal_id, digit, label}` (Drive class, audited with the digit and label; no `op_id`, since a replay finds the notice gone) sends the digit alone through `pane.send_text`. collied sends it only to a ready `claude` agent (never `blocked`, where a digit could pick a permission option) with no banner, and only when the visible screen, read just before the write, lists that digit with that label directly above an empty input box (the dim placeholder counts as empty): notices reuse digits, and a digit must never land in a draft. It then holds the input box lock for up to 1 s, until the box shows something other than empty or the digit, since the option Claude Code runs 400 ms later can fill the box and a prompt pasted meanwhile would submit that fill.
  - The phone shows the options as buttons for a Claude Code agent that is not blocked or scrolled up, 600 ms after first seeing them (Claude Code ignores a digit typed sooner, leaving it in the box).
  - Option effects are Claude Code's: Chat in main session and feedback option 4 (`/plugin disable cc-plugin-you-should-know@builtin`) fill the box unsent (Claude Code would submit the note only with no input box, and collied answers only above an empty one), and Enter from the key strip is refused while the box starts with `/`; feedback options 1 to 3 log an event about the tip (enums and counts, never its text or the transcript). A Claude Code plugin whose band draws this shape is answered the same way, and its option's code runs (see the threat model). What follows a rating is answered on the machine.
- Prompt text rejects ESC and C0/C1 controls because herdr pastes it with bracketed paste.
- Residual race (herdr side): herdr checks the foreground agent before queuing the text and the delayed Enter, so if the agent exits in between, the shell receives the prompt. Closing it needs a conditional input in herdr (`expect: {terminal_id, state_change_seq, foreground pid}` on `agent.prompt` / `agent.send_keys`), to be proposed upstream.
- Mutations (`agent.prompt`, `agent.send_keys`, `agent.type_text`, `task.new`, `task.archive`, `terminal.run`, `terminal.send_keys`, `attachment.begin`, `attachment.commit`) carry a client `op_id`; collied keeps a per-peer outcome cache so a retry after a dropped connection returns the first result.
- **Task folders.** `task.options` also returns `roots`, the canonical `[tasks] roots`. `task.folders {path}` (Drive class, read-only so no `op_id`, audited with the path and count, never the names) lists the folders directly inside a folder under the roots. collied opens the canonical path one component at a time from its root with `openat(O_DIRECTORY | O_NOFOLLOW)`, so a folder swapped for a symlink after the check fails instead of leading outside, and refuses (`folder is hidden`) a path through a folder below the root that starts with a dot or, on macOS, carries `UF_HIDDEN`, such as `~/.ssh` or `~/Library`. Of at most 10,000 scanned entries it returns at most 500, sorted case-insensitively: valid `FolderName`s (1 to 255 bytes; no leading dot, `/`, `\`, control, format or invisible character, or surrounding whitespace) that are directories, or symlinks resolving to a directory under the roots, and on macOS not `UF_HIDDEN`. Nothing inside the folders is read.
  - `new_folder` on `task.new` (a `FolderName`) is created inside `cwd`, which is opened and refused when hidden the same way; a path reaching 1024 bytes is refused. collied runs `mkdirat(parent_fd, name, 0755)` (any existing entry, symlink included, is `folder already exists`) and checks that `<parent>/<name>` resolves under the roots to that folder (same device and inode) before starting the agent there; nothing else is created. The audit target is `<path> (created)`, else `<cwd> new_folder="<name>"`. The `op_id` covers the whole request, so a retry replays the first result. A failed start leaves the folder and says so.
  - Only the phone keeps the base folder, per machine (`taskBases` in `prefs.json`), as `task.folders` returned it, so a folder collied refuses is never stored; New Task completes names locally and sends `<base>/<name>`, which collied checks like any `cwd`.
- **Clone.** `clone` on `task.new` (a `CloneSource`, exclusive with `new_folder` and `worktree`) is `owner/repo` (GitHub), `https://host[:port]/path` or `git@host:path`, every path segment ASCII letters, digits, `.`, `_` or `-`, starting with neither `.` nor `-`. Both ends refuse any other transport, a local path, userinfo, a query, `..` or a leading `-` at parse time. collied creates the folder (the last segment without `.git`) inside `cwd` as for `new_folder`, then clones into it: `owner/repo` with `gh repo clone -- owner/repo <folder>` when `gh` is in `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` or `~/.local/bin`, otherwise (or when gh exits 4, not logged in, and left the folder empty) with `git clone -- https://github.com/owner/repo.git <folder>`; a URL with `git clone -- <url> <folder>`.
  - The child gets null stdin, `GIT_TERMINAL_PROMPT=0`, `GH_PROMPT_DISABLED=1`, none of collied's `GIT_*` variables, no `GH_TOKEN` or `GITHUB_TOKEN`, and, through `GIT_CONFIG_COUNT`, `protocol.allow=never` with only `https` and `ssh` allowed (`file`, `ext`, `git` and `http` denied explicitly), which outranks config files and survives a `url.<base>.insteadOf` rewrite. It runs in its own process group, killed 75 s after the first attempt or when dropped.
  - A failed clone returns the cleaned tail of git's stderr (at most 1000 bytes) and removes the folder if it is empty again. The audit target is `<cwd> clone="<source>"`, or `<folder> (cloned) clone="<source>"` after a successful clone, which stays if the agent then fails to start. The phone waits 165 s for the reply.
- **Pull request worktree.** `task.new`'s `worktree` can be `{"mode": "pull_request", "number": N}`, N from 1 to 2^32 - 1. collied lists the repository with herdr as for Create, then runs `gh pr view N --json headRefName,headRefOid,isCrossRepository` in its checkout, with the linked pull request read's `gh` and environment (30 s).
  - A pull request from a fork (`isCrossRepository`) is refused: its branch is someone else's code, and a project's agent settings in it would run on the machine. The untrusted head branch must pass the typed branch name rules (ASCII letters, digits, `/`, `.`, `_` and `-`, no `..`, no leading `-`, no trailing `/`, at most 255 bytes) and `git check-ref-format --branch`, the head commit must be 40 or 64 lowercase hex digits, and `.worktree/<branch with / as ->` must not exist.
  - collied fetches only that branch, with the clone's environment (`git fetch --no-tags --no-recurse-submodules --no-write-fetch-head origin -- +refs/heads/<branch>:refs/remotes/origin/<branch>`), checks that `origin/<branch>` is the head commit gh named (else `try again`), and creates a tracking branch unless the branch exists; an existing local branch at another commit refuses the task and is not moved. The task then continues as Create. The gh read, the checks and the fetch share one 75 s budget. The audit target is `<cwd> pull_request=<N>`; the phone waits 165 s for the reply.
- **Resume.** `task.sessions {cwd}` (Drive class, read-only so no `op_id`, audited with the path and count, never the prompts) lists up to 20 recent sessions of a folder under the roots, newest first, for the allowed kinds among `claude` and `codex`, leaving out sessions a herdr agent already reports as its `agent_session`.
  - Claude Code sessions are the `<uuid>.jsonl` files directly in `~/.claude/projects/<project dir of cwd>/`. Codex sessions are the rollouts under `$CODEX_HOME/sessions/YYYY/MM/DD/` (newest folders first, at most 10,000 listed; a plain `.jsonl` wins over its `.jsonl.zst`) whose first line is `session_meta` with that exact `cwd`, the file name's id and a `cli` or `vscode` source.
  - Only the 400 newest files of each kind are opened (`O_NOFOLLOW | O_NONBLOCK`), reading at most their first 256 KiB (a compressed rollout decodes with an 8 MiB window limit). Chat and the status readers read only plain rollouts: Codex decompresses a rollout before appending, so a live session is never compressed.
  - An entry has the kind, the session id (a lowercase UUID), the mtime and the first line of the first human prompt, cleaned and capped at 160 characters like `last_prompt`. A session whose head holds no complete prompt is listed with an empty one if the transcript is longer than the head, and left out otherwise. The prompt line goes to the phone only: never logged, audited or pushed.
  - `resume` on `task.new` (a `SessionId`, exclusive with `new_folder`, `worktree` and `clone`) makes `prompt` optional. collied refuses a kind other than `claude` or `codex`, a session whose transcript is not in that folder, and one a herdr agent already reports. It starts the agent with `args: ["--resume", <id>]` for Claude Code (2.1.296) or `["resume", <id>, "--no-daemon"]` for Codex (0.162.1); without a prompt nothing is typed and the startup dialog check is skipped. The audit target is `<cwd> resume=<id>`.
- **Ultracode.** `ultracode` on `task.new` (default false; refused for agents other than Claude Code) is the Ultracode switch of Claude Code's `/effort` picker, which Claude Code 2.1.299 also takes at launch as a session setting: collied adds `["--settings", "{\"ultracode\":true}"]` to `args` (after `--resume <id>` on a resume), which herdr 0.9.4 quotes for the shell. Claude Code leaves it off when unavailable (dynamic workflows off, or a model without it), so once the agent is ready collied waits up to 1 s for the input box's top rule to carry the `ultracode` tag (`─── ultracode ─`); otherwise the start fails with `agent_not_ready` ("ultracode could not be enabled; nothing was sent"), leaving the workspace open and the prompt unsent.
- **Agent kinds.** `[tasks] agents` in `collied.toml` defaults to `["claude", "codex", "copilot"]`. `task.options` offers those herdr has a manifest for (`server.agent_manifests`), the first as the default, and `task.new` refuses any other. herdr 0.9.5 starts each with `agent.start` and its canonical executable (a missing CLI fails the start, leaving the workspace open) and reads their state from its screen manifests (codex 2026.10.11.1, copilot 2026.08.29.1).
  - Codex: collied passes `--no-daemon`, so Codex's SessionStart hook inherits the launching pane's environment instead of a shared app-server's, keeping `/new` and resume reports bound to that pane. The hook (version 10, `herdr integration install codex`) reports only the session; `collied doctor` warns about a missing or older hook. Codex falls back to `unknown` when no rule matches, so a Codex agent that is `unknown` but `interactive_ready` counts as started.
  - A startup prompt (Codex's or Copilot's folder trust, Codex's update picker) fails the start with `agent_blocked`, to be answered in the terminal. herdr does not rule every one `blocked`, so before the prompt collied reads a Codex or Copilot agent's screen and fails the start the same way if it shows a numbered option (`❯`, `›` or no cursor) or folder trust wording, or cannot be read. For Codex's update picker, nothing is typed and the message ends "Codex is asking to update. Answer it in Terminal."
  - On macOS herdr refuses an `agent.start` whose launch line exceeds the terminal's canonical input limit while the shell starts (`agent_start_input_failed`); collied answers `too_large`, asking to wait for the prompt and try again.

## Tailscale (libtailscale, pinned commit, never tagged upstream)

- libtailscale `main@d1dc45d` (bindings 0.2.0, with the listener fd-passing fix 258321b) as a git submodule. Upstream pins tailscale.com v1.104.1; patch 0001 only raises its `go` directive to 1.27.3, and patch 0011 only raises tailscale.com to v1.104.2 in `go.mod` and `go.sum`, since no upstream commit uses it yet. Requires Go ≥ 1.27.3; builds use `GOTOOLCHAIN=local`, `-mod=vendor`, `-trimpath`, `-buildvcs=false`, `-ldflags=-w`.
- collie calls neither `tailscale_getremoteaddr`, which before 0.2.0 returned the wrong peer 17% of the time under concurrent fd churn in testing, nor `tailscale_loopback`, which would open a 127.0.0.1 TCP listener (SOCKS5 + LocalAPI) on the machine and which iOS reclaims on suspend. The series (patches 0002 to 0010):
  1. `tailscale_accept_with_addr` returns the peer `ip:port` from the record that carries the fd (upstream's holds the IP only). A per-listener lock keeps concurrent accepts from interleaving a record whose `MSG_WAITALL` read was cut short; the short-read path keeps the control message (upstream drops it and miscounts on `EINTR`); a failed accept closes any fd it received; an accept that waited for the lock re-checks that the listener is open. The tailnet end-to-end tests check each accepted address and whois against its dialer under concurrent accepts.
  2. `tailscale_whois_json(sd, addr)` via the in-memory LocalClient (as `tailscale_status_json`).
  3. Disable log upload to log.tailscale.com in Go (`TS_NO_LOGS_NO_SUPPORT`): a c-archive snapshots the environment at load, so a later `setenv` is invisible to Go.
  4. Guard the per-handle `lastErr` with a mutex (also where `getremoteaddr` sets it): upstream's unsynchronized write is a Go data race when one handle is used from several threads.
  5. Keep the Go copy of each accepted fd open until C has received it: macOS's unix-socket GC can dispose of a socket whose only reference is in flight, losing the peer's first bytes (reproduced at about 1 in 150 connections).
  6. `tailscale_dial_timeout` and `tailscale_set_advertise_tags`.
  7. Socketpair proxy: a non-blocking Go end so close always delivers EOF (a lost shutdown wakeup left readers hanging), shutdowns through `Control` so they never hit a reused fd number, cleanup once as soon as either direction ends (upstream waits for both), no fd-number-keyed map.
  8. `UserLogf` discarded: tsnet otherwise prints the interactive login URL to stderr every few seconds.
  9. Listener socket close waits for in-flight `sendmsg` (and item 5 sends each fd inside its `os.File` `Control`), so no fd number can be reused under a send.
  10. `tailscale_rebind(sd, default_if)`. iOS can defunct netmon's route socket while the app is suspended (XNU exempts only local and system sockets), and on iOS netmon has no time-jump check, so it never sees another change and the node keeps binding to the Wi-Fi interface the phone left. The call records `default_if` from NWPathMonitor (`netmon.UpdateLastKnownDefaultRouteInterface`, like Tailscale's own apps) so new sockets bind to it, injects a netmon event and waits up to 1.5 s for netmon to re-read the interfaces through a routing-table sysctl, not its route socket, and publish a move as a major link change (engine rebind, DERP reconnect, control connection closed), then runs the LocalAPI `rebind` and `restun` debug actions: magicsock re-binds its UDP sockets, reconnects any DERP connection that misses a 3 s ping, forgets the peers' direct paths and re-STUNs.
  11. `logtail.Disable()` next to `TS_NO_LOGS_NO_SUPPORT`: with uploads off, every log line was still written to the `tailscaled.log*.txt` buffer, read back and compressed. `crates/tailnet/tests/end_to_end.rs` asserts both files stay empty.
  12. `tailscale_close` first cancels a context every dial derives from: netstack's close aborts only the TCP endpoints registered when it starts and waits for later ones, so a racing dial held the close, and the node restart, up to its 5 s timeout. collie-core closes a replaced node while its dials are in flight.
- The iOS archive is built with `-tags=ios,ts_omit_portmapper`: no NAT-PMP, PCP or UPnP probes of the Wi-Fi gateway on every netcheck. collied keeps its port mapper, so a direct path to a phone behind a hard NAT can still form from the Mac's side.
- Vendored module patches (`patches/<import path>/<file>.patch`, applied after `go mod vendor`; go.sum still verifies every module):
  - tailscale.com `tsnet/tsnet.go`: with no advertised tags specified, keep the existing requests (read through the sanitized `LocalBackend.Prefs()` API before startup), so fresh nodes stay untagged and an old tagged node can be observed and rejected without removing its requests or forcing reauthentication. Explicit nonempty requests keep upstream behavior.
  - tailscale.com `ipn/ipnlocal/peerapi.go`: never open the kernel peerapi listener when netstack is present; upstream binds it to every interface in netstack mode, exposing a TCP port to the LAN. Tests and `collied doctor` check that no kernel TCP listener exists ([Kernel TCP listener check](#kernel-tcp-listener-check)).
  - gvisor `tcp/connect.go` + `stack/stack.go`: a SYN reusing a 4-tuple in TIME-WAIT goes to the forwarder instead of being dropped (the cause of a 63 s dial stall).
  - tailscale.com `wgengine/netstack/netstack.go`: close link queues before aborting endpoints so `tsnet.Server.Close` cannot hang.
  - tailscale.com `wgengine/magicsock/magicsock.go`: `TS_DEBUG_MAGICSOCK_BIND_LOOPBACK=1` binds the UDP sockets to 127.0.0.1 and ::1 instead of every interface. Only the tailnet tests set it (with `TS_DISABLE_PORTMAPPER`), so the macOS firewall never prompts for a new test binary; collied and the app leave it unset.
- Every patch applies with `patch --fuzz=0`: a hunk whose context lines changed fails the build, naming the patch; one whose context only moved still applies.
- Bumping: move the submodule, rebase the patches and review upstream's changes to the files they touch; redo a patch that no longer applies by hand, never force it. `crates/tailnet/testcontrol` must use the same tailscale.com as libtailscale's patched `go.mod` (`crates/tailscale-sys/tests/versions.rs` checks the build's copy). To run a newer tailscale.com than upstream pins, run `go get tailscale.com@vX.Y.Z` and `go mod tidy` in a copy of the submodule with the series applied, save the `go.mod`/`go.sum` diff as a patch and do the same in `testcontrol`; drop the patch once upstream pins that version or newer.
- Control sees Hostinfo `App` `libtailscale`, `Package` `tsnet`, `IPNVersion` `1.104.2-ERR-BuildInfo` (the suffix from `-buildvcs=false`) and `GoVersion`, but no libtailscale version, so it cannot tell 0.2.0 from an older one. What Tailscale keys its libtailscale notice on is unknown (collie's nodes were flagged while already reporting 1.104.1); stamping `-X tailscale.com/version.longStamp=...` and `shortStamp` waits on that answer.
- Gate per connection, before the WebSocket upgrade: whois(peer) must show an untagged node, not shared in, owned by the owner user. The owner is the daemon's verified positive embedded self user before listening; the optional `[tailnet] owner_user_id`, the persisted owner and every paired phone must agree, and a first pairing cannot choose or replace it. Then:
  - paired `StableID` with a pinned TLS key → full session (`hello` first, then the allowlist). While a pairing window is open, a paired phone's `pair.complete` goes through the same y/N confirmation as a new phone's and replaces its record, so a phone that removed the machine while it was unreachable pairs again without a revoke. A paired phone's `unpair`, which the app sends when it removes a connected machine, revokes it as `collied peers revoke` does: collied answers, then removes it, drops its push tokens and closes its sessions;
  - unpaired (or paired without a TLS key), while a locally opened pairing window is active → pairing-only session: `hello` and `pair.complete` only, one attempt, then close;
  - otherwise a fixed `403` without reading the request, close, and log; the phone treats 403 as final.
  - At most 4 live sessions per node: a fifth evicts that node's oldest, so a phone reconnecting after iOS killed its sockets is never locked out. Global cap 64. Revocation cancels in-flight replies and re-checks authorization before every frame.
- Phone: `tailscale_dial`s the IP of the Mac's pinned entry in its own netmap (`tailscale_status_json`) after the ownership and whois checks in [tailnet.md](tailnet.md#pairing-and-connection-authorization); no DNS lookup.
- `tailscale_up` blocks until Running and is not cancellable; collied drives its own state machine from `status_json` (`BackendState`, `AuthURL`) and always calls `tailscale_start` first.
- Accepted fds are AF_UNIX socketpairs: collied awaits the listener's readability with tokio's `AsyncFd`, accepts, and reads each fd as a non-blocking `tokio::net::UnixStream`.
- magicsock binds a UDP socket on real interfaces: that is the WireGuard tunnel itself and the one unavoidable non-tailnet socket. No TCP listener exists outside the tailnet.

## Mutual TLS

Inside the tunnel, after the whois gate and before the WebSocket upgrade: TLS 1.3 only, RFC 7250 raw public keys (no certificates), ECDSA P-256 with SHA-256 only, and no session resumption (it would skip the key check). Each side pins the other's key by the SHA-256 of its SubjectPublicKeyInfo (`KeyPin`, base64url); the shared verifiers are in `crates/tls`.

- collied makes its P-256 key on first start (`tls-key.json`, PKCS#8, 0600 in the data dir). Its pin is in the pairing QR (`k=`, invite `v=2`), and the phone keeps it as the machine's `key`. A new key means pairing every phone again.
- The phone's key is a non-exportable Secure Enclave key, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` so lock-screen decisions can connect. collie-core holds only its public key and asks the app to sign each handshake. The simulator uses a software key.
- A full session needs the phone's pinned key (`peers.json` `tls_key`). A pairing session takes any P-256 key, and confirming the pairing records it.
- A peer the gate rejects gets the fixed clear `403` before any TLS, so nothing from it is parsed; the phone recognizes it from the first bytes (`Sniff`) and stops retrying. A machine presenting another key is a pin violation, and collied refusing the phone's key reaches the phone on its first read as `KeyRefused` (TLS 1.3 checks the client after the client's side is done); both stop retrying and ask to pair again.
- After the handshake collied runs the gate again under the peers, pairing and sessions locks and refuses the connection on a different decision, such as a revoke, a pairing or the window closing during the handshake. The per-node session cap and the registration happen under those same locks.

## Negotiated protocol compatibility

Revision 26 is the first negotiated baseline; the floor is 26 (`PROTOCOL_MIN_VERSION`) and the ceiling 29 (`PROTOCOL_VERSION`). Revisions 3 through 25 used exact matching and have no retained codecs: update both peers once to reach the baseline; paired keys do not change.

`hello.protocol_version` offers the highest supported revision and the optional `protocol_min_version` the floor (absent: that one revision). The daemon selects the highest common revision and returns it as `protocol_version`, with its own `protocol_min_version` and `protocol_max_version` and the selected `capabilities`. It rejects a reversed or zero range, a duplicate capability, an unknown request field or a malformed parameter; an empty intersection closes the session with `unsupported_protocol`, the daemon's maximum and which side to update. The phone rejects a selection outside the common range or below the highest common revision, and capabilities it did not implement.

Omitted offer capabilities mean exactly the baseline set, currently `terminal_grants_v1`; `[]` opts out, and unknown names are ignored and never echoed. A baseline phone omits its singleton floor and baseline capabilities, so its hello has revision 25's fields and a strict revision-25 daemon refuses the version rather than a new field; nothing falls back or sends revision-25 operations. A wider offer sends its floor explicitly, which revision 26 accepts; the current phone offers 26 to 29, so a revision-25 daemon rejects its hello as malformed.

`terminal_grants_v1` names the existing P-256 terminal grant codec and the optional pairing `terminal_key`. Without it, the phone omits the key and refuses terminal methods locally; the daemon rejects an unsolicited key or terminal method and never serializes terminal challenge or grant results. Every request, daemon result and event passes through the negotiated codec, which for revision 26 covers the complete baseline, including current request parameters and enum variants; unknown events cannot be emitted. Paired sessions, pairing and short-lived approval or bootstrap connections all negotiate through `Session::hello`, after TLS pinning, whois, pairing windows and authorization.

Rules for new revisions:

- Retain the current and previous two negotiated revisions; raise the floor only once three real codecs exist.
- Before the advertised range widens, every wire change gates its fields and enum variants (request, parameter, response or event) for each retained revision.
- A future relay grant or encrypted payload format needs its own implemented capability and codec; `terminal_grants_v1` promises nothing about them.
- Never claim pre-baseline compatibility by widening a range.
- Before removing a revision, publish the new floor in the release notes and the update guide, and test both upgrade orders with serialized fixtures for every retained revision and for peers below the floor.

The checked-in compatibility fixtures exercise the real revision-26 to 29 codecs; synthetic 30/31 ranges test negotiation arithmetic, not claimed codecs.

## Approvals

The agent reconcile (`approvals.rs`) issues one approval per `blocked` `terminal_id`: `{approval_id (16 B), terminal_id, agent_label, workspace_label, snippet, tool, reason, options, choices, accepts_input, has_text_field, supports_note, nonce (32 B), created_at_ms, expires_at_ms}`. It expires after 600 s (`approvals::TTL`, not a `collied.toml` key). collied reads the screen with `pane.read source=detection` and the matched rule id with `agent.explain`, whose output carries raw pane text and is never exposed.

- **Menu.** collied answers only Claude Code's select menu: agent kind `claude`, a rule in `prompt::CLAUDE_MENU_RULES` (herdr claude manifest 2026.10.11.1), and the last numbered block after the dialog's last rule (one above it is old output), numbered from 1 without gaps, with exactly one `❯`. Anything else raises an approval with no options, which the phone shows but cannot decide.
  - Renamed sessions: Claude Code draws a `/rename` or `--name` session's name on a rule (`─── <name> ─`) under a question's footer, which herdr 0.9.5 rules `live_blocked_form_named_session`. Under that rule only, `prompt::without_session_name` cuts the name rule and everything below it and reads the rest as `live_blocked_form`, provided that rule carries text after its dashes (so a menu typed into an idle input box is not read), follows a line ending in "Esc to cancel", and has only blank lines and task panel rows below. A footer wrapped in a very narrow pane is not cut, so that question is answered in the terminal. Fixtures: `crates/collied/tests/fixtures/claude-2.1.300`.
  - Folder trust: the only unnumbered menu read is the folder trust prompt ("No, exit", then "Yes, I trust this folder"; rule `live_blocked_form`), and only in its exact layout: one `❯` line, one-line options at the cursor's label column set off by blank lines, each mapping to its own decision and one carrying trust wording. It is then handled as a numbered menu.
- **Other agent kinds.** Codex and Copilot CLI prompts are not parsed: their approval's alert has no actions and never goes on a Live Activity, and `approval.decide` is refused (`invalid_params`, nothing sent). Any agent can be answered by hand ([Prompts without decisions](#prompts-without-decisions)). A pending approval ends when its snippet no longer matches the screen, so a new prompt never shows with the old command.
- **Why no approval actions for Codex and Copilot** (codex-cli 0.160.1, Copilot CLI 1.0.94): an approval is never taken from screen parsing alone, Copilot has no usable non-screen source, and Codex's is not built.
  - Codex's `PermissionRequest` hook hides the terminal prompt until it exits, gets a stale `HERDR_PANE_ID` from the shared daemon's environment, and must be trusted by hand. Its app-server sends approvals (`item/commandExecution/requestApproval`) to every same-uid client, but with `approvals_reviewer = "auto_review"` Codex asks the user only when neither its hooks nor its guardian decide (in a test the guardian approved the request itself). A phone path would rarely fire and would have to bind each request to a pane (herdr rule, dialog command, thread cwd and lsof agreeing).
  - Copilot's `permissionRequest` hook fires before allow rules, locks the terminal while it waits, never sees path prompts and carries no request id; its SDK extension path needs the global experimental flag, uses `@experimental` permission RPCs and gets the session's whole RPC surface.
  - Revisit if Codex's `approvals_reviewer` is set to `"user"` or Copilot's extension and permission APIs become stable.
- **Settings pickers** (`prompt::settings_picker`): `/effort` and, in Claude Code 2.1.294, `/config`'s time format, output style and flagged message pickers change a setting, run no tool and grant nothing, so they raise no approval (no alert, Live Activity count or watch entry). Each is matched on its exact text under the last `▔` border, whitespace removed, for agent kind `claude` under `live_blocked_form` or the renamed-session rule. Any other dialog, or a picker whose text a later Claude Code changes, still raises one until it is added; so does `/advisor`, whose "No advisor" reads as a decision. `/model` needs nothing: herdr leaves its status unchanged. A suppressed picker still shows on the agent screen and takes arrows, Enter and Esc. Fixtures: `crates/collied/tests/fixtures/claude-2.1.294`.
- **Options.** Each decision maps to exactly one option label: `approve` to `Yes`, `Yes, proceed` or `Yes, I trust`; `approve_always` to `Yes, and don't ask again` and similar; `deny` to `No` or `No, ...`. A decision matching zero or several options is not offered, nor is any other option ("Yes, and switch to auto mode"). A menu without an approve or approve-always option (questions, plan prompts) is not a permission prompt and offers no decision, not even `deny`.
- **Choices.** `choices` lists any parsed menu, permission prompts included, as `{index (0-based), label, current}`, labels stripped of controls, bidi and format characters and capped at 120 chars. An approval with no `options` is answered with `approval.decide {decision: "choose", choice: <index>}`. A permission prompt never takes `choose`, which would bypass the decision mapping (Deny is sent as Esc).
- **Note.** `supports_note` is set when the menu offers `approve` or `deny` and "Tab to amend" shows under its last option, not in the body above, which can quote any text.
- **Tool.** `collied hook`, Claude Code's `PermissionRequest` hook, sends `{session_id, tool_name, shown}` over the control socket, `shown` being what the dialog shows of the call: for Bash the command and Claude's description, else the file path, URL, query or pattern, if any. It never answers (no output, exit 0, 2 s limit), so the dialog appears as usual with or without collied. The hook runs beside the dialog, which may be answered before collied looks, so a report counts only when its dialog offers decisions and each `shown` part is a run of whole dialog lines, whitespace removed. collied keeps each session's last report (at most 64 sessions, each for the approval TTL). A matching report sets `tool` to `{name, summary}` (cleaned like the context, at most 600 chars with the name) and the alert context to `<Tool>: <summary>`.
- **Reason.** Claude Code can ask even in auto or bypass mode and says why only in the dialog (the 2.1.308 hook input has no reason field): at the question's margin under the command block's closing `╌` rule, above a blank line (or the deny countdown), the question and option 1, in rows barred with `│ ` (2.1.308) or plain (2.1.295, unattended). Fixtures: `crates/collied/tests/fixtures/claude-2.1.308`, `claude/bash-countdown.txt`.
  - `prompt::without_reason` reads it only there, for agent kind `claude` with a parsed menu and paired dashed rules: rows joined, escape sequences dropped, whitespace collapsed, cut at 200 chars with `…`. A reason with any other control, bidi or invisible format character, or that only repeats whole dialog lines, is not set and the screen is read whole. A set reason's rows are removed before anything else reads the screen.
  - The reason as shown is hashed into every fingerprint and counts in drift, so no decision acts on a stale reason. The encrypted alert body is the context, cut first to fit the phone's 600 characters, then the reason on its own line; the Live Activity shows only the context's first lines, so a long command can push the reason out there.
  - No version bump: `reason` is an optional, additive field on a server-to-phone type that every retained codec passes whole; an older app ignores it, and an older collied sends none.
- **Snippet and labels.** The snippet is the end of the dialog (a menu's last 12 body lines), at most 200 chars in whole lines (a line alone too long is cut with a leading `…`), without Claude Code's tips. Labels are at most 64 chars. Both have controls, bidi and format characters and box borders stripped.
- **Context** (`prompt::context`): the dialog from the last horizontal rule to the last option block, at most 600 chars with `…`, controls, bidi and format characters stripped, lines kept. A Bash prompt gives `Bash: <every non-empty line between the header and the last "Do you want to" question>`, Claude's description included, since plain text cannot tell it from a command line. The approver acts on this text, so a command must not be able to hide its own lines (with a `Tip:` line, a blank line, a fake question or option): nothing in the command block is dropped, and `Tip:` lines are skipped only at the dialog's margin, never between the first and last `╌` rule. Another tool gives `<Tool>: <target>` (`Edit: src/main.rs`); else the question line; else the dialog's first line (and the next when it ends in `:`).
- **Fingerprint.** `state_change_seq` moves only on status changes, so it misses a new question under a still-`blocked` agent. The approval is bound to SHA-256 over the length-prefixed agent kind, rule id, `terminal_id`, agent session id, dialog region (last horizontal rule through the last option, cursor included) and reason. collied also keeps, per option, the fingerprint with the cursor on that option.
  - Deny countdown: in a session it takes for unattended (2.1.295 on), Claude Code shows `⚠ Claude Code will automatically deny this request in M:SS, to avoid blocking progress on an unattended session` (or `about N minutes` / `about N seconds`), changing every second. `prompt::without_deny_countdown` removes it before approvals or the drive paths that type into a dialog read the screen: only for agent kind `claude` with a parsed last option block, in that exact wording on up to three rows of its own, where Claude Code draws it (at the dialog's margin, above a blank line, the question and option 1). A copy in the transcript or the command stays. Its ticking neither reissues nor supersedes the approval; when Claude Code denies on its own, the agent leaves `blocked` and the approval ends.

### `approval.decide`

1. Rate limit per paired `StableID`: 1/s, burst 5 (`rate_limited`).
2. Claim. Any attempt burns a pending approval, whatever the result; a burned id answers `approval_already_resolved`, an unknown one `approval_not_found`.
3. Expiry, nonce (constant time), decision offered. `choose` needs empty `options` and an index inside the menu; the decoder requires `choice` exactly with `choose`. A `note` needs `approve` or `deny` and `supports_note`; the decoder takes one line of at most 200 characters without bidi or invisible format characters, so the amend field still parses once it wraps (onto at most 4 rows). Anything else is `invalid_params`.
4. Re-read the screen: still `blocked`, same `state_change_seq` and fingerprint, else `superseded`. Re-check that the peer is still authorized.
5. Keys, from a fixed set (`up`, `down`, `enter`, `esc`), never pane text:
   - Deny is a single `esc`, wherever the cursor is, when its label ends in `(esc)` or on the folder trust prompt, whose "Esc to cancel" exits like "No, exit".
   - Otherwise: arrows to the target option, 150 ms pause, re-read (the fingerprint must equal that option's cursor fingerprint, else `superseded`), peer re-checked, then `enter` in its own call, since lost arrows would confirm another option. Digit shortcuts are not used; their behaviour varies across Claude Code versions.
   - `choose` always takes this path and never sends `esc`.
   - With a `note`, Approve and Deny take this path too (never `esc`), adding before `enter`: `tab`, a poll (every 100 ms, up to 1 s) until the option under the cursor shows its amend field (`Yes, and tell Claude what to do next`, `No, and tell Claude what to do differently`), the note through herdr's `pane.send_text`, and a poll until the option reads `Yes, <note>` or `No, <note>`, the rest of the dialog unchanged throughout. The peer is re-checked before each write, and each poll requires the agent still `blocked` with the same `state_change_seq`. On any mismatch nothing more is sent, not even `esc` (in the amend field it cancels the whole prompt): `superseded`, and the next reconcile issues a new approval.
6. Settle: poll `agent.list` every 250 ms for up to 3 s (`approvals::SETTLE`) for the agent to leave `blocked` or move its `state_change_seq`.

The decide budget is 6 s from the claim to the last key; no key is sent after it. With the 3 s settle, a decision answers in under 10 s.

| Outcome | When |
|---|---|
| `applied {decision, by}` | final key sent, agent left `blocked` within the settle |
| `unconfirmed {decision, by}` | final key sent (or its send timed out, it may have arrived), agent still `blocked` |
| `chosen {choice, by}`, `chosen_unconfirmed {choice, by}` | the same two for `choose`, as their own outcomes so an older app decodes them as `other`. A multi-question form stays `blocked` on its next question: `chosen_unconfirmed`, then a new approval |
| `superseded` | fingerprint, seq or cursor mismatch; amend field or note not shown; budget spent before the final key; bad nonce; decision not offered; peer no longer authorized; herdr failed; on reconcile, the agent left `blocked` or moved seq without a decision |
| `expired` | past `expires_at_ms`, at decide or on reconcile |

Every attempt is audited with its decision (`choose <index>`, `<decision> with note`) and result, replays, rate-limited and expired ones included; frames over the per-peer frame limit log only the first of a run, as `rate_limited`, and never reach this limiter. Sent keys are logged as `terminal=<id> keys=<keys>`; the note never is.

**Reissue.** A resolved approval is never reused. While the agent stays `blocked`, the next reconcile issues a new one (new id and nonce), sent at once to live sessions. It alerts for a new blocked episode, a changed screen (seq or fingerprint) or an expired previous alert, but not for the same prompt within 30 s of the last alert, so bad attempts cannot flood the phone. The APNs collapse id and `thread-id` derive from `terminal_id` ([APNs](#apns)), so a new alert replaces the dead one.

**Drift.** `state_change_seq` also stays put when a form moves to its next question, a question is answered on the Mac, or a dialog finishes drawing after the approval was built. So each reconcile re-reads every pending, undecided approval of a `claude` agent and rebuilds it when what it tells the phone changed (snippet, `reason`, `options`, menu labels, `accepts_input`, `has_text_field` or `supports_note`; not the cursor alone). The rebuilt approval does not alert within 30 s of the episode's last alert, so typing on the Mac cannot become an alert stream.

### Prompts without decisions

Every agent takes manual input on permissions, trust prompts, questions and plans: every terminal button stays enabled (Codex's Shift+Left included), and the composer sends a typed answer whenever the agent is blocked, an approval is pending or a Codex question editor is open. Manual input relies on the paired session, not an approval nonce, expiry or LocalAuthentication: it can grant permissions, accept plans or trust a folder, and a changed prompt receives whatever the user sends.

- `agent.send_keys` forwards the closed key list after checking the live agent identity and peer authorization, with no approval, menu or decision check; blocked startup prompts take input too. For a Claude Code agent the fresh read shows not blocked, keys and typed answers still respect a scrolled transcript and a mirrored slash command, whatever approval metadata the phone holds.
- `agent.type_text {op_id, terminal_id, text}` sends bracketed-paste text and Enter in one ordered `pane.send_input` write, without selecting a free-text option, reading an answer back or binding to a prompt fingerprint; the terminal buttons focus the intended control first. Newlines and tabs are allowed; unsafe controls, bidi and invisible format characters are rejected; the 32 KiB prompt limit applies.
- `agent.prompt` still refuses blocked agents, so the composer answers them through `agent.type_text`; attachments wait for the next normal prompt. `accepts_input` and `has_text_field` are descriptive metadata and restrict nothing.
- The phone queues terminal keys and typed answers in order, approval card answers included. A failed input cancels queued actions with a visible error; an agent-to-shell transition discards pending agent input.
- Authorization is re-checked before every herdr write; both methods carry an `op_id` through the outcome cache. Audit: keys to a blocked agent log `<terminal_id> blocked keys=<keys>`; `agent.type_text` logs the terminal and result, never the text.
- collie-core: `type_text(machine_id, terminal_id, text)`; `decide` takes `ApprovalDecision::Choose { choice }` and a note (checked before sending); `PendingApproval` carries `choices`, `accepts_input`, `has_text_field` and `supports_note`. The lock-screen path sends no note.
- No version bump: the method, `choices`, `accepts_input`, `has_text_field`, `supports_note`, `note`, the `choose` decision and the two outcomes are additive. An older app ignores `choices` and decodes the new outcomes as `other`; an older collied sends no `choices` (it defaults to empty) and no `accepts_input`, `has_text_field` or `supports_note` (all default to false), and answers `choose` and a `note` with `invalid_params` and `agent.type_text` with `unknown_method`, so the app and collied update together.

## APNs

- `[apns]` in `collied.toml` holds `key_id`, `team_id` (10 uppercase alphanumerics), `bundle_id` and the key's location; `key` with `key_path`, or a store for the other OS, is an error. `collied apns test` sends a test alert through the selected sender to every registered device of a paired phone and reports acceptance, not display.

| Key location | macOS | Linux |
|---|---|---|
| `key = "keychain"` | the default when omitted | config error |
| `key = "systemd-creds"` | config error | the default when omitted ([APNs key on Linux](#apns-key-on-linux)) |
| `key_path` (a 0600 file owned by the user, opened without following symlinks) | legacy; `collied doctor` warns | the fallback when systemd-creds is unavailable; `collied doctor` warns while systemd-creds works |

- Keychain item (macOS): generic password in the login keychain, service `dev.rbstp.collied.apns`, account = key ID. Its ACL trusts only the storing program's designated requirement: a collied signed with the same Developer ID Application identity (team `RM3UT3MMSR`) and identifier `dev.rbstp.collied` reads it without a prompt; any other program prompts or is refused. `just collied-install` builds and signs it that way (hardened runtime, timestamp), installs it to `~/.cargo/bin/collied` as a fresh inode and restarts a loaded launchd agent; a `cargo install` build is ad hoc signed and cannot read the item unattended.
- `collied apns import <AuthKey_ID.p8>` (macOS) needs the `[apns]` ids, refuses a file named for another key ID, reads it with the `key_path` checks and requires an ES256 key. It stores the key (keeping an existing item), reads it back and compares, rewrites `key_path` to `key = "keychain"` (atomic, same mode, never through a symlink), then asks y/N before deleting the file if it is still the same inode.
- `collied doctor` (macOS) checks the signature, reads the item with user interaction disabled as the daemon does, signs a provider token as a dry run, and warns about any `.p8` left in `<data dir>/apns`.
- Tokens arrive by `push.register` and are stored per `StableID` in `push.json` (0600, atomic) with the device's notification key and environment (Debug builds sandbox, TestFlight production; collied keeps a client for each). Every send re-checks the pairing, so a registration racing a revoke never gets an alert. `Unregistered` and `BadDeviceToken` drop the token; revoking a peer forgets its tokens. Direct sends use a 64-alert queue, dropped when full, and 10 s per send; the relay's policy is [below](#relay-sender).
- Approval alert: push type `alert`, priority 10, `apns-expiration` = approval expiry, `apns-collapse-id` = base64url of the first 16 bytes of SHA-256(`terminal_id`). A device whose Live Activity for that terminal shows approvals gets the approval there instead, and the alert only if the activity push fails or the approval is still pending 2 min later ([Approval on the activity](#approval-on-the-activity)).
- Approval clear: when the agent of an alerted approval is no longer blocked (answered anywhere, or gone), collied pushes `{"aps":{"content-available":1},"approval_id":…,"node_id":…}` to every registered device: push type `background`, priority 5, no collapse id, `apns-expiration` 0, since APNs keeps one undelivered push per app and a stored clear would displace a pending alert. It names the approval the phone's alert carries, so each alert gets at most one clear; the record is in memory only, so an alert whose agent moves on while collied is stopped gets none. The woken app (`remote-notification` mode) removes only the delivered alerts with that `node_id` and `approval_id`; since iOS may delay or drop the clear, it also removes alerts of approvals no longer pending whenever it runs.
- Done alert: when an agent's turn of 30 s or more ends (checked each 1 s reconcile, after approvals). A turn runs from `working` to the next `done` or `idle`, a `blocked` inside it included; `blocked` to `idle` (a denial, Esc) and `unknown` end it silently. An agent's first poll never alerts; a turn under way when collied first sees it is timed from then. The 30 s, equal to the approvals' alert gap, skips quick replies and slash commands and limits a flapping agent to one alert per 30 s per terminal. The record is in memory only.
  - Push type `alert`, priority 10, `apns-expiration` 0 and the approval alert's collapse id, so a terminal shows one notification, the latest. A done alert cannot replace a pending approval: it needs the agent out of `blocked`, which supersedes that approval, and the single send queue keeps the order. `mutable-content: 1` runs ColliePush for the encrypted title and body, PR watch wake and archive-on-merge alerts included.
  - A device registered with `mute_done` (the app's "Notify when an agent finishes" off; in `push.json`, omitted when false) gets none. A followed agent's Live Activity gets only a silent status update. In the foreground, the app shows no banner or sound for the done alert of the agent on screen.
- Live Activity update tokens are stored beside the device's token: [Live Activities](#live-activities).

| Public alert field | Value |
|---|---|
| `aps.alert` | `{"title":"Collie","body":"An agent needs attention"}`; done alerts use `An agent finished` |
| `aps.thread-id`, collapse ID | base64url of the first 16 bytes of SHA-256(`terminal_id`) |
| `aps.mutable-content`, `aps.sound` | `1`, `default` |
| `node_id`, `event_id`, optional `approval_id` | opaque machine, fresh event and approval lookup IDs |
| `enc` | versioned authenticated display envelope, canonical unpadded base64url |

The alert as sent carries no category. ColliePush adds `APPROVAL` locally only after authenticating display content that offers both Approve and Deny, and restores the private terminal ID for navigation. An extension timeout, unavailable key or failed decryption leaves the generic alert without approval controls. The app authenticates encrypted responses again before classifying a decision.

### Relay sender

`[push.relay]` selects the fixed publisher endpoint `https://collie-push.rbstp.dev/v1/send`, `[apns]` direct delivery for self-built apps; configuration rejects both together. `collied setup` sets up the relay, with no APNs credential, unless run with `--direct-apns`. [relay.md](relay.md) describes the deployed relay.

No version bump: optional `relay_grant` registrations and `hello.push_mode` require both `relay_grants_v1` and `encrypted_display_v1`. The configured sender determines `none`, `direct` or `relay`; no endpoint comes from the phone. Grants persist only beside their own device or activity in private `push.json`, redacted in diagnostics. HTTP sends carry only the grant, in a sensitive Authorization header, and the strict v1 encrypted or generic envelope, never a caller-provided destination, topic or URL. Redirects are refused; responses are capped at 1 KiB and each attempt at 15 s.

Relay delivery has its own bounded worker: a 64-job ingress and at most 64 each of pending encrypted destinations, recent activity cadence records and routed-approval deduplication records. Routine updates keep only the newest state per activity and go out at most once per 60 s per agent and phone, unchanged refreshes included. Ready urgent updates, clears, alerts and ends bypass that cadence and run first; an urgent retry due later never blocks ready routine work. When cadence tracking is full, replacing a record first pauses all routine work for 60 s, so the limit still holds. Direct APNs keeps its own cadence and send order.

Network failures, timeouts, 429, 5xx and unexpected non-JSON responses (such as Cloudflare error 1027 HTML) enter bounded exponential backoff with random jitter; Retry-After (seconds or date) is clamped to one hour and a daily quota reset to 24 hours ahead. An exhausted routine daily quota pauses only routine work, keeping the reserved urgent budget; other outages pause everything queued. The server enforces installation-wide quotas across machines, so the remaining budget is unknown locally. Non-approval work expires after 2 min, approval work when its approval expires (at most one hour). A restart loses all work: there is no durable payload queue or exactly-once claim, so an ambiguous accepted send can be duplicated.

Before every attempt, retries included, the worker re-checks the pairing, the exact destination token and grant generation, grant and approval expiry, the approval's live state, and whether the activity was replaced or ended; a clear or newer activity state replaces obsolete pending work. Only an authenticated `410 invalid_route` removes the exact token or grant that failed, never a newer one; configuration and authorization errors keep registrations for repair or renewal. A failed activity send keeps the encrypted approval-notification fallback. The control status (`collied doctor`) shows counts, the earliest grant expiry, the last send error and retry or reset times, never grants, destinations or payloads. A push outage does not block the tailnet or control tasks.

### Encrypted display envelope

- The phone generates a 32-byte notification key per paired machine, stored in the shared Keychain (`AfterFirstUnlockThisDeviceOnly`) and in a 0600 App Group mirror, excluded from backups and protected until first unlock, so CollieWidgets can decrypt without Keychain access. Only the authenticated tailnet `push.register` sends it to collied, which keeps it beside the token in private `push.json` and never logs it. Pairing again rotates it; unpair or revoke removes it.
- No version bump: the additive `display_binding` registration field and the replacement APNs and ActivityKit codec require the explicitly negotiated `encrypted_display_v1` capability; revision 26's omitted capabilities still mean only `terminal_grants_v1`. A peer without the encrypted codec cannot register push or activity tokens. Persisted registrations without the encrypted-display marker or activity binding send no private display content and stay disabled until refreshed. There is no plaintext compatibility path.
- `enc` is canonical unpadded base64url of `header || nonce(12) || ciphertext || tag(16)`, ChaCha20-Poly1305 with a fresh random nonce. `header` is binary `version(1 byte = 1) || kind(1 byte) || node_id_length(1 byte) || scope_length(1 byte) || node_id(UTF-8) || scope(UTF-8) || event_id(16 random bytes)`; node and scope are 1 to 64 ASCII letters, digits, underscores or hyphens. Kinds: `1` alert, `2` activity state, `3` private static attributes. AAD is the bytes `collie.push.v1`, a zero byte, the header, and SHA-256 of the 32-byte destination notification key, so the key binds the receiving phone and machine, and the authenticated header binds kind, machine, scope and event. The public `event_id` is the header event in unpadded base64url; the widget reads it from the envelope because ActivityKit exposes only `content-state`.
- Alerts: scope is the opaque thread ID; plaintext is `{"v":1,"title":...,"body":...,"terminalId":...,"offersApproval":...}`, with `approvalId` only on approval alerts. ColliePush compares the authenticated machine, thread, event and optional approval with the public lookup fields, then restores title, body and routing locally. The body is the approval context when there is one; done and agent alerts carry their own complete body. Unsupported versions, noncanonical encoding, oversized input and failed authentication produce no private text or controls.
- Activities: the phone gives each a fresh UUID `bindingId` before ActivityKit assigns its activity ID, and sends `display_binding: {node_id,binding_id}` with its token over the tailnet. State is kind `2` under this scope (`{"v":1,"state":...}`); static attributes keep only opaque machine, terminal, node and binding IDs and a kind `3` envelope of `{"v":1,"machineLabel":...,"title":...}`. Initial, local and remote updates and ends all carry only ciphertext. A widget checks the envelope against its own immutable node and binding before using any state; without keys (before first unlock after a reboot, too) it shows a neutral `Collie` state without approval controls.
- Limits: envelopes 3,800 encoded characters; APNs payloads 4,096 serialized bytes; static activity attributes 1,536 bytes; each encrypted initial, update or end state 2,400 bytes; attributes and state together 4,000 bytes, leaving ActivityKit framing room. The remote sender always reserves the full static-attribute allowance; the phone checks both caps and the combined size before every local update. An oversized alert is dropped; an activity that cannot be encrypted or fit falls back to the approval notification where it applies. Alert bodies are visibly truncated at 1,800 JSON-escaped bytes and activity approval context at 600 bytes before its inner command seal, on whole Unicode scalars.
- Still observable: IDs, generic categories, priority and urgency, timing, size, and the update or end lifecycle. Public activity relevance is omitted remotely and zero locally, and activity alert text is generic. The raw APNs token stays a delivery destination. No push carries an approval nonce.
- [protocol/push-display-vectors.json](protocol/push-display-vectors.json) holds exact Rust and CryptoKit vectors for all three kinds and relay-compatible public payloads. [protocol/live-activity-content-state.json](protocol/live-activity-content-state.json) describes the private state before the outer seal. Its inner approval command uses the [notification-vector.json](protocol/notification-vector.json) seal, authenticated by approval ID, which never appears outside the authenticated display envelope.

## Lock-screen approval

- Category `APPROVAL` has two actions, Approve and Deny (no "approve always"), both `authenticationRequired`: iOS makes the user unlock first, then launches the app in the background without UI.
- `AppModel.decideFromNotification` holds a background task assertion and calls `decide_from_notification(node_id, approval_id, decision, budget_ms: 20000)`; the budget is capped at 20 s, and 0 is refused. This one-shot session runs outside the connection supervisor: start the node from cached state (never a login), wait for the pinned Mac in the netmap, dial, `hello`, take the nonce from the cached snapshot or `approval.list`, then `approval.decide`, never retrying past the budget.
- It fails at once with `Unauthorized` when Tailscale is not set up on the phone, the node reports `NeedsLogin` or `NeedsMachineAuth`, the netmap violates the pin, or `hello` reports the phone unpaired.
- The outcome and per-step timings (node up, connect, lookup, decide) are logged on device. A follow-up local notification in the same thread claims success only for `applied`:

| Background outcome | Follow-up | Opens the approval |
|---|---|---|
| `applied` | "Approved/Denied: agent. The agent moved on." | no |
| `unconfirmed` | "..., not confirmed": keys sent, agent still looks blocked | yes |
| `expired` | expired, nothing was sent | no |
| `superseded` | the prompt changed, nothing was sent | yes |
| `already_resolved`, `not_found` | no longer pending, nothing was sent | no |
| `unreachable` at `decide` | could not confirm the decision reached collied | yes |
| `unreachable` earlier, `unknown_machine`, `unauthorized`, `failed` | "Couldn't reach collied, open to decide" | yes |

- Tapping the alert opens the agent's session on the Agents tab (the iPhone has no Approvals tab; the Apple Watch keeps its approval list), resolving a pending approval by node and approval id first; after it has ended, a validated notification thread still opens the agent. Structured in-app approval actions pass LocalAuthentication (`deviceOwnerAuthentication`, a fresh `LAContext` each time); manual terminal input does not.

## Attachments

The Agent screen attaches a photo or file to a prompt: the phone uploads it over the tailnet session, collied stores a private copy and returns its absolute path, and the app inserts the path into the prompt draft, so the agent reads the file from disk. Nothing goes through herdr.

### Flow

1. `attachment.begin {op_id, name, size, sha256}` answers `{upload_id}` (16 random bytes, hex). `name` (`AttachmentName`: 1 to 64 characters, no control, bidi or format characters, no `/` or `\`, no surrounding whitespace, not `.` or `..`) is only a hint; `size` is 1 byte to 20 MiB; `sha256` is lowercase hex of the whole file.
2. `attachment.chunk {upload_id, offset, data}` in order: `offset` must equal the bytes received so far; `data` is padded standard base64 of 1 byte to 32 KiB, so a chunk frame stays under the 64 KiB frame cap. collie-core sends one chunk at a time and awaits each reply.
3. `attachment.commit {op_id, upload_id}` answers `{path}` once the received size equals `size` and the SHA-256 matches; otherwise the partial file is deleted and the error is `invalid_params` (size) or `checksum_mismatch`.
4. `attachment.abort {upload_id}` is best effort and always answers `ok`.

An upload is bound to the session and peer `StableID` that began it; another session, even of the same phone, gets `not_found`. Nothing resumes across connections: closing the session drops its uploads (collie-core reports them as interrupted). `begin` and `commit` go through the `op_id` outcome cache, so a retried commit returns the stored path. Authorization is the `agent.prompt` gate (a paired, full session), re-checked on every frame and before `begin`, each chunk and the commit.

collie-core's `upload_attachment(machine_id, name, data, progress)` checks name and size, computes the SHA-256, runs begin, chunks and commit, and reports progress after each acknowledged chunk; any failure sends `attachment.abort`. UniFFI 0.32 does not forward Swift task cancellation to Rust, so the app cancels with `cancel_uploads(machine_id)`, which fails the upload with `Cancelled` and aborts it on the Mac.

No version bump: the methods, responses and error codes (`too_large`, `checksum_mismatch`) are additive. An older collied answers `unknown_method`, which collie-core reports as "update collied".

### Limits

| Limit | Value |
|---|---|
| File size | 20 MiB, checked by the phone, the protocol decoder and collied |
| Chunk | 32 KiB decoded, in order, never past the declared size |
| Uploads in flight | 2 per session (`rate_limited` beyond) |
| Stored bytes | 200 MiB: committed files (the larger of length and allocated blocks) plus the declared size of every upload in flight; `begin` answers `too_large` beyond |
| Stored entries | 1000 under the root, uploads in flight included, so tiny files cannot exhaust the disk or slow `begin`'s scan; `begin` answers `too_large` beyond |
| Chunk rate | own bucket per paired `StableID`, 128/s, burst 128 (4 MiB/s); collie-core retries a rate-limited chunk up to 8 times with backoff. Other attachment frames use the shared 20/s bucket |

### Storage

- Root: `~/Library/Caches/dev.rbstp.collied/attachments` on macOS, `$XDG_CACHE_HOME/collied/attachments` (else `~/.cache/collied/attachments`) on Linux, with no spaces so the path reads cleanly in a prompt. Created 0700; an existing root that is a symlink, owned by someone else or not exactly 0700 stops collied at start.
- Each upload gets a fresh `<root>/<16 hex>/` (0700, `create_dir`, fails if it exists). Data goes to a `.part` file opened `create_new` with `O_NOFOLLOW`, mode 0600; the commit fsyncs it and renames it, inside that directory, to the sanitized name. Files are never executable.
- Sanitized name: `[A-Za-z0-9._-]` kept, each run of anything else becomes `-`, leading dots and dashes dropped, at most 64 characters keeping an extension of up to 16 alphanumerics, `attachment` when nothing is left (`.env` becomes `attachment.env`).
- Audit: `attachment.begin` with the sanitized name, and one `attachment.commit` line per committed upload with result `ok size=<bytes> sha256=<first 12 hex>`. Chunks and aborts are not audited; content and base64 are never logged.
- `collied doctor` prints an `attachments` line: root, mode, bytes stored.

### Cleanup

- Session close: its uploads in flight are dropped and their directories removed.
- Every 10 s: uploads idle for 60 s are dropped with their directories.
- At start and every hour: root entries older than 24 h are removed (symlinks as links, never followed). At start, directories still holding a `.part` from a previous run are removed too.

## Files from Chat

Chat links file paths in agent messages and tool records: absolute paths of two or more components, relative paths that start with `./` or have a folder and an extension, bare names with a common extension, and Markdown links with no scheme or `file:`, never hidden names or tokens with `..`, `://`, `*`, `$`, `=`, `@` or `\`. In an agent session's Terminal, the selection menu offers Open when no http link is selected and the selection holds exactly one such path. Either opens a read-only preview; collied decides what may be read.

### Flow

1. `file.open {terminal_id, path}` (Read class; `path` 1 to 1024 bytes, no control characters) answers `file_opened {download_id, name, size, kind, sha256}`.
   - collied takes the agent's checkout as `agent.changes` does, joins a relative path to it, refuses `..`, requires the result under a task root, then opens the parent one component at a time from the root with `O_NOFOLLOW` (`open_beneath`) and the file with `O_NOFOLLOW | O_NONBLOCK`.
   - `open_beneath` refuses a folder that starts with a dot or carries `UF_HIDDEN`, except the checkout path's own folders when the file lies below the checkout, so a worktree in `<repo>/.worktree/<branch>` opens its files. A hidden folder below the checkout, or on a path outside it, is still refused, so a checkout that is or lies inside a hidden folder (an agent started in `~/.ssh` or under `~/Library`) exposes the non-hidden regular files below it, as the threat model notes.
   - Hidden names, symlinks, folders and anything but a regular file are refused with a plain message (`invalid_params`). `kind` is `image` (PNG, JPEG, GIF, HEIC or WebP by extension), `pdf`, `text` (other files whose first 8 KiB are UTF-8 without a NUL) or `other`; an unknown kind decodes as `other`. A file over 20 MiB, or over 1 MiB for text, is refused with `too_large` and its `fstat` size before any content is sent. `sha256` is computed from the open descriptor.
2. `file.chunk {download_id, offset}` answers `file_chunk {data}`: up to 32 KiB of base64 from `offset`, read with `pread` from the same descriptor, so a chunk frame stays under the 64 KiB frame cap. A file that shrank fails with "The file changed while it was read"; one rewritten in place fails the phone's checksum. Chunks draw from the attachment chunk bucket (128/s).
3. `file.close {download_id}` always answers `ok`.

A download is bound to the session and peer `StableID` that opened it (another session gets `not_found`), at most 2 per session (`rate_limited` beyond), and closed by `file.close`, at session end or after 60 s without a chunk. Nothing is copied, cached or written on the machine. `file.open` is audited with `<terminal_id> path="<path>"` and its outcome; chunks and closes are not, and content never reaches a log or a push.

collie-core's `open_file(machine_id, terminal_id, path)` fetches chunks 4 at a time (retrying a rate-limited chunk up to 8 times), checks each chunk's length and the whole file's SHA-256, and always sends `file.close`, waiting at most 1 s for its answer since collied also drops the file with the session. A `not_found` chunk reads as an interrupted transfer, which the viewer offers to retry. `cancel_downloads(machine_id)` stops a transfer when the viewer closes, yet lets a pending `file.open` answer so the file it opened is closed too. The viewer keeps the bytes in memory; Share writes a copy to a fresh folder in the app's temporary directory (complete Data Protection), removed when the viewer closes.

## Draft sync

Claude Code keeps unsent text in its input box, and herdr's `agent.prompt` pastes after it. For agent kind `claude` only:

- `agent.draft {terminal_id}` answers `{text}`: the box's text from the visible screen (`pane.read source=visible format=ansi`), `""` when it shows only its dim placeholder, `null` when the phone may pre-fill nothing (another agent kind, no box, an opaque box).
  - The box is the last block on screen between two horizontal rules drawn from column 0, its first row at column 0 and the others indented two spaces, so a typed row of `─` never closes it. A first row other than `❯` (bash mode's `!`), or a collapsed paste or image placeholder (`[Pasted text #1 +40 lines]`, `[Image #1]`, `[...Truncated text #1 ...]`), makes the box opaque: its screen text is not its content. Dim text (placeholder, completion hints) is not typed text.
  - Claude Code 2.1 soft-wraps the draft (wrap-ansi `{hard: true, trim: false}` at the terminal width minus 4) and hides the space at each wrap; `draft.rs` (`Wrap::join`) rejoins rows as a soft wrap, a split word or a typed newline.
  - Controls, bidi and format characters are dropped, trailing whitespace is trimmed, and the text is capped at 32 KiB.
- `agent.prompt` takes an optional `expected_draft`, what the phone last saw. After the ready check, collied reads the box before the paste and fails closed:

| The box | `agent.prompt` |
|---|---|
| empty | goes ahead. Prompts queued while Claude Code works draw above the spinner, outside the box, so they read as an empty box, are never cleared, and the new prompt queues after them |
| missing or opaque | `draft_not_cleared`, nothing sent: whatever replaced the box may still take the paste, and an opaque box may be a shell command or hold content the phone never saw |
| a selection below it | `input_unfocused`, nothing sent, and `agent.draft` answers `null`; the phone asks the user to press ↑ and send again |
| equal to `expected_draft` (both normalized) | clears it, then re-reads every 100 ms for up to 1 s until the box is empty, else `draft_not_cleared`, nothing sent |
| any other draft, or no `expected_draft` | `draft_changed`, nothing sent, with the current text in `ErrorBody.draft` so the phone can show it and send again to replace it. The audit line is `draft_changed` alone: draft text is never logged |

- Why `input_unfocused` (Claude Code 2.1.310, herdr 0.9.5): `down` on the box's last row selects the background task pill, then the agent list below it. The box draws as before, but a paste may be dropped and herdr's Enter opens the tasks dialog or switches agent, so without this check `agent.prompt` answered ok for prompts that never arrived (#588).
- Clearing, verified on Claude Code 2.1.310 in herdr 0.9.5 for a draft of N visual rows with the cursor anywhere: N times `ctrl+e`, `ctrl+u`, `backspace` (clear a row, join it to the one above) empties the cursor's row and those above it, then N-1 times `ctrl+k`, `ctrl+k` (join the next row, then clear it). Never `down` (on the last row it selects the task pill while a task runs), `ctrl+c` (interrupts a working agent) or `ctrl+d` (exits Claude Code on an empty input); no key used interrupts a working agent. collied sends them itself, whatever the phone's `Key` allowlist holds, in batches of at most 16 with authorization re-checked before each; herdr has no `delete` key name.
- The phone loads the box's text into an empty prompt field once per visit to the agent's screen and treats it as the machine's until the phone edits it. Until then, a new non-null `last_prompt` triggers one `agent.draft` read: an empty box means the text was sent on the machine, so the field empties (its attachments stay). `last_prompt` comes from human prompts only, so text deleted on the machine, an approval, a background task's turn or `last_prompt` going null leave the field alone.
- No version bump: the method, response, field and error codes are additive. An older collied answers `agent.draft` with `unknown_method`, which collie-core returns as no draft, so the phone never sends it `expected_draft`. An older app sends no `expected_draft`, so a Mac draft refuses its prompt rather than being appended to. An older app reads `input_unfocused` as `unrecognized` and shows collied's message; an older collied never sends it.
- **Slash command mirror.** While the phone's draft starts with `/`, its command token (up to the first whitespace) is mirrored into the box, so Claude Code's command menu shows on the machine and in the phone's terminal view.
  - `agent.slash_draft {terminal_id, command, expected_draft}` (Drive class, idempotent so no `op_id`, audited with the terminal only) takes a `SlashCommand`: `""`, or `/` and up to 63 of `A-Z a-z 0-9 _ : . -`, so nothing can end the paste early. For a ready `claude` agent (never `blocked`, launch pending, or another agent or session) without a "Jump to bottom" banner, collied first replaces the draft as `agent.prompt` does, with `expected_draft`. A non-empty `command` is then pasted, after the ready, banner and authorization checks are repeated and the box reads as an empty `❯` (else `agent_not_ready`), in one bracketed `pane.send_text` (herdr 0.9.3 has no paste without Enter). collied re-reads every 100 ms for up to 1 s until the box holds exactly the command, and only then replies and releases the lock: a paste takes up to about 110 ms to render, and a next call that read the box empty would paste after it (`/stat/statu`). Other text gives `draft_changed`, an empty or unreadable box `agent_not_ready`, and nothing more is written. It never sends Enter or a key; a paste that did not land heals on the next call.
  - The phone mirrors only keyboard typing (the iOS keyboard's dictation and paste included, never the app's own dictation, paste, restored drafts or text it sets), for a Claude Code agent that is not blocked or scrolled up, never while dictating or sending, and only while it knows the box holds nothing or a command. Calls go one at a time, 150 ms after the last keystroke; the box is cleared once when the draft stops starting with `/` or empties. A `draft_changed` with the command this screen last asked for (a lost reply) is replaced; other text pauses the mirror and shows until the next send, so machine text is never replaced unseen. A reopened screen trusts the box only when it holds a bare command equal to its draft's token. Comparing tokens, not text, keeps a hint drawn after a completed command (`/rename  [name]`) from triggering a write.
- Picking a command: once the mirror catches up, the key strip's ↑ ↓ move Claude Code's highlight and ⇥ takes it. 150 ms later the phone reads `agent.draft` and takes the box's command into its draft, keeping its own arguments (`/mod opus` and ⇥ give `/model opus`); if that read was missed, a `draft_changed` at send whose command extends the draft's does the same. Send is refused after ↑ or ↓ until ⇥ or an edit. ⏎ and ⌃⏎ are off while the box holds a command no prompt covers, and keys queued before the mirror landed lose their Enter; collied also refuses `enter` and `ctrl+enter` to a non-blocked Claude Code agent whose box starts with `/` (`agent_not_ready`).
  - `agent.prompt`, `agent.send_keys` and `agent.slash_draft` share one lock, so another session's input never lands between a mirror's read and its paste. Only the phone's send runs a mirrored command: after any mirror call in flight, `agent.prompt` clears the token (it equals `expected_draft`) and pastes the whole draft with Enter. A partial command runs Claude Code's top match.
- Key strip (`keysShown` in `prefs.json`): Shift and Control are never sent alone; the next key goes out as one `Key` (`shift+tab`, `shift+left`, `ctrl+enter`, Control with a letter), so collied still sees only its closed list. Key shortcuts (`strip-shortcuts.json`) send one `Key`, text through `agent.prompt` with `expected_draft: ""`, or, for a Terminal shortcut, a command through `terminal.run`.
- Codex and Copilot: collied refuses `agent.slash_draft`, and the phone never calls it. collied cannot read their input box, so it could neither check nor clear it, and their prompts paste after whatever it holds, so a mirrored token would lead the prompt sent.
- Residual: text typed on the Mac between collied's read and its clearing keys is cleared too; text typed after the empty re-read is appended to by the paste. A typed newline exactly where the next word would not have fit reads as a space. When Claude Code limits the box to a viewport (a draft taller than its visible rows), only the visible rows are read and cleared, so the re-read refuses the prompt.

## Linked pull requests

Each `Agent` can carry an optional `pull_request`: `number`, `state` (`open`, `draft`, `merged`, `closed`), `checks` (`passing`, `failing`, `pending`, `none`), `url`, `failing_checks` (names), `remarks` (reviews plus comments) and `conflicting`. No version bump: the fields are additive on a server-to-phone type, and both enums read an unknown value as `unknown`.

- **Daemon**: a task beside the reconcile loop wakes every 30 s. It works only while a phone is connected or a paired phone has "Archive when the PR merges" on (then, with no phone connected, it reads only agents it could archive; see below), and only with `gh` in `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` or `~/.local/bin`; without `gh` no agent has a pull request.
  - It finds each agent's checkout as `agent.changes` does (`foreground_cwd`, else `cwd`, through `resolve_cwd`, so only inside the task roots), then the repository root and branch; an agent outside a repository or on a detached head has none. In the checkout it runs `gh pr view --json number,state,isDraft,url,statusCheckRollup,mergeable,reviews,comments,headRefOid --jq '.reviews |= length | .comments |= length'` with no argument: gh finds the current branch's pull request, so no branch name reaches the command line, and reviews and comments reach collied as counts only, never their text.
  - Cadence: at most once per 2 minutes per checkout and branch. A pull request last read as `MERGED` is not read again while the checkout's `HEAD` (`git rev-parse --verify --quiet HEAD`) is still its `headRefOid`, except at least every 30 minutes, so a new pull request from the same commit is still found. Open, draft and closed pull requests, and entries whose last read failed, are read every 2 minutes. "no pull requests found" caches none; any other failure (no login, network, timeout) keeps the last value for one refresh, then shows none, and logs nothing. A read whose branch changed while `gh` ran is dropped. Any change to what the phone is shown sends `flock.changed`.
  - `gh`, here and for `gh poi`, runs from a fixed path with `GH_PROMPT_DISABLED=1`, without `GH_TOKEN`, `GITHUB_TOKEN` or the enterprise token variables, with null stdin, a timeout (30 s here) and `kill_on_drop`. Any other state, or a `url` that is not `https://` or holds whitespace or control characters, drops the read. `failing_checks` holds at most 10 distinct names of failing check runs (`name`) or status contexts (`context`), in rollup order, each stripped of control and format characters and `"` and cut at 100 characters. `conflicting` means `mergeable` is `CONFLICTING`.
- **Checks** (from `statusCheckRollup`): a status context passes on `SUCCESS`, is pending on `PENDING` or `EXPECTED`, and otherwise fails; a check run is pending until `COMPLETED`, then passes on `SUCCESS`, `NEUTRAL` or `SKIPPED` and otherwise fails. Any failure makes `failing`, else any pending `pending`, else `passing`; an empty rollup is `none`.
- **Phone**: grid cards, Inbox rows and the agent screen's header show a badge with the state's icon, color and number, plus a check icon while the pull request is open or a draft. - `collied doctor` warns when `gh` is missing or `gh auth status` fails.

### Watching a pull request

For a Claude Code agent whose linked pull request is open or a draft, the session menu offers "Watch PR" every 2, 5, 15 or 30 minutes; while the terminal has a watch, whichever pull request it follows, the menu offers "Stop watching #N, every M min" instead. `Agent.pr_watch` (`number`, `url`, `every_minutes`) carries it, and the badge shows "Watching" (only the eye on grid cards) when it follows the linked pull request. `agent.watch_pull_request {terminal_id, watching, every_minutes}` starts or ends the watch. Starting needs `every_minutes` of exactly 2, 5, 15 or 30, a Claude Code agent whose linked pull request is open or a draft with a URL of the form `https://host/owner/name/pull/number` in GitHub's characters, a checkout on a branch, `gh` installed and `gh auth status` passing (otherwise the error asks to run `gh auth login` on the machine). Stopping takes no `every_minutes`; watching the same pull request again only changes the interval. Watches belong to the machine, one per terminal, kept in `pr-watches.json` (0600, data directory) with the interval, checkout, branch and the `StableID` of the phone that started them, so they survive a restart.

- **Reads**: a daemon task ticks every 30 s, with or without a phone, and reads each watched pull request once its interval has passed since the last read (at once for a new watch, a watch started again, and after a restart). It runs `gh api graphql --hostname <host>` in the data directory, with the owner and name as `-f` variables and the number as `-F`, in the linked pull request read's environment. The query asks for the signed-in user, the state, `mergeable`, the head commit, the base branch's required check names (`baseRef.branchProtectionRule.requiredStatusChecks.context` and `baseRef.rules.nodes.parameters.requiredStatusChecks.context` from `RequiredStatusChecksParameters`), the head commit's rollup state with its check runs and status contexts (name, outcome, `isRequired`), and the author, URL and time of the last 20 comments and 20 reviews. It asks for no body, so no comment or review text reaches collied.
- **Wakes**, queued on the watch until the agent takes them:
  - A failing check: once per check until it passes again or the head moves.
  - All required checks passing: once per head commit. The required names are the base branch's, from its protection rule and rulesets, plus any listed check marked `isRequired`. Each must be listed and pass, so a required check that has not reported holds it, as does a rollup state of `EXPECTED`; an optional check failing or running does not. With no required check, every listed check must pass and the rollup must not be `PENDING` or `EXPECTED`. A required check from a rule the signed-in user cannot read is known only once it reports.
  - A comment or review newer than the newest seen, by someone other than the signed-in `gh` user. Times are compared, with URLs breaking ties within a second, so a deleted comment that lets an older one into the window wakes nothing. The first read only records what is there.
  - `mergeable` turning `CONFLICTING`; `UNKNOWN` keeps the last answer.

  An empty check list keeps the last check state.
- **Prompt**: while changes are queued, each tick looks up the agent in `agent.list` and wakes it only when it is an idle or done Claude Code agent whose checkout is still on the watched repository root and branch; otherwise the wake waits (after a branch switch, say). The wake goes through `Driver::prompt` and all its guards, with no `expected_draft`: an agent that has just started working, a box holding text, a scrolled screen or a blocked agent refuses it, nothing is cleared, and the next tick tries again. Right before the write, a fresh status read refuses an agent that is no longer Claude Code, and the authorization check confirms the watch still exists for that URL and its phone is still paired, so "Stop watching" or a revoke during the attempt types nothing.
  - The prompt is one line naming at most 10 changes: `Pull request #N (<url>) changed: check "<name>" failed; new review <url>; ...`. Check names lose control and format characters and quotes and are cut at 100 characters; comment and review URLs must be `https://` without whitespace or control characters.
  - A head move drops queued check changes, and a queued failure, pass or conflict that no longer holds before the wake is dropped.
- **After a wake**: an audit line (`pr.wake`, the terminal id, the summary and the pull request URL) and an alert "Woke \<agent>" with the summary (for example "CI failed on #123") through the done alert path, so `mute_done` silences it.
- **Wake prompts in Chat**: collied records each wake's exact prompt, summary and time per terminal in `pr-wakes.json` (0600, data directory), never in the log or a push. It keeps the last 20 per terminal, apart from the watch, so they outlive it (a merge ends the watch right after its last wake) and a restart. It drops a terminal's list once its pane closes or its agent exits (the terminal is missing from a non-empty `agent.list` read by the watch task, which also runs while wakes are remembered and no watch is active).
  - `agent.history` sets `HistoryMessage.origin` (`kind: "pr_watch"` and the summary) on a main-thread user message whose text equals a remembered prompt for that terminal. `Agent.last_prompt_origin` is set when `last_prompt` equals a remembered prompt's first line cut the same way. Marking compares text only, not who typed it: re-sending a wake's exact text also shows as a wake. Wakes are keyed by herdr's terminal id, which herdr reassigns when it restores a session after a reboot, losing earlier marks.
  - Chat shows a marked message as one collapsed "PR watch: \<summary>" row with the eye, expanding to the full prompt; grid card previews and the Inbox show the same line instead of the prompt. The app shows an unknown `kind` as an ordinary message. No version bump: both fields are optional and additive on server-to-phone types, which no retained revision decodes strictly, so an older app ignores them and an older collied sends neither, showing the wake as an ordinary prompt.
- **Stops**: the watch ends, with anything queued, when:
  - the pull request is merged or closed;
  - 10 wakes in a row held only comments and reviews (a wake with any other change resets the count);
  - 8 reads in a row failed (no `gh`, no login, network, an unreadable answer);
  - the terminal is missing from a non-empty `agent.list`;
  - the phone that started it is revoked, unpairs, or is no longer paired when the task ticks (a revoke while collied was stopped);
  - the user picks "Stop watching".
  The menu and badge follow through `flock.changed`.

### Archiving when the pull request merges

A merged pull request's badge reads "Merged" (only the icon on grid cards), and the session menu puts Archive first. Settings > Sessions > "Archive when the PR merges" (off by default; `archiveOnMerge` in `prefs.json`, absent until the user picks it) makes collied archive the task itself. collie-core sends `task.archive_on_merge {enabled}` (Drive class, audited with `enabled=`) to every connected machine when it changes and to each machine at the start of every session, after `push.register`; the app sets it at launch only once the user has picked it, so a phone that never did leaves the machines' setting alone. collied keeps the `StableID`s of the phones that turned it on in `archive-on-merge.json` (0600, data directory), so it holds with no phone connected and across a restart; it is on while any phone in that file is still paired. Any phone turning it off empties the file, so a `StableID` a phone no longer uses (after a reinstall) cannot keep it on; a revoke or unpair removes that phone.

- **When**: on the linked pull request task's 30 s tick. With the setting on and no phone connected, the task still runs, with one herdr snapshot per tick, only for agents that pass the workspace check below, at the same once per 2 minutes per checkout and branch, so a merge is noticed within about 2 minutes either way; those reads do not change the pull requests a phone is shown. Only a fresh `gh pr view` that finds `MERGED`, or a kept merged result, makes the agent a candidate, at most once per 2 minutes; a value cached within those 2 minutes never does. A candidate that fails a check is tried again at the next fresh or kept read.
- **Checks, all read fresh in this order** (`Driver::archive_if_merged`):
  1. The setting is on.
  2. A herdr snapshot in which the terminal's workspace is a linked worktree and every pane of that workspace is an agent that is idle or done with no subagent running. A plain shell pane, an agent working, blocked or unknown, or a Claude Code agent with a running subagent, an unreadable transcript or an incomplete subagent scan (more than 8 workflow directories, or files past the 8 opened per scan that were never read before) holds it.
  3. `git status --porcelain --untracked-files=normal --ignore-submodules=none` in the checkout prints nothing (ignored files do not count; a submodule with changes, untracked files or a commit other than the recorded one does, whatever `.gitmodules` or the config say; the repository's filter commands are blanked as for diffs), and `git ls-files -v --recurse-submodules` lists no assume-unchanged (lowercase tag, as `core.ignoreStat` sets) or skip-worktree (`S`) entry in the checkout or a submodule, since `git status` does not look at those files.
  4. `gh pr view --json number,state,headRefOid` again still says `MERGED` with the same number.
  5. `git merge-base --is-ancestor HEAD <headRefOid>` (a 40 or 64 hex character id only): the checkout holds no commit the pull request does not.

  Then `Driver::archive_merged` runs `task.archive`'s archive: it checks the workspace again on its own snapshot, refuses a regular folder (it never only closes the pane), and, after its last authorization check and right before `worktree.remove`, requires the checkout herdr is about to remove to be the one whose pull request was read, and runs the git checks on it once more. That authorization check is that a paired phone still has the setting on, so turning it off or revoking the phone stops an archive in flight before the removal. Unlike a manual archive it does not run `gh poi`, which deletes every merged branch and removes other clean worktrees of the repository, whatever their agents are doing.
- **After**: one audit line per attempt that reached `archive_merged` (`collied`, `task.archive`, the terminal id, `PR #N merged: <result>`); candidates that fail an earlier check are not audited. On success, an alert "Archived \<agent>" with "PR #N merged" through the done alert path, so `mute_done` silences it, and `flock.changed`.

## Git reads

Git changes, the archive checks and the pull request branch checks run git in the agent's checkout through one builder (`git::git_command`) that treats the repository's config as untrusted: null stdin, no `GIT_*` variables from collied's environment, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `core.fsmonitor=false`, `diff.external=` and an 8 s timeout. Diffs pass `--no-ext-diff` and `--no-textconv`, and `diff` and `status` blank the repository's `filter.<driver>.clean` and `.process` commands. In a partial clone (for example `--filter=blob:none`), a diff that needs a missing blob would fetch it, running programs the repository configures, such as `remote.<name>.uploadpack`, `core.sshCommand` or a credential helper. `GIT_NO_LAZY_FETCH=1` stops that fetch (git 2.45, and the 2.39.4 to 2.44.1 security releases). For older git, an empty `GIT_ALLOW_PROTOCOL` refuses every transport, overriding any `protocol.*.allow` in the repository's config, and a blank `fetch.bundleURI` on the command line, which the fetch inherits, keeps it from starting `git-remote-https` for a bundle URI before that check (its setup can run a credential helper for `http.sslCertPasswordProtected`). Such a read fails instead.

## Conversation history

`agent.history` is a read method on the paired connection. The phone sends a terminal ID, optionally `before` or `after`, and a case-insensitive search `query`. Cursors bind the agent kind, session UUID, file device and inode, byte offset and a hash of the preceding 64 bytes; replacement, truncation, changed cursor bytes or a session change reset the page. The daemon resolves the live agent before reading and verifies its identity again before replying. A missing agent identity or an unreadable file returns `available: false` with a distinct `unavailable_reason`. Session identity comes from herdr, never a folder or recency guess; reporting a missing identity lets the next poll recover. An existing empty transcript returns `available: true` with no messages. No version bump: an older daemon rejects the additive method, and the phone keeps Terminal available.

- Copilot CLI reads the conversation selected for the pane (Live Copilot conversation in [Context and inbox](#context-and-inbox)), not herdr's ID, which can be stale after `/new`; while that selection is missing or ambiguous, the reply is `available: false` with its own reason and nothing is read. Since `/new` can switch conversations without changing herdr's ID, the daemon selects again after the read and refuses a page read from another session. The selection accepts the name Copilot gives a session after its first prompt (`name` in `workspace.yaml`, with `user_named: false`) like one the user set.
- `latest: true` (revision 27, with no cursor or query) reads only the last two user messages and the last two assistant text messages, in conversation order, from the same 2 MiB tail window with the same per-record caps, within 40 KiB. Tool calls, results, events, subagent records and empty or whitespace-only text never count, and thinking and reasoning are never read (except a Claude progress update written as thinking, below); a record mixing text and tool calls counts only its text. The reply carries no cursors, and fewer messages when the window holds fewer.
- The reader uses the summaries' Claude and Codex transcript locations, and Copilot CLI's `session-state/<session>/events.jsonl` under `COPILOT_HOME` (default `~/.copilot`). A blocking worker reads at most a 64 KiB format header and a 2 MiB history window without holding the shared transcript mutex, consuming only newline-terminated records, so a partial append is retried. Backward pages and forward updates carry distinct cursors; replies hold at most 40 message blocks and 40 KiB of serialized messages, below the 64 KiB transport limit. Oversized records are skipped with an explicit notice, and cursors still progress. Large text is truncated on UTF-8 boundaries for display; search matches before truncation. No transcript content or search text is written to audit, push or notification state. Stable record and block IDs prevent duplicates across pages and reconnects.

**Claude.** The reader takes main-thread user and assistant content blocks, `tool_use` and `tool_result` included, and excludes synthetic replies, foreign session records and user records the harness injected rather than the user typed (`isMeta`, such as skill text and subagent hand-backs, compaction summaries, and `task-notification` origins). No version bump for any of the following: each arrives as an ordinary message.

- A subagent hand-back leaves a one-line `event` message, "Subagent finished: \<description>" (the description, else the agent type, from the subagent's meta file); a task notification, having no structural status or summary field, leaves "Background task finished".
- A slash command (a user record with no `promptSource` and not `isMeta`, whose string content starts with `<command-name>` or `<command-message>` and names a `/` command) leaves its name and arguments, such as "/effort high"; its `<local-command-stdout>` record is left out. A typed prompt always has a `promptSource`, so it is never taken for one. These lines carry no other record text, are capped at 120 characters without control characters, and are left out of search.
- A `!` shell command (a user record with no `promptSource` and not `isMeta`, whose string content is `<bash-input>CMD</bash-input>`) shows as the user's message `! CMD`, so search and the grid Chat preview see it. The record after it, `<bash-stdout>OUT</bash-stdout><bash-stderr>ERR</bash-stderr>`, becomes one `tool` result with no call ID: stdout, then stderr on the next line when not empty, both without terminal escape sequences (removed before truncation and search); a command with neither leaves no result. Chat shows a `tool` result with no call ID and no parent call as its own collapsed activity row, never grouped with the tool calls around it.
- A prompt sent while Claude is working is written only as an `attachment` record (`attachment.type` `queued_command`, `commandMode` `prompt`, `origin.kind` `human`) once Claude Code absorbs it into the running turn; its `prompt` (a string, or text and image blocks) shows as an ordinary user message at that record's place, reaching search and the grid Chat preview. A prompt that waits for the turn to end is written as a `user` record with `promptSource` `queued` instead, never as both, so neither shows twice. Other attachments and queued commands (task notifications, subagent hand-backs, coordinator messages) stay hidden.
- Claude 5.1 and later (parsed from `message.model`, such as `claude-opus-5-5`: a family name, a major version and an optional one- or two-digit minor) write the short progress update before a tool call as a second thinking block, after the reasoning block, instead of a text block. Claude Code writes each block as its own record sharing `message.id`, numbered in `apiBlockIndex`. Since thinking blocks lead a message, a main-thread thinking block at index 1 or later (`apiBlockIndex` plus its position in the record) from such a model is that update and shows as ordinary assistant text, reaching the grid Chat preview and, by the same rule, `last_line` (the Inbox latest reply and the watch). The rule needs no neighboring record, so a page or tail window that splits the message still shows it. A lone or first thinking block stays hidden as reasoning, as does every thinking block of an older model, a synthetic reply or a subagent record.
- Subagents: Claude Code keeps each subagent's records in `<session>/subagents/agent-<id>.jsonl` beside the session's transcript, with `agent-<id>.meta.json` naming the parent Agent call (`toolUseId`). The reader adds a subagent's records right after the Agent call, tagged with that call's ID in `parent_call_id` (additive); forward pages also add them after its hand-back (`origin.from`), so an open Chat gets the steps when a background subagent finishes. It opens these files like the transcript (no symlink, non-blocking), only for an id of letters and digits and only through real directories under the session's directory. A page's subagent files share one more 2 MiB tail window, plus up to 64 KiB of each file's head for its prompt; the page is marked omitted when records in between are left out, and a subagent that does not fit what is left of the window starts the next page. Subagent records get the same per-record caps and count toward the page's 40 blocks and 40 KiB: a subagent larger than the room left keeps its first step and its latest ones and marks the page omitted, and its call starts the next page only when not one step fits. Context and the last line still ignore subagents.

**Codex.** Current Codex (0.160 and later, or a header window containing `item_completed`) uses `UserMessage` and `AgentMessage` completion events for conversation text, avoiding their overlapping `response_item` messages; older Codex uses `response_item` messages. Both read `function_call` and `custom_tool_call` and their outputs with call IDs; encrypted reasoning and internal instructions are excluded.

**Copilot CLI.** The file must start with a `session.start` naming the selected conversation. The reader shows typed `user.message` content with no `source` or `source: "user"` (other sources, such as autopilot, `skill-*` or `agent-<id>` outside a subagent, were injected and are left out; a subagent's `agent-<id>` prompt is kept), `assistant.message` content with each of its `toolRequests` as a call, and `tool.execution_complete` results (`result.content`, or `error.message` for a failed call) paired by `toolCallId`. `tool.execution_start` duplicates the request and is not shown; reasoning, system prompts, hooks, model and usage records are excluded. A `system.notification` of kind `agent_idle` or `shell_completed` leaves a "Subagent finished" or "Background task finished" `event` line. Subagent records share the file, marked with the child's `agentId`, and are tagged in `parent_call_id` (additive, no version bump) with their `parentToolCallId`, or, for the child's prompt, which has none, with the `toolCallId` of its `subagent.started` or of another record of that child in the same 2 MiB window. A child record whose call is not in the window is left out rather than shown as the parent's conversation. Record IDs come from each event's `id`.

**Phone.** The session switches only its content area, keeping its composer and approval paths. Chat projects records into a lazy timeline: text replies stay visible, and consecutive tools form one collapsed activity row, pairing calls and results by call ID. Activity row IDs survive prepends and appended results; idle polls do not rebuild the timeline. An Agent call's disclosure nests its subagent's prompt, tool calls (collapsed) and reply, matched by `parent_call_id` wherever the call sits in the loaded timeline, and its activity row counts the subagent steps. Chat keeps an ID-based scroll position, loads older pages on demand, and polls only the appended portion while visible and in the foreground. Search keeps every matching record visible with matches highlighted, scans bounded batches back to the beginning (stopping when cleared or when Chat closes), navigates matches by stable ID, and polls for new matches once the older scan completes. Terminal keeps keys and wrapping, with a Chat handoff button for interactive prompts, and still serves shells and unavailable transcripts; its scrollback stays bounded because it controls repeated screen snapshots.

## Plan usage

Claude Code passes the plan's limits only to the status line command, as `rate_limits.five_hour` and `rate_limits.seven_day` (`used_percentage`, 0 to 100, and `resets_at`, Unix seconds) on its stdin, at each refresh: a new reply, `/compact`, a mode change, or a window reaching its reset. On disk it keeps them only in a cache that `/usage` refreshes, in `~/.claude.json`, which also holds account data collied should not read. Codex's rollout `token_count` events carry `rate_limits`, but `primary` and `secondary` are null for credit-metered workspaces, so the daemon asks the local Codex app-server for `account/read` and `account/rateLimits/read` every five minutes and keeps only `individualLimit`'s used credits, allowance and reset date. A confirmed sign-out, or a successful response without a limit, clears the Codex reading and publishes the change to the phone; a failed fetch keeps the last reading. Codex manages its own OAuth token. Copilot's premium quota comes from GitHub's `GET /copilot_internal/user`, which also answers for a seat an enterprise assigns (Copilot below).

- **Tap**: `collied statusline` reads the status line JSON from stdin (at most 1 MiB), keeps the two windows (percentage rounded and clamped to 0 to 100, reset time in ms) and, for a lowercase-UUID `session_id`, `context_window.context_window_size` (1K to 100M), and drops the rest (`spend_limit` included). It merges them into `usage.json` (0600, data dir) under an exclusive `flock` on `usage.lock`, so concurrent sessions do not lose each other's windows, then replaces the file atomically without `sync_all` (a full drive flush on macOS; the next refresh redoes a lost write).
  - Each session reports the limits from its own last reply, so they merge per window: the later `resets_at` wins, then, within the same window, the higher percentage, since usage only grows there; a window missing from one session's input is kept until its reset time. `recorded_ms` moves only when the input agrees with the merged result, so a quiet session's older figures neither replace newer ones nor look fresh.
  - The status line runs several times a second while a reply streams, so an unchanged value is stamped again at most once a minute, and input that changes nothing leaves the file alone. Input without `rate_limits` keeps the last limits, so a session before its first reply does not erase them. At most 64 sessions' windows are kept, the oldest seen first out. The tap starts no runtime and prints nothing; the README line runs it in the background.
- **Daemon**: `Transcripts` re-reads `usage.json` (`O_NOFOLLOW`, regular file, at most 64 KiB) only when its size or mtime changed: for `flock.snapshot` and `approval.list`, when it derives a `claude` agent's transcript (for the session's window), and on the reconcile loop's 1 s herdr poll, which costs one `fstat`. The plan belongs to the machine, not a session, so it goes out on the snapshot as `Flock.plan_usage` (`five_hour` and `seven_day`, each `used_percent` and `resets_at_ms`, and `recorded_ms`), with or without a Claude Code agent open. When it changes and a phone has a session open, that tick sends `plan.usage` for a present plan or `flock.changed` to refresh a cleared one; the phone's core applies it to its cached flock. There is no separate timer. The session's window replaces the model table for `context_left` and also keys the transcript cache. No version bump: the field is additive on a server-to-phone type, and an older app ignores the unknown event.
- **Phone**: an Agents and Usage segmented control sits above the chosen layout, whose picker is disabled while Usage shows. Usage shows one card per machine with a plan recorded: the machine and the recording's age, then a Claude Code row with "5-hour usage limit" and "Weekly usage limit" blocks, a Codex row with a "Monthly usage limit" block when Codex reports an individual limit, and a Copilot row with a "Monthly premium usage" block when collied read one.
  - A block has a title, a full-width bar with an elapsed-time tick, the amount used (percent for Claude; used and allowed credits for Codex and Copilot, or requests when the Copilot seat is not token-billed, or "Unlimited" with no bar for a seat without a cap) and the reset (the 5-hour reset as a clock time, the weekly one as a countdown, Codex and Copilot as a date). Copilot use past the allowance keeps the bar full and shows the real amount.
  - A window past its reset is hidden. Claude data over 5 minutes old and Codex and Copilot data over 10 minutes old are dimmed. The card redraws every minute while on screen; nothing is fetched beyond the list's cache refresh.
- **Copilot**: a task beside the Codex one runs `gh api --hostname github.com copilot_internal/user` every five minutes, with or without a phone, with the linked pull requests' `gh` setup (fixed path, no token variables, a 30 s timeout; [Linked pull requests](#linked-pull-requests)) and the user's own `gh auth login`. It reads github.com only, so collied needs no host setting; GitHub Enterprise Cloud with data residency (`*.ghe.com`) is not read.
  - `--jq` reduces the answer inside `gh` to `token_based_billing`, `quota_reset_date`, `quota_reset_date_utc` and `quota_snapshots.premium_interactions`, so the login, account id, tracking id, organization and enterprise lists and service endpoints never reach collied.
  - collied keeps `used` (`entitlement` minus `remaining`, at least 0, plus `overage_count`, so use past the allowance counts whether GitHub reports it as a negative `remaining` or in `overage_count`), `limit` (`entitlement`), `unlimited`, `token_based_billing` and `resets_at_ms` (from `quota_reset_date_utc`, else `quota_reset_date` as UTC midnight), as `copilot` in `usage.json` and on `PlanUsage`.
  - No `gh`, `gh` exit code 4 (no login), an HTTP 404, an answer without `premium_interactions`, or an `entitlement` of 0 on a limited seat clears the reading; any other failure (network, timeout, a malformed answer, a reset already past) keeps the last one. The chat and completions quotas are not read. Nothing from `gh` is logged, audited or pushed. No version bump: `copilot` is an optional, additive field on a server-to-phone type, which an older app ignores.
- **`collied doctor`**: `plan usage` says when the tap last recorded the limits and how many sessions' windows it holds, or warns that it has recorded nothing. `copilot` reports the daemon's last read of Copilot premium usage while that reading is under 10 minutes old; otherwise it asks GitHub once itself and says that the usage is readable, that there is no `gh`, login or premium quota, or why the read failed.

Security: [Status line tap](threat-model.md#status-line-tap), [Copilot premium usage](threat-model.md#copilot-premium-usage).

## Token cost

The Usage view's "Tokens and cost" card reads `usage.costs` (revision 28, a read method) with a range (`today`, `7d` or `30d`) and the phone's current UTC offset in minutes (within 18 hours), so days end at the phone's midnight; the one offset applies to the whole range, so after a daylight saving change the earlier days are off by an hour. The reply carries `scanning`, the token totals (input without cached input, output, cache read, cache write), the estimated cost and cache savings, one cost per day of the range, oldest first, and at most 32 model rows by cost (then tokens), each with its agent, model id, tokens, `cost_usd` and `cache_savings_usd` (both null when the model has no price). Totals cover every model, listed or not; only priced models add to costs. The audit log leaves the method out, like `flock.snapshot`, since the card polls it.

- **Sources**: the transcript readers' roots: Claude Code's `projects` (every `*.jsonl`, subagent and workflow transcripts included), Codex's `sessions/YYYY/MM/DD/rollout-*.jsonl` and `rollout-*.jsonl.zst`, and Copilot CLI's `session-state/*/events.jsonl`. The walk never follows a symlink (directory entries are typed without following them, and files open with `O_NOFOLLOW` and `O_NONBLOCK` and must be regular), skips names starting with `.`, descends at most 5 levels and lists at most 20,000 files per root, counting only files modified in the last 32 days (by `lstat`). When a root hits the cap, indexed files missing from the listing are kept rather than forgotten. Codex compresses a rollout idle for 7 days to `.jsonl.zst` and decompresses one it resumes, writing the new form before removing the old; while both forms exist, only the plain file (same session id) is listed, as Codex itself reads that one.
- **Claude Code**: `assistant` records with `message.usage` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` and its `cache_creation.ephemeral_1h_input_tokens` part), `speed: "fast"` and `message.model`. Sidechain records count; `<synthetic>` records are skipped. Claude Code writes one record per content block, and a resumed session repeats earlier records in its new file, so a record counts once per `message.id` plus `requestId` across all files, kept by the first file (in path order) to read it. A message's block records repeat its input and cache counts, but a streamed message's earlier ones (seen in subagent transcripts) carry a partial `output_tokens`, so the file keeps the output it counted for each key and adds only the increase when a later record of the same key, in this scan or a later one, reports more.
- **Codex**: `event_msg` `token_count` events with `info.last_token_usage` (`input_tokens` includes `cached_input_tokens` and `cache_write_input_tokens`, which are subtracted), under the latest `turn_context`'s model. A call with more than 272,000 input tokens, cached included, is marked long. An event is skipped before any `turn_context`, or when its `total_token_usage` equals the last counted one (Codex repeats unchanged events). When the counters restart (`total_token_usage` equals `last_token_usage`), Codex can later replay that first request of the new sequence, so its timestamp and `last_token_usage` are kept (as a hash), and a restart to that exact event again is skipped without changing the last counted total. A later request that restarts with the same counters at another time still counts, and a zeroed `total_token_usage` forgets the kept first request. Current Codex forks and subagent rollouts start their own counts rather than copying the parent's `token_count` events (checked against 0.163 rollouts), so no fork suppression is needed.
- **Copilot CLI**: `session.usage_record` events, one per model call of the main agent and each subagent: `data.usage.model`, `inputTokens` (which includes `cacheReadTokens` and `cacheWriteTokens`, and marks the call long above 272,000) and `outputTokens`. Current Copilot CLI writes the model and the cache split; a record without a model (as in the scrubbed `copilot-subagents.jsonl` capture) counts under `unknown`, with no price. Copilot bills premium requests, so its cost is an API-equivalent estimate, and the card says so.
- **Model ids**: at most 64 characters of letters, digits and `._:/[]-`, else `unknown`, so only plain ids leave the machine.
- **Index**: `usage-costs.json` (0600, data dir) keeps, per transcript path, its device and inode, size, the offset just past its last complete line, Codex's current model, last counted total and current sequence's first request (as hashes), the token sums per 15-minute UTC slot, model, fast mode and long call, and the hashed Claude keys it counted with their slot and output.
  - A scan reads each file from its offset to its size in 1 MiB chunks and consumes only newline-terminated lines (a line over 8 MiB is skipped), so a partial last line is read again once complete. A file whose size is unchanged is not opened past `fstat`. A file that shrank, or whose device or inode changed, loses its counts and keys and is read again from the start.
  - A compressed rollout cannot be read from an offset, so it is decoded (with the pure-Rust `ruzstd`) and read whole whenever its device, inode or size changes. The decoder's window is limited to 8 MiB, as for Resume, and decoding stops past 512 MiB of output; a file that decodes past that, or fails to decode, is recorded with no counts until it changes.
  - Slots and keys older than 32 days are dropped at the end of each scan, as are files that disappeared or went quiet. A scan that changed the index encodes it under the lock and replaces it atomically after releasing the lock. A format change bumps its version, and an index of another version is discarded and rebuilt. A file that a resumed copy deduplicated against takes the shared records with it when deleted, until the copy is read again from the start.
- **Scans**: `usage.costs` starts a scan on its own thread unless one is running or one finished in the last 15 s (monotonic clock), then answers at once from the index, so a cold scan never holds up the request or the connection. The scan holds the index lock only to merge one file, so a reply during a cold scan has the totals so far and `scanning: true`. A first scan of about 4 GB of transcripts takes a few seconds; a later one, a fraction of a second.
- **Prices**: `crates/collied/data/prices.json` holds LiteLLM's `model_prices_and_context_window.json` entries for `anthropic` and `openai` chat and responses models: input, output, cache read, cache write and one-hour cache write rates per token, OpenAI's rates above 272K input tokens, and the fast-mode multiplier. `just prices` refreshes it, and LiteLLM's license beside it, from the commit pinned in the justfile; collied fetches nothing at runtime.
  - Lookup lowercases the id, drops a `[...]` suffix (Claude Code's `[1m]`) and a provider prefix, writes Claude ids with `-` for `.` (Copilot's `claude-opus-5.5` is Claude Code's `claude-opus-5-5`), then tries the id without a trailing `-YYYYMMDD`.
  - A cache rate the table lacks is the input rate; a missing one-hour rate is the plain cache write rate. A long call uses the above-272K rates where the table has them; only OpenAI's above-272K tier applies, not other tiers such as Claude Haiku 5.5's above-100K rates. Fast mode multiplies every rate. Cache savings are cache reads times the input rate less the cache read rate.
- **Phone**: each machine's card asks on appear, when the range or the machine's link changes, and on pull to refresh, then every 2 s while `scanning`. A failed read keeps the figures already shown for the same range and retries while they are still partial; a new range starts from a spinner. Token sums saturate rather than overflow. A session below revision 28 refuses the method locally, and the card asks to update collied on that machine. Swift Charts draws the daily cost for 7 and 30 days.

Security: [Agent transcripts on the Mac](threat-model.md#agent-transcripts-on-the-mac).

## Starred agents

- `agent.star {terminal_id, starred}` (Drive class: audited and rate limited) stars or unstars a pane and sends `flock.changed` so every session refetches. Starring reads `session.snapshot` and answers `not_found` for a terminal herdr does not list; unstarring reads nothing, so it works for a pane already gone.
- collied keeps the stars in `stars.json` (0600, data dir), one set per machine shared by all of the owner's paired phones, as `terminal_id` to `pane_id`: herdr gives every pane a new `terminal_id` when it restores its session (after a reboot) but keeps the `pane_id`, and a cross-workspace move does the reverse. On each `flock.snapshot`, and every second in the reconcile loop while a star is missing from that tick's `agent.list` at its last pane (a shell pane, a closed pane, a restore or a move; with or without a phone connected, at the cost of one more `session.snapshot` per tick), collied keeps a star whose terminal is listed (updating its pane id), moves one whose terminal is gone to the terminal now in its pane, and drops the rest. A snapshot with no pane changes nothing, since herdr answers before it restores its panes. `pane_id` never leaves the machine.
- The snapshot carries them as `Flock.starred` (additive, no version bump, but the app and collied update together since client params deny unknown fields). A star survives an app reinstall (the first snapshot after pairing again lists it), a phone offline or reconnecting (the phone never prunes; it shows what the cached snapshot lists), an agent exiting (its pane stays) and a herdr restore. It goes when its pane closes or a phone removes the machine (`unpair` clears them all). Starring needs the machine reachable. Gaps: a pane id herdr reuses for a new pane within about a second (or while herdr is unreachable) takes the old star with it, and a move followed by a herdr restore in that window loses the star. Closing every pane keeps their stars, since an empty list is not trusted, and a new pane that gets one of their pane ids inherits that star.
## Terminals

A pane with no agent is a plain shell: herdr keeps the pane and its `terminal_id` when the agent exits (verified on 0.9.3). The phone lists shells, shows their screen and types into them under the rules below. Security: [Shell input from the phone](threat-model.md#shell-input-from-the-phone).

### Opt-in

```toml
[terminals]
enabled = true   # false, the default, when the section or the key is absent
```

- Read at start (`ServerConfig.terminals`), so a change needs a restart, which ends every session. No method changes it; only `collied apns import` and `collied setup`'s push step rewrite `collied.toml`.
- Off: `flock.snapshot` has `terminals: []` and no `terminals_enabled`, and every `terminal.*` request but `terminal.lock` (always `ok`) answers `terminals_disabled` before any herdr call, audited.
- `pane.read` reads agent panes only, whatever the setting.

### What is a shell

- A pane is a shell when its `PaneInfo.agent` is absent and its `terminal_id` is not in `session.snapshot.agents`, which includes agents herdr is still launching. Before every write collied checks this on a fresh snapshot, never a cache, and also refuses while an approval is pending on the terminal: hook-driven approvals see an agent before herdr does.
- `flock.snapshot` lists shells as `Terminal {terminal_id, workspace_id, label, cwd}`: the herdr pane name, and the foreground process's directory, else the pane's. Titles a program sets (`terminal_title`, which a zsh theme fills with the running command) never leave the machine.

### Grants

- **Terminal key.** A second Secure Enclave P-256 key beside the TLS key, created with `.userPresence` and `kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly`: every signature needs Face ID or the passcode, and removing the passcode destroys the key. Only the simulator uses a software key, behind a LocalAuthentication prompt.
- **Registration.** `pair.complete` carries `terminal_key` (base64url of the 91-byte SubjectPublicKeyInfo). The pairing fails (audited `invalid terminal key`) unless it is a P-256 key other than the session's TLS key, which would sign without Face ID. The machine's y/N prompt says whether the key is none, new, unchanged or a replacement. collied keeps the key in the peer record, which pairing again replaces whole, so a pairing without a key forgets it. The phone keeps its paired key in `machines.json` and answers `TerminalKeyMissing` (pair again), before any Face ID, when its current key differs, as after the passcode was removed.
- **Challenge.** `terminal.challenge {terminal_id}` needs a stored key (else `terminal_key_missing`) and a shell, and answers `{terminal_id, challenge, ttl_ms: 60000}`: 32 random bytes, one outstanding per session, a new one replacing it. Issuing one is not audited.
- **Grant.** `terminal.grant {terminal_id, challenge, signature}` burns the session's challenge on any attempt. The signature is ECDSA P-256 with SHA-256, DER, base64url, over `u32be(len) || bytes` of each of `"collie terminal grant v1"`, the machine's node ID (on the phone, the one pinned at pairing), the `terminal_id` and the challenge (`protocol::terminal_grant_message`). collied verifies it with the stored key and answers `{terminal_id, ttl_ms: 300000}`, else `terminal_locked` with the reason.
- A grant covers one terminal in one session for 5 minutes (`terminal::GRANT_TTL`, not a `collied.toml` key) and is bound to the key that verified it; at most 16 per session. Grants and challenges live in collied's memory only (lock order peers, sessions, terminals). They end with `terminal.lock`, the session, a revoke, unpair or re-pairing, an agent seen on the terminal, and a collied restart.

### Watch and input

- `terminal.watch {terminal_id, lines?, low_data?}` needs a live grant and shares the session's one watch, and its events, with `agent.watch`. It reads nothing while the session has no live grant for the terminal under the peer's current key (a new grant resumes it) and ends with `flock.changed` when the pane closes or an agent starts in it. `agent.watch {terminal_id: null}` stops either kind.
- `terminal.run {op_id, terminal_id, text}`: one line of `PromptText` (no control, bidi or invisible format character), sent as `pane.send_input` with `keys: ["enter"]`, the one ordered write `herdr pane run` makes (verified on 0.9.3 with sh and zsh). On macOS, herdr 0.9.5 refuses a line over the canonical input limit while the pane is in canonical mode, as a starting shell is; collied answers `too_large` (wait for the prompt, then retry) and keeps nothing else of herdr's message.
- `terminal.send_keys {op_id, terminal_id, keys}`: at most 16 keys from the closed `Key` list. It leaves out ctrl+d, ctrl+z and ctrl+r, which would widen `agent.send_keys` too; ctrl+j and ctrl+m, which submit like Enter without its checks; and ctrl+o and ctrl+t, which open Claude Code and Codex transcript views the scrolled-up check may miss, so later keys could answer a prompt hidden behind them.
- Both go through the `op_id` outcome cache. herdr targets panes by `pane_id` and reuses pane ids, so right before the write collied reads the snapshot again: an agent there now gives `not_found` and drops the terminal's grants. It then requires the peer, a grant of the session that sent the operation under the peer's current key, and no pending approval, else `terminal_locked` (never `not_paired`, which would stop the phone reconnecting). A retry from the phone's next session replays the first attempt, still checked against the first session's grant. A herdr error from these writes keeps only its code, since its message may quote the input. Nothing checks the foreground process: ctrl+c and answers reach whatever runs in the shell.
- `terminal.lock` ends the session's grants and terminal watch.
- Creating shell panes (`tab.create`) is a follow-up.

### Audit

| Method | Target | Result |
|---|---|---|
| `terminal.challenge` | `<terminal_id>` | refusals only |
| `terminal.grant` | `<terminal_id>` | every attempt: `granted ttl=300s`, or the error with its reason |
| `terminal.watch` | `<terminal_id>` | `ok` or the error |
| `terminal.run` | `<terminal_id>` | `ok` or the error; never the text or its length |
| `terminal.send_keys` | `<terminal_id> keys=ctrl+c,enter` | `ok` or the error |
| `terminal.lock` | none | `ok` |

### Phone

- The app passes the terminal public key to collie-core at start and on every foreground, since the Keychain item is readable only while unlocked. A new connection starts locked and never resumes a shell watch by itself: grants are per session.
- On `.background`, not on inactive (the Face ID sheet makes the app inactive), `lock_terminals` locks every terminal on the phone, then sends `terminal.lock` to each connected machine; any answer but `ok` closes that machine's session, which ends its grants.
- When its agent exits, the agent screen becomes the pane's terminal. Face ID runs only from the unlock button or an input, with a fresh `LAContext` each time (no reuse duration); a cancelled prompt sends nothing. The input is a one-line command field without autocorrection, smart punctuation or dictation.
- The Agents list and grid show shells under "Terminals", with no grid preview, which would need a grant. The inbox and Live Activities stay agents only; notification actions, the Live Activity intent and the lock-screen decide never send `terminal.*`.

- Pure Swift, no CollieCore, no network. It shares only `Sources/Shared`, the App Group `group.dev.rbstp.collie` and the notification keys' Keychain access group with the app.
- It authenticates the display envelope against node, thread, event and approval IDs before replacing title and body and restoring the terminal ID. Only authenticated content offering a decision gets the approval category; on failure or timeout the generic original shows, without controls.

- Codex alert context leaves out the user-input region before an assistant response. For a structured question on Codex 0.162.1's detection screen, it is the text between the last `Question N/M (K unanswered)` heading and the first numbered choice, wrapped lines joined, read only while the screen ends with the exact submit or notes footer. ## Menu bar app (macOS)

CollieBar (`Mac/`) is its own XcodeGen project, leaving the iOS project untouched: pure Swift, no packages, no CollieCore, a SwiftUI `MenuBarExtra` with `LSUIElement` (no Dock icon).

- It talks to collied only over the control socket, like the CLI, with three requests: `watch`, `pair` (then `confirm`) and `peers_list`. It opens no listener and reads none of collied's data files; Open Audit Log hands `audit.log` to Console.
- `watch` is read-only and not audited, like `status`: collied answers `{"type":"watch","pending_approvals":N,"collied_version":"VERSION"}` at once and again whenever the pending count changes. It does not subscribe to the phone event broadcast, whose receiver count means a phone is connected. An open connection means running, EOF off; a failed connect is retried every 2 s, the app's only polling. The menu shows this connection's `collied_version`, never the installed binary's, or version unavailable without one. No version bump: `collied_version` is an optional additive field on the local control reply; the phone protocol is unchanged.
- While collied is off, Set Up runs `~/.cargo/bin/collied setup` in Terminal through a private 0700 command file that quotes the path and removes itself before exec, or if Terminal cannot open, so it needs no Automation permission or shell interpolation. Setup keeps its own signature check and prompts.
- Turn Off, Turn On and Quit run `collied stop` or `collied start` through the plist's `ProgramArguments[0]`, without a shell, so launchd's semantics (disabled until `start`, across reboots) stay in one place. The socket cannot do it: a stopped collied has no socket, and `KeepAlive` would restart one stopped from inside. A collied run by hand, outside launchd, is not stopped.
- Pairing shows what `collied pair` shows, with 60 s to answer: the QR (correction level M), then the candidate's identity, terminal key change and any pairing it replaces, each phone string escaped like `collied::printable`. Pair is not the default button and is live only 1 s after the candidate appears, the window's `tcflush`; it sends one answer, never on its own. Only the QR image is kept: the invite is never shown as text, copied, logged or stored, and window restoration is off. Closing the window cancels, as Ctrl-C does.
- Open at Login uses `SMAppService.mainApp`, off by default.
- `just mac-install` signs it with the Developer ID (team `RM3UT3MMSR`) and the hardened runtime, without App Sandbox (which would block the socket and running collied) or entitlements, so it needs no App ID or provisioning profile. Notarization (`just mac-notarize`) is needed only to run it on another Mac without a Gatekeeper prompt.
- Its unit tests have no host app, so they never launch it against the live socket.

## Bar widget (Linux, Omarchy)

CollieTray (`Linux/CollieTray`) is CollieBar for the Omarchy shell: a third-party Quickshell plugin, `rbstp.collie`, with one `service` (`Service.qml`) for the shell and a `bar-widget` (`Panel.qml`) per monitor's bar. It sends CollieBar's exact control socket lines through Quickshell's `Socket`, with the same `watch` states, 2 s retry and version display; `peers_list` runs when the menu opens, and each pairing gets its own connection.

## Live Activities

The lock screen and the Dynamic Island show an agent only while the user follows it: off by default, at most 5 at once on the phone. The phone starts each activity from the foreground; collied only updates and ends it. Push-to-start is unreliable from background wakes, so it is not used.

### Phone and collie-core

- Following starts an `Activity` (`pushType: .token`) with the agent's current state and registers each update token with that agent's Mac, again on every foreground. The app's title for the agent (its terminal title, at most 64 characters) is encrypted in the static attributes and fixed for the activity's life; collied's pushes carry the agent name or kind. Unfollowing ends the activity at once and tells the Mac.
- collie-core keeps push and activity registrations per machine in memory only and sends them on every connection, `push.register` first, since collied takes the APNs environment from it. It sends an end the Mac has not acknowledged on every connection until it answers, even after an app kill, from `activity-ends.json` in the state dir (0600, atomic; per machine, only `activity_id` and end time, at most 16). At start it loads only paired machines' ends under 8 h old, since collied has expired older activities, and ignores an unreadable file; removing a machine drops its ends.

### Protocol

- `push.activity_token {activity_id, terminal_id, token, shows_approvals?, display_binding?}` and `push.activity_end {activity_id}`, both `MethodClass::Push`. `activity_id` is ActivityKit's `Activity.id` (`[A-Za-z0-9-]`, at most 64); `token` is the update token in hex (64 to 256 characters, redacted in `Debug`). `shows_approvals` (omitted when false) means the activity shows an approval's command and buttons; collie-core always sends `true`, since every activity the app starts carries the Mac's node id.
- No version bump: push and activity registrations require the negotiated `encrypted_display_v1`; peers without it keep ordinary tailnet operations but cannot register this codec. The optional activity binding is sent only with that capability.

### collied

- Stored in `push.json` (0600, atomic) under `activities`: `{stable_id, activity_id, terminal_id, token, environment, registered_at, shows_approvals, display_binding}`.
- Bound to the session's `StableID`: a device registers, replaces and ends only its own activities. The same `activity_id` or `terminal_id` from that device replaces the old entry, so an activity the phone never ended holds no slot. The environment is the device's own from `push.register` (`not_found` without one). At most 8 per device (`too_large` beyond). Ending an id the device does not have answers `ok`.
- Dropped on `push.activity_end`, on revoke, at start for peers no longer paired, on `Unregistered` or `BadDeviceToken`, when the terminal is gone, and quietly (no push, audited `ended: expired`) 8 h after that `activity_id` first registered, since ActivityKit ends an activity 8 h after it starts.
- Updates come from the 1 s agent reconcile, after the approvals pass, never from terminal output. Per activity:
  - first sight (a new activity, a new token, or a collied restart): one update without alert;
  - content changed: an update, at most one per 2 s (a change inside the gap goes out on the first reconcile after it); a status change alone never alerts, since the end of a turn is the [done alert](#apns);
  - an approval routed to the activity ([below](#approval-on-the-activity)): in the same reconcile, whatever the gap;
  - nothing changed: the same content every 10 min, moving the stale date while the Mac is up;
  - the terminal missing from two reconciles in a row: `end` with `dismissal-date` = now + 60 s, then the token is dropped. A failed `agent.list` (herdr down) changes nothing.
- Every send re-checks the pairing. The audit log has one line per register (`push.activity_token`, target `<terminal_id> activity=<activity_id>`) and per end (`push.activity_end`, `ended: agent gone` or `ended: expired`); tokens are never logged or audited.

| Header | Value |
|---|---|
| `apns-push-type` | `liveactivity` |
| `apns-topic` | `<bundle_id>.push-type.liveactivity` |
| `apns-priority` | 10 for the update carrying an approval alert; 5 for every other update, refresh and end |
| `apns-expiration` | for the update carrying an approval alert, the approval's expiry, as for the alert it replaces; now + 5 min for every other |
| `apns-collapse-id` | none |

```json
{"aps":{"timestamp":1791028800,"event":"update","content-state":{"v":1,"enc":"<authenticated envelope>"},
        "stale-date":1791029700,"alert":{"title":"Collie","body":"An agent needs attention"}},
 "node_id":"nMAC","event_id":"<opaque event>"}
```

- `timestamp`, `stale-date` (now + 15 min) and `dismissal-date` are Unix seconds; `alert` is present only on an approval alert. Public relevance scores are omitted so status does not leak through ranking.
- `content-state` is exactly `{v:1,enc}` for initial, local, update and end state ([Encrypted display envelope](#encrypted-display-envelope)). [protocol/live-activity-content-state.json](protocol/live-activity-content-state.json) describes the decrypted `state`; [protocol/push-display-vectors.json](protocol/push-display-vectors.json) holds the wire vectors.

### Approval on the activity

- A device that follows an agent gets that agent's approvals offering Approve and Deny on the activity alone: one alert expands the Dynamic Island with the command and both buttons, and no approval notification comes. Any other prompt, such as a question, a plan or a Codex or Copilot prompt, goes as the approval alert, without actions.
- Only an activity registered with `shows_approvals` takes approvals. Without a current encrypted display binding an activity gets no private state, and an urgent send that cannot be encrypted falls back to the encrypted approval notification.
- When `alert_due` lets an approval alert go out, paired devices without such an activity for the terminal get the approval alert. A device with one gets, in the same reconcile, a priority 10 activity update with a generic `aps.alert` and encrypted state holding `approvalId` and the inner context `enc`, sealed to that device's notification key like the alert's `enc` (AAD = `approval_id`; none without a key or a context) and cut at 600 JSON-escaped bytes, so the update fits APNs' 4 KB with labels at their caps. The approval alert's rate limits decide whether it alerts, so an approval alerts once either way.
- A reissue that `alert_due` keeps quiet reaches only the activity, as a priority 5 update without alert carrying the new `approvalId` and `enc`, so its buttons never decide a burned approval.
- Fallback: if the activity push fails (any APNs or network error, or a dead token, dropped as usual), or the activity or the agent is gone by push time, the device gets the approval alert at once.
- Late fallback: APNs accepts pushes to an activity the phone has ended (dismissed, ended by iOS while suspended, Live Activities off, an update dropped by iOS's budget or replaced while offline), and nothing tells collied. So an approval that alerted on an activity and is still pending, and not being decided, 2 min later also goes to that device as the approval alert, once, never on top of the early fallback. The cost: a user who has not answered within 2 min gets the notification as a reminder, and a dead activity delays the alert by up to 2 min. Both timers live in collied's memory; a restart reissues pending approvals, which alert again.
- The inner `enc` is sealed once per device and approval and repeated inside freshly sealed outer envelopes on later updates, so coalescing still sees an unchanged state. Once the approval resolves or the agent leaves `blocked`, the next update omits `approvalId` and `enc` and coalesces normally, without alert. An `end` never carries them.
- On the phone, `AgentActivityAttributes` carries the Mac's `nodeId`. The widget authenticates the whole state against its node and activity binding, then opens the inner command for the lock screen and the expanded Dynamic Island, `privacySensitive` so it is redacted while locked. Failed authentication shows a neutral display without buttons; authenticated blocked state without a command shows "Approval needed". Approve and Deny appear only with a command that decrypts. Their `LiveActivityIntent` requires authentication, so iOS makes the user unlock first; the intent then takes the notification actions' path in the app ([Lock-screen approval](#lock-screen-approval)).

## `collied setup`

One interactive command adds a Mac or a Linux machine, or updates one in place. It reuses the subcommands' code through a small `setup::Host` trait, so unit tests check the step order and skip rules against a fake; only the service backend differs per OS. Each step checks its own done state, so a rerun resumes where the last one stopped:

| Step | Done when | Otherwise |
|---|---|---|
| login | the daemon answers `status` with backend `Running`, which it does only once its node passes the ownership checks; a loaded job first gets 20 s, for a daemon `just collied-install` just restarted | unload a loaded job without disabling it (a crash loop or a logged-out daemon holds the node lock or the socket), run `collied login`, and if that fails start the job again |
| service | the plist on disk is what `install` would write, the job is loaded, and the daemon's `started_ms` is not older than the binary's mtime | `service install` (bootout, then bootstrap), then wait up to 60 s for the daemon, up to 10 s of it for an untagged device in its netmap, so a node that has just started does not trigger the policy hint; on a timeout print the last 20 lines of `collied.err.log`. A plist with another `--config` stops setup: run `collied --config <path> setup` |
| doctor | no fail line | stop: fix, then run setup again |
| push | `[push.relay]` or `[apns]` is in `collied.toml` | offer it: by default add `[push.relay]`; with `--direct-apns`, ask for the `.p8` (key ID from `AuthKey_<KEY_ID>.p8`), team and bundle IDs, append `[apns]` and run `apns import`, restoring the old config if the import fails. A new file is created 0600; an existing one is rewritten atomically, keeping its mode. Then restart the service so the daemon reads it |
| pair | never: phones may need to pair again after an update | offer `collied pair` |

Before any step, setup refuses unless stdin is a terminal, so `yes | collied setup` cannot answer the pairing prompt, and unless it runs as the regular file (not a symlink) `~/.cargo/bin/collied`, or a packaged `/usr/bin/collied` on Linux, Developer ID signed as `dev.rbstp.collied` on macOS. So the service never runs an unsigned binary or `target/release`, which the next `cargo build` replaces. Setup never confirms a pairing: the `y` typed after the `tcflush` does.

On Linux the service rows read:

| Step | Done when | Otherwise |
|---|---|---|
| login | as on macOS, where "loaded" is any `ActiveState` but `inactive` and `failed` (a unit restarting after a crash counts); while a daemon answers, only `active` counts, so a foreground `collied run` beside a restart loop is refused as running outside the service | `systemctl --user stop` (the unit stays enabled), `collied login`, and if that fails `collied start` |
| service | the unit file on disk is what `install` would write (executable, `--config`, pinned `XDG_*_HOME`), the unit is loaded, and `started_ms` is not older than the binary's mtime | `service install` (`daemon-reload`, `enable`, `restart`), then wait as on macOS; on a timeout print the last 20 lines of `journalctl --user -u collied.service` |

On Linux, setup also stops when the user manager loads `collied.service` from another file or applies a `collied.service.d` drop-in, when the unit pins another `XDG_DATA_HOME` (another node's data dir, so setup would log in a new node), or when it runs another `--config`. The direct APNs step stores the key as [APNs key on Linux](#apns-key-on-linux) describes, and never prints it.

Doctor's `service` line reports the same state on both OSes: `up to date`, or a warn naming what setup would do. It is skipped with a warn when doctor is not the installed binary, since the check compares the service with the running binary. On Linux it adds that the unit stops at logout when the user does not linger.

The control socket's `status` reply carries `started_ms` and `user_peers` (visible untagged nodes of the daemon's verified user; visible does not mean TCP-reachable), both with serde defaults; setup treats a daemon reporting neither as outdated. The phone protocol is unchanged.

On macOS, an interactive login without an auth key prints the URL and QR, then tries once to open the URL through `/usr/bin/open` with an argument array, only if it is HTTPS with exact authority `login.tailscale.com` (port 443 optional) and no userinfo. Failure is nonfatal. Noninteractive, auth-key and custom-control logins only print the URL.

Startup verifies the node's own user identity ([tailnet.md](tailnet.md)) before exposing any listener or the control socket, with no first-phone-owner fallback. A restarted node reports `Running` from Tailscale's netmap disk cache, which can lack the user profiles, so its own-address whois answers "peer not found" until control sends the live map: `collied run` and `collied login` repeat the whole check while whois gives exactly that answer, up to their start deadlines (60 s and 10 minutes), then fail with the usual error. Any other failure, a mismatch included, stops at once. Admission and the post-TLS gate recheck the self identity and a fresh peer whois, so changing the owner or tagging the running node refuses new sessions instead of rebinding trust. Local reauthentication requires stopping the daemon first; `collied login` prints Tailscale's last login error.

User ownership gives the embedded daemon its user's network privileges, not a separate service tag's confinement. [tailnet.md](tailnet.md) covers doctor's `reach` line and setup's policy hint, key expiry, scoped state reset, reauthentication and the physical-device and corporate VPN acceptance gap.

### Paths

| What | macOS | Linux |
|---|---|---|

Verified: herdr 0.9.3 on Linux puts its socket at `$XDG_CONFIG_HOME/herdr/herdr.sock` (mode 0600), not under `XDG_RUNTIME_DIR`.
- tsnet creates an empty `~/.local/share/tailscale` (0700) for a non-root user; collied keeps its node state only in `<data dir>/tsnet`. A system tailscaled (root, `/var/lib/tailscale`) is untouched: the embedded node is a separate device with its own keys.

### Embedded node ownership

Both OSes use the same user-owned node rules; doctor fails if the node has tags. E2E nodes have private userspace state and no tags, under a local control plane that models same-user and foreign-user ownership. The Linux display-kind fixture changes only test netmap OS metadata: the platform never authorizes a peer. Neither daemon calls the native Tailscale CLI, changes system routes or reads the system VPN's account or state.

### systemd user unit

`collied service install` makes the data dir private, writes the unit with the canonical executable and `--config` paths (0644, through `collied.service.tmp` and a rename), runs `daemon-reload`, checks that the user manager loads the unit from that file (`FragmentPath`), then runs `enable` and `restart`. With another unit of that name, or another `XDG_CONFIG_HOME` in the manager, the check fails the install (the written file stays) instead of reporting success for a unit that never starts.

```ini
# Written by `collied service install`; rewritten on every install.
[Unit]
Description=collie daemon: herdr agents over the tailnet
Documentation=https://github.com/rbstp/collie
StartLimitIntervalSec=0

[Service]
Type=exec
ExecStart="<exe>" "--config" "<config>" "run"
Environment="XDG_DATA_HOME=<dir>"
Environment="XDG_CACHE_HOME=<dir>"
Environment="XDG_CONFIG_HOME=<dir>"
Restart=always
RestartSec=2s
RestartSteps=5
RestartMaxDelaySec=1min
UMask=0077
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectSystem=strict
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectKernelLogs=yes
ProtectControlGroups=yes
ProtectClock=yes
ProtectHostname=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
RestrictNamespaces=yes
LockPersonality=yes
MemoryDenyWriteExecute=yes
SystemCallArchitectures=native
SystemCallFilter=@system-service
SystemCallErrorNumber=EPERM
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK

[Install]
WantedBy=default.target
```

The `--config` pair appears only when `--config` was given. No `User=`, no socket activation, no listener.

**Quoting** follows systemd.syntax:

| Field | Rule |
|---|---|
| `ExecStart=` executable | absolute UTF-8 path with no `"`, `'` or `\`, else install refuses; quoted, `%` doubled (systemd does not expand `$` there) |
| `ExecStart=` arguments | quoted; `\` and `"` escaped; `%` and `$` doubled |
| `Environment=` | the whole `KEY=value` quoted; `\` and `"` escaped; `%` doubled (`$` is literal there) |
| every field | control characters and non-UTF-8 paths are refused |

A test runs `systemd-analyze --user verify` on a unit with such characters in its paths, where systemd-analyze and a user manager exist.

**Pinned XDG.** A unit the user manager starts (at first login, or at boot with linger) does not get `XDG_*_HOME` from the session (verified on the dev machine). So the unit pins `XDG_DATA_HOME`, `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` to what the installing CLI resolved, fallbacks included; otherwise the daemon could use another data dir (control socket, peers), attachments root and herdr socket than the CLI. `HERDR_*` is not captured, as with launchd: `[herdr] session` in `collied.toml` picks a session.

**Restart** gives launchd's KeepAlive without a hot loop: the delay grows from 2 s to 1 min, and `StartLimitIntervalSec=0` means systemd never gives up. collied exits when the tailnet listener fails for good, so the manager restarts it.

**Sandboxing** is best effort: in a user manager most of these settings rely on unprivileged user namespaces, and systemd skips them where those are unavailable. `ProtectSystem=strict` leaves the home directory and `/run/user` writable in a user unit. `UMask=0077` always applies.

| Command | `systemctl --user` |
|---|---|
| `collied stop` | `disable --now`, then `reset-failed`: off across logouts and reboots until `collied start`; the unit file stays. Fails when the unit file is not installed |
| `collied start` | `enable`, then `start` unless already active. Fails when the unit file is not installed |
| `collied service uninstall` | `disable --now` (when the file exists), remove the file, `daemon-reload`, `reset-failed`; refuses when the unit runs but its file is not at that path |

- A user unit runs while the user has a session; `loginctl enable-linger` keeps it running without one. The launchd agent likewise runs only in the GUI session.
- `just collied-install` on Linux builds in release, copies the binary to `~/.cargo/bin/collied` as a fresh inode (the running daemon keeps its copy until it restarts) and restarts the unit if it is active.

### Kernel TCP listener check

`tailnet::kernel_tcp_listeners(pid)` lists the kernel TCP sockets in LISTEN state that a live process (checked with signal 0) holds, for doctor's `listen` line and the tailnet `end_to_end`, e2e and collied server tests. It never reports an error as an empty list.

- macOS: `/usr/sbin/lsof`, by absolute path. Apart from exact copies of the three-line warning lsof prints for a mount point it cannot stat() (macOS mounts disk images under the temp folder; the warning never affects socket rows), any stderr, or an exit other than 0 or 1, is an error.
- Linux: the socket inodes from the `socket:[N]` links in `/proc/<pid>/fd`, matched against the LISTEN rows (state `0A`) of `/proc/<pid>/net/tcp` and `tcp6`, after checking the table header. It skips an fd closed during the listing, and a missing `tcp6` table when there is no IPv6 stack (no `/proc/sys/net/ipv6`); any other read or parse error is an error.

### APNs key on Linux

Each machine has its own APNs key (own key ID, revoked on its own), so a Linux machine pushes when the Mac is off. The default store is `key = "systemd-creds"` ([APNs](#apns)).

- The credential is `<data dir>/apns/<KEY_ID>.cred`, named `collied-apns-<KEY_ID>`. The name is sealed in it, so a credential renamed or copied for another key ID does not decrypt. collied always passes the name, since an empty or missing one skips systemd's check of the sealed name.
- collied runs `systemd-creds --user --no-ask-password {encrypt|decrypt} --name=collied-apns-<KEY_ID> - -`, stdin to stdout (at most 64 KiB each way), never through a file, and zeroizes the decrypted key after use. It runs `systemd-creds`, `systemctl`, `systemd-analyze`, `loginctl` and `journalctl` by absolute path (`/usr/bin`, else `/bin`, else `/run/current-system/sw/bin`), never from `PATH`.
- The credential file gets the `key_path` checks (0600 regular file owned by the user, opened with `O_NOFOLLOW`).
- The daemon, `collied apns test` and doctor decrypt the credential each time they load the key.

`collied apns import AuthKey_<ID>.p8` makes the same checks as on macOS, without the signature check, then:

1. Encrypts the key and writes the credential itself (0600, `O_NOFOLLOW`, atomic), since systemd-creds would write its output file with the umask's mode. It decrypts and compares the new credential before storing it, and reads it back and compares after.
2. Keeps an existing credential that decrypts to the same key, unless only the new one has a TPM2 seal. An existing credential that no longer decrypts, or holds another key, fails the import.
3. Rewrites `[apns]` to `key = "systemd-creds"` (the default, so nothing to rewrite without a key line).
4. Asks y/N to delete the original file, only if it is still the same inode.

If systemd-creds cannot encrypt (no systemd, no `systemd-creds.socket`, systemd older than 256, a container), import says so, copies the key to a 0600 `<data dir>/apns/AuthKey_<KEY_ID>.p8` (an existing file there is kept and must hold the same key), points `key_path` at it and offers the same delete (not when the imported file is that copy). If `<KEY_ID>.cred` already exists, a failed encrypt fails the import: it never falls back to a plaintext file.

**Seal.** An unprivileged caller cannot choose the key with `--with-key`. systemd's varlink service (`io.systemd.Credentials`, behind `systemd-creds.socket`) seals with the host key plus the TPM2 when a TPM2 is usable, else the host key alone, and silently falls back to the host key alone if TPM2 sealing fails. So collied reads the seal from the credential header: the first 16 bytes after base64 decoding are the key type id (ids from systemd `src/shared/creds-util.h`, v261 and main). The dev machine (T2 Mac hardware) has no TPM2: host key only.

The first encrypt on a machine makes systemd create `/var/lib/systemd/credential.secret` (root, 0400). The credential stops decrypting after an OS reinstall, a machine-id change, a uid or user name change, or a restore to another machine: import again from the backup.

**Doctor** on Linux has no `codesign` line. Its `apns` line:

| State | Result |
|---|---|
| credential, host key | ok, "host key only (no usable TPM2)"; warn when `systemd-analyze has-tpm2` finds a usable TPM2 (import again to bind it) |
| credential, host key and TPM2 | ok, "host key and TPM2" |
| credential, TPM2 only | ok, "TPM2" |
| credential, null key | fail, "null key, not encrypted" (integrity only) |
| credential, unrecognized seal | warn, "unrecognized seal" |
| credential missing or not decrypting | fail |
| `key_path`, systemd-creds works | warn: encrypt it with `collied apns import` |
| `key_path`, systemd-creds unavailable | ok: "0600 file fallback (systemd-creds unavailable): protected by its mode only" |

Only with `key_path` does doctor probe systemd-creds, by encrypting and decrypting a test value named `collied-apns-doctor-probe` (on a machine with no credential yet, that first encrypt creates the host secret). As on macOS, doctor also signs a provider token as a dry run and warns about any other `.p8` in `<data dir>/apns`.

**Storage difference.** Other unprivileged users cannot decrypt the credential, but any process of the same UID can, without a prompt: nothing binds it to one application, as the Keychain ACL binds the macOS key to the Developer ID signed collied. Same-UID malware on Linux can read the key, not only use collied to send pushes. The 0600 fallback is protected by its mode only. Details: [threat-model.md](threat-model.md).

### `collied status`

On both OSes, `collied status` also prints `tags:` (`(none)`, or `(not reported)` when the node status failed) and, when herdr answers, `agents: N` and one terminal-escaped line per agent (status, name or kind, workspace label, `terminal_id`): what the phone would see, from the daemon's herdr `session.snapshot` mapped as for `flock.snapshot`. A flock too large for one control line is left out (`too many to list here`), so the status request, which is also the liveness probe, never fails on a large session. The control reply's `tags`, `flock` and `flock_too_large` have serde defaults, so a newer CLI still reads an older daemon's reply.

The watch app's Usage list always shows every window.
  - Freshness: each reading carries its own source timestamp; none counts as stale. A stale rectangular reading shows an orange dot beside its countdown; a missing or expired one, a dim gauge with "No data". Missing circular tracks are dim and dashed, with `--` in the center when no shown ring has data. A reset dims that ring until fresh usage arrives. The watch stores its last successful phone receipt time separately, so old data never makes its source timestamp fresh.
  - Timeline: entries every five minutes in one-hour batches, plus entries at stale transitions and resets within that hour, at most 19 per batch so watchOS never archives a full day of rectangular layouts at once; then another timeline from cached data. An empty or expired timeline retries after 15 minutes. Snapshot requests outside the widget gallery also read cached usage; sample values are for previews only. Changed usage reloads the complication at once; opening the watch app or receiving unchanged usage republishes cached usage and reloads it at most once a minute. A failed cache write stays eligible for retry.
  - Both families link to `collie-watch://usage`, a details screen with percentages, exact reset times, reading ages and the last phone sync, its cards in watchOS 26 Liquid Glass inside a shared `GlassEffectContainer`.

## Client runtime

- collie-core runs one connection supervisor per paired machine, each with its own backoff, request queue and link state, so a machine that is off affects only its own section.
  - Backoff 3, 4, 8, 16, 30, 60 s, reset after 30 s connected. While the phone's tailnet is offline it waits, re-checking every 3 s and at once when the node first reaches Running.
  - An auth failure stops the link until the next resume or manual retry, which dials and checks everything again, so a transient failure never strands a link until a relaunch. Only a known, wrong self identity is a self-ownership failure: a tagged self node, a user other than the paired owner, an own-address whois naming another node or user, or a self node with a positive user and StableID but no Tailscale address. A self node without a positive user or StableID, or a failing own-address whois (a node restarted after a suspend answers "peer not found" from its netmap disk cache until control sends the live map), is retried like a failed status call.
  - A protocol version mismatch also stops the link, naming the side to update (collied sends its version in `unsupported_protocol`). Requests fail at once with that message until the next resume or manual retry dials again, so an update needs no new pairing.
  - A machine the netmap reports offline is not dialed, since a 20 s dial to a dead peer occupies the node every machine shares. Its link is `Unavailable`: re-checked locally after 3, 6, 12, then every 15 s (every 3 s for 30 s after a resume, and from 3 s again after any other outcome), dialed once online, and dialed anyway every 15 min in case control is wrong. Pairing, lock-screen decisions and each reconnect request (a resume or a manual retry) dial once regardless, since the netmap can be stale right after a resume; an attempt that ends before the dial (failed status call, phone key not loaded) does not use up that dial.
  - A session that receives nothing for 45 s (collied pings every 15 s) times out and reconnects, so a machine that slept or lost power does not stay Connected.
  - A foreground after 10 s or more in the background reconnects at once (iOS suspends sockets without a close); a shorter gap gets a 3 s probe. For 10 s after a resume, failures (the old session's close, a node rebuilding its paths or not yet running) retry after 0.5, 1, then 2 s, with the link kept Connecting and no error shown. A failure from just before the resume is cleared and retried at once, the normal backoff restarts, auth failures still stop at once, and later failures use the normal backoff. A snapshot request cut off by the reconnect answers from the cache. A resume also moves an `Unavailable` link back to Connecting and dials it at once.
- Manual retry (`reconnect(machine_id)`): pull to refresh on the Agents list retries every machine, a tap on a machine's header retries that one. A live session gets the 3 s probe; any other link is dialed at once, past the offline flag.
- Offline reason: a link that is not connected carries an `OfflineReason` on `MachineFlock`, classified from what each attempt already reads (the node's status, then the dial), with no extra polling. It is the sentence under the link's pill ("offline", "retrying").

  | Link | Detected by | Reason shown |
  |---|---|---|
  | `Offline` | the phone's node is not `Running` (or not started) | "This phone is not connected to Tailscale. Sign in again or check the network." |
  | `Unavailable` | the netmap reports the machine's node offline | "\<machine> is asleep or off. Last seen \<time> ago.", from the peer's `LastSeen` in the node's status; without one, or with Go's zero time, the last sentence is left out |
  | `Waiting` | the netmap reports the machine online and the dial is refused (`connection was refused`) or runs out its attempt (`context deadline exceeded`) | "\<machine> is online, but collied is not answering. Run collied start there." |
  | `Waiting` | any other dial error, including a dial forced past the offline flag | "Cannot reach \<machine>." |

  TLS, pin, hello and version failures carry no reason and keep their own messages. The classification reads libtailscale's error text, which a concurrent failure on the same node can replace (`check_unlocked` in the tailnet crate), so at worst a reason names another dial's cause; a machine that just powered off can also read as not answering until control marks it offline. The reason clears when an attempt or a resume moves the link back to Connecting.
- Connection errors: the Machines tab shows the offline reason, or else the error itself, in a compact glass card with a button that copies the full error without navigating or retrying. The Agents layouts show under a machine's section header only the offline reason, or a version mismatch naming the side to update. Debug terminal demos take `COLLIE_DEMO_CONNECTION_ERROR` to show these errors without a live machine.
- The Agents tab reads the core's cache every 3 s (`agent.status` events keep it current), and every 0.25 s while a machine waits for a dial or its first list, or for the node during the 20 s after the tab appears (an offline link with no error can also be a node that never runs, logged out or with no network). The fast reads touch only the cache and leave a machine whose last read failed to the 3 s read. The tab asks connected machines for `flock.snapshot` when it appears, on pull to refresh, after a close and every 60 s, which covers shells (no event lists them) and an older collied that sends no title changes. When reconcile first finds herdr unreachable, collied sends `flock.changed`; the refetch fails with `herdr_unavailable`, which collie-core keeps on the link's view until a snapshot works, so the list shows the outage and asks for a snapshot every 3 s until it ends.
- Node recovery, for a node whose paths died while the app was suspended. On cellular, carrier NATs silently drop idle UDP mappings and TCP state, so the home DERP connection looks open until its 120 s read deadline. On any network iOS can defunct the node's UDP sockets, which ends wireguard-go's receive loop for them (health "The MagicSock function ReceiveIPv4 is not running"); a rebind replaces the sockets without restarting the loop, so the node receives only through DERP until restarted.
  - Rebind (`tailscale_rebind`) when no machine is connected 3 s after a resume from a suspend or 10 s or more in the background. Not sooner: a dial in flight during a rebind can stall for its whole 5 s attempt, and a healthy reconnect takes well under 3 s.
  - Restart when no machine has connected 10 s after the resume while the node reports Running and a machine still dialing or failing is online (or the node cannot report status), and on a manual retry while dials fail. The node is taken out of the slot and closed once only dial attempts hold it (a lock-screen decide holds it until answered); a new node starts from the same state and every link redials. The close fails a dial in flight at once, so a restart does not wait out its 5 s; a link failed that way, or waiting for a node start, shows connecting rather than an error or offline. Measured with the phone on the Mac's Wi-Fi: every reconnect that came at all did so within 7 s of the resume, rebind included, while a node the rebind did not help stayed unreachable until a restart or relaunch, which connected within seconds.
  - Immediate restart, without the rebind or the 10 s wait, of a node with the receive-loop warning: when a dial to a machine Tailscale reports online had already failed on it before the resume and nothing is connected, or when such a dial fails past the resume grace in the foreground. Measured on Wi-Fi: most resumes with the warning still connected within a second through DERP, but once a dial to the online Mac had failed, nothing connected until a restart, and with a 10 s wait on each resume a short visit never got there.
  - Requests queued meanwhile wait for the new node. The old node is put back instead when a machine connects in the meantime (no session is cut) or the app is suspended (a waiting lock-screen decide gets it at once); a restart whose node another restart already replaced does nothing. The restart holds the node-start lock, so a waiting lock-screen decide gets the new node and two nodes never share the state dir. If the new node cannot start, the restart tries again at once, then the next resume or manual retry does.
- Network changes: the app reports the interface `NWPathMonitor` routes through (Wi-Fi, cellular or wired, never a VPN tunnel; empty with no path) with `network_changed`; the first report is only recorded. Once a move to another interface, or back after no path, has held 1 s (the path can flap at the edge of Wi-Fi), the node is rebound with the new interface. A live session then gets the 3 s probe and is redialed only if it fails: its TCP runs inside the node and survives the move once the node reaches the machine again, but iOS reports no error when it does not, so it would otherwise last until the 45 s silence limit. Every other link is redialed past the offline flag with the resume grace. If nothing connects within 15 s (three dial attempts) while the node reports Running and a machine still dialing or failing is online, the node restarts as above. That check, like the 10 s one after a resume, is dropped when the path changed or a resume came since, and restarts only the node its flow started with. A move reported while the core is suspended rebinds the node at once, so a lock-screen decide binds to the new interface; the redial waits for the next resume. A Wi-Fi network replaced by another on the same interface without a gap is not a move.
- Diagnostics: each resume writes one line to the device log (subsystem `dev.rbstp.collie`, category `core`): the background time, whether the core was suspended, the node's backend state and health warnings, and per machine the link phase before the resume, the time since its last dial, its last error and whether the netmap reports it online. Path changes (`network path: en0 to pdp_ip0`), rebinds and restarts are logged with their reason and outcome; a restart also logs when it closes the old node, how long it waited for its holders and how long the close took. No keys, tokens or nonces.
- Snapshot plus sequence: `flock.snapshot` returns the `seq` it reflects; every event frame carries `seq`; the client drops `seq <= last applied`; unknown events still advance the cursor.
- Mutations are never replayed automatically, except a prompt to an unreachable machine: up to 5 attempts a minute apart (at once when the link reconnects while its agent screen is open), none later than 270 s after the first.
  - The app holds one such prompt per agent in memory, so resends continue after the screen closes until the app process ends, and stop when the machine is removed. A screen opened meanwhile shows it with its spinner, even over text loaded from the machine's box. Editing it, tapping the spinner, the agent exiting, or a different prompt sent from that screen stops it (the new one waits for any attempt in flight). A prompt that never arrived and that no screen shows returns to the agent's saved draft with a one-time "may not have been sent" note. The agent's last prompt is compared only when read with the link up. Not detected: a new agent started in the same pane before the resend would receive it.
  - Each retry is `resend_prompt`, which collie-core sends only under the `op_id` an unanswered identical prompt still holds (kept 300 s of wall time from its first send; collie-core reports `Unreachable` only while it holds it), and otherwise refuses with `NotResent`, sending nothing; only the user's Send mints an `op_id`. collied replays an attempt that arrived instead of typing the prompt twice. Its outcome cache lives in memory for 600 s, so a collied restart forgets the `op_id`; before each retry the phone treats the prompt as sent when the agent's last prompt changed to its first line, which covers most of that case.
- Lock-screen approve and deny over an authenticated tailnet session has no prior art; the flow is under [Lock-screen approval](#lock-screen-approval), and its timings still need measuring on device.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| libtailscale has no git tags and lags tailscale.com releases | security updates can be ours to carry | pin SHA + patch series; track upstream (0.2.0 at `d1dc45d`) |
| Peer attribution race in `getremoteaddr` (fixed upstream in 0.2.0) | wrong peer authorized | `tailscale_accept_with_addr` (patch 0002); never call `getremoteaddr` |
| Go runtime size | ~20 MB per binary (iOS stripped), ~25 MB collied | measure per slice; Go archives built with `-w` |
| Cold start in a background launch | Approve from lock screen fails | tsnet state cached, node started from cache (never a login), 20 s budget cap, follow-up local notification on every outcome; measure on device |
| Suspend/resume leaves stale DERP/magicsock state | slow reconnects | redial on foreground past a stale offline flag, rebind after 3 s, node restart after 10 s or at once when the UDP receive loop has stopped, resume diagnostics ([Client runtime](#client-runtime)) |
| Wi-Fi to cellular leaves the node bound to the old interface | no reconnect until a relaunch | `NWPathMonitor` feeds the interface to the node: rebind with a netmon refresh, probe or redial links, node restart after 15 s, path changes logged ([Client runtime](#client-runtime)) |
| herdr server load (status entry polls `pane.get` every 100 ms) | CPU with many panes | measure; fall back to `agent.list` polling if needed |
| UniFFI + Swift 6 | build friction | bindings compile in Swift 6 language mode; no async foreign traits on hot paths |
| APNs `.p8` is team wide | leak allows pushes to every app on the team | dedicated revocable key per machine; on macOS a Keychain item whose ACL trusts only the Developer ID signed collied; on Linux a systemd user credential, which any same-UID process can decrypt; payload never carries the nonce; limits in [threat-model.md](threat-model.md#same-uid-malware-on-the-mac) |
| APNs payload transits Apple | project names exposed | all alert and Live Activity display content (initial, update, end) is authenticated ciphertext; generic public text, opaque IDs, urgency, lifecycle, timing and size stay visible; nonces and decisions stay on the tailnet |
| Answering a blocked prompt outside approvals | bypasses nonce/expiry | collied refuses prompts while `blocked`; keys and typed answers reach a blocked agent only over the paired session, with authorization re-checked before each write; audited |
| Prompt delivered after agent exit | prompt runs as a shell command | foreground check before send; conditional input in herdr upstream |
| Retried mutations | duplicate prompts/tasks | `op_id` outcome cache |
| A paired phone writes files on the Mac | disk use, files an agent may read | size, rate, in-flight, 200 MiB and 1000 entry caps; private 0600 non-executable files in a 0700 cache dir; 24 h retention; [threat-model.md](threat-model.md#attachment-uploads) |
| Older app vs newer collied | decode failures | additive events, errors and statuses decode to `Unrecognized`; anything else bumps `PROTOCOL_VERSION` |
| Shell input from a paired phone | command execution as the user | off by default, `collied.toml` only; its own method class; a grant signed by a Secure Enclave key behind Face ID, per terminal, session and 5 minutes; the pane re-read before every write; audited without the text; [threat-model.md](threat-model.md#shell-input-from-the-phone) |

## Release sample workspace

Welcome and Settings open a clearly labeled, bundled sample workspace in Debug and Release builds. Its core is a synthetic in-memory implementation of the agent and approval interfaces, with no daemon, relay, pairing or network client; prompts, terminal input and approval decisions append visible local results. The sample authenticator is private to the view that builds this core; real approvals keep device-owner authentication. The sample creates no Live Activities or push registrations, and New task is disabled in it.

Reset replaces the sample session and Exit dismisses it. Sample screens suppress persistence and cache pruning for real preferences, agent drafts, viewed changes, inbox markers, snoozes and layout order. Arbitrary fixture files, developer launch flags and screenshot environment overrides stay Debug-only. No version bump: the sample uses no wire protocol.

## Desktop distribution

Desktop releases (collied for macOS and Linux, CollieBar, CollieTray) share the TestFlight version tag and exact source commit. TestFlight dispatches the desktop workflow from master with that tag and SHA, so the master-only signing environment accepts it; a protected master-only manual dispatch also publishes. One publisher owns each release: it rejects moved tags and mismatched source markers, keeps already uploaded signed packages when a draft is retried, and verifies a completed release without replacing its assets.

macOS packages are Developer ID signed, hardened and notarized, and the publisher and the installer check the daemon's strict signature and notarization online. Linux packages are checked against a glibc 2.39 floor. An installer runs only when the user runs it: it copies the daemon to a fresh regular `~/.cargo/bin/collied` (the path setup requires) and changes only the executable of an existing launchd plist or systemd unit, keeping its config, environment, data and stopped or running state. Linux packages may instead own a regular `/usr/bin/collied`, which setup and doctor accept when it is the running executable. Package operations run no root hooks against user homes or sessions.

[Desktop release downloads](desktop-releases.md) has the assets, installation, AUR adoption, release controls and validation gates. No protocol change or version bump.

## Push relay

The Worker and D1 implementation under `relay/` provides a bounded authenticated send contract, fixed topics, deterministic provider JWTs and atomic indexed installation and global quotas. Released builds deliver through the production relay, whose hourly Cron trigger runs its bounded retention cleanup. [relay.md](relay.md) has the contract, local measurements and retention bound. No version bump: no phone or daemon wire type changes.

## Attested push control validation

The relay authenticates installation enrollment with Apple App Attest (the pinned attestation root, and the CMS receipt checked independently against Apple Root CA G3), and later operations with assertions over a stateless five-minute HMAC challenge bound to the operation, exact destination, pairing, installation, environment and prior counter and epoch. One D1 transaction advances the replay and control counters and changes routes; a conditional zero-row update alone never authorizes a route. Every send checks registered generations and revocation epochs, and an APNs expired or unregistered destination revokes only the matching generation and destination.

The Swift client serializes control transactions across suspension points, keeps credentials in a ThisDeviceOnly Keychain record, pins the publisher endpoint and keeps pending offline revocations. It enrolls only for a paired daemon that reports relay mode through the negotiated capabilities; the daemon persists bounded redacted grants privately and reports its actual sender mode, so direct senders never trigger enrollment. [relay.md](relay.md#attested-control-contract) has the contract, limits, renewal and retention. No version bump: optional `relay_grant` registration fields are sent only with the implemented `relay_grants_v1` and `encrypted_display_v1` capabilities, the optional server-to-phone hello `push_mode` is omitted without relay negotiation, revision 26 remains the codec, and older peers never receive new request fields.

The isolated Free-plan benchmark failed the CPU gate for full App Attest verification, so production runs on Workers Paid with the single internal crypto actor and a provisional shared 250 ms CPU ceiling ([validation report](reviews/relay-free-tier.md)).

## Internal relay crypto prototype

Apple verification and APNs signing run in one internal SQLite Durable Object, separate from the public HTTP policy and D1 state. The actor derives verification policy from trusted deployment bindings, has no public HTTP handler, stores no application data and uses one fixed name; missing or exhausted compute fails closed, with no inline fallback. Shared per-location control and enrollment admission limits repeated verification from rotating sources; it is not a global spending cap. Local real-actor tests do not establish deployed Free-plan viability. See [relay.md](relay.md#internal-crypto-prototype). No version bump: the public relay and phone-daemon wire contracts are unchanged.

## Simulator relay isolation

The local Simulator relay ([simulator.md](simulator.md)) provisions a software P-256 identity into a private local D1 and a DEBUG Simulator container, through a separate entry that refuses enrollment and fixes sandbox APNs. Everything after it (control proofs, route commits, encrypted payloads, quotas) uses the production validators and, in a Miniflare harness, the production `RelayCrypto` class. Production has no local key, local send secret, synthetic enrollment verifier or unsupported-attestation fallback; its Worker graph excludes `relay/dev`, and a separately seeded development database never counts as evidence of production trust. The Swift identity import and mock destinations compile only for DEBUG Simulator, the daemon's loopback sender switch only with debug assertions, and the exact loopback ATS exception only into DEBUG Simulator bundles; Release uses the fixed HTTPS publisher endpoint. No protocol change or version bump.

## Isolated VM and Simulator tailnet

The [VM procedure](vm-simulator.md) runs the Debug daemon in an owned macOS guest and the Debug iOS Simulator on the host. An account-free testcontrol server, DERP relay and mock publisher on host loopback reach guest loopback ports 8788 to 8790 through task-key SSH reverse forwards; each side runs its own STUN server on 8791. No owner Tailscale account, APNs key, home directory or Keychain enters the guest.

`COLLIE_VM_TEST=1` works only in Debug macOS and Debug iOS Simulator Rust builds. It requires a private `collie-vm-test` directory and a bounded private, non-symlink `vm-tailnet.json` with a synthetic test auth key, fixes the control URL at `http://127.0.0.1:8789`, and selects a separate data directory, state folder and Keychain namespace. The Simulator checks the Debug capability symbol before initialization, so a Release-profile core fails closed. Pairing pins, mutual TLS, owner checks, registration and relay proofs run their normal code, and the harness confirms only its expected candidate at the daemon's ordinary prompt. Release and physical-device artifacts exclude the test entry. No protocol change or version bump.
