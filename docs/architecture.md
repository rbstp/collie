# collie architecture 🐑

```
iPhone (Collie.app)                                   Mac
┌───────────────────────────────┐                     ┌──────────────────────────────────────┐
│ SwiftUI (Swift 6, UI only)    │                     │ collied (launchd agent, user)        │
│  └ CollieCore (UniFFI)        │   tailnet (WG)      │  ├ tailnet node  tag:collie-mac      │
│     ├ protocol codec          │ ── WebSocket/JSON ─▶│  │   tailscale_listen :port only     │
│     └ tailnet node (libts)    │   dial only         │  ├ whois gate → paired node IDs      │
│ CollieWidgets  (Swift only)   │                     │  ├ protocol allowlist + audit log    │
│ ColliePush NSE (Swift only)   │◀── APNs ────────────│  ├ approvals (nonce, expiry, replay) │
└───────────────────────────────┘                     │  ├ APNs client (Keychain .p8, HTTP/2)│
                                                      │  └ herdr client ─▶ herdr.sock (0600) │
                                                      └──────────────────────────────────────┘
```

## Decisions (2026-10-03)

- Phone node is user-owned (interactive login); Mac node is `tag:collie-mac`. Authorization = paired `StableID` + configured owner user ID + untagged.
- libtailscale: upstream submodule pinned by SHA + patch series in `crates/tailscale-sys/patches`.
- iOS project generated by XcodeGen from `Collie/project.yml`; `.xcodeproj` is not checked in.
- APNs alert: herdr agent name (else agent kind) and workspace label. Never terminal text, snippet or nonce.
- macOS: arm64 only.

## herdr integration (verified against 0.9.3 source and live socket)

- The socket answers **one request per connection** (NDJSON, 5 s timeouts, 1 MiB line). collied opens a connection per call; long calls (`events.subscribe`, waits) get their own.
- herdr has **no auth**: same-UID means full control. collied's allowlist is the only boundary between the phone and every shell on the Mac.
- **No global agent-status stream.** `pane.agent_status_changed` is per pane and `pane.updated` does not fire on status changes. collied keeps one subscription connection: all lifecycle events plus one status entry per agent pane, rebuilt (subscribe, then `session.snapshot`) on `pane.created/closed/moved/exited/agent_detected`, `workspace.closed` and `events_lost`. An entry for a vanished pane goes silent rather than erroring, so rebuilds are driven by lifecycle events. A 5 s `agent.list` reconcile diffed on `state_change_seq` plus `ping` covers silent streams.
- Agents are keyed by `terminal_id`; `pane_id` changes on cross-workspace moves and is never sent to the phone. Status set is `idle | working | blocked | done | unknown`.
- **No output stream** in the JSON API. While a phone watches an agent (`agent.watch`), collied polls `agent.read {source: recent_unwrapped, format: ansi}` at about 4 Hz and pushes `agent.output` only when the content hash changes. `herdr terminal session observe` (binary protocol, exact version match) is a later option.
- `agent.prompt` refuses blocked agents, but herdr's `agent.send_keys` does not. collied rejects `agent.prompt` and `agent.send_keys` for an agent it sees as `blocked` (re-read with `agent.get` just before the call), so a blocked prompt can only be answered through `approval.decide`.
- Prompt text rejects ESC and C0/C1 controls because herdr pastes it with bracketed paste.
- Residual race (herdr side): herdr checks the foreground agent before queuing the text and the delayed Enter. If the agent exits in between, the shell receives the prompt. Closing it needs a conditional input in herdr (`expect: {terminal_id, state_change_seq, foreground pid}` on `agent.prompt` / `agent.send_keys`); to be proposed upstream.
- Mutations (`agent.prompt`, `agent.send_keys`, `task.new`) carry a client `op_id`; collied keeps a per-peer outcome cache so a retry after a dropped connection returns the first result instead of re-running.

## Tailscale (libtailscale, pinned commit, never tagged upstream)

- libtailscale `main@59d4bb8` as a git submodule; `tailscale-sys/patches` bumps tailscale.com v1.94.1 → v1.104.0 (latest, also fixes the Go 1.27 jsonv2 build break). Requires Go ≥ 1.27.1; builds use `GOTOOLCHAIN=local`, `-mod=readonly`, `-trimpath`, `-ldflags=-w`.
- **`tailscale_getremoteaddr` is unsafe for identity**: its map is keyed by the Go-side fd number, so with concurrent fd churn it returned the wrong peer 17% of the time in testing. Plus `tailscale_loopback` would open a 127.0.0.1 TCP listener (SOCKS5 + LocalAPI) on the Mac. Both are avoided with a small patch series applied by `tailscale-sys`:
  1. `tailscale_accept_with_addr` returns the peer `ip:port` carried in the same `sendmsg` as the fd; the racy fd-keyed map is no longer written.
  2. `tailscale_whois_json(sd, addr)` via the in-memory LocalClient (same mechanism as `tailscale_status_json`).
  3. Disable log upload to log.tailscale.com in Go (`TS_NO_LOGS_NO_SUPPORT`), since a c-archive snapshots the environment at load and a later `setenv` is invisible to Go.
  4. Guard the per-handle `lastErr` with a mutex: upstream writes it unsynchronized, a Go data race on a string when one handle is used from several threads.
  5. Keep the Go copy of each accepted fd open until C has received it: macOS's unix-socket GC can dispose of a socket whose only reference is in flight, and the peer's first bytes are lost (reproduced at about 1 in 150 connections).
  6. `tailscale_dial_timeout` and `tailscale_set_advertise_tags`.
  7. Socketpair proxy: non-blocking Go end so close always delivers EOF (a lost shutdown wakeup left readers hanging), cleanup exactly once, no fd-number-keyed map.
  8. `UserLogf` discarded: tsnet otherwise prints the interactive login URL to stderr every few seconds.
  9. Listener socket close waits for in-flight `sendmsg` (and patch 5 sends each fd inside its `os.File` `Control`), so no fd number can be reused under a send.
- Vendored module patches (`patches/<import path>/<file>.patch`, applied after `go mod vendor`; go.sum still verifies every module):
  - tailscale.com `ipn/ipnlocal/peerapi.go`: never open the kernel peerapi listener when netstack is present. Upstream binds it to every interface in netstack mode, which exposed a TCP port to the LAN. `crates/tailnet/tests/end_to_end.rs` and `crates/e2e` assert the process has no kernel TCP listener; `collied doctor` checks the running daemon the same way.
  - gvisor `tcp/connect.go` + `stack/stack.go`: a SYN reusing a 4-tuple in TIME-WAIT is handed to the forwarder instead of dropped (was the 63 s dial stall).
  - tailscale.com `wgengine/netstack/netstack.go`: close link queues before aborting endpoints so `tsnet.Server.Close` cannot hang.
- Gate per connection, before the WebSocket upgrade: whois(peer) must show an untagged, not shared-in node owned by the owner user. The owner is `[tailnet] owner_user_id` in `collied.toml` when set; otherwise the first phone confirmed at the Mac (`collied pair`, y/N showing node, StableID and login) fixes it in `peers.json`, and every later peer must match. Then:
  - paired `StableID` → full session (`hello` first, then the allowlist);
  - unpaired, while a locally opened pairing window is active → pairing-only session: `hello` and `pair.complete` only, one attempt, then close;
  - otherwise answer a fixed `403` without reading the request, close, and log; the phone treats 403 as final and stops retrying.
  - At most 4 live sessions per node: a fifth evicts that node's oldest (a phone reconnecting after iOS killed its sockets is never locked out). Global cap 64. Revocation cancels in-flight replies and re-checks authorization before every frame.
- Phone: `tailscale_dial` to the Mac's MagicDNS name, then checks via `tailscale_status_json` that the dialed IP belongs to the Mac node ID pinned at pairing. It never uses `tailscale_loopback` (iOS reclaims that listener on suspend).
- `tailscale_up` blocks until Running and is not cancellable; collied drives its own state machine from `status_json` (`BackendState`, `AuthURL`) and always calls `tailscale_start` first.
- Accepted fds are AF_UNIX socketpairs: await readability with `AsyncFd`, then `tailscale_accept`, then `set_nonblocking`, then `tokio::net::UnixStream`.
- magicsock binds a UDP socket on real interfaces: that is the WireGuard tunnel itself and is the one unavoidable non-tailnet socket. No TCP listener exists outside the tailnet.

## Approvals

The agent reconcile (`approvals.rs`) issues one approval per `blocked` `terminal_id`: `{approval_id (16 B), terminal_id, agent_label, workspace_label, snippet, options, nonce (32 B), created_at_ms, expires_at_ms}`. `expires_at_ms` is `created_at_ms + approval_ttl` (`ServerConfig`, `approvals::TTL` = 600 s; not a `collied.toml` key). The screen comes from `agent.explain` (matched rule id; never exposed, its output carries raw pane text) and `pane.read source=detection`.

- **Menu.** Only Claude Code's numbered select menu is answered: agent kind `claude` and a rule in `prompt::CLAUDE_MENU_RULES` (herdr claude manifest 2026.09.11.1). The menu is the last numbered block on screen, numbered from 1 without gaps, with exactly one `❯`. Anything else still raises an approval, with no options: the phone shows it, nothing can be decided.
- **Options.** Each decision (`approve`, `approve_always`, `deny`) maps to exactly one option label (`Yes` / `Yes, proceed` / `Yes, I trust`; `Yes, and don't ask again` and similar; `No` / `No, ...`). A decision matching zero or several options is not offered. Questions and free-form choices offer nothing.
- **Snippet and labels.** Snippet: the end of the dialog (for a menu, its last 12 body lines), at most 200 chars. Labels: at most 64 chars. Both have controls, bidi and format characters and box borders stripped.
- **Fingerprint.** `state_change_seq` only moves on status changes, so a new question under a still-`blocked` agent would not change it. The approval is bound to SHA-256 over the length-prefixed agent kind, rule id, `terminal_id`, agent session id and dialog region (last horizontal rule through the last option, with the cursor; spinners and status lines outside it are excluded). collied also keeps one fingerprint per option: the region as it reads with the cursor on that option.

### `approval.decide`

1. Rate limit per paired `StableID`: 1/s, burst 5 (`rate_limited`).
2. Claim. Any attempt on a pending approval burns it, whatever the result; a burned id answers `approval_already_resolved`, an unknown one `approval_not_found`.
3. Expiry, nonce (constant time), decision offered.
4. Re-read the screen: still `blocked`, same `state_change_seq`, same fingerprint, else `superseded`. Re-check that the peer is still authorized.
5. Keys, from a fixed set (`up`, `down`, `enter`, `esc`), never pane text:
   - Deny is a single `esc` when its label ends in `(esc)`, or on the folder trust prompt, whose "Esc to cancel" exits like "No, exit". It does not depend on the cursor.
   - Otherwise the arrows to the target option, 150 ms pause, re-read: the fingerprint must equal that option's cursor fingerprint (else `superseded`), peer re-checked, then `enter` in its own call. Arrows and Enter are never sent together: lost arrows would confirm another option. Digit shortcuts are not used; their select or submit behaviour varies across Claude Code versions.
6. Settle: poll `agent.list` every 250 ms for up to 3 s (`approvals::SETTLE`) for the agent to leave `blocked` or move its `state_change_seq`.

The decide budget is 6 s from the claim to the last key; no key is sent after it. With the 3 s settle, a decision answers in under 10 s.

| Outcome | When |
|---|---|
| `applied {decision, by}` | final key sent, agent left `blocked` within the settle |
| `unconfirmed {decision, by}` | final key sent (or its send timed out, it may have arrived), agent still `blocked` |
| `superseded` | fingerprint, seq or cursor mismatch; budget spent before the final key; bad nonce; decision not offered; peer no longer authorized; herdr failed; on reconcile, the agent left `blocked` or moved seq without a decision |
| `expired` | past `expires_at_ms`, at decide or on reconcile |

Every attempt is audited with its decision and result, including replays, rate-limited and expired ones; sent keys are logged as `terminal=<id> keys=<keys>`.

**Reissue.** A resolved approval is never reused. If the agent is still `blocked`, the next reconcile issues a new approval (new id and nonce), sent at once to live sessions. Its alert is rate limited per terminal: a new blocked episode, a changed screen (seq or fingerprint) or an expired previous alert always alerts; the same prompt reissued within 30 s of the last alert does not, so bad attempts cannot flood the phone. Alerts carry `terminal_id` as APNs collapse id and `thread-id`, so a new alert replaces the dead one on the phone.

## APNs

- `[apns]` in `collied.toml`: `key_id`, `team_id` (10 uppercase alphanumerics), `bundle_id`, and the key's location: `key = "keychain"` (the default when omitted) or the legacy `key_path` (a 0600 file owned by the user, opened without following symlinks; `collied doctor` warns). Both at once is an error. `collied apns test` sends a test alert to every registered device of a paired phone.
- Keychain item: generic password in the login keychain, service `dev.rbstp.collied.apns`, account = key ID. Its ACL trusts only the program that stored it, recorded by its designated requirement, so a rebuild signed with the same Developer ID Application identity (team `RM3UT3MMSR`) and identifier `dev.rbstp.collied` reads it without a prompt; any other program prompts or is refused.
- `just collied-install` builds collied in release, signs it (`Developer ID Application: ... (RM3UT3MMSR)`, identifier `dev.rbstp.collied`, hardened runtime, timestamp), installs it to `~/.cargo/bin/collied` as a fresh inode and restarts the launchd agent if it is loaded. A plain `cargo install` build is ad hoc signed and cannot read the item unattended.
- `collied apns import <AuthKey_ID.p8>`, run from the signed binary: needs `[apns]` ids, refuses a file named for another key ID, reads the file with the `key_path` checks, checks it is an ES256 key, stores it (an existing item is kept), reads it back and compares, rewrites `key_path` to `key = "keychain"` in `collied.toml` (atomic, same mode, never through a symlink), then asks y/N before deleting the file (only if it is still the same inode).
- `collied doctor` checks the signature (Developer ID requirement and identifier, `codesign` line), reads the item with user interaction disabled (what it reads is what the daemon reads unattended), signs a provider token as a dry run, and warns about any `.p8` left in `<data dir>/apns`.
- Tokens arrive by `push.register` and are stored per `StableID` in `push.json` (0600). Each token carries its environment (Debug builds: sandbox, TestFlight: production); one collied keeps a client for each. Every send re-checks the pairing (a registration racing a revoke never gets an alert); `Unregistered` and `BadDeviceToken` drop the token; revoking a peer forgets its tokens. Queue of 64 alerts, dropped when full; 10 s per send.
- Approval alert: push type `alert`, priority 10, `apns-expiration` = approval expiry, `apns-collapse-id` = `terminal_id`.

| Field | Value |
|---|---|
| `aps.alert.title` | herdr agent name, else agent kind, else `agent`; never the terminal title or a title the pane's program reports |
| `aps.alert.body` | `Blocked in <workspace label>` |
| `aps.thread-id` | `terminal_id` |
| `aps.mutable-content` | 1 (ColliePush) |
| `aps.category` | `APPROVAL`, only when both approve and deny are offered |
| `approval_id`, `node_id` | lookup keys for the app |

The payload never carries the snippet, terminal text or the nonce: it is a hint, and the decision goes over the tailnet.

## Lock-screen approval

- Category `APPROVAL` has two actions, Approve and Deny (no "approve always"), both `authenticationRequired`: iOS makes the user unlock the device first, then launches the app in the background without UI.
- `AppModel.decideFromNotification` holds a background task assertion and calls `decide_from_notification(node_id, approval_id, decision, budget_ms: 20000)`. The budget is capped at 20 s; 0 is refused. It is a one-shot session, independent of the connection supervisor: start the node from cached state (never a login), wait for the pinned Mac in the netmap, dial, `hello`, take the nonce from the cached snapshot or `approval.list`, then `approval.decide`. It never retries past the budget.
- Immediate `Unauthorized` (no waiting) when Tailscale is not set up on the phone, the node reports `NeedsLogin` or `NeedsMachineAuth`, the netmap violates the pin, or `hello` reports the phone unpaired.
- The report carries the outcome and per-step timings (node up, connect, lookup, decide), logged on device. A follow-up local notification in the same thread never claims success unless the outcome is `applied`:

| Background outcome | Follow-up | Opens the approval |
|---|---|---|
| `applied` | "Approved/Denied: agent. The agent moved on." | no |
| `unconfirmed` | "..., not confirmed": keys sent, agent still looks blocked | yes |
| `expired` | expired, nothing was sent | no |
| `superseded` | the prompt changed, nothing was sent | yes |
| `already_resolved`, `not_found` | no longer pending, nothing was sent | no |
| `unreachable` at `decide` | could not confirm the decision reached collied | yes |
| `unreachable` earlier, `unknown_machine`, `unauthorized`, `failed` | "Couldn't reach collied, open to decide" | yes |

- Tapping the alert itself opens the Approvals tab on that approval. In the app, every decision first passes LocalAuthentication (`deviceOwnerAuthentication`, a fresh `LAContext` each time, so one unlock never covers a later approval); nothing reaches collie-core otherwise.

## ColliePush (notification service extension)

- Pure Swift, never links CollieCore; shares only `Sources/Shared` and the App Group `group.dev.rbstp.collie` with the app. No network, no secrets.
- collie-core mirrors the last connection result per Mac node ID (`last_ok_ms`, `last_fail_ms`, nothing else) to `reachability.json` in the App Group. If the alert's `node_id` last failed, the NSE appends " (Mac may be unreachable, open collie to check)" to the body. Everything else passes through unchanged.

## iOS

- Only the app target links CollieCore (Rust + Go). The Go runtime starts at image load through a `__mod_init_func` initializer, so the widget extension and the NSE stay pure Swift and share an App Group container (reachability hint, Live Activity state).
- UniFFI 0.32.2 bindings compile in a Swift 5 language-mode package target (generated async foreign-trait code fails Swift 6 checking, uniffi-rs #2458/#2818); the app itself is Swift 6 strict.
- One xcframework, one static library per slice (device, simulator): the Rust staticlib bundles the Go c-archive linked by `tailscale-sys`.

## Client runtime (patterns taken from t3code)

- One connection supervisor in collie-core: backoff 3, 4, 8, 16 s; reset after 30 s connected; wait while offline; stop on auth failures. On foreground after 10 s or more in background, reconnect immediately (iOS suspends sockets without a close); shorter gaps get a 3 s probe.
- Snapshot plus sequence: `flock.snapshot` returns the `seq` it reflects; every event frame carries `seq`; the client drops `seq <= last applied`; unknown events still advance the cursor.
- Mutations are never replayed automatically; a retry reuses its `op_id`.
- Live Activities: t3code abandoned push-to-start as unreliable from background wakes. Start activities from the foreground, register update tokens on every foreground, priority 5 for routine updates and 10 for alerting ones, always set a stale date. Push-to-start stays a Phase 4 experiment, not a dependency.
- No prior art for authenticated lock-screen approve/deny (t3code only deep-links). collie's flow is described under [Lock-screen approval](#lock-screen-approval); its timings still need measuring on device.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| libtailscale unmaintained (no tags, bump PRs closed, tailscale.com v1.94.1) | security updates are ours to carry | pin SHA + patch series; bump tailscale.com in the patch; track upstream releases |
| Peer attribution race in `getremoteaddr` | wrong peer authorized | patch 1; never call `getremoteaddr` |
| Go runtime size | ~20 MB per binary (iOS stripped), ~25 MB collied | measure per slice; Go archives built with `-w` |
| Cold start in a background launch | Approve from lock screen fails | tsnet state cached, node started from cache (never a login), 20 s budget cap, follow-up local notification on every outcome; measure on device |
| Suspend/resume leaves stale DERP/magicsock state | slow reconnects | re-dial on foreground; time it in diagnostics |
| herdr server load (status entry polls `pane.get` every 100 ms) | CPU with many panes | measure; fall back to `agent.list` polling if needed |
| UniFFI + Swift 6 | build friction | Swift 5 mode bindings target; no async foreign traits on hot paths |
| APNs `.p8` is team wide | leak allows pushes to every app on the team | dedicated revocable key; Keychain item whose ACL trusts only the Developer ID signed collied; payload never carries the nonce; limits in [threat-model.md](threat-model.md#same-uid-malware-on-the-mac) |
| APNs payload transits Apple | project names exposed | alert carries agent and workspace labels only, never terminal text or the nonce; detail fetched over the tailnet |
| Answering a blocked prompt outside approvals | bypasses nonce/expiry/audit | collied refuses prompt/keys while `blocked` |
| Prompt delivered after agent exit | prompt runs as a shell command | foreground check before send; conditional input in herdr upstream |
| Retried mutations | duplicate prompts/tasks | `op_id` outcome cache |
| Older app vs newer collied | decode failures | additive events/errors/statuses decode to `Unrecognized`; anything else bumps `PROTOCOL_VERSION` |
